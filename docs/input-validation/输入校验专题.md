## 1. 问题与目标

### 1.1 要解决的问题

- **前端**：全仓 `src/frontend/src` 中 `maxlength` / `minlength` / `pattern` / `required` 使用数为 **0**（唯一命中是 `utils/jsonSchema.js` 的 JSON Schema 关键字白名单，与输入框无关）。绝大多数输入只做 `trim()` + 非空，路径、URL、密钥、提示词、聊天输入完全无约束。
- **后端**：存储引擎为 **bbolt 单文件 KV**（[db.go](../../src/lib/data/db.go)），没有 DDL、没有列类型 / NOT NULL / CHECK / 外键 / VARCHAR(n)，业务约束只能靠代码。现状是「按域选择性校验」：文件化域（知识库 / 记忆 / 场景 / MCP）路径安全较扎实，而 **LLM 配置、项目配置 KV、路径配置、会话/任务状态** 几乎"来者不拒"。
- **结果**：空名、超长名、非法 URL、非法路径、越界数值可以一路落库；运行期靠"读不到 / 解析失败就回落默认"吸收，表现为"保存成功但无效"。

### 1.2 目标（可验收）

1. 界面**每一个**可写输入都有明确的四级判定：**必填（M）/ 长度（L）/ 格式（F）/ 业务关联（B）**，并在组件上可逐项核对。
2. 后端**每一个**写库/写文件入口在落盘前复验 M/L/F/B 四类，**后端是唯一可信边界**（前端校验仅用于防误操作）。
3. 校验失败**可定位、可提示**：返回明确错误（字段 + 原因），不使用静默截断 / 静默丢弃。
4. 存量非法数据**不因新校验而崩溃**：校验只加在写侧，读侧保持现有兜底。
5. 消息面**零变更**（失败走既有 `{ok:false,error}` 信封），不触发 [61-消息一览](../spec/60-reference/61-消息一览.md) 冻结。

### 1.3 非目标

- 不做 WAF / 注入防护专项（另属安全域）。
- 不做存量数据批量清洗（只在加载侧容忍 + 编辑保存时自然收敛）。
- 不追求"前端一处配置全站生效"（长文本与短名称上限不同，禁止在通用组件设全局默认上限）。

## 2. 校验口径（四级定义）

| 级别 | 定义 | 前端 | 后端 | 失败行为 |
|---|---|---|---|---|
| **M 必填** | 不允许空 / 纯空白 | 输入框红框 + 保存按钮禁用或提交前提示 | 落盘前拒绝 | 返回错误，不写 |
| **L 长度** | 字符数上下限（按 Unicode 字符计，非字节） | `maxlength`（原生可用的控件）+ 提交前长度判断 | 落盘前按同一上限复验 | 返回错误（**不静默截断**） |
| **F 格式** | 结构合法性（URL / 绝对路径 / 标识符 / 数值 / 文件名） | 正则 / `type=number` / 提交前校验 | 同规则复验（同一正则集中定义） | 返回错误 |
| **B 业务关联** | 与其他对象的关系（唯一性、引用存在、归属、状态机、上限） | 能本地判的本地判（如重名） | 必须复验（前端不可信） | 返回错误 |

> 口径原则：**前端校验 = 体验，后端校验 = 正确性**。任何一条 B 类规则不得只在前端实现。

## 5. 后端问题清单

### 5.1 链路与兜底事实

```
MQ 信封(persist/envelope.go) → facade → internal/<域> → data.Table.Insert/Update/Upsert/ReplaceAll → bbolt
```

- 唯一落盘出口：[table.go `putRecord`](../../src/lib/data/table.go#L352-L368)，值 = JSON 文本，**无列类型、无长度语义**。
- DB 层能兜底的只有：**主键唯一**（`Insert` → `ErrExists`）、**事务原子性**、**索引一致性**；NOT NULL / CHECK / 外键 / VARCHAR(n) 全部不存在。
- 信封层：JSON 解析失败被忽略（`persist.go:497-499`）、类型不符取零值；data 请求不携带 uid（身份校验只在 instance-claim 一层）。

## 8. 边界与验收

- **边界**：校验只在写侧；读侧继续容忍脏数据（避免"打开即报错"）。前端校验失败不发送 MQ；后端校验失败返回既有错误信封。
- **不做**：不引入 JSON Schema 驱动的通用表单框架（现有字段量不值得）。
- **验收（可机器判定）**：
  1. 前端：对 §4 每个字段注入超长 / 空 / 非法格式 → 不发出 MQ（或发出后被拒）+ 有可见提示。
  2. 后端：绕过前端直接发 MQ（非法值）→ 返回 `ok:false` 且 **DB/文件无变化**。
  3. 存量：含非法旧值的配置可正常打开、列表不报错。
  4. `rg -n "maxlength" src/frontend/src` 覆盖 §3 命名类字段；后端 `go test` 新增用例全绿。
