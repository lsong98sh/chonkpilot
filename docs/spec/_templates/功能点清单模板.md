**场景表约定**

- 必填列：`ID` / `场景名` / `类型` / `前置条件`（无则写“无”）/ `操作步骤` / `预期结果` / `测试`。
- 可空列：`穿透点`（= 代码位置 / 消息主题 / 分支条件；无则写 `—`）。
- `类型` 取值见 [30-FP分级规范 §7](../30-function-points/30-FP分级规范.md) 情况清单；若使用“正常 / 边界 / 异常 / 恢复 / 并发 / 安全”等短标签，须能对应到 §7 维度。

**「测试 / TC」列说明**

- 含义：该**场景**对应的测试用例编号，格式 `TC-<分类码>-<功能点序号>-<场景序号>`，例 `TC-WIN-001-01`。
- 与「可测性」的分工：`可测性` 是**功能点级**的验证等级（自动 / 半自动 / 手动 / 不可测）；`测试` 是**场景级**的用例锚点。二者不可互相替代，也不得在 `测试` 列只写“自动 / 手动”。
- 维护场景级用例时本列必填 `TC-*`；若项目采用 [51-FP与测试映射](../50-testing/51-FP与测试映射.md) 的**分类级**映射、不维护场景级编号，则本列统一写 `—`（不得留空），并在该功能点「可测性」中注明“测试资产见 51”。
