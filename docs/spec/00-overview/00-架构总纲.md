## 1. 产品定位

ChonkPilot 是 **Windows 桌面端 AI 助手 / IDE 工具**：

- 后端 Go，前端 Vue；**唯一宿主 = GUI**（**go-webview2** 定制宿主，无 Wails），核心全 lib 化。
- 前端 `dist` 经 `go:embed` 打进 exe，最终单文件发布。
- **MQ 消息面是唯一交互通道**（devtool 按钮除外）：前端→后端只有 `POST /publish`，无 `/call` RPC；请求-响应通过 `publish + Promise 收集结果` 实现。
- 架构 = **分层单体**：核心全部是 lib，由唯一宿主 `src/desktop` 内嵌装配。

## 5. 通信模型

### 5.1 MQ（唯一跨组件通道）

- 自建门面 `framework/host/src/core/mq`（类型别名 → 实现 `chonkpilot-framework/plugin/src/runtime/bus`）：`Emit(*Future)/On` 为**唯一发送入口与订阅**（Go/JS 对称）。
  - 不 Await = 事件（fire-and-forget）；Await = 请求-响应（订阅者写回 `Result`，发起方 await 收集，无独立 RPC `Call`）。
- **进程内内存 MQ 为唯一实现**（宿主内 server / gateway / mcp-server 共享同一总线；**插件为进程外**，经插件桥/UDS 接入，不共享宿主内存总线）。
- **主题**：业务写**相对 kebab `域-动作`**（`session-start`、`task-done`、`tool-call`）；前缀 `chonk.` 由宿主在 `mq.New(Prefix)` 注入一次，业务代码不出现 `chonk.` 字面。
- **上下文**：`instance_id` 由**总线信封/前端 mq 统一注入**（跨端信封与不可变元数据必带；`session-start` 的 `instance_id` 属 `x-chonk.topics` 不可变字段），**不等于每个 payload 字段都显式携带**；`instance-register` 事件自身带 `instance_id`（单实例同样携带）。（2026-11-04 核对）

### 5.2 HTTP 面

| 端点 | 用途 | 状态 |
|------|------|------|
| `POST /publish` | 消息面（事件 + 请求-响应统一入口） | ✅ 唯一业务入口 |
| `/show/` | 资源字节流（直接读文件返回流，不走 mq） | ✅ 唯一业务豁免 |
| `/plugin-ui/` · `/plugins/<id>/api/<action>` | 插件 UI 静态资源与插件动作面（前端 → 插件，非 MQ） | ✅ |
| `/themes.css` · `/api/log/tail` · `/api/log/sources` | 主题资产、宿主日志查询 | ✅ |
| `--test-port` 端点 | 测试驱动（`/eval` `/click` `/input` …） | ✅ 测试专用 |

> `/call`（dataCalls ~40 方法）与 `/events` 为遗留 RPC 面，**已清零**（全仓无 handler）；目标态无 RPC。（2026-11-04 核对）

## 6. 关键边界与状态模型

- **session / turn → 会话层**：gateway 只把 session/turn 当执行上下文参数，不持有其语义。
- **tool_pair → 会话层（调用层）**：回合产物，创建/回填/续轮全在会话层；gateway 收「执行请求」发「执行结果事件」，不感知 tool_pair。
- **任务树 → tasktree 表**（server 数据面权威落库，`parent_node_id` + `top/parent` 索引）；gateway 执行池（`execPool`）只持**执行态**（内存五态 + `task-done` 事件），树/重试/取消编排在 server。
- **变更探测 → 文件服务**；**文件读写 → 工具层**（路径一律全路径）。
- **安全域** = gateway **Low IL + Job 写隔离**（stdio 下游/插件进程；`chonkpilot-util/sandbox`）；agentbox 沙箱已删除 → 见 [14-安全域-agentbox](../10-architecture/14-安全域-agentbox.md)。（2026-11-04 核对）
- **实例边界**：单实例与多实例**统一以 instance-id 标识**；数据/文件按 workdir / datadir 分根；主题不带 workdir 分段。
- **状态模型**：只有数据层持有**权威状态**（持久化）；gateway / 会话层 / 文件服务 / 插件仅持**运行态**，UI 持**展示态**——崩溃可重建、从数据层恢复。

## 7. 数据与配置层级（概览）

一句话：**三级库 + 一级资源**。

| 级别 | 位置 | 存什么 |
|------|------|--------|
| 系统 | 随 exe 发布的 embed 资源 + `<exeDir>/capability/`（**无 db**） | 出厂默认值、契约、出厂能力 |
| 用户 | `~/.chonkpilot/chonkpilot.db` | LLM 定义、用户级配置、场景（MCP 为 `capability/mcps/` 文件） |
| 项目 | `<workDir>/.chonkpilot/chonkpilot.db` | 团队共享配置、项目能力 |
| 项目用户 | `<workDir>/.chonkpilot/users/<OS 用户名>/chonkpilot.db` | 会话数据、个人本机态（窗口/布局） |

- fallback 按 key：`prjusr → prj → usr → 系统资源`，首个命中生效；删本层 key = 恢复继承。
- 多记录集合（llms / mcps / scenarios）走**专用表或文件**，不参与逐 key 继承；"选哪个"才是可继承参数 key。

> 完整规则见 [02-配置层级](02-配置层级.md)。

## 8. 端到端数据流（概览）

一次用户消息的主链路：

```text
宿主：GUI(前端 v-mq)
  └─ POST /publish ─▶ 会话层(server)
        ├─ 读 session/turn（经数据面）
        ├─ 构建上下文 → 调 LLM
        ├─ LLM 请求工具 → mq: tool-call ─▶ mcp-gateway（唯一入口）
        │      └─ inprocess mcp-server（.tool.md 契约）─ runtime=builtin ─▶ 进程内执行（或插件 MCP server）─ JSON 结果
        ├─ 收 mcp-tasks-report / tool-result（MQ 回环）→ 回填 tool_pair → 续轮
        └─ 落库：message / turn / tasktree（经数据面 persist）
  ◀─ data-*-refresh / 事件推送 ─ GUI 更新
```

完整时序（含取消、异步、后台、压缩、通知）见 [01-端到端数据流](01-端到端数据流.md)。
