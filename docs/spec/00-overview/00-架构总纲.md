## 1. 产品定位

ChonkPilot 是 **Windows 桌面端 AI 助手 / IDE 工具**：

- 后端 Go，前端 Vue；**两种宿主**：**GUI**（**go-webview2** 定制宿主，无 Wails）与 **CLI**（console），共享同一套 lib（核心全 lib 化）。
- 前端 `dist` 经 `go:embed` 打进 exe，最终单文件发布。
- **MQ 消息面是唯一交互通道**（devtool 按钮除外）：前端→后端只有 `POST /publish`，无 `/call` RPC；请求-响应通过 `publish + Promise 收集结果` 实现。
- 架构 = **分层单体**：核心全部是 lib，按编译参数 / 内嵌关系组合成不同运行形态。

## 2. 运行形态

| 形态 | 组成 | 状态 |
|------|------|------|
| **GUI 单一应用** | `src/desktop`（桌面单体壳）内嵌 server lib（含 gateway + mcp-server + 插件），同进程内存 MQ；宿主实现 = `src/lib/gui`（两壳共用） | ✅ 默认 / 主力 |
| **server 常驻** | server lib + exe（console 常驻；Windows service 为目标态）；`--manage-addr` 暴露 mcp 管理端点 | ✅ console |
| **MCP 契约服务** | `src/lib/mcp-server` lib（导出 `RegisterContracts`，由 server/gateway 装配进自建 `mcp.Server`）；独立 exe（`src/others/mcp-server`）走 `--http`/`--stdio`/`--service` | ✅ 两种 |
| **工具层 executor** | `src/lib/mcp-tools` 三个分类 exe（core / desktop / browser），为**执行层**：由 mcp-server **spawn-on-call**、用完即退，**with agentbox**（安全域/沙箱，🔵） | ✅（agentbox 🔵） |
| **CLI 单体** | `src/desktop/cli` console 宿主，同 lib 集（AsyncMode: never），无前端 / 无 WebView2（"临时 data-dir + 会话隔离"已实现，见 [2A-cli](../20-modules/2A-cli.md) §9） | ✅ |
| **分布式多机** | 去中心化 MQ（自研）之上的多实例部署 | ⏳ 远期 |

> 组件间一律经 mq 交互（**单体亦然**）。唯一豁免：GUI↔server 的 `/show` 字节流，以及测试端口端点白名单。

> **（2026-09-16 后：目标形态与去中心化 MQ 原则 —— 用户口径「目前原则是：前端加上 gui 在客户端，服务器是 llm / gateway / filesys / data 等合在一起一个 exe 作为服务。消息可以通过 http 协议在 gui 和 llm server 之间直接路由。这就是我说的去中心化 mq。内部采用内存，外部用 bridge。」）**
> **目标形态**：**客户端 = 前端 + GUI**；**服务端 = llm + gateway + filesys + data 等合并为一个 exe（服务）**；**消息经 HTTP 在 GUI 与 llm server 之间直接路由**。
> **原则 =「内部采用内存，外部用 bridge」**（进程内内存总线 + 跨端 bridge(HTTP) 路由），即去中心化 MQ 的落地语义。**上表各形态为当前实现 —— 当前仍是单体合并单进程**，客户端/服务端分离为**演进方向**（消息面不变）。见 [42 §2 (72)](../40-roadmap/42-决策记录.md) · [11-MQ与消息 §1/§7](../10-architecture/11-MQ与消息.md) · [40 T-24](../40-roadmap/40-演进计划.md)。

## 4. 分层与依赖（自底向上，依赖单向）

| 层 | 职责 | 依赖 | 对外形态 |
|----|------|------|---------|
| 0 基建（MQ） | 事件（pub/sub）+ 请求-响应（publish + Promise）统一通道 | — | 内存 MQ |
| 1 数据层 | 三级 chonkpilot.db + Table/Query DAO + 迁移/seed；**权威状态唯一持有** | workdir / datadir 分根 | lib API + 变更消息 `data-*-refresh` |
| 2 mcp-gateway | **工具唯一入口**：Registry / Provider / TaskManager、异步/后台/取消、第三方代理；内嵌 mcp-server 扫描 `.tool.md`（executor 由 mcp-server 按需 spawn；gateway 只做路由/聚合，不 spawn executor；with agentbox 🔵） | 纯运行态（无 DB） | mq 方法面 + `task-done`/`tool-changed` 事件 |
| 3 会话层（LLM 服务层） | 回合执行 + tool_pair 回填 + 任务树编排落库 | 1、2 | server lib/exe |
| 4 文件服务 | 文件监听（变更）+ 目录列表/文件操作；**不含 /show** | workdir 分根 | `filesys.*` 消息 |
| 5 插件 | 内嵌 lib Hook（compress / history）；KB（原语文件）；CB（🔵） | MQ 事件 | 事件订阅；工具注入/UI 内容（🔵） |
| 6 UI | IDE / CLI，纯消费者 | 3、1、4 | 接入层（薄壳） |

依赖方向全部单向；唯一回环（工具完成 → 回合继续）经 MQ 事件解耦。

## 5. 通信模型

### 5.1 MQ（唯一跨组件通道）

- 自建门面 `src/lib/core/mq`：`Emit(*Future)/On` 为**唯一发送入口与订阅**（Go/JS 对称）。
  - 不 Await = 事件（fire-and-forget）；Await = 请求-响应（订阅者写回 `Result`，发起方 await 收集，无独立 RPC `Call`）。
- **进程内内存 MQ 为唯一实现**（GUI / CLI / server / gateway / 插件共享同一总线）。
- **主题**：业务写**相对 kebab `域-动作`**（`session-start`、`task-done`、`tool-call`）；前缀 `chonk.` 由宿主在 `mq.New(Prefix)` 注入一次，业务代码不出现 `chonk.` 字面。
- **上下文**：payload 一律携带 `instance-id`（含 register，单实例同样携带）。

### 5.2 HTTP 面

| 端点 | 用途 | 状态 |
|------|------|------|
| `POST /publish` | 消息面（事件 + 请求-响应统一入口） | ✅ 唯一业务入口 |
| `/show/` | 资源字节流（直接读文件返回流，不走 mq） | ✅ 唯一豁免 |
| `--test-port` 端点 | 测试驱动（`/eval` `/click` `/input` …） | ✅ 测试专用 |

> `/call`（dataCalls ~40 方法）与 `/events` 为遗留 RPC 面，**已清零 / 待核对**，目标态无 RPC。

## 6. 关键边界与状态模型

- **session / turn → 会话层**：gateway 只把 session/turn 当执行上下文参数，不持有其语义。
- **tool_pair → 会话层（调用层）**：回合产物，创建/回填/续轮全在会话层；gateway 收「执行请求」发「执行结果事件」，不感知 tool_pair。
- **任务树 → tasktree 表**（server 数据面权威落库，`parent_node_id` + `top/parent` 索引）；gateway TaskManager 只持**执行态**（内存五态 + `task-done` 事件），树/重试/取消编排在 server。
- **变更探测 → 文件服务**；**文件读写 → 工具层**（路径一律全路径）。
- **安全域** = agentbox 沙箱（🔵，根限定 workdir）→ 见 [14-安全域-agentbox](../10-architecture/14-安全域-agentbox.md)。
- **实例边界**：单实例与多实例**统一以 instance-id 标识**；数据/文件按 workdir / datadir 分根；主题不带 workdir 分段。
- **状态模型**：只有数据层持有**权威状态**（持久化）；gateway / 会话层 / 文件服务 / 插件仅持**运行态**，UI / CLI 持**展示态**——崩溃可重建、从数据层恢复。

## 7. 数据与配置层级（概览）

一句话：**三级库 + 一级资源**。

| 级别 | 位置 | 存什么 |
|------|------|--------|
| 系统 | 随 exe 发布的 embed 资源 + `<exeDir>/capability/`（**无 db**） | 出厂默认值、契约、出厂能力 |
| 用户 | `~/.chonkpilot/chonkpilot.db` | LLM/MCP 定义、用户级配置、场景 |
| 项目 | `<workDir>/.chonkpilot/chonkpilot.db` | 团队共享配置、项目能力 |
| 项目用户 | `~/.chonkpilot/data/<prj-id>/chonkpilot.db` | 会话数据、个人本机态（窗口/布局） |

- fallback 按 key：`prjusr → prj → usr → 系统资源`，首个命中生效；删本层 key = 恢复继承。
- 多记录集合（llms / mcps / scenarios）走**专用表或文件**，不参与逐 key 继承；"选哪个"才是可继承参数 key。

> 完整规则见 [02-配置层级](02-配置层级.md)（依据 2026-09-10 冻结记录整理）。

## 8. 端到端数据流（概览）

一次用户消息的主链路：

```text
宿主：GUI(前端 v-mq) 或 CLI
  └─ POST /publish ─▶ 会话层(server)
        ├─ 读 session/turn（经数据面）
        ├─ 构建上下文 → 调 LLM
        ├─ LLM 请求工具 → mq: tool-call ─▶ mcp-gateway（唯一入口）
        │      └─ inprocess mcp-server（.tool.md 契约）─ 由 mcp-server spawn ─▶ 工具层 executor exe（with agentbox 🔵）─ stdout JSON
        ├─ 收 task-done（MQ 回环）→ 回填 tool_pair → 续轮
        └─ 落库：message / turn / tasktree（经数据面 persist）
  ◀─ data-*-refresh / 事件推送 ─ GUI / CLI 更新
```

完整时序（含取消、异步、后台、压缩、通知）见 [01-端到端数据流](01-端到端数据流.md)。
