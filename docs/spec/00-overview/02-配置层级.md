## 1. 目标与原则

**一句话**：配置 = **四级库/资源**（系统 / 用户 / 项目 / 项目私有），按 key 逐级 fallback。

| 原则 | 说明 |
|------|------|
| 三级一机制 | usr / prj / prjusr 同一套 DAO / schema / 迁移代码，仅**数据根不同** |
| 系统级不落库 | 系统级 = 代码常量 + `<exeDir>/capability/`（含出厂场景 `<exeDir>/capability/scenarios/`；出厂数据源 `src/initdata/`）；配置页只读展示（**capability 文件树四级均可读写**，见 §7.2） |
| 一 key 一决策 | config 表多为标量 / 极小 JSON；多记录集合走专用表或文件树 |
| 覆盖即可见 | 分层值 = **整值覆盖**（非深合并）；删除本层 key = 恢复继承上级 |
| 内容库独立 | codegraph 索引保持独立目录，不并入 chonkpilot.db |
| 不做历史迁移 | 旧 `config.json` / 旧版 db 不导入（如需要另做一次性工具） |

## 2. 三级库 + 一级资源

| 级别 | 载体 | 路径 | 可编辑 |
|------|------|------|:---:|
| **系统** | 资源（**无 db**） | 代码常量 + `<exeDir>/capability/`（含 `<exeDir>/capability/scenarios/`；源 `src/initdata/`） | 资源文件可改；配置页只读展示 |
| **用户**（usr） | `chonkpilot.db` | `~/.chonkpilot/chonkpilot.db` | ✅ |
| **项目**（prj） | `chonkpilot.db` | `<workDir>/.chonkpilot/chonkpilot.db` | ✅（团队共享，可入版本库） |
| **项目用户**（prjusr） | `chonkpilot.db` | `~/.chonkpilot/data/<prj-id>/chonkpilot.db` | ✅（本机本项目） |

> 系统级"无库"是**推翻性决策**（早前"系统级也有库"作废）。

## 3. fallback 解析（按 key）

```text
读：prjusr.<key>  →  prj.<key>  →  usr.<key>  →  系统默认（资源/常量）
                 首个命中即生效
写：只写当前层（不写上级、不写下级）
重置：删除本层该 key → 自动回落继承
悬空引用：被引用对象（provider / mcp / 场景）已删 → 清本层引用、沿链回落
```

注意：

- **整值覆盖**，不做深合并（`window.width` 是独立 key，不存在部分合并）。
- **多记录集合**（`llms`）不参与逐 key fallback；**"选哪个"**（如 `defaultLLM`）才是可继承 key。
- **无 fallback 的项**：凭据类（apiKey 仅在 usr 定义中）、prj/prjusr 专属数据（会话、任务树、个人运行态）。

---

## 4. 键粒度

- 单值 → config 表一个 key，值 `{"v": "..."}`。
- 结构体**必须拆 key**：窗口几何拆 `window.x` / `.y` / `.width` / `.height` / `.maximized`，**不存整块 JSON**。
- 数组型（`skip_dirs` 等）保留为单 key 的 JSON 数组字符串。

## 6. 物理布局与路径解析

### 6.1 目录布局

```text
~/.chonkpilot/                          ← usr 数据根
├── chonkpilot.db                       # 用户配置（llms/偏好）
├── 用户偏好.md                          # 记忆库用户偏好类别（唯一用户级记忆文件）
├── capability/                         # 用户级能力面（6 扁平子目录，见 §7.2）
│   ├── prompts/ tools/ resources/ skills/ agents/ scenarios/
├── data/<prj-id>/                      ← prjusr 数据根（每项目一份）
│   ├── chonkpilot.db                   # 会话/任务树/快照/个人运行态（codegraph.status / vfts.status 亦落此库）
│   ├── capability/                     # 项目私有级能力面（6 扁平子目录，见 §7.2）
│   ├── logs/                           # GUI 宿主文件日志（gui.log，2MiB 滚动）
│   └── tmp/uploads/                    # 附件上传 / 截图落点（gui.upload / gui.capture）
└── tools/                              # 外部工具链安装（既有）

<workDir>/.chonkpilot/                  ← prj 数据根（随项目走；= `-data-dir` 缺省值）
├── chonkpilot.db                       # 团队共享配置（含 project-id；vfts 文件清单 file_list 亦在此库）
├── capability/                         # 项目级能力面（6 扁平子目录，见 §7.2）
├── codegraph/                          # codegraph 索引（index.db = bbolt 单文件库；元信息 meta.json）
├── vfts/                               # vfts 全文索引（meta.json + collection/）
├── memory/                             # 记忆库项目级类别（<类别>.md）
└── backup/                             # 「导入 / 恢复出厂前」自动备份（chonkpilot-config-backup-*.json）

<exeDir>/capability/                    ← 系统级资源（随发布）
├── prompts/ tools/ resources/ skills/ agents/ scenarios/   # 6 扁平子目录（scripts 亦在 prompts/ 下）
└── executors/chonkpilot-*-executor.exe # 内置执行器（core/desktop/browser）
```

> ① capability **四级同构**：系统 `<exeDir>/capability/` · 用户 `~/.chonkpilot/capability/` ·
>    项目 `<workDir>/.chonkpilot/capability/` · **项目私有 `~/.chonkpilot/data/<prj-id>/capability/`**；
>    每级下 **6 个扁平子目录**：`prompts/` `tools/` `resources/` `skills/` `agents/` `scenarios/`
>    （**删除**旧 `knowledge/{skills,prompts,resources}` 归并层；旧 `capability/{tools,knowledge/...}` 作废）。
> ② **场景根移入 capability**：删除与 capability **平级**的独立 `scenarios/` 根 →
>    场景根 = `<级别根>/capability/scenarios/`（`<exeDir>/capability/scenarios/` 等）。
> ③ **四级均可读写**（原「系统级只读」作废）。
> ④ 同名定位/覆盖优先序 = **项目私有 > 项目 > 用户 > 系统**。
> ⑤ CLI 数据根三态语义见 §6.3（取代旧「恒用临时目录」）。
> ⑥ **每级 capability 下再增 `mcps/`**（MCP server 配置：一个 server 一个文件 `<名>.json`；**非原语类型**，不入 6 类知识库原语）——上列「capability/」目录树中各 `capability/` 下均含 `mcps/`，见 §7.3。

> **出厂数据唯一源 = `src/initdata/`**（**不再 go:embed**）：构建脚本把源同步到产物目录。
> 出厂源 = `src/initdata/capability/{prompts,tools,resources,skills,scenarios}`（已扁平化：删 `knowledge/` 归并层、场景根移入 capability）；
> 构建同步 = `build-mcp-server.ps1` 铺 `capability/{prompts,tools,resources,skills}`、
> `build-desktop.ps1` 场景落 `dist/desktop/capability/scenarios/`、出厂包 = 单包 `capability-<ver>.zip`（+ `initial.zip`）。
> executor `--help` 亦从磁盘读契约（`<exeDir>/capability/tools/<cat>/`，`--root` 可覆盖）。

> **`logs/` 与 `tmp/uploads/` 归属（B 方案，desktop 缺省即 `data_dir == ""`）**：**日志 `logs/`**（宿主文件 sink `gui.log`）与**附件/截图 `tmp/uploads/`**（`src/lib/gui/bridge/upload.go` · `capture.go` → `bridge.uploadRoot()`）均**随 prjusr 数据根**、**不再落 prj 数据根**；**`-data-dir` 显式给出时**（含 CLI 临时形态）prj 与 prjusr 同根 → `logs/` 与 `tmp/uploads/` 落该数据根。
> 补登 `vfts/`（`src/vfts/server/workspace.go:60-62`）、`memory/`（`src/lib/data/persist/persist_memory.go:130`）与 usr 根 `用户偏好.md`（同文件 `:9`）。


### 6.2 prj ↔ prjusr 绑定（prj-id）

```text
解析 prjusr 数据根：
  1. 打开 <workDir>/.chonkpilot/chonkpilot.db
  2. 读 config 表 key `project-id`
     ├─ 不存在 → 生成 uuid(v4)，写入 prj 库（仅首次）→ prjusr 根 = ~/.chonkpilot/data/<uuid>/
     └─ 存在   → prjusr 根 = ~/.chonkpilot/data/<值>/
```

- `project-id` **必须、不可改**；被删除 = 视为会话重置（旧 uuid 目录需手动清理）。
- **不做** usr 侧映射表；目录移动/改名后仍能找回数据。

### 6.3 CLI 形态

**数据根三态语义（方案 B，D-45 · 2026-10-01 反转）**：

| `--data-dir` | 语义 |
|---|---|
| **不传** | **临时隔离（默认）**：tmp 建空根 + 复制 usr/prj/prjusr 三级**配置**（`usr` 覆盖、`prj` 后被 `prjusr` 覆盖；含 `llms` 表，不含会话数据），退出即弃——批处理不污染真实配置、不与 GUI 冲突 |
| **`--data-dir=`**（显式留空） | **真实根**（与 GUI 一致：prj=`<workDir>/.chonkpilot`、prjusr=`~/.chonkpilot/data/<id>`），**会话数据写入**；参与 work-dir 占用校验 + prjusr 试开冲突报错（I-74 · D-45） |
| **`--data-dir=<路径>`** | 该路径作 **prjusr 数据根**（`data.SetDataHome` 重定位）；prj 仍按 `<workDir>/.chonkpilot`（无则 tmp 空根，不污染 cwd）（**不新增** `--prjusr-dir`） |

- 「传空」与「未传」由 `flag.Visit` 判定（`flag` 包无法区分，需显式判定参数是否出现）。
- 实现落点 `src/lib/cli`（`PrepareDataDir`/`ResolveDataMode`；I-158 上移自 `src/desktop/cli/dataprep.go`，L2 = `src/test/chonkpilot-cli/unittest`）。
- 契约 `instance-register.data_dir` 字段**保留**，61-消息一览 零变更（下发的 `data_dir` 按上表解析）。

### 6.4 多实例解析

```text
instance-register {instance_id, work_dir, data_dir}
  → resolvePrj()     = <work_dir>/.chonkpilot/chonkpilot.db
  → resolvePrjUsr()  = ~/.chonkpilot/data/<project-id>/chonkpilot.db
  → resolveUsr()     = ~/.chonkpilot/chonkpilot.db（全局单例）
```

- 连接按**最终 db 路径**缓存 + 引用计数。
- **同一 Windows 用户、同一项目双开 GUI：不允许**——由 **work-dir 占用锁**（`LockFileEx` 模式，`src/lib/core/lockfile`）在**启动 / 选目录入口**非阻塞校验，占用即**明确报错退出**（I-74；此前**无**该锁，第二实例实际被 prj 库的 bbolt 独占 flock 卡住）。
- **同一 Windows 用户、不同项目双开：允许**（D-02）：各项目 data-dir 独立，无 bbolt 冲突。

## 7. Schema 与文件化能力

### 7.1 三层同构桶

三层桶集合完全一致（全量 migration，空桶无妨）：

```text
_meta  _migrations  config  llms  mcps
sessions  turns  messages  scenarios  permission  tasktree  meta
sessions_by_created  turns_by_session  messages_by_turn
tool_pair_by_turn  tool_pair_by_task  tasktree_by_parent  tasktree_by_top
```

- config 表：主键 = key，值 `{"v": <字符串>}`；约定前缀 `security-*` / `window.*` / `layout.*`。
- **MCP 定义已改四级文件化 `capability/mcps/<名>.json`（§7.3）**：旧 usr KV `mcpServers`（专用表 `mcps`）**已彻底废弃、代码零兼容**（不再回落读取，历史数据不迁移）；`mcps` 桶仅为历史遗留空桶（migration v4 仍建，**无任何消费方**）。
- 专用表（**仅 usr 层**；字段与消费方见 [64 §5](../60-reference/64-配置项一览.md)）：

### 7.2 capability 四级同构（6 扁平子目录）

| 级别 | 根 |
|---|---|
| 系统 | `<exeDir>/capability/` |
| 用户 | `~/.chonkpilot/capability/` |
| 项目 | `<workDir>/.chonkpilot/capability/` |
| **项目私有** | `~/.chonkpilot/data/<prj-id>/capability/`（prjusr 数据根下） |

每级下 **6 个扁平子目录**（**删除**旧 `knowledge/{skills,prompts,resources}` 归并层）：
`prompts/`（命令）· `tools/`（工具）· `resources/`（知识）· `skills/`（技能）· `agents/`（智能体）· `scenarios/`（场景）；
**另有 `mcps/`**（MCP server 配置：一个 server 一个文件 `<名称>.json`；**非原语类型**，不入知识库 6 类）——见 §7.3；
**系统级另有 `executors/`**（内置执行器 exe）。
**四级均可读写**（原「系统级只读」作废）；同名定位/覆盖优先序 = **项目私有 > 项目 > 用户 > 系统**。

**场景 = `<级别根>/capability/scenarios/` 下的一个目录**（**删除与 capability 平级的独立 `scenarios/` 根**；旧 `<exeDir>/scenarios/`、`~/.chonkpilot/scenarios/`、`<workDir>/.chonkpilot/scenarios/` 及更早的 `capability/prompts/<场景>/` 均作废）：

```text
<级别根>/capability/scenarios/<场景目录>/
├── scenario.json      # {name, description}（相对目录 = 场景目录名）
├── main.agent.md      # 主 agent（固定文件名）
└── *.agent.md         # 其余子 agent（每文件 = 一个 agent）
```

- 场景级别：**四级 app（系统级）/ user / project / prjusr**（**四级均可写**，**不是优先级链、无覆盖**）。
- 维护字段仅 `name` / `description` / 相对目录；app 级出厂场景**可编辑**（出厂内容 = **磁盘目录** `<exeDir>/capability/scenarios/`（源 `src/initdata/capability/scenarios/`，构建脚本投放），**不再 embed、不再自动物化**；根缺失即缺装（提示重新安装或用 `initial.zip` 恢复））。
- 独立提示词文件：知识库提示词放 `capability/prompts/*.prompt.md`；**系统文档（非原语）**放 `capability/system/*.md`（如 `summary.md` 摘要提示词、`system-directory.md` 目录/env 说明、`memory/<类别名>.md` 记忆类别沉淀提示词）。`summary.md` 被删则由 **embed 内置**（出厂文件 `src/initdata/capability/system/`）保底；`capability/system/system-directory.md`（纯文本）= **目录层**注入系统提示词（四级数据根 + `capability/` 子目录 + DSL env 说明），**有场景 / 通用模式两条路径都注入**，见 [25 §3](../10-architecture/25-MCP与场景分层模型.md)；`capability/system/memory/<类别名>.md`（纯文本）= 记忆类别沉淀提示词（9 份 = 8 项目级类别 + 用户偏好），读序 项目 → 用户 → 系统级磁盘 → embed 内置，见上表。

**知识库** = 6 扁平子目录下的 `*.type.md` 原语文件（工具 `tools/`、技能 `skills/`、提示词 `prompts/`、资源 `resources/`、智能体 `agents`），**四级**（系统/用户/项目/项目私有）；`system/` 为**非原语**系统文档目录（如 `summary.md`），与 6 个原语目录并列但**不进知识库原语树 / 不进左侧导航**（前端按类型 token 天然滤除）。

**运行时消费（T-29 已接线）**：系统级 `<exeDir>/capability` 由内嵌 gateway **self 节点**扫描承载；用户级/项目级根在 `instance-register` 时经 `src/lib/llm/server/server.go onInstanceRegister`（根解析 `persist.CapUserRoot/CapProjectRoot`，规则单源 = `internal/capfs`）→ gateway `servers/register`（dir 节点，`scope=instance_id`）接入。工具暴露名带节点前缀（系统 `self_` / 用户 `<id>-user_` / 项目 `<id>-project_`），故同名契约不冲突、并存；`hot=true` 的契约工具进 LLM 工具面。（prjusr 级的运行时 dir 节点接入**未做**（属后续批次，见 [41](../40-roadmap/41-未决项登记.md)）；数据层能力树（knowledge/scenario 域）四级已可用。）

**恢复默认**：**用户级/项目级/项目私有级字段**可一键恢复**上一级**默认值，入口 = **输入框后的「恢复默认」按钮**（取上一级值回填当前输入为未保存草稿，落库沿用该界面既有保存语义）。（capability 文件树**四级均可读写**（原「系统级（app）只读」作废）；前端四级页签 UI 属 [P3] 批次。）重名现状：知识树/知识库原语为**级别页签**（**无合并列表**），原「复制到项目级」（含重名**数字后缀**，见 [39 KB-008-S02](../30-function-points/39-知识库与原语.md)）**已按用户口径移除**；场景合并列表的同名跨级 `-系统/-用户/-项目` 后缀见 [37 SCEN-008-S03](../30-function-points/37-场景.md)。

### 7.3 MCP 配置四级文件化

MCP server 配置 = **四级 `<级别>/capability/mcps/<名称>.json` 文件**（一个 server 一个文件；文件名 = server 名 + `.json`，名须满足 `^[A-Za-z][A-Za-z0-9_]*$`）：

```text
<级别根>/capability/mcps/<名称>.json      # 单文件 = 该 server 的字段 JSON（transport/url/runtime/args/env/hot_tools/isolate/sandbox…）
```

| 级别 | MCP 配置根 |
|---|---|
| 系统 app | `<exeDir>/capability/mcps/` |
| 用户 user | `~/.chonkpilot/capability/mcps/` |
| 项目 project | `<workDir>/.chonkpilot/capability/mcps/` |
| 项目私有 prjusr | `~/.chonkpilot/data/<prj-id>/capability/mcps/` |

- **同名跨级 = 最具体级优先、整条覆盖**（`prjusr > project > user > app`；**非字段级合并**）；**同名跨级只生效一份**（生效定义 = 命中的最具体级那一条）→ **只 spawn 一份**。
- **旧 usr KV `mcpServers`（专用表 `mcps`）已彻底废弃**：**不再回落读取、代码零兼容**，历史数据不迁移。
- **数据面**：`mcp` 域消息面 `data-mcp-{list,load,save,delete}` + 订阅面 `data-mcp-refresh`（见 [61 §3.1](../60-reference/61-消息一览.md)）；gateway 装配（`src/lib/llm/server/gateway_servers.go loadGatewayServers` → `mergeGatewayServers(nil, loadMcpFileEntries)`）**唯一来源** = 四级合并视图。
- **UI**：MCP 配置页（[20-gui §5](../20-modules/20-gui.md)）增**级别选择**（四级，文案复用 `fileTree.kb_level_*`）；读写走新数据层（不再整表替换 usr KV）。
- **运行期冷缓存退化放行**（配套）：`filterWhitelistByLevel`（白名单级别矩阵过滤）在**工具可见性缓存为空（未预热）**时**不做剔除、按原白名单放行**（避免冷启动误剔）。
