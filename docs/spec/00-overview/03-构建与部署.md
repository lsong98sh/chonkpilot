## 1. 唯一构建方式

**所有构建必须通过根目录脚本完成，禁止单独调用 `go build` / `wails build` / `npm run build`**（脚本内部调用除外）。

根目录仅存在以下 6 个构建脚本：

| 脚本 | 用途 | 产物 |
|---|---|---|
| `build-desktop.ps1`（**唯一发行脚本**，可选 `-Debug`） | 桌面单体：前端 → 宿主 exe → 契约/executor → 插件 → 内置引擎 → 出厂数据包 | `dist/desktop/` + `dist/initdata/` |
| `build-plugins.ps1` | 外挂插件 exe（由 `build-desktop.ps1` 调用） | 插件目录 |
| `build-mcp-server.ps1` | 独立 MCP server 部署（executor + exe + capability） | `dist/other/` |
| `build-mcp-gateway.ps1` | 独立 MCP gateway（与 mcp-server 同目录、共用 capability） | `dist/other/` |
| `build-codegraph.ps1` | codegraph 引擎（console + CGO） | `dist/plugins/codegraph/` |
| `build-vfts.ps1` | vfts 引擎（console + CGO，链接 zvec） | `dist/plugins/vfts/` |

**唯一形态 = desktop**。不存在 gui / browser / flash 形态，也不存在 `dist/gui/`、`dist/server/`、`chonkpilot-server.exe`、`chonkpilot-gui-client.exe`、`chonkpilot-flash.exe`、`chonkpilot-cli.exe`，以及 `build-gui.ps1` / `build-browser.ps1` / `build-standalone-*.ps1` / `build-dsl-executor.ps1`。运行时形态标识 `window.__ck.form` 恒为 `desktop`。

**前端单入口单落点**：源码 = 仓库级 `src/frontend`（入口 `index.html`）；`npm run build` 产物直投 `src/desktop/frontend/dist`（宿主壳 `//go:embed all:frontend/dist`）。不存在 `embed.html` / `build:embed` / 镜像步骤。

### 1.1 最终构建不等待

会话中最后一次构建，发起 `.\build-desktop.ps1` 后后台运行，不等待完成。

## 2. 桌面单体（`build-desktop.ps1`）

流程：

1. **kill 旧实例** —— 仅 `chonkpilot`。
2. **前端** —— `src/frontend` 内 `npm ci`（缺 `node_modules` 时）+ `npm run build` → `src/desktop/frontend/dist`。
3. **宿主** —— `src/desktop` 内 `go build -ldflags "-H windowsgui"` → `dist/desktop/chonkpilot.exe`（壳 = 一行 `host.Main(distFS, Options{Form: FormDesktop})`，实现见 `src/lib/gui/host`）。
4. **契约与 executor** —— 调 `build-mcp-server.ps1`（产物 `dist/other/`），把其 `capability/` 覆盖式同步到 `dist/desktop/capability/`。
5. **工具前门与 self-tools** —— `chonkpilot-core-mcp-server.exe` → `dist/desktop/mcps/core-mcp/`（工具唯一前门，宿主拉起常驻）；`chonkpilot-self-tools.exe` → `dist/desktop/mcps/self-tools/`（系统级内置工具的外部注册/执行进程；P0a 2026-10-29 起暴露名 = 原名）。
6. **插件** —— 调 `build-plugins.ps1`；manifest 源 = `src/initdata/capability/plugins/`，exe 落 `capability/plugins/<id>/`。
7. **内置引擎** —— 调 `build-codegraph.ps1` / `build-vfts.ps1` → `dist/desktop/mcps/{codegraph,vfts}/`；`zvec_c_api.dll` 必须与 vfts 引擎 exe 同目录。
8. **`mcps/` 兜底镜像** —— `dist/other/mcps` 存在则把子项覆盖镜像到 `dist/desktop/mcps`（保留 `codegraph/`、`vfts/`）；不存在则保留既有 `mcps/` 并提示；两处皆缺 → 告警不中断。
9. **出厂场景** —— `src/initdata/capability/scenarios/**` 覆盖式同步到 `dist/desktop/capability/scenarios/`（磁盘目录，不 embed）。
10. **出厂数据包** —— `dist/initdata/`：`capability-<ver>.zip`（= `dist/desktop/capability/` 全量）+ `initial.zip`（= `dist/desktop` 全量，含 exe）；`<ver>` = 时间戳。

产物：

```text
dist/desktop/
├── chonkpilot.exe
├── zvec_c_api.dll                      # vfts 运行库
├── capability/
│   ├── prompts/ tools/ resources/ skills/ agents/ system/
│   ├── scenarios/                      # 出厂场景（覆盖式同步）
│   ├── executors/                      # chonkpilot-{script,web}-executor.exe
│   └── plugins/<id>/                   # manifest 插件（plugin.json + exe）
├── mcps/
│   ├── core-mcp/chonkpilot-core-mcp-server.exe
│   ├── self-tools/chonkpilot-self-tools.exe
│   ├── codegraph/chonkpilot-codegraph-mcp-server.exe
│   ├── vfts/chonkpilot-vfts-mcp-server.exe + zvec_c_api.dll
│   └── markitdown/                     # 可选文档转换服务（见 §5.3）
└── (无其它)

dist/initdata/
├── capability-<ver>.zip
└── initial.zip
```

> **内置 ≠ 默认接入**：codegraph / vfts 默认不开启、不注册，设置页开关开启后才拉起/注册。`compress` 已内建在会话侧，不是插件。

## 3. MCP server 部署（`build-mcp-server.ps1`）

1. 编译 `chonkpilot-mcp-server.exe`（源 `src/others/mcp-server`）→ `dist/other/`。
2. 部署契约：`src/initdata/capability` → `capability/`（`prompts/tools/resources/skills/agents/system` 六棵；排除未发布草稿 `skills/se/`）+ 域工具契约 `src/lib/llm/contracts/tools/*.tool.md` → `capability/tools/server/`。
3. 编译 executor → `capability/executors/`：当前为 `chonkpilot-script-executor.exe` + `chonkpilot-web-executor.exe`（其余工具随插件；`--help` 从磁盘读契约）。

首次生成 `config.json`（已有不覆盖）。

```text
dist/other/
├── chonkpilot-mcp-server.exe
├── chonkpilot-mcp-gateway.exe          # build-mcp-gateway.ps1 产出到同目录
├── config.json
└── capability/{prompts,tools,resources,skills,agents,system}/ + executors/
```

运行形态：

| 形态 | 命令 |
|---|---|
| HTTP | `.\chonkpilot-mcp-server.exe --http`（默认 `127.0.0.1:5700`，端点 `/mcp`） |
| stdio | `.\chonkpilot-mcp-server.exe --stdio` |
| Windows 服务 | `.\chonkpilot-mcp-server.exe --service install`（需管理员） |

## 4. MCP gateway 部署（`build-mcp-gateway.ps1`）

- 产物与 mcp-server **同目录**（`dist/other/`），**共用同一份 `capability/`**。
- gateway 内嵌 mcp-server lib：进程内扫描契约根 + spawn executor，不依赖独立 `chonkpilot-mcp-server.exe`。
- 前置：`dist/other/capability` 必须存在（先跑 `build-mcp-server.ps1`）。

```powershell
.\chonkpilot-mcp-gateway.exe -transport stdio
.\chonkpilot-mcp-gateway.exe -transport http://127.0.0.1:5556
.\chonkpilot-mcp-gateway.exe -transport sse://127.0.0.1:5556
```

## 5. 外置组件

### 5.1 codegraph（`build-codegraph.ps1`）

- 源 = 同级仓 `chonkpilot-plugins/codegraph/src/engines/treesitter`（非主模块），`CGO_ENABLED=1`。
- 产物：`dist/plugins/codegraph/chonkpilot-codegraph-mcp-server.exe`（发行时并入 `dist/desktop/mcps/codegraph/`）。
  查询工具「一工具一 exe」已无消费方（PLUGIN-EDGE-1，2026-10-28：插件进程内直挂工具、主仓无对应 tool 契约）→ 不再构建/投放；
  保留该 exe 的**唯一**用途 = L4 门禁 `run_index_gate.py` 的只读自检 `-dump <ws>`。
- 索引回路在 codegraph 插件内（引擎库内联），无独立 indexer exe、不 spawn stdio 引擎子进程。

### 5.2 vfts（`build-vfts.ps1`）

- 源 = 同级仓 `chonkpilot-plugins/codegraph/src/engines/vfts`，`CGO_ENABLED=1`（链接 zvec C-API）。
- 产物：`dist/plugins/vfts/chonkpilot-vfts-mcp-server.exe` + `zvec_c_api.dll`（发行时并入 `dist/desktop/mcps/vfts/`）。
  `vfts_query` 的「一工具一 exe」已无消费方（PLUGIN-EDGE-1，2026-10-28）→ 不再构建/投放。
- `third_party/zvec/` 的头 / 链接库 / 运行库随源码入库，clean clone 可直接构建；jieba 词典 `//go:embed` 编入 exe。
- 索引回路在 vfts 插件内（引擎库内联），无独立 indexer exe、不 spawn stdio 引擎子进程。

### 5.3 文档转换服务（`src/mcps/markitdown/build-mcps.ps1`）

- Office / PDF → Markdown，供 vfts 全文索引（`plugins.codegraph.vfts.docs` 开关）。
- 独立脚本，**不接入** `build-desktop.ps1` 必经路径（PyInstaller 冻结慢）：`.\src\mcps\markitdown\build-mcps.ps1`（默认 onedir，`-Onefile` 可选）。
- 产物 → `dist/desktop/mcps/markitdown/`（`markitdown-mcp.exe` + `_internal/` + `README.md` + `THIRD-PARTY-NOTICES.txt`）。
- 单进程 HTTP，只监听 `127.0.0.1`（默认 7317）：`/mcp`（工具 `convert_to_markdown`）+ `/vfts/health`、`/vfts/convert`（内部快通道）。
- 随产品发、**默认不启动**；由用户在 MCP 配置页手动注册/启动。

## 6. 变更后必须重新编译

| 修改了什么 | 需要运行 |
|---|---|
| **任何修改（收尾默认）** | `.\build-desktop.ps1` |
| Vue 组件 / 前端 JS·TS | `.\build-desktop.ps1`（`npm run build` → `src/desktop/frontend/dist` → go:embed） |
| Go 后端（gui / data / filesys / 插件） | `.\build-desktop.ps1` |
| 外挂插件（`chonkpilot-plugins/*`，同级仓） | `.\build-desktop.ps1`（内部调 `build-plugins.ps1`） |
| mcp-server / mcp-tools（handler、`*.tool.md`） | `.\build-mcp-server.ps1` |
| codegraph / vfts 引擎 | `.\build-codegraph.ps1` / `.\build-vfts.ps1` |
| 文档转换服务（`src/mcps/markitdown`） | `.\src\mcps\markitdown\build-mcps.ps1`（独立） |

> 前端单独校验一律走 `.\build-desktop.ps1`；**不要裸跑 `npm run build`**（产物不落到 embed 落点）。

## 7. 工具契约同步

工具契约**按域分源**：server 域 = `src/lib/llm/contracts/tools/*.tool.md`；插件域 = `chonkpilot-plugins/<plugin>/src/tools/<cat>/*.tool.md`（如 `file` 11 个）。`src/initdata/capability/` 仍承载 prompts / skills / resources / agents / system。`build-mcp-server.ps1` / `build-plugins.ps1` 分别覆盖式同步到产物 `capability/tools/{server,...}` 与 `capability/plugins/<plugin>/tools/`。

> 例外：file 域 11 个工具随 `file` 插件迁出主仓，契约唯一源 = `chonkpilot-plugins/file/src/tools/file/*.tool.md`（`build-plugins.ps1` 拷到插件目录）；主仓 capability 不再含 file 契约。

修改 handler 后必须同步：

- 参数变更 → 更新 `parameters.properties`
- 行为变更 → 更新 `description`
- 文件名（不含扩展名）必须等于 `name` 字段
- 纯 bug 修复 / 后端重构 → 不改契约

## 8. 禁止事项

- 禁止单独调用 `go build` / `wails build` / `npm run build`（必须走脚本）。
- 禁止新增 gui / browser / flash 形态的构建脚本或产物目录。
- 禁止把出厂数据打进 `dist/desktop` 之外的位置（仅 `dist/initdata/`）。
- 禁止 `--test-port` 进入 release 产物（仅 `build-desktop.ps1 -Debug` 编入 `debugport`）。

## 9. 开发期依赖策略（跨仓本地 replace）

**口径（2026-10-29，用户拍板）：不发新版本；主仓与所有独立仓之间、独立仓相互之间的 `github.com/lsong98sh/*`
依赖，一律用本地 `replace` 指向同机源码目录。正式发版时一次性切回版本号并删除 replace 节。**

- 适用范围（TOPO-1，2026-10-29）：`chonkpilot-{plugin-framework → framework/plugin/src, framework/host, agent, util, webview2}` 与
  `chonkpilot-plugins/<id>/src`（含 `shared`、`*/src/lib`、`codegraph/src/engines/*`、`*/src/engine`）；本地克隆与主仓同级，统一位于 `E:\BizWorks\`。
- 写法：`replace <module> => <相对路径>`，路径按 **该 `go.mod` 所在目录**计算（例：`src/lib/llm` →
  `../../../../chonkpilot-framework/host/src`；`chonkpilot-plugins/codegraph/src/engines/vfts` →
  `../../../../chonkpilot-framework/plugin/src`）。相对路径优先，避免跨盘符/换机失效。
- `github.com/jchv/go-webview2` 同样指向本地 fork 仓 `chonkpilot-webview2`（**唯一源**；插件仓 `third_party` 内嵌副本已于 2026-10-30 删除，`browser/src/engine` 一并改指该仓）。
- **版本漂移**：插件仓 `require` 的框架版本（`v0.1.1`）低于本地源码（`v0.1.3+`），replace 后**实际编译本地新版**；
  改 replace 或框架 API 后必须逐仓 `go build ./...` 验证（本节口径变更亦须复核）。
- `go.sum` 中对应条目可保留（replace 到本地目录后不再校验），**不得**为了让 `go mod tidy` 通过而删 replace。
- **正式发版时**：各仓发布新版本 → 主仓/插件仓 `require` 升到新版本 → 删除所有 `github.com/lsong98sh/*`
  的 replace 行 → `go mod tidy` → 跑 `.\build-desktop.ps1`。
