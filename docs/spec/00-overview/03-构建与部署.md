## 1. 唯一构建方式

**所有构建必须通过根目录构建脚本完成，禁止单独调用 `go build` / `wails build` / `npm run build`。**

| 脚本 | 用途 | 产物目录 |
|------|------|---------|
| `build-desktop.ps1`（**主力**，原名 `build-standalone-gui.ps1`） | 桌面单体（GUI 单体 + CLI）（内部串联 mcp-server 契约构建 + codegraph/vfts 引擎，全量插件内置） | `dist/desktop/`（见 §2） |
| `build-mcp-server.ps1` | mcp-server 单体部署（executor ×3 + exe + capability 契约） | `dist/other/`（与 gateway exe **同目录共用** capability） |
| `build-mcp-gateway.ps1` | mcp-gateway 部署（exe 与 mcp-server **同目录**，共用 `dist/other/capability`） | `dist/other/` |
| `build-codegraph.ps1` | codegraph mcp-server（独立 console，**CGO 允许**） | `dist/plugins/codegraph/`（发行时并入 `dist/desktop`、`dist/server` 根） |
| `build-vfts.ps1` | vfts mcp-server（独立 console，**CGO 允许**，链接 zvec） | `dist/plugins/vfts/`（exe + `zvec_c_api.dll`；发行时同上并入发行根） |
| `build-gui.ps1`（**GUI 客户端形态专用**，原名 `build-split.ps1`，[42 §2 (72)](../40-roadmap/42-决策记录.md)） | **GUI 客户端形态**构建（受 tag 影响的宿主 exe 重编，`-tags split`）：客户端 `chonkpilot-gui-client.exe` / `chonkpilot-cli-client.exe` + **服务端 `chonkpilot-server.exe`（llm + gateway + filesys + data 合一）**；capability/ 与内置引擎（codegraph/vfts）+ `zvec_c_api.dll` 从 `dist/desktop/` 复用（缺失才回退各自构建脚本） | 客户端 `dist/gui/`；服务端 **`dist/server/`**（GUI 与 browser **共用**；browser 静态页 [42 §2 (136)](../40-roadmap/42-决策记录.md)：**内嵌**进 `chonkpilot-server.exe`，源 = `src/server/frontend/dist`，由 `build-browser.ps1` 投放） |
| `build-browser.ps1`（**仅前端**，[42 §2 (115)](../40-roadmap/42-决策记录.md)） | **browser 形态前端**：在 `src/frontend` 内 `npm ci`（缺依赖时）+ `npm run build`（入口 `index.html`） | **`src/server/frontend/dist/`**（[42 §2 (136)](../40-roadmap/42-决策记录.md)：browser 静态面 **go:embed 进 `chonkpilot-server.exe`**，落点 = `src/server/frontend.go` 的 `//go:embed all:frontend/dist`；服务端 exe 由 `build-gui.ps1` 产出。**先 build-browser 再 build-gui** 才会把静态页嵌进 exe） |

> 注：历史上曾描述 `build-standalone-cli.ps1`，**该脚本不存在**——CLI 由 `build-desktop.ps1` 第 3 步一并产出。
>

### 1.1 构建流程约定

- **最终构建不等待**：会话中最后一次构建，发起 `.\build-desktop.ps1` 后**后台运行**（不等完成），避免阻塞后续交互。
- ✅ **前端源码工程已独立为 `src/frontend`（2026-09-19 落地）**：前端工程为仓库级 `src/frontend`；构建产物**投放两个宿主壳的 embed 落点**（`src/gui/frontend/dist` = vite `build:embed` 的 outDir（客户端壳），`build-desktop.ps1` 再从该目录**镜像**到 `src/desktop/frontend/dist`（桌面单体壳）；两壳均 `//go:embed all:frontend/dist`），双入口 `index.html` = browser / `embed.html` → 重命名 `index.html` = GUI embed；browser 形态产物独立落 **`dist/server/www`**（见 [41 D-28](../40-roadmap/41-未决项登记.md) §2 与 [42 §2 (115)](../40-roadmap/42-决策记录.md)）。

### 1.3 工具契约同步规则（重要）

`src/lib/mcp-tools/internal/contracts/tools/*.tool.md` 是 LLM 识别工具**名称 / 参数 / 行为**的唯一契约（embed 进 executor）。修改 handler 后必须同步：

- **参数变更** → 更新 `parameters.properties`
- **行为变更** → 更新 `description`
- **文件命名**（不含扩展名）必须**等于** `name` 字段
- **不修改**：纯 bug 修复、后端重构

> 契约的**两份形态**（权威源 / executor 内嵌）与**部署副本漂移**的检测、恢复见 **§7**（`.\sync-contracts.ps1`）。

### 1.4 分离形态编译开关（`-tags split`）

- **默认构建（桌面单体 / 合并单进程）= 不加 tag**：`build-*.ps1` 产出的 GUI/CLI 均为合并形态（GUI 内嵌 server）。
- **分离形态 = 显式 `-tags split`**（被该 tag 编入的是**分离专属逻辑**；默认构建走同目录 `*_inprocess.go` 空实现）：
  - `src/plugins/plugin/instance`：`StartHeartbeat`（30s 发布 `instance-heartbeat`）+ `Manager.Sweep`（90s 视同实例退出）；
  - `src/lib/llm/server/sweep_split.go`：30s ticker → `Manager.Sweep(90s)` → 既有 `exitInstance` 清理；
  - `src/lib/data/persist/sweep_split.go`：30s 扫描 → `LastBeat` ≥90s → 既有 `instanceGone` 解绑；
  - `src/plugins/plugin-{codegraph,vfts}/sweep_split.go`：实例超时 → 既有 `instanceGone`。
  - 心跳取值**单一来源** = `src/lib/core/heartbeat`（周期 30s / 超时 90s，见 [24-lib §2](../20-modules/24-lib.md)）。
- ✅ **已提供专用构建脚本 `.\build-gui.ps1`（无参数，原名 `build-split.ps1`）**（2026-09-16，**实跑通过**）：只重编受 tag 影响的宿主 exe（**`chonkpilot-gui-client.exe` / `chonkpilot-cli-client.exe`**（`dist/gui`） / **`chonkpilot-server.exe`** = llm+gateway+filesys+data 合一（`dist/server`），均含 `-tags=split`）；capability/、**scenarios/**（app 级场景，随服务端 exe 同目录投放）与内置引擎 exe 属**形态无关资产**，优先从 `dist/desktop/` 复用。〔订正（2026-09-16）：原表述"构建脚本不传该 tag / 分离形态须手工 `go build -tags split`"**已作废** —— 现由 `build-gui.ps1` 产出。〕
- 客户端心跳发布侧接线 = GUI `instance.StartHeartbeat(bus, instanceID, bridgeURL)`（`--bridge-url` = 分离形态下与 server 的 bridge 对端地址（HTTP）登记口；旧名 `-nats-url` 保留为已废弃兼容别名）。
- 受该开关影响的参数与行为：[62-命令行与参数 §1](../60-reference/62-命令行与参数.md)（`--bridge-url`）· [64-配置项一览](../60-reference/64-配置项一览.md)（`-bridge-url`）· [61-消息一览](../60-reference/61-消息一览.md)（`instance-heartbeat`）。

## 2. 桌面单体（`build-desktop.ps1`，无参数）

流程（6 步）：

1. **kill 旧实例** —— `chonkpilot` / `chonkpilot-cli` / `chonkpilot-gui-client` / `chonkpilot-cli-client` / `chonkpilot-server`（释放 exe 占用）。
2. **前端构建** —— 仓库级 `src/frontend` 内 `npm ci`（缺 `node_modules` 时）+ `npm run build:embed`（入口 `embed.html`）→ 产物落 `src/gui/frontend/dist`（vite outDir），把 `embed.html` **复制改名 `index.html`** 后**镜像到 `src/desktop/frontend/dist`**（桌面单体壳的 `//go:embed all:frontend/dist` 落点）。
3. **GUI 编译** —— 在 `src/desktop` 内 `go build -ldflags "-H windowsgui"` → `dist/desktop/chonkpilot.exe`（宿主壳 = 一行调用 `gui.Main(distFS, Options{Form: FormDesktop})`，实现见 `src/lib/gui`）。
4. **CLI 编译** —— 在 `src/desktop/cli` 内 `go build`（console，无 `-H windowsgui`）→ `dist/desktop/chonkpilot-cli.exe`。
5. **契约 + executor** —— 调用 `build-mcp-server.ps1`（产物 `dist/other/`）；把 `dist/other/capability/` 拷入 `dist/desktop/capability/`；并把 **app 级场景**（源 `src/lib/data/scenarios/`）拷入 `dist/desktop/scenarios/`（与 `capability/` **平级**，随发布只读，[25 §8.1 #8](../10-architecture/25-MCP与场景分层模型.md)）。
6. **内置 MCP 引擎** —— 调用 `build-codegraph.ps1`、`build-vfts.ps1`（产物 `dist/plugins/*`）；把 `chonkpilot-codegraph-mcp-server.exe`、`chonkpilot-vfts-mcp-server.exe` 与 `zvec_c_api.dll` 拷到 `dist/desktop/` 根（与 GUI/CLI exe 同级）。

产物（[42 §2 (16)](../40-roadmap/42-决策记录.md)）：

```text
dist/desktop/
├── chonkpilot.exe                        # webview2 宿主（内嵌 server→persist→filesys + gateway(内嵌 mcp-server) + 插件 compress/history/memory；前端 dist go:embed）
├── chonkpilot-cli.exe                    # console 宿主，同 lib 集（AsyncMode: never），无前端无 WebView2
├── chonkpilot-codegraph-mcp-server.exe   # codegraph 引擎 exe（出厂内置 MCP）
├── chonkpilot-vfts-mcp-server.exe        # vfts 引擎 exe（出厂内置 MCP）
├── zvec_c_api.dll                        # vfts 运行库（必须与 vfts 引擎 exe 同目录）
├── capability/                           # 契约 + executor×3（来自 dist/other）
└── scenarios/                            # app 级场景（仅出厂场景「开发场景」default/；源 src/lib/data/scenarios，随发布只读，25 §6/§8.1 #8）
```

运行：`cd dist/desktop ; .\chonkpilot.exe`；CLI：`cd dist/desktop ; .\chonkpilot-cli.exe --prompt 'hello' --work-dir .`

> **全量组件约定**：桌面单体（`dist/desktop/`）发行目录必须覆盖**全部插件与 MCP** —— 内嵌 lib 插件（`compress` / `history` / `memory` / `vfts` 插件侧）随 exe 编译；外置 MCP 引擎（`codegraph`、`vfts`）以 exe 置于**发行根**（与宿主 exe 同级——插件按「宿主 exe 同目录」解析引擎），`zvec_c_api.dll` 与 vfts 引擎 exe 同目录。**"内置" ≠ "默认接入"**：codegraph / vfts **默认不开启、不注册**（工具不进 LLM 工具面），须由**设置页开关**开启后才拉起/注册（见 [42 §2 (17)](../40-roadmap/42-决策记录.md)）。

## 3. mcp-server 部署（`build-mcp-server.ps1`）

流程（3 步）：

1. **编译 server** —— 在 `src/others/mcp-server`（exe 外壳）内 `go build` → `dist/other/chonkpilot-mcp-server.exe`（Streamable HTTP，默认 `127.0.0.1:5700`，端点 `/mcp`）。
2. **部署契约** —— 覆盖式同步到 `capability/`：
   - `tools/` 源 = `src/lib/mcp-tools/internal/contracts/tools`（executor `--help` 的同一嵌入源）；
   - `skills/` `prompts/` `resources/` 源 = `src/lib/mcp-server/contracts/`。
3. **编译 executor** —— 三个分类 exe 落到 `capability/tools/<cat>/`（契约与执行器**同目录**，`*.tool.md` 的 runtime 相对 md 解析）：`core` / `desktop` / `browser`；随后逐个 `--help` 验证。

另：首次生成 `config.json`（已有不覆盖）：`timeout_sec=300`、`defaults.skip_dirs` 等。

产物：

```text
dist/other/
├── chonkpilot-mcp-server.exe
├── chonkpilot-mcp-gateway.exe           # build-mcp-gateway.ps1 产出到同一目录
├── config.json
└── capability/
    ├── tools/{core,desktop,browser}/   # *.tool.md + chonkpilot-*-executor.exe 同目录
    ├── skills/  prompts/  resources/   # *.skill.md / *.prompt.md / *.resource.md
```

运行形态（必须显式指定）：

| 形态 | 命令 |
|------|------|
| HTTP 前台 | `.\chonkpilot-mcp-server.exe --http`（`--http=0.0.0.0:5700` 指定地址） |
| stdio（IDE spawn） | `.\chonkpilot-mcp-server.exe --stdio` |
| Windows 服务 | `.\chonkpilot-mcp-server.exe --service install`（需管理员；服务运行 = HTTP） |

## 4. mcp-gateway 部署（`build-mcp-gateway.ps1`）

- **与 mcp-server exe 同目录（`dist/other/`）**：gateway exe 不再另建 dist 目录与 capability 副本 —— 两 exe **共用 `dist/other/capability`**；脚本仅清理旧名 `chonkpilot-gateway.exe` 残留。
- 编译 `chonkpilot-mcp-gateway.exe`（源 = `src/others/mcp-gateway`；gateway **内嵌 mcp-server lib**，进程内扫描 capability 契约根 + spawn executor，**不依赖独立 mcp-server.exe**）。
- 前置：`dist/other/capability` 必须存在（先跑 `build-mcp-server.ps1`）。

运行：

```powershell
.\chonkpilot-mcp-gateway.exe -transport stdio
.\chonkpilot-mcp-gateway.exe -transport http://127.0.0.1:5556
.\chonkpilot-mcp-gateway.exe -transport sse://127.0.0.1:5556
.\chonkpilot-mcp-gateway.exe -transport http://127.0.0.1:5556 -servers-file servers.list   # 接入列表
```

> 缺省 `-capability` 探测 exe 目录/`capability`；`config.json` 同 mcp-server 自动探测。

## 7. 工具契约同步规则（重要）

`src/lib/mcp-tools/internal/contracts/tools/*.tool.md` 是 LLM 识别工具名称/参数/行为的**唯一契约**（embed 进 executor，部署见 `build-mcp-server.ps1`）。修改 handler 后必须同步：

- **参数变更** → 更新 `parameters.properties`
- **行为变更** → 更新 `description`
- **文件命名**：文件名（不含扩展名）必须等于 `name` 字段
- **不修改**：纯 bug 修复、后端重构

### 7.1 契约的两份形态（同源；勿手改部署目录）

| 形态 | 位置 | 谁读 |
|------|------|------|
| ① **权威源** | `src/lib/mcp-tools/internal/contracts/tools/**/*.tool.md` + `src/lib/mcp-server/contracts/{skills,prompts,resources}` | `build-mcp-server.ps1` 第 2 步**覆盖式拷贝** → `capability/`（mcp-server/gateway 运行时扫描的正是这份副本） |
| ② **executor 内嵌** | `src/lib/mcp-tools/internal/contracts/contracts.go`（`//go:embed tools`） | executor exe（仅 `<exe> --help <tool>` 输出） |

`dist/other/capability`、`dist/desktop/capability` 与 `dist/server/capability` 只是**部署副本**：直接手改副本会让 ① 与副本**静默分叉**（曾现于 `dist/desktop/capability/tools/core/file_diff.tool.md`）。**契约变更一律只改源**。

### 7.2 漂移检测与恢复（`sync-contracts.ps1`，非构建脚本）

```powershell
.\sync-contracts.ps1                     # 权威源 -> capability 覆盖式同步（默认 dist/other + dist/desktop）
.\sync-contracts.ps1 -Dist desktop        # 只同步 dist/desktop（也接受 other / server）
.\sync-contracts.ps1 -Check              # 只报漂移、不写盘；有漂移时退出码 1
```

- **覆盖前先打印**将改动的文件清单：`drift`（副本被手改）/ `missing`（副本缺失）/ `orphan`（源中已不存在的孤儿契约，同步时删除）；
- 同步后逐文件比对 SHA256，输出 `identical` 或 `drifted-n`；
- **幂等**：重复执行无副作用；只写 4 类契约 md（`*.tool.md` / `*.skill.md` / `*.prompt.md` / `*.resource.md`），**不触碰** `capability/` 下的 executor exe；
- **② 内嵌侧本脚本覆盖不到**：脚本比对「tools 源最新 mtime vs executor exe mtime」，源更新即提示 `WARN embed 可能过期`。

**漂移了怎么办**：跑 `.\sync-contracts.ps1` 把副本覆盖回源（副本里手改的内容会丢失——需要保留就先回填到源）；若改的是 **mcp-tools 源**，必须再跑 `.\build-mcp-server.ps1` **重建 executor** 才能消除 ② 的差异（`build-desktop.ps1` 第 4 步会内部调用它并重铺 `dist/desktop/capability`）。
