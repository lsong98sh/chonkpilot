## 1. 唯一构建方式

**所有构建必须通过根目录构建脚本完成，禁止单独调用 `go build` / `wails build` / `npm run build`。**

| 脚本 | 用途 | 产物目录 |
|------|------|---------|
| `build-desktop.ps1`（**主力**，原名 `build-standalone-gui.ps1`） | 桌面单体（GUI 单体 + CLI）（内部串联 mcp-server 契约构建 + codegraph/vfts 引擎，全量插件内置） | `dist/desktop/`（见 §2） |
| `build-mcp-server.ps1` | mcp-server 单体部署（executor ×3 + exe + capability 契约） | `dist/other/`（与 gateway exe **同目录共用** capability） |
| `build-mcp-gateway.ps1` | mcp-gateway 部署（exe 与 mcp-server **同目录**，共用 `dist/other/capability`） | `dist/other/` |
| `build-codegraph.ps1` | codegraph mcp-server（独立 console，**CGO 允许**） | `dist/plugins/codegraph/`（发行时并入 `dist/desktop`、`dist/server` 根） |
| `build-vfts.ps1` | vfts mcp-server（独立 console，**CGO 允许**，链接 zvec） | `dist/plugins/vfts/`（exe + `zvec_c_api.dll`；发行时同上并入发行根） |

### 1.1 构建流程约定

- **最终构建不等待**：会话中最后一次构建，发起 `.\build-desktop.ps1` 后**后台运行**（不等完成），避免阻塞后续交互。
- ✅ **前端源码工程已独立为 `src/frontend`（2026-09-19 落地）**：前端工程为仓库级 `src/frontend`；构建产物**投放两个宿主壳的 embed 落点**（`src/gui/frontend/dist` = vite `build:embed` 的 outDir（客户端壳），`build-desktop.ps1` 再从该目录**镜像**到 `src/desktop/frontend/dist`（桌面单体壳）；两壳均 `//go:embed all:frontend/dist`），双入口 `index.html` = browser / `embed.html` → 重命名 `index.html` = GUI embed；browser 形态产物独立落 **`dist/server/www`**（见 [41 D-28](../40-roadmap/41-未决项登记.md) §2 与 [42 §2 (115)](../40-roadmap/42-决策记录.md)）。

### 1.3 工具契约同步规则（重要）

`src/initdata/capability/tools/*.tool.md` 是 LLM 识别工具**名称 / 参数 / 行为**的唯一契约（**出厂数据唯一源**；executor **不再内嵌**，`--help` 亦从磁盘读）。修改 handler 后必须同步：

- **参数变更** → 更新 `parameters.properties`
- **行为变更** → 更新 `description`
- **文件命名**（不含扩展名）必须**等于** `name` 字段
- **不修改**：纯 bug 修复、后端重构

> 契约的**权威源（`src/initdata/`）与部署副本**、**副本漂移**的检测与恢复见 **§7**（`.\sync-contracts.ps1`）。

## 2. 桌面单体（`build-desktop.ps1`，无参数）

流程（9 步）：

1. **kill 旧实例** —— `chonkpilot` / `chonkpilot-cli` / `chonkpilot-gui-client` / `chonkpilot-cli-client` / `chonkpilot-server`（释放 exe 占用）。
2. **前端构建** —— 仓库级 `src/frontend` 内 `npm ci`（缺 `node_modules` 时）+ `npm run build:embed`（入口 `embed.html`）→ 产物落 `src/gui/frontend/dist`（vite outDir），把 `embed.html` **复制改名 `index.html`** 后**镜像到 `src/desktop/frontend/dist`**（桌面单体壳的 `//go:embed all:frontend/dist` 落点）。
3. **GUI 编译** —— 在 `src/desktop` 内 `go build -ldflags "-H windowsgui"` → `dist/desktop/chonkpilot.exe`（宿主壳 = 一行调用 `gui.Main(distFS, Options{Form: FormDesktop})`，实现见 `src/lib/gui`）。
4. **CLI 编译** —— 在 `src/desktop/cli` 内 `go build`（console，无 `-H windowsgui`）→ `dist/desktop/chonkpilot-cli.exe`。
5. **契约 + executor** —— 调用 `build-mcp-server.ps1`（产物 `dist/other/`）；把 `dist/other/capability/` 拷入 `dist/desktop/capability/`（**扁平** `prompts/` + `tools/` + `resources/` + `skills/` + `executors/`）。
6. **出厂场景** —— 把 `src/initdata/capability/scenarios/**` **覆盖式同步**到 `dist/desktop/capability/scenarios/`（**不删 `scenarios/` 目录本身**）。出厂场景现为**磁盘目录**（**不再 embed、不再物化**），见 [25 §6/§8.1](../10-architecture/25-MCP与场景分层模型.md)。
7. **内置 MCP 引擎** —— 调用 `build-codegraph.ps1`、`build-vfts.ps1`（产物 `dist/plugins/*`）；分别落到 `dist/desktop/mcps/codebase/` 与 `dist/desktop/mcps/vfts/`（`zvec_c_api.dll` 必须与 vfts 引擎 exe 同目录）——插件按「宿主 exe 同目录/`mcps/<engine>/`」解析引擎。
8. **`mcps/` 兜底镜像**（`[8/9] stage mcps/`，**可选、幂等、不冻结**）—— 文档转换服务产物按「兜底镜像」处理，**不**在桌面构建内生成：
   - `dist\other\mcps` **存在** → 把其**子项**覆盖镜像到 `dist\desktop\mcps`（**保留 `codebase/`、`vfts/` 引擎目录**，不整目录删除）；
   - `dist\other\mcps` 不存在、`dist\desktop\mcps` **已存在** → **保留**既有 `mcps/` 并打印提示；
   - **两处皆不存在** → 醒目**警告**（提示文档索引 `vfts.docs` 将不可用、指引跑 `build-mcps.ps1`），**不中断构建**。
   冻结仍为**独立步骤**（`src\mcps\markitdown\build-mcps.ps1`，见 §5.3）——桌面构建只做该目录的**兜底镜像**，不做 PyInstaller 冻结。
9. **出厂数据包**（`[9/9] pack factory data`）—— 生成到 **`dist/initdata/`**（**不进 `dist/desktop`**）：
   **单包 `capability-<ver>.zip`**（= `dist/desktop/capability/` **全量**，含 `executors/` exe；2026-10-01 P2 起合并为单包，旧 4 分包 `capability-tools/-knowledge/-executors/-scenarios` 作废）·
   **`initial.zip`**（完整出厂包，**内含 exe**，= `dist/desktop` 全部内容（排除 `.chonkpilot/`），供用户自行恢复安装）。
   `<ver>` = 日期时间戳（`yyyyMMdd-HHmmss`；无独立版本源）；**不做任何哈希/版本清单校验**。

## 3. mcp-server 部署（`build-mcp-server.ps1`）

流程（3 步）：

1. **编译 server** —— 在 `src/others/mcp-server`（exe 外壳）内 `go build` → `dist/other/chonkpilot-mcp-server.exe`（Streamable HTTP，默认 `127.0.0.1:5700`，端点 `/mcp`）。
2. **部署契约** —— 覆盖式同步 `src/initdata/capability` → `capability/`（4 棵**平坦**子树）：
   - `tools/` 源 = `src/initdata/capability/tools`；
   - `skills/` / `prompts/` / `resources/` 源 = `src/initdata/capability/{skills,prompts,resources}`（2026-10-01 P2 扁平化：旧 `knowledge/` 归并层作废）。
3. **编译 executor** —— 三个分类 exe 统一落到 `capability/executors/`（扁平命名 `chonkpilot-<cat>-executor.exe`；契约 `tools/<cat>/*.tool.md` 的 runtime 相对 md 写 `../../executors/<cat>.exe`）：`core` / `desktop` / `browser`；随后逐个 `--help` 验证（`--help` 从磁盘读契约）。

另：首次生成 `config.json`（已有不覆盖）：`timeout_sec=300`、`defaults.skip_dirs` 等。

产物：

```text
dist/other/
├── chonkpilot-mcp-server.exe
├── chonkpilot-mcp-gateway.exe           # build-mcp-gateway.ps1 产出到同一目录
├── config.json
└── capability/
    ├── prompts/<...>/*.prompt.md
    ├── tools/{core,desktop,browser}/*.tool.md
    ├── resources/<...>/*.resource.md
    ├── skills/<...>/*.skill.md
    └── executors/chonkpilot-{core,desktop,browser}-executor.exe
```

运行形态（必须显式指定）：

| 形态 | 命令 |
|------|------|
| HTTP 前台 | `.\chonkpilot-mcp-server.exe --http`（`--http=0.0.0.0:5700` 指定地址） |
| stdio（IDE spawn） | `.\chonkpilot-mcp-server.exe --stdio` |
| Windows 服务 | `.\chonkpilot-mcp-server.exe --service install`（需管理员；服务运行 = HTTP） |

### 5.3 文档转换服务（`build-mcps.ps1`，源 `src/mcps/markitdown`）

- **定位**：把 **Office / PDF** 转成 Markdown 文本（尽量附定位信息：PDF 页码 / xlsx sheet / pptx slide），
  供 **vfts 全文索引**读取非文本格式（vfts 默认扩展名集只含源码 + `.txt/.md`，二进制文件被 `isBinary` 跳过，
  故 Office/PDF 需先经本组件抽取）。**索引侧接入已于 2026-09-29 落地**（`vfts.docs` 开关；见 [38 §2/§3](../30-function-points/38-检索与索引.md)）。
- **构建（独立脚本，不接入 `build-desktop.ps1` 必经路径——冻结慢）**：

```powershell
.\src\mcps\markitdown\build-mcps.ps1            # onedir（默认，冷启动快）
.\src\mcps\markitdown\build-mcps.ps1 -Onefile    # onefile（单文件，冷启动慢）
```

- **产物** → `dist/desktop/mcps/markitdown/`：`markitdown-mcp.exe`（PyInstaller 冻结）+ `README.md` + `THIRD-PARTY-NOTICES.txt`。
  **默认 `--onedir`**：另含 `_internal/` 依赖目录——脚本把 PyInstaller 产出的子目录**平铺**到该目录（`markitdown-mcp.exe` 落根下），
  **投放布局本目录内自洽、须与 `_internal/` 一并投放**；`-Onefile` 时无 `_internal/`（单文件）。
- **与桌面构建的关系（2026-09-29 说明）**：`dist/desktop/mcps/`（转换服务产物）**不由 `build-desktop.ps1` 生成**——
  PyInstaller 冻结**不并入**桌面构建（冻结慢，见上）。`build-desktop.ps1` 只把 `dist\other\mcps` **兜底镜像**到
  `dist\desktop\mcps`（存在即把**子项**覆盖镜像、**保留 `codebase/`/`vfts/` 引擎目录**；否则保留既有 `mcps/` 并提示；
  两处皆缺则告警、**不中断**，见 §2 步 8）——故先跑 `build-mcps.ps1` 产出的 `mcps/markitdown/` 会**跨桌面构建保留**。
  发行/打包流程：先 `build-mcps.ps1`（或直接用已产出的 `mcps/`），再 `build-desktop.ps1`。
- **运行形态**：单进程 HTTP，**只监听 `127.0.0.1`**，默认端口 `7317`（被占自动另选，实际端口入状态文件）；同一端口两个入口：
  - **MCP（Streamable HTTP）`/mcp`**：工具 `convert_to_markdown(uri_or_path)`；**不预置**进产品，由 MCP 配置页手动注册；
  - **vfts 内部快通道**：`GET /vfts/health`（**无 token**）/ `POST /vfts/convert`（需 `X-Chonk-Token`）。
- **状态文件**：`<installRoot>/mcps/markitdown/state.json`（与 exe 同目录）；目录只读时回落到
  `<data-dir>/mcps/markitdown/state.json`（Windows = `%LOCALAPPDATA%\chonkpilot`，插件侧两处都探）；
  内容 `{pid, port, token, version, started_at, exe_dir}`，优雅退出时删除。
- **随产品发，但默认不启动、且产品不代为拉起**：由用户在 MCP 配置页**手动注册/启动**（vfts 插件**只探测、不 spawn**；
  设置页 `vfts.docs` 开关只决定是否把文档类纳入索引，不负责启动服务）。
- **依赖与第三方许可**：钉版本 = `src/mcps/markitdown/requirements.txt`（每项注明许可）；
  产物内组件许可汇总 = `src/mcps/markitdown/THIRD-PARTY-NOTICES.txt`（随产物投放）。**无 GPL/AGPL 传染性组件**。
- ⚠️ **冻结体积与杀软误报**：默认 `--onedir` 为目录（`markitdown-mcp.exe` 仅 17.0 MB，依赖在 `_internal/`，总计约 168 MB），
  **无自解压步骤**（**冷启动到 `/vfts/health` 可用 ≈4.4s**）；`-Onefile` 为自解压式单 exe（80.0 MB，**冷启动 ≈9.6s**），
  部分杀软会启发式**误报**（onedir 不触发），必要时对 `markitdown-mcp.exe` 加白名单。实测体积与冷启动耗时见
  `src/mcps/markitdown/README.md` §5。

## 7. 工具契约同步规则（重要）

`src/initdata/capability/tools/*.tool.md` 是 LLM 识别工具名称/参数/行为的**唯一契约**（**出厂数据唯一源** `src/initdata/`，部署见 `build-mcp-server.ps1`）。修改 handler 后必须同步：

- **参数变更** → 更新 `parameters.properties`
- **行为变更** → 更新 `description`
- **文件命名**：文件名（不含扩展名）必须等于 `name` 字段
- **不修改**：纯 bug 修复、后端重构

### 7.1 契约的形态（权威源 → 部署副本；勿手改部署目录）

| 形态 | 位置 | 谁读 |
|------|------|------|
| ① **权威源** | `src/initdata/capability/tools/**/*.tool.md` + `src/initdata/capability/{skills,prompts,resources}/**` | `build-mcp-server.ps1` 第 2 步**覆盖式拷贝** → `capability/`（mcp-server/gateway 运行时扫描的正是这份副本） |
| ② **executor `--help`** | 无独立副本 —— executor **不再内嵌**，`--help` 从磁盘 `capability/tools/<cat>/` 读同一份契约（`--root` 可覆盖） | executor exe（`<exe> --help [<tool>]`） |

`dist/other/capability`、`dist/desktop/capability` 与 `dist/server/capability` 只是**部署副本**：直接手改副本会让 ① 与副本**静默分叉**（曾现于 `dist/desktop/capability/tools/core/file_diff.tool.md`）。**契约变更一律只改源**。

### 7.2 漂移检测与恢复（`sync-contracts.ps1`，非构建脚本）

```powershell
.\sync-contracts.ps1                     # 权威源 -> capability 覆盖式同步（默认 dist/other + dist/desktop）
.\sync-contracts.ps1 -Dist desktop        # 只同步 dist/desktop（也接受 other / server）
.\sync-contracts.ps1 -Check              # 只报漂移、不写盘；有漂移时退出码 1
```

- **覆盖前先打印**将改动的文件清单：`drift`（副本被手改）/ `missing`（副本缺失）/ `orphan`（源中已不存在的孤儿契约，同步时删除）；
- 同步后逐文件比对 SHA256，输出 `identical` 或 `drifted-n`；
- **幂等**：重复执行无副作用；只写 4 类契约 md（`*.tool.md` / `*.skill.md` / `*.prompt.md` / `*.resource.md`），**不触碰** `capability/` 下的 executor exe；
- **② 无内嵌副本**：executor 不再 `go:embed` 契约，`--help` 从磁盘读同一份 → 无 embed 副本可漂移。

**漂移了怎么办**：跑 `.\sync-contracts.ps1` 把副本覆盖回源（副本里手改的内容会丢失——需要保留就先回填到源）；改了 `src/initdata/` 契约 → 跑 `.\build-mcp-server.ps1` 重铺 `capability/` 即可（`build-desktop.ps1` 第 5 步会内部调用它并重铺 `dist/desktop/capability`）。
