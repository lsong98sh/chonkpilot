## 1. 定位与边界

本插件只做一件事：**把宿主已有的会话能力接给 LLM**，自身不含任何会话写策略、不直接开库。

| 类别 | 内容 |
|------|------|
| **插件进程** | `chonkpilot-plugins/session`（独立 Go module，MCP server = http，契约 `*.tool.md` 以 `//go:embed` 打入 exe） |
| **宿主能力** | `src/lib/llm/plugindata/sessionquery.go`（读 + 授权 + 审计）· `src/lib/llm/server/plugin_caps_session.go`（桥方法） |
| **做** | 跨会话检索（keyword / semantic / hybrid）、列会话、会话元数据、分页历史、**持久状态 / 最终回复查询**、建/续跑/改名/打开；跨用户模式的**前置门控**与审计 |
| **不做** | 会话删除（`session_delete`） |
| **相邻能力** | vfts 会话全文索引（含子会话 / 工具结果）在 codegraph 插件侧，见 [2B §3.5](2B-vfts.md) |
| **限制** | 全量向量索引只覆盖**当前用户**（跨用户目标仍按候选惰性补索引，避免代他人产生 embedding 成本）；HNSW 仅用于无过滤条件的 semantic 检索 |
| **不破的铁律** | 插件**不得直接打开 bbolt**（C8）：一律经宿主 `plugin/v1/*`；`work_dir / user / dialog_id` 不出现在工具 schema（上下文注入） |

## 2. "本会话"解析（工具面唯一约定）

LLM **不需要、也不应该**知道自己的 session_id。宿主在每次 `tools/call` 注入
`_meta.chonkpilot`（`session` / `top_session` / `work_dir` / `instance_id` / `turn` …）；
插件原样转发，宿主据此解析。工具参数里的 `session_id` **只表达"我要操作谁"**。

| `session_id` 传值 | 解析 | 适用 |
|---|---|---|
| 省略 / `"@self"` | `_meta.session`（缺失回退 `top_session`） | get / history / status |
| `"@top"` | `_meta.top_session`（缺失回退 `session`） | 用户说"这个对话" |
| 普通 id | 显式目标（仍走归属 / 跨用户校验） | 由 list / search 返回的 id |
| 其它 `@…` | `args_invalid`（不猜） | — |

- **检索**的 `session_id` 是**过滤条件**：省略 = 全部会话（不回落 self），便于"跨会话回忆"。
- **self 永不取参数**：授权与归属只用注入值；参数 id 不能用来冒充当前会话。
- 结果锚点：`session_get` / `session_list` / `session_search` 的每条记录带
  `self`（= 当前执行会话）与 `top`（= 用户可见顶层对话），让模型能把"本会话"锚定到列表项。

## 3. 跨用户模式（`targets`）

配置键：`plugins.session.cross-user` = `private`（缺省）| `llm` | `public`。
**读序 usr → prj → 缺省 private**；非法值一律按 `private`（安全侧收敛，不回落更宽层）。

| 模式 | `targets` 省略 | `targets:["*"]` | `targets:["alice"]` |
|---|---|---|---|
| **private** | 仅自己 | `permission_denied` | `permission_denied` |
| **llm** | 仅自己 | 全项目用户 | 指定用户 |
| **public** | **自己 + 全项目**（自己恒在首位 + 排序加权 1.25） | 全项目 | 指定用户（仍加权自己） |

硬规则：

1. `private` 下的非 self 目标返回 **`permission_denied`**，**不静默收窄成空结果**（空结果会被
   模型解读成"确实没说过"）。
2. 用户名必须是**单段目录名**（拒空 / `.` / `..` / `/` / `\` / `:` / 控制字符 / >64 字符）——
   防 `users/../../…` 越界（该校验同时覆盖 `session.export` 的 `resolveUser`）。
3. 共享数据根形态（`Options.DataDir != ""`，无 `users/` 分支）下显式跨用户 → `unsupported`；
   当前用户仍可读同一根。
4. 最多 **8** 个目标用户（`maxCrossUserTargets`；`["*"]` 同口径截断）。
5. 跨用户读取属于 G-102「历史记录读取」放行面：**成功一次汇总一条审计**（`action` +
   `targets` + `count`）；拒绝也落 `denied`。审计落 `<pluginDataDir>/_audit/audit.jsonl`。

| `session_send` | `prompt`、`session_id?`（省略/`@top` = 顶层）、`wait_sec?` | `plugin/v1/session.run`（带既有 `session_id`） |

全部 `hot: true`（LLM 可见）；manifest `hot_tools` 同步登记。工具名 = 契约文件名。
**保留 `session_status`**：`task_status` 依赖发起轮次存活（`plugin/v1/task.result` 需要 turn 在内存中），
而 `session_create(wait_sec=0)` 的父轮很快结束、也没有 inbox 通知；`session_status` 直接读库，
在任意轮次都能取到 `state` + 最终 assistant 文本（见 §7.1）。
**不新增 `session_delete`**：删除仍走 UI / data 面。

**检索语义（keyword，缺省）**：Go 侧大小写不敏感子串匹配——全文短语权重 3、空格/标点分隔的词元各权重 1；
`snippet` = 命中位置两侧 `context_runes`（缺省 60）；结果按 score 降序、时间降序；
自己用户的命中 ×1.25。**semantic / hybrid 见 §8**。

**预算与截断**：

| 项 | 值 | 超限表现 |
|---|---|---|
| browse 扫描会话 | 500 | `truncated=true` |
| search 扫描会话 / 消息 | 200 / 200k | `partial=true` |
| semantic 候选消息 | `max-scan`（缺省 2000） | `partial=true` |
| semantic 单次补索引 | `max-embed-per-call`（缺省 64） | `partial=true`（未建向量的消息不参与打分） |
| semantic 全量索引 | 后台逐用户全部消息（role ≠ system） | 进度见结果 `index`（`state=indexing/ready/error`） |
| search 命中上限 | `limit`（缺省 20，上限 100）；内部候选 400 | `truncated=true` |
| 单条历史消息正文 | 32k 字符 | 消息 `truncated=true` |
| 历史分页 | `target_messages`（缺省 50）/ `target_bytes`（缺省 200KB） | `has_more=true` |

## 5. 宿主能力契约（`plugin/v1/*`）

六个方法由主仓 `SetPluginRegistry` 注册（**不改框架**；不覆盖框架已映射的
`session.list/get/history`，避免破坏 codegraph 现有调用形状）。

| 方法 | 入参（关键） | 出参 |
|---|---|---|
| `session.browse` | `work_dir`、`targets?`、`include_sub?`、`kind?`、`since?`、`limit?`、`offset?`、`session`、`top_session` | `{sessions[], total, scanned_users, truncated}` |
| `session.read` | `work_dir`、`session_id`（可 `@self`/`@top`/省略）、`targets?`、`view`（`meta`/`history`）、`before_turn_id?`、`target_messages?`、`target_bytes?`、`session`、`top_session` | `{user, session, turns?[], has_more, truncated}` |
| `session.search` | `work_dir`、`query`、`targets?`、`roles?`、`session_id?`、`since?`、`limit?`、`context_runes?`、`mode?`（keyword/semantic/hybrid）、`session`、`top_session` | `{hits[], total, ..., truncated, partial, search_mode, indexed, approx?, index?, elapsed_ms}` |
| `session.status` | `work_dir`、`session_id`（可 `@self`/`@top`/省略）、`turn_id?`、`wait_sec?`、`targets?`、`session`、`top_session` | `{user, session, state, turn_status, turn_id, text?, output?, updated_at, waited_ms}` |
| `session.run` | `instance_id?`、`work_dir?`、`session_id?`（缺省 = 新建）、`title`、`prompt`、`agent?`、`scenario_id?`、`wait_sec?`、`turn?`、`tool_call_id?` | `{session_id, dialog_id, turn_id, task_id, state, text?, error?}` |
| `session.open` | `instance_id?`、`work_dir?`、`session_id?`（可 `@self`/`@top`/省略）、`dialog_id?` | `{window_id, session_id, dialog_id}`；无 GUI → `unsupported` |

- 装配：`plugindata.New(...)` 后由宿主调用 `srv.SetPluginData(store)`；`nil` → `method_not_found`。
- 窗口打开：宿主在 gui Env 就绪后调用 `srv.SetChatWindowOpener(...)`（内部 = `env.OpenChatWindow`）；
  未注入（headless）→ `unsupported`。
- 实现：`plugindata/sessionquery.go` 复用 `sessionPrjUsrDir` / `ListDialogFiles`（语义）/
  `OpenExistingDialog` / `sessions`·`turns`·`messages` 表；**按 `session_id`/`turn_id` 走索引查询**，
  不复制 `export.go` 的全表 `ForEach` 读法。

### 5.1 配置页（自持 webui）

- `webui/config.html`（embed）→ `POST /plugins/session/api/{load,save,reset}` → 插件动作 →
  `plugin/v1/config.user.{load,set,delete}`，只写 **usr** 层。
- 字段：`plugins.session.cross-user`（private/llm/public）、`plugins.session.run.max-concurrent`（0..50）、
  语义检索 7 项（`semantic.enabled/base-url/api-key/model/max-embed-per-call/auto-index/hnsw-threshold`，见 §8.1）。
- 跨字段校验：勾选"启用语义检索"时 `base-url` 与 `model` 必填；`max-embed-per-call` 1..256；
  `api-key` 用 password 输入框（secret 不回显）。
- 读序（宿主侧）：**usr → prj → 缺省**；页面只负责个人设置，项目默认由 prj 配置提供。
  读取必须用 `UserConfigGet`（合并有效值，含 `plugins.*`）——`UserConfigView` 是设置页 / 导出视图，
  会**剔除**插件配置，用它读会永远回落缺省。
- 错误码：`args_invalid` / `permission_denied` / `auth_required` / `unsupported` / `not_found` /
  `method_not_found` / `internal`。

## 7. 写入语义（批次 B / C）

| 工具 | 语义 | 实现 |
|---|---|---|
| `session_create` | 建**顶层**对话（新 dialog，kind=main）+ 首轮 auto 跑 | `plugin/v1/session.run`（`session_id` 缺省）：`SessionEnsure` 自举 → `startScheduledTurn` → `kind=llm` 任务节点 → **detached** 取消级联 |
| `session_send` | 向既有会话追发一轮 | 同 `session.run`（带 `session_id`）：`ensureDialogIndex` 定位对话 → 追加 turn；`session_busy` 明确报错 |
| `session_rename` | 改标题 | 框架 `plugin/v1/session.rename` → `data-session-title`（异步受理）；插件先经 `session.read(view=meta)` 反查 `dialog_id`，并同时发 `id`（框架信封字段名）与 `session_id` |
| `session_status` | 查**持久化**轮次状态 + 最终 assistant 文本（可等待） | `plugin/v1/session.status` 直读对话库；不依赖调用轮次 / `task_status` / inbox（见 §7.1） |
| `session_open` | 帮用户打开对话窗口 | `plugin/v1/session.open` → 宿主 `gui.Env.OpenChatWindow`（与托盘 / `gui.window.open-chat` 同一实现；已打开则激活） |

固定口径：

- `session_create` **永远顶层**（无 `parent_session_id` 参数）、`prompt` 必填、**auto 跑首轮**、无 draft 分支；
  `session_id` 由宿主生成（`split-<random>`），调用方不可指定。
- **父子关系只用于取消级联**：`childTurn.barrier=false`（`registerDetached`）→ 父轮 `awaitDelegatedChildren`
  不等它；`llm-cancel` / `task-stop` 仍经 `closeDelegatedChildren` / `closeDelegatedInSubtree` 关闭它。
- 任务节点 `TopSession = 目标会话`（目标会话内的工具节点可经 `LatestLLMSessionNode` 挂到它下面），
  `ParentID = 调用方工具节点`（`task-stop` 子树级联可命中）。
- **并发上限** `plugins.session.run.max-concurrent`（usr 优先，prj 作默认；缺省 **3**；<=0 = 不限）：
  超限时阻塞排队，直到有空位或调用 ctx 结束（返回 `session_busy`）。
- **turn 级幂等 v1 不保证**：同一 `prompt` 重试会再跑一轮（会话创建只在 `session_id` 缺省时发生一次）；
  需要严格幂等时由调用方用 `wait_sec` 等终态后再决定是否重试。

### 7.1 `session_status`（异会话结果读取）

问题：`session_create(wait_sec=0)` / `session_send(wait_sec=0)` 返回 `running` 后，父轮很快收尾。
此时 **没有在飞的工具**承载结果，也**没有 inbox 通知**；`task_status` 的 `plugin/v1/task.result`
要求发起轮次仍在内存里（父轮结束后 `turn_not_found`）。因此增加持久化状态能力：

- 读 `turns` 表最新（或 `turn_id` 指定）轮次：`status` / `updated_at`；`state` 归一为
  `running | done | incomplete | error | interrupted | cancelled | not_started`。
- 读该轮最后一条 `role=assistant` 正文 → `text`（终态 = 最终回复）；`running` 时同一文本放 `output`。
- `wait_sec` > 0：500ms 轮询到非 `running` 或超时（上限 600）；`waited_ms` 回传实际耗时。
- 不新增 MQ 主题 / 不写 inbox；跨用户复用 `resolveTargets`（G-102 读取 + 审计）。
- 与 `task_status` 的分工：轮次**仍在执行**且需要任务树 / 部分工具输出 → `task_status`；
  父轮已结束、只要会话终态与最终回复 → `session_status`。

## 8. 向量语义检索（SESSION-SEMANTIC-1）

动机：关键词检索答不了"交付的事怎么样了"（问法与原话不同）。语义检索把消息正文与查询映射到同一
向量空间，按余弦相似度排序。**默认关闭**，需用户配置任意 OpenAI 兼容 `/embeddings` 服务。

### 8.1 配置（usr 优先、prj 作默认）

| 键 | 缺省 | 说明 |
|---|---|---|
| `plugins.session.semantic.enabled` | `false` | 总开关；false 时 `mode=semantic/hybrid` → `semantic_disabled` |
| `plugins.session.semantic.base-url` | — | OpenAI 兼容 base（自动追加 `/v1/embeddings` 或 `/embeddings`） |
| `plugins.session.semantic.api-key` | — | 可选 `Authorization: Bearer` |
| `plugins.session.semantic.model` | — | embedding 模型名；**换模型 → 旧向量自动失效重建** |
| `plugins.session.semantic.max-embed-per-call` | `64` | 单次补索引上限（1..256） |
| `plugins.session.semantic.min-score` | `0.20` | semantic 命中阈值（低于丢弃） |
| `plugins.session.semantic.max-scan` | `2000` | 候选消息上限，超出 `partial=true` |
| `plugins.session.semantic.auto-index` | `true` | 首次语义检索时后台全量补索引当前用户全部消息（role ≠ system） |
| `plugins.session.semantic.hnsw-threshold` | `512` | 用户向量数 ≥ 该值时，无过滤 semantic 检索走 HNSW（0 = 缺省） |

### 8.2 工具面

- `session_search(mode=keyword|semantic|hybrid)`；缺省 `keyword`，行为与 v1 完全一致。
- **semantic**：`score = cosine`，低于 `min-score` 丢弃；`snippet` = 关键词命中位置，否则正文开头。
- **hybrid**：`score = 0.65×cos + 0.35×(keyword/max_keyword)`；命中带 `semantic_score` / `keyword_score`。
- 自己用户的命中 ×1.10（public / 多用户下"优先自己"）；keyword 模式仍是 ×1.25。
- 返回 `search_mode` / `indexed`（本次补写条数）；`approx=true` = 本次走 HNSW 近似检索；
  `index` = 后台全量索引状态（`state/done_dialogs/total_dialogs/indexed_messages/new_vectors`）。
  预算耗尽或仍有消息缺向量 → `partial=true`。

### 8.3 索引与事务

- 向量表 `session_vectors` 落**各自对话库**（与 `messages` 同库）：
  `{message_id, session_id, turn_id, role, model, dim, vec}`；`vec` = base64(小端 float32)。
- **惰性索引**：检索发现缺向量 → 批量嵌入（每批 16，单次最多 `max-embed-per-call` 条）→ 写回；
  历史消息随多次检索逐步覆盖。`indexed=0` = 没有新补写。
- **全量索引**（`auto-index=true`）：首次语义检索时后台起任务，逐对话把**全部可索引消息**
  （user / assistant / tool，跳过 system）批量补成向量；同一 workdir+user 同 model 的 `ready`
  任务复用，`error` 下次检索重试（已写向量保留）。进度经 `session.search` 的 `index` 字段回传。
- **HNSW**（`sessionhnsw.go` + `hnswlite`）：无过滤条件（无 `session_id` / `roles` / `since`）的
  semantic 检索按 workdir+user 建全局图并缓存（节点 key = `dialog_id\x00message_id`）；命中后按
  dialog 分组回表取消息。带过滤条件 → 回落精确扫描（近似召回 + 过滤会放大漏检）。
  向量写入后图立即失效重建；结果带 `approx=true`。
- 事务边界：候选收集 + 读已有向量在**只读事务内**，HTTP 与写入都在事务外（不持锁跨网络）。
- 失败策略：查询向量失败 → `semantic_unavailable`；补索引 / 全量索引失败 → 保留已写向量 +
  `index.state=error`（下次检索重试），不让单条失败拖垮整次检索。
- HNSW 实现 = `plugindata/hnswlite`（CC0 来源的 graph + distance，无持久化 / 无三方依赖）。
