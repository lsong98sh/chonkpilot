## 1. 定位

**进程内单例 lib，位于基座最底层**，持有 `work_dir` 维度的**动态、不落库**状态。

| 项 | 结论 |
|----|------|
| 形态 | lib（不是层 / 不是模块 / 不是插件） |
| 依赖位置 | `core` 之上；`data` / `filesys` / `llm` / `gateway` 之下 |
| 能力面 | Go 函数调用（同步） |
| 事件面 | MQ：`workdir-opened` / `workdir-closed`（[61 §2.5](../60-reference/61-消息一览.md)） |
| 进程形态 | 恒 in-proc |
| 持久化 | 无（纯内存，崩溃即丢，随窗口重建） |

**判据**：需要同步拿到结果 → lib；需要跨进程通知 → MQ。

## 2. 职责与边界

**做：**

1. 工作区注册表：哪些 `work_dir` 当前打开（只存打开态 + `OpenedAt`）。
2. 引用计数：首个实例注册 → `workdir-opened`；最后一个退出 → `workdir-closed`（判据 = 实例视图）。
3. 物理布局的唯一算法（子包 `workspace/layout`）：`workDir` / `.chonkpilot` / `users/<OS 用户>`（`data.PrjUsrPath` / `data.UserDirName` 已改为转发）。
4. 打开时初始化目录（**只建不删**）。
5. 路径解析与边界校验（词法 + 真实路径，防符号链接 / 目录联接越界；`workspace/layout`）。
6. （消费方按需）`Resolve(instanceID)` 提供 `instance → work_dir` 的唯一解析口（读实例视图）。
7. **PM 门面**（P5，SANDBOX-WRITE-1 §7.2）：`OpenProject / CreateWindow / Hide / Close /
   CreateDialog / CreateSession`（薄门面 → `ProjectOps` 端口，PM **不持有窗口句柄**）+
   `Route / Mark`（MQ 分发策略，唯一实现，`src/lib/gui/mqpolicy` 只做类型转换）。

**不做：**

1. `workdir-closed` 时**不删任何磁盘内容**、不清索引。
2. 不做业务清算（取消 turn / 释放 busy 锁 / 注销 capability / persist 解绑仍归各消费者）。
3. 不管窗口句柄（`work_dir → 主窗口` 映射仍在 GUI 窗口层，经 `ProjectOps` 端口调用）。
4. 不定义「关闭 / 隐藏」的交互策略（属于窗口层）。
5. **不复刻实例视图**：`workspace.Manager.Instances` 已改为**委托** `framework/runtime/instance.Manager`
   （P5 步骤 1）；**PM 与 server 共源**一份 `instance-register/exit` 投影（入口装配器把同一份注入
   workspace 与 llm-server）。data/persist 仍自持 `kernel.View`（实例绑定表，见 §7），不属 PM 投影（2026-11-04 核对）。

> ⚠️ 路径校验是**内部纪律**，不是安全边界：in-proc 插件可直接 `os.WriteFile` 绕过；真正的边界是 OS 级沙箱（[14-安全域](../10-architecture/14-安全域-agentbox.md)）。

## 4. 生命周期

```text
register(work_dir 首次出现)
  → 先把事件写入唯一实例视图（instance.Manager.HandleRegister）
  → 建 Space（确保 .chonkpilot/、users/<user>/ 存在）
  → 发 workdir-opened
register(已存在)
  → 更新实例视图，不发事件
exit
  → 先从实例视图取该实例 work_dir，再摘除
  → 该 work_dir 已无实例 → 发 workdir-closed → 清内存（保留目录）
```

- 幂等：同 `instance_id` 重复 register 不重复发事件；重复 exit 无副作用
  （视图按 id 覆盖 / 删除）。
- 空值忽略：`instance_id` / `work_dir` 为空 → 不动作。
- **订阅顺序 = -1**：本包先于实例视图自身订阅（order 0）执行，读到的是「本条事件处理完」的
  确定状态；视图随后的同名处理幂等 —— 因此不依赖两个订阅者的注册先后。
- `workdir-closed` 的 `instance_id` = 触发归零的实例。
- 键 = `work_dir`（实际只 `TrimSpace + ToLower`，**未做 `filepath.Clean`**；`manager.go:305-307`）。已知限制：`C:\a` 与 `C:\a\.` / `C:\a\` 会被当作两个 Space（2026-11-04 核对）。`user` 只是实例属性，不参与分桶。

## 5. 消费方

| 消费方 | 用法 |
|---|---|
| `appwire` | `Bus → workspace → Facade → Filesys → Server` 装配序；**先建实例视图**再同时注入 workspace 与 server（单源）；`Shutdown` 逆序 |
| `filesys` | `Resolve` 解析基目录（G-21 信任边界不变）；路径函数直接用子包 `workspace/layout`；订阅 `workdir-opened/closed` 驱动**整个工作区一次递归监听** |
| `data` | 只共享**布局算法**（`PrjUsrPath` / `UserDirName` 转发到 `workspace/layout`）；**实例绑定表与四级存储（app / usr / prj / prjusr）仍归 data**，不与 PM 合并（见 §7） |
| `llm/server` | 经 `Options.InstanceManager` 接收**与 PM 同一份**实例视图（P5）；workdir 解析沿用既有口径 |
| `gui/mqpolicy` | `SetRouter(app.Workspace.Router())` → 分发策略与 PM 共用发布账本 / 反查视图；本包只剩 `dispatch.Sink ↔ workspace.Sink` 转换 |
| `gui/host` | `SetProjectOps(hostProjectOps{open: openProjectAs})` → `OpenProject` 走既有唯一开窗实现 |
| `gateway` | 沙箱根按调用方 `work_dir`，不依赖 PM 注册表 |

## 6. 异常与重启恢复

| 问题 | 答案 |
|---|---|
| 状态落在哪 | 纯内存，进程级 |
| 用户输入是否受理即持久化 | 不适用（PM 不接用户输入） |
| 非终态收口 | 无（没有 pending/running） |
| 重启后 | 从空开始；窗口 `instance-claim → register` 自然重建，无需对账 |
| `workdir-opened` 重复语义 | 不重放；晚连接插件的补发由插件桥 `instance_replay` 承担 |
| 崩溃影响 | 只丢计数；下次 register 重建（目录本来不删） |

## 7. 关键设计决策

| 决策 | 结论 | 理由 |
|---|---|---|
| lib 而非 MQ 组件 | 能力面 = 函数调用；事件面 = MQ | 调用方要同步拿结果（handler 第一行）；MQ 请求-应答是无谓往返 |
| 由 PM 发 `workdir-opened/closed` | 引用计数唯一持有者 | 各服务各自数引用必然漂移；`workdir-closed` 必须只有一个判断点 |
| 关闭不删盘、不清索引 | 只发事件 | 用户关窗口 ≠ 销毁工程；索引/数据下次 opened 时按需恢复 |
| 路径校验留在唯一入口 | 每个 handler 第一行调 | 抽成公共工具会被绕过（G-21 越权口子的由来） |
| 不复刻实例身份视图 | 直接**委托**框架 `instance.Manager`（P5 起单源） | 两套身份会分叉；PM 只补 workdir 维度，不另存副本 |
| **不与 data 合并实例绑定表** | **决策：不合并（2026-10-29）** | PM = **项目（work_dir）维度**；data = **app / usr / prj / prjusr 四级存储**，职责不同。且 data 侧是**同步 API**（`data.PrjUsr(instanceID)` 立刻要 `*DB`）+ 总线异步时序不保证 + `LastBeat` 是活性而非工作区——合并需把大量同步调用点改异步，收益仅是“少一张表” |
| **PM 与实例视图合并（P5）** | **✅ 已实施（2026-11-03）**：`workspace.Manager` 删除 `byInst` / `Space.Instances`，实例解析全部读 `instance.Manager` | 两份 `instance-register` 投影必然漂移；单源后 `Resolve` / `InstanceIDs` / 开闭判定口径一致 |
| **布局算法拆子包** | **✅ 已实施**：`workspace/layout`（`Layout` / `Of` / `EnsureDirs` / 路径函数） | `filesys` / `data` 只需路径语义，不必连带实例视图与事件订阅；主包保留同名薄封装，调用点零改动 |
| **PM 不持有窗口句柄** | **✅ 已实施**：动作经 `ProjectOps` 端口 | 无 GUI 形态仍可运行 PM（只读能力 + 路由不依赖窗口） |
| **路由收归 PM** | **✅ 已实施**：`Router.Route` 唯一实现，`mqpolicy` 只做类型转换 | 主题分级 / 自发布账本 / workdir 收紧只有一份；`WorkDirPolicy` 保留薄封装以免调用点与测试漂移 |

## 8. 边界与已知限制

- **隐藏目录的事件成本（2026-10-29 已缓解）**：隐藏子树的事件在 **入队前**即丢弃（不进 60ms 队列、不做归一/真实路径解析/JSON/广播），进程内只剩一次段名匹配；`droppedHidden` 计数可观测。
  **上限**：Windows `ReadDirectoryChangesW` 是「单句柄 + 子树」模型（`bWatchSubtree=true`），库层无法让内核不上报 → 内核通知本身仍存在。要完全消除需改为**逐目录句柄**（`bWatchSubtree=false`），代价是句柄/挂起读随目录数增长，**评估不采用**（G-86 ①）。
- **计数漂移**：漏一次 `instance-exit`（进程被杀）会让 workdir 永不关闭；desktop 形态无心跳超时 → 兜底 = 托盘退出时全量收口（既有路径）。
- **`filesys.watch/unwatch` 已无副作用**：契约字段（含 `recursive`）保留，前端展开/折叠不再影响监听范围。
