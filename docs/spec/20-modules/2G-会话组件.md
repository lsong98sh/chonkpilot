## 1. 定位与边界

会话组件是**完美组件**：独立、可单测、零外部组件依赖。它只回答「发生了什么」，不回答「接下来做什么」。

| 类别 | 内容 |
|------|------|
| **依赖** | 标准库 + `chonkpilot-agent/chat` + **`store` 端口**（`Store / DB / Table / Tx` 接口与 `Record / ChatMsg` 等契约类型） |
| **不依赖** | `chonkpilot-data` / bbolt / Chat 实现 / Router / Gateway / MQ / LLM / executor（不 import、不调、不订阅） |
| **提供** | 对话目录（dialogs）、会话树、轮次、消息、上下文快照、任务树、收件箱、派生（fork）+ **开箱即用的 Dispatcher** |
| **不提供** | 模式/策略判定、LLM 调用、工具执行、UI 布局、总线、后台队列、配置快照 |

「组件内置 Dispatcher」与「零外部依赖」不冲突：内置实现是**纯函数**（无 IO、无 goroutine、不持锁），核心包只定义接口。

### 1.1 做 / 外包 / 不做

| 能力 | 归属 | 说明 |
|------|------|------|
| 对话目录 + 会话树 + 轮次/消息/快照/任务树/inbox 落库 | **做** | 本组件 |
| Dispatcher（Relay / Fanout / Record）+ Terminator / Selector | **做** | 纯决策，可被外部替换 |
| 串行、worklist、并发调度、重试 | **外包** | 宿主（turn 循环 + `inbox_items`；同一 `(instance, session)` 同时只有一个 turn） |
| token 级流式增量 | **外包** | llm-server → MQ；组件只发「整条消息」级事件 |
| 工具调用循环 | **外包** | MCP / executor（llm-server 侧） |
| MQ 主题与 payload | **外包** | 最外层 adapter；组件不认主题名 |
| 配置 / 策略快照 | **不做** | 配置永远现读 prjusr，会话不冻结策略 |
| Guardrails / 多模态 / 语音 | **不做** | 留白 |

### 1.2 Persist Provider（持久化端口，2026-10-24 落地）

组件只声明「要什么」，不关心「怎么存」：

```
component.New(Options{Store: store.Store, Sink, Clock, Dispatcher})
```

| 端口 | 职责 | 一树一库（bbolt）实现 |
|------|------|------------------------|
| `Store.Catalog()` | 对话目录库（prjusr；`dialogs` 表） | `data.OpenSharedLayer(prjusr)` |
| `Store.OpenDialog(id)` / `ExistingDialog(id)` | 打开 / 只开已存在的对话库 | `dialogs/dialog-<hex>.db` |
| `Store.CloneDialog(src,dst)` | 派生的一致性快照 | bbolt `Tx.WriteTo` |
| `Store.DeleteDialog(id)` / `DialogFileName(id)` / `NewID()` | 删除 / 命名 / id 生成 | `data.DeleteDialog` / `data.DialogFileName` / UUID v4 |
| `Store`（**可选**）`DialogPurger.PurgeDialog(id)` | 整对话删除：目录行 + 库文件（「删主 session = 删整对话」用；类型断言探测，不并入 `Store`） | 组件 `store.Memory` 已实现；主仓适配器 `storeadapter` **已实现**（P4-2 批次二，2026-10-28）；**活动位不清**（宿主调用点补偿） |
| `DB.Table / DB.Update`、`Table.Get/Insert/Upsert/UpdateIn/Delete/ForEach/Query`、`Tx.Get/Insert/Put/Delete/ForEach` | 行级读写 + 单事务 | `data.Table` / `data.Tx` 薄适配 |

实现位置：主仓 `src/lib/data/internal/storeadapter`（bbolt）；组件仓库 `store/memory.go`（内存参考实现，供单测与演示）。
**组件仍然决定表名 / 主键 / 行字段**（会话域 schema）；Store 只决定「切几本库、怎么落盘、事务怎么提交」。
token 估算 / 三段边界 / 简化态构造的唯一实现也已在组件内（`EstimateTokens*` / `LocateZones` / `BriefMessages`），
数据面（`chonkpilot-data`）只做薄转发。

## 2. 概念模型

| 概念 | 定义 |
|------|------|
| **Dialog（对话）** | 一棵会话树 + 一个库文件。有**自己的 id 与 title**（与原「sessions 面板」一一对应） |
| **Session（会话）** | 树里的节点：`{session_id, title, kind, parent_id, forked_from}`。每库**恰有 1 个主 session**（`parent_id == ""`），其余为子会话（单聊 / 多聊 / 子聊天） |
| **Participant** | `{id, kind: human\|llm, role}`。**每 session 至多 1 个 `kind=llm`**；更多 agent → 子会话 |
| **Dispatcher** | 投递策略接口，`Create` 时注入；组件内置若干实现（§6） |
| **Utterance** | 一条话语：「谁说了什么」= `{From, Role, Body, At, ClientMsgID}` |
| **Turn** | 一次一来一回。`Dispatch` 时无 open turn 则自动开，`Finish` 自动关 |

关键约定：

- **两个 id 无关**：`dialog_id` 与 `session_id` 各自独立生成（UUID），互不派生。
- **title**：`dialog.title` 是**主 session 标题的副本**，主 session 重命名时同步；子会话重命名不同步。
- **寻址**：UI 与所有会话类接口用 `(dialog_id, session_id)` 定位。

| 形态 | 结构（同一个库里） |
|------|--------------------|
| 单聊 | 1 行 session（`parent_id=""`，`participants={human, llm}`） |
| 多 agent | 1 行主 session + N 行子 session（各自一个 llm），全部同库 |
| 子聊天 | 子 session 再挂子 session（`parent_id` 成树） |

**正文只存一份**：一树一库，所有 session 的消息在同一 `messages` 表里，按 `session_id` 归属。因此**不再需要 root 引用行，也不需要 `post_seq`**（跨会话展示序由 `created_at` 纳秒 + 宿主按 `(instance, session)` 串行写入保证 —— `busy` 注册表 + turn 循环）。

## 3. 存储布局与数据模型

```text
prjusr/chonkpilot.db
  dialogs   {dialog_id(PK), file, title, kind, updated_at}   ← 原「sessions 面板」；可重建索引

dialogs/dialog-<hex(dialog_id)>.db      ← 一个库 = 一棵会话树（真源）
  sessions     主 session 1 行 + 子会话 N 行
  messages     正文
  turns        轮次
  tasktree     任务树
  inbox_items  收件箱
  snapshot     上下文快照（history / snapshot_turn）
```

> 无 `_meta.schema_version` / `_migrations`：迁移框架已整体移除（2026-10-25），库结构 = `bucketsFor` 直建。

### 3.1 真源与副本

| 数据 | 真源 | 副本 |
|------|------|------|
| 会话树（含 title/kind/parent） | 库内 `sessions` 表 | `dialogs` 的 title/kind/updated_at |
| 消息/轮次/任务树/收件箱/快照 | 库内对应表 | 无 |

`dialogs` 表是**可重建索引**：文件在、行缺失 → 扫库补行；行在、文件缺失 → 标记 broken 或删行。因此「主 session 改名 → 同步 dialog.title」可以只做**尽力双写 + 启动对账**，不需要跨库事务。

> **P4 / C12（2026-11-03）**：`kind="crontab"` 是**保留类型** —— 对账补行时若库内主 session 缺 `kind`，**沿用既有目录行的 `crontab`**，不回落成 `main`（否则定时任务对话会因对账而出现在用户列表）。用户可见列表只取 `ListVisibleDialogs`，对账仍扫全量 `ListDialogs`。
>
> **G-99（2026-11-03，列表可见性开关）**：`ListVisibleDialogs(catalog, includeCrontab)` 的开关由调用方按插件配置 **`plugins.crontab.show-in-session-list`**（usr 层，缺省 `false`）传入 —— `true` → `kind="crontab"` 的顶层对话**进入**用户会话列表（`data-session-list`）；`false` / 键缺失 / 读库失败 / 值非 `"true"` → **排除**（fail-closed 到「不显示」）。`data-session-latest` 与活动位回落**恒传 false**（crontab 会话不得成为「当前活动会话」缺省回落值）；对账仍用 `ListDialogs` 全量。

### 3.2 表与字段

**`dialogs`（prjusr）**

| 字段 | 说明 |
|------|------|
| `dialog_id` | 主键（UUID，与 session_id 无关） |
| `file` | 文件名（`dialog-<hex(id)>.db`）；路径规则唯一实现 `data.DialogDBPath` |
| `title` / `kind` | 主 session 标题 / 形态的副本（列表展示用）。`kind` 取值含 `main` 与 `crontab`（定时任务顶层对话，**缺省不进**用户会话列表，可由 `plugins.crontab.show-in-session-list` 打开；见 §3.1 / [61 §0.6](../../60-reference/61-消息一览.md)） |
| `updated_at` | 最近活动（排序用） |

**`sessions`（库内）**

| 字段 | 说明 |
|------|------|
| `session_id` | 主键 |
| `title` | 会话标题（主 session 的 title 是 dialog 的真源） |
| `kind` | `main / group_chat / sub_chat / crontab / crontab_task`（仅展示/归属，组件不解释语义）。`crontab` = 定时任务**根会话**（`parent_id=""`），`crontab_task` = 每任务的子会话（`parent_id` = 根会话） |
| `origin` | 执行主体（可选属性；空 = 用户会话，`scheduler` = 定时任务驱动；**仅非空才写键**） |
| `parent_id` | 主 session 为 `""`；子会话指向父 `session_id` |
| `forked_from` | 派生来源（fork 后为新库内的源 id）；空 = 非派生 |
| `created_at` / `updated_at` | UTC 纳秒固定 9 位（`RFC3339FixedNano`） |
| `lifecycle` / `agent` / `scenario_id` / `llm` / `purpose` / `goal` / `playbook` / `convergence` | **可选属性列**（`component.SessionAttrs`，对齐 data 侧 `sessionRowFromEnsure`）：**仅非空才写键** —— 空值不落键，普通会话行形状不变 |

**`messages`**

| 字段 | 状态 | 说明 |
|------|------|------|
| `role` / `content` / `created_at` / `turn_id` / `session_id` | 既有 | `role=tool` 时 `content` = `{call,result,async}` JSON |
| `sender_agent` / `mentions` | 既有 | 群聊发言标识 |
| `client_msg_id` | **新增** | 幂等键（同 session 内唯一），命中即回放 |

索引：`messages_by_session`（`session_id + created_at`）、`messages_by_turn`（`turn_id + created_at`，删除级联兜底）。

**`turns`**：`turn_id / session_id / status(running|completed|aborted|interrupted) / finish_reason / summary / full_tokens / brief_tokens / created_at / updated_at`（duration 由两个时间戳相减，不新增字段）。索引：`turns_by_session`、`turns_by_status`。

**`snapshot`**：主键 = `session_id`；字段仅 `history` / `snapshot_turn`。**不含 `config_rev` / 配置快照**。

**`tasktree`**：字段沿用现网（`task_id / top_session / session_id / status / closed …`）。`top_session` = 主 session；`session_id` = 产出该节点的会话（语义字段）。

**`inbox_items`**：字段沿用现网（`session / turn_id / type / llm / content / think / effort / scenario_id / idempotency_key / source / status / created_at`），`status ∈ pending / consumed / discarded`。

### 3.3 存储规则

- 路径唯一实现 `data.DialogDBPath`；文件名 `dialog-<hex(dialog_id)>.db`，规避非法字符与路径穿越。
  文件名 / id 生成与反解**唯一实现** `data.DialogFileName` / `data.NewDialogID` / `data.DialogIDFromFile`
  （`internal/sessionstore` 与 `session/component` 都委托，不各写一套）。
- 库**短开**：`OpenDialog` 返回 `release`，必须配对；按路径引用计数、不常驻。
- 打开失败（锁/损坏）**报错上抛，不回落 prjusr**。
- 删除 dialog：删 `dialogs` 行 + 删库文件（`DeleteDialog`，带 `dialogs/` 父目录守卫，幂等）。

跨库枚举与 DTO 整形、输入校验、错误文案留门面）。data 侧会话域门面**已无并行表访问实现**。

### 4.1 寻址

- **所有会话类调用必须带 `(InstanceID, Scope, DialogID, SessionID)`**；只给 `session_id` 无法定位库（两个 id 无关、prjusr 无 session 索引）。
- 缺 `DialogID` → `E_DIALOG_REQUIRED`（**不做全局反查**，避免再造一张 session→dialog 索引）。
- `ListDialogs` 只读 prjusr，不打开任何库；`ListSessions` / 其余调用才打开对应库（短开）。

### 4.2 Dispatch（唯一内容入口）

```go
type DispatchCmd struct {
    InstanceID, Scope, DialogID, SessionID string
    Utterance                               // From / Role / Body / At / ClientMsgID
}

type DispatchRes struct {
    MessageID string
    TurnID    string
    Decisions []Decision   // DeliverLocal / ToChild / ToParent / Finish / Persist
    Replayed  bool         // 幂等命中：不再发事件、不再投递
}
```

执行序（固定）：

1. 幂等检查：`client_msg_id` 命中 → `Replayed=true`，不写、不发、不投递。
2. 无 open turn 且未指定 `turn_id` → 自动 `OpenTurn`。
3. `dispatcher.Dispatch(ctx, u)` —— **纯决策**，不持锁、不做 IO。
4. 本地执行 `Persist`：消息行 + turn 计数 + `updated_at`，**一个事务**。
5. 提交后发事件（`TurnOpened` / `MessageAppended` / `TurnClosed`），不持锁、允许回调内再调组件。
6. 返回 `DeliverLocal / ToChild / ToParent` 给外部 adapter 执行。

硬约束：

- `From.Kind == human` 时**强制 Persist**（受理即持久化）。
- `Dispatch` 只产出决策，不执行投递（组件无 IO）。
- 决策回流（child → parent → 再投 child）由**宿主**（turn 循环取队头，`inbox_items` 承载）驱动，**禁止递归 Dispatch**。

### 4.3 事件（提交后同步回调）

```go
type Sink interface { Emit(Event) }   // 同步、只入队、不得 panic、不得长阻塞
```

| 事件 | 触发 | 关键载荷 |
|------|------|----------|
| `DialogCreated` | CreateDialog / EnsureDialog 首次落库 | `dialog_id, session_id, title, kind` |
| `DialogDeleted` | DeleteDialog | `dialog_id` |
| `SessionCreated` | CreateSession | `dialog_id, session_id, parent_id, kind` |
| `TitleChanged` | RenameDialog / RenameSession | `dialog_id, session_id, title, is_dialog_title` |
| `MessageAppended` | Dispatch 提交后 | `dialog_id, session_id, turn_id, message_id, role` |
| `TurnOpened` | 自动/显式开轮 | `dialog_id, session_id, turn_id` |
| `TurnClosed` | CloseTurn / Finish / Abort | `dialog_id, session_id, turn_id, status, finish_reason` |
| `SnapshotSet` | SetSnapshot | `dialog_id, session_id, snapshot_turn` |
| `Finished` | Finish / Abort | `dialog_id, session_id, turn_id, reason` |

事件语义：**提交后、不持锁、可重入、不重放**。事件丢失不影响一致性（数据面为准）。

### 4.4 错误码

| 码 | 场景 |
|----|------|
| `E_DIALOG_NOT_FOUND` | dialog 不存在 |
| `E_SESSION_NOT_FOUND` | session 不在该 dialog 内 |
| `E_DIALOG_REQUIRED` | 缺 `dialog_id` |
| `E_TURN_CLOSED` | `turn_id` 指向已关闭轮次（不允许"关后再补"） |
| `E_TURN_NOT_FOUND` | 显式传了不存在的 `turn_id` |
| `E_PARTICIPANT_LIMIT` | 同一 session 出现多个 llm 参与者 |
| `E_BACKEND` | 库打开/写入失败（不回落） |
| `E_UNSUPPORTED` | 存储端口缺少该能力（当前仅：删主 session = 删整对话，需可选端口 `DialogPurger`；此时**不改任何数据**） |

幂等命中**不是错误**（`Replayed=true`）。

> **〔2026-10-24 P1a 追加〕** 另有两个码（表未列、组件 Go 侧使用；**P1 未接消息面 → 非 61 契约变更**）：
> `E_MAIN_LIMIT`（一个对话库恒有且仅有 1 个主 session：`CreateSession` 缺 `parent_id`、或删主 session）；
> `E_INVALID`（入参校验：标题 > 128 字符 / 含控制字符等）。

## 5. fork

机制：**拷文件 + 一次 id 重映射 + 一条 dialogs 行**（不做逐行复制/序列化）。

| 步骤 | 规则 |
|------|------|
| 1 | 生成新 `dialog_id`（与 session id 无关）；目标文件 `dialog-<hex(new)>.db` 已存在 → 报错不覆盖 |
| 2 | `Tx.CopyFile` 复制源库（**必须用 bbolt 备份 API**，`os.Copy` 会拷到撕裂快照） |
| 3 | 单事务重映射：`sessions.session_id`（含主 + 子）、`sessions.parent_id`、`sessions.forked_from`(→源 id)、`messages.session_id`、`turns.session_id`、`tasktree.top_session` / `tasktree.session_id`、`inbox_items.session` |
| 4 | 写 `dialogs` 行（新 dialog_id / 新文件 / 新主 session 的 title / kind / now） |
| 5 | 发 `DialogCreated` |

档位：

| 档 | 实现 |
|----|------|
| `full` | 上述全流程（整个树一起派生） |
| `context` | **不拷文件**：新建空库，只写 `snapshot`（源主 session 的 history / snapshot_turn）+ 主 session 行 |

不复制：`inbox_items`（`full` 档也清空）、任何配置。

原子性：跨库非原子 —— 文件先落、`dialogs` 行后写；崩在中间 → 文件成孤儿，由「扫库补行」收敛（§3.1）。

> **实施（🆕 2026-10-24，P4 已落地 + 端口化）**：唯一实现 = **组件 `Component.ForkDialog`**（复制库走
> `Store.CloneDialog`，重映射在组件内单事务完成）；数据面门面 `SessionFork`（`data-session-fork`）与
> `storeadapter` 一起调组件（不再有 `data.ForkDialog`）。
> 依赖方向：`data → session → store`（单向，无循环）。
> GUI 入口 = 会话列表第 3 枚按钮（full 档，成功后刷新列表）。
> `full` = `DB.BackupToFile`（bbolt `Tx.WriteTo` 一致性快照）+ 单事务重映射（sessions 主键 /
> parent_id / forked_from、messages / turns 的 session_id、snapshot 主键、tasktree 两列）；
> `context` = 空库 + 主 session 行 + 源主 session 快照。成功/失败都会清理半成品文件。
> 组件事件 → MQ 映射在 `appwire/sessionmq`（**装配层**；只发既有 `session-new` / `data-session-title-changed`）。
> 放装配层而非组件内的原因：`chonkpilot-agent/session` 的依赖方向断言（`deps_test.go`）禁止其依赖 MQ 客户端。

## 6. Dispatcher

### 6.1 接口（纯）

```go
type Dispatcher interface { Dispatch(Context, Utterance) []Decision }

type Context struct {
    DialogID     string
    Session      SessionInfo      // id / parent_id / participants / kind
    Self         ParticipantID    // 本 session 的 llm 参与者
    Round        RoundState       // 大轮次：已回流 agent、轮次号、目标序列（外部派生后注入）
    Conf         DispatcherConf   // EndMarker / RoundLimit / ReturnToParent / Targets
}

type Decision struct {
    Kind   DecisionKind // Persist | DeliverLocal | ToChild | ToParent | Finish
    Child  string       // ToChild 的目标 session（同一 dialog 内）
    Reason string
}
```

**状态外置**：`RoundState` 由外部从 `turns / messages` 派生后注入；Dispatcher 无内存态 → 可回放、崩溃后可从库重建。（对齐 AutoGen 的 selector 以「当前消息 + 历史」为输入、LangGraph 的 state + checkpointer。）

> **实施进度（2026-10-24）**：`Context` / `Decision` / `Dispatcher` 接口与 **`PersistOnly`**（恒 `[Persist]`）
> 已在 P1b-1 落地（`session/component/dispatch.go`）；`Relay` / `Fanout` / `Record` 与
> `Terminator` / `Selector`（§6.2/§6.3）属 **P2**。`Dispatch` 只就地执行 `Persist` 与 `Finish`（关轮），
> `DeliverLocal` / `ToChild` / `ToParent` 原样返回给宿主（由 turn 循环依序执行）。

### 6.2 三件套

| 件 | 接口 | 内置实现 |
|----|------|----------|
| `Terminator` | `Done(Context, Utterance) (bool, reason)` | `TextMention(s)` / `MaxRounds(n)` / `AnyOf` / `AllOf` |
| `Selector` | `Next(Context) []sessionID` | `FixedOrder`（= round_robin）/ `Manual`（`Context.Round.Targets` 指定）；LLM 选择器**由外部实现**（要 IO） |
| `Route` | `Dispatch(Context, Utterance) []Decision` | `Relay` / `Fanout` / `Record` |

### 6.3 内置 Route

| 实现 | 规则 |
|------|------|
| `Relay{terminator, returnToParent}` | `from != self` → `[Persist, DeliverLocal]`；`terminator.Done` 或 `from == self` → `returnToParent ? [Persist, ToParent] : [Persist, Finish]` |
| `Fanout{terminator, selector}` | `from == self` 且未终止 → `[Persist, ToChild(selector.Next…)]`；`from == child` 未收齐 → `[Persist]`；收齐未终止 → `[Persist, ToChild(selector.Next…)]`；收齐且终止 → `[Persist, Finish]` |
| `Record{}` | 恒 `[Persist]`（旁听 / 只入库） |

场景 = 参数组合：普通聊天 `Relay{returnToParent:false}`；子对话 `Relay{returnToParent:true}`；多 agent `root: Fanout` + `child: Relay{returnToParent:true}`。

> **实施进度（🆕 2026-10-24，P2 决策层已落地）**：`Relay{Terminator, ReturnToParent}` / `Fanout{Terminator, Selector}` /
> `Record` 与 `TextMention` / `MaxRounds` / `AnyOf` / `AllOf` / `FixedOrder` / `Manual` 均在
> `session/component/route.go` · `terminator.go` · `selector.go`，**纯决策**（无 IO / 无锁）。
> 组件只就地执行 `Persist` 与 `Finish`；`DeliverLocal` / `ToChild` / `ToParent` 原样返回给宿主
> （`TestFanoutViaDispatch` 断言组件不代投子会话）。
>
> **串行 / worklist / 重启恢复归宿主（2026-10-28 订正）**：「每 dialog 一个串行邮箱」方案（原
> `src/lib/llm/sessionmail` + prjusr `dialog_mailbox` 表）**已整体删除、不接生产**（用户拍板「如果没用，
> 可以不用」，[49 §2.2](../40-roadmap/49-待实现项.md)）。三项职责在生产里已有承载：
> 串行 = `busy[instKey(instance, session)]`（同一 `(instance, session)` 同时只有一个 turn，运行中再发
> 入 `inbox_items`，队满降级 `next_turn`）；受理即落盘 / 重启恢复 = `inbox_items` 的
> `pending / running / consumed`；禁递归 = turn 循环「一轮跑完再取队头」。

### 6.4 三个决策示例

**单聊**（`{human, llm}`，`Relay`）

| 输入 | 决策 |
|------|------|
| human 说 "你好" | `[Persist, DeliverLocal]` → 外部调 llm |
| llm 回 "在" | `[Persist, Finish]` → 关轮 |

**多 agent**（主 session `{human, llm_main}` + 子 A/B，主用 `Fanout`，子用 `Relay{returnToParent:true}`）

| 输入 | 决策 |
|------|------|
| human → 主 | `[Persist, DeliverLocal]` |
| llm_main（无结束标志） | `[Persist, ToChild(A)]` |
| 子 A 产出结论 | `[Persist, ToParent]` |
| 主收到 A（B 未回） | `[Persist]` |
| 主收到 B，未终止 | `[Persist, ToChild(C)]`（下一轮目标由 `Selector` 给） |
| 主收到 main 且含 `TERMINATE` | `[Persist, Finish]` |

**子聊天**（子再挂子）

| 输入 | 决策 |
|------|------|
| 父投给中间层 | `[Persist, DeliverLocal]` |
| 中间层产出 | `[Persist, ToParent]` 或 `[Persist, ToChild(孙)]`（由该层 Dispatcher 决定） |

### 6.5 群聊纯决策（SESSION-1 外移，2026-10-31）

群聊**不另立组件**（§1.1）：投递对象 / `@` 解析 / 机读标记 / 断点补跑等**纯判定**归组件
（`session/component/groupdecide.go`），宿主 `src/lib/llm/server/groupchat_sched.go` 只保留
副作用（读名册 / 读写展示板 / 起子轮次 / 生命周期回写 / 消息广播）与 `busy` 串行调度。

| 纯函数 | 语义（与抽取前逐字一致） |
|--------|--------------------------|
| `GroupMentions(body, roster)` | 解析发言**末行** `@` 名单并归一到名册 agent；`@全体`/`@所有人`/`@all` → `[GroupAllMention]`；裸名按名册唯一同名归一 |
| `GroupIsPublic(mentions)` | 无 `@` 或 `@全体` → 公开条（投给全体） |
| `GroupIrrelevant / GroupConverged / GroupNotMet` | 机读标记：首个非空行「无关」/ 单独一行「【已收敛】」/「【未达成】」 |
| `GroupRoundInput(agent, opening, prev)` | 上一轮发言合并成一条，定向条按 `@` 过滤；无匹配 → 回落布置任务 |
| `GroupNextTargets(roster, mainAgent, spoken)` | 公开条 → 全体（名册顺序）；定向条 → 仅被 `@` 者；无人认领 → 主 agent 兜底 |
| `GroupConclusionCounts / GroupLastSays` | 展示板结论计数（首条布置任务不计）与各 agent 末条发言 |
| `GroupResumePlan(rounds, rows, roster, mainAgent)` | 断点补跑计划（有结论跳过、只补无结论者；本轮已齐 → 下一轮起） |
| `GroupWorkSessionID(groupID, agent)` | 干活子会话确定性 id（净化 + 短哈希） |
| `GroupEnsureMain(roster, mainAgent)` | 主 agent 不在名册 → 置首位（「发起者 / 兜底裁判」） |

**边界不变**：组件无 IO / 无 goroutine / 不持锁；串行叫号、子轮次执行、生命周期回写、
`subchat-*` 广播仍在宿主（§1.1「串行、worklist、并发调度 = 外包」）。消息面零变更。

## 7. 顺序、幂等与并发

- **同 dialog 顺序单调**：宿主保证同一 `(instance, session)` 串行（`busy` 注册表 + turn 循环 + `inbox_items`）；组件不保证跨 dialog 顺序。
- **跨会话展示序**：所有 session 在同一个库，靠 `created_at`（纳秒固定 9 位）+ 串行写入保证；不需要 `post_seq`。
- **幂等**：`client_msg_id` 在 session 内唯一；命中 → `Replayed=true`（不写、不发、不投递）。
- **原子性**：单条消息 + turn 计数 + `updated_at` 同一 bbolt 事务。
- **可重入**：事件回调不持锁，允许回调内再 `Dispatch`（外部须排队 —— 既有 inbox / turn 循环，防深递归）。

## 8. 崩溃恢复与异常

| 场景 | 处置 |
|------|------|
| 崩溃后存在 `running` turn | 启动清理置 `interrupted` + `finish_reason=interrupted`（沿用 `TurnCleanupStale`），不猜不补 |
| fork 中断（文件已落、行未写） | 「扫库补行」收敛：遍历 `dialogs/` 补 `dialogs` 行 |
| 目录行在、文件缺失 | 标记 broken 或删行（二选一，启动对账决定） |
| 主 session 改名后 dialogs.title 未同步 | 启动对账按库内 title 回填 |
| 删除中途失败 | 行先删；`DeleteDialog` 幂等可重试 |
| 库打开失败 | 报错上抛，不回落 prjusr |
| fd 泄漏 | 短开 + 引用计数 |
| 投递丢失 | 组件只保证"已落库"；at-least-once 由宿主 `inbox_items`（`pending / running` 重放）负责 |
| 半创建会话（行在库空） | 视为空对话；首次 `Dispatch` 补全 |
