## 3. 边界与待办

- **取消语义**：`llm_run` 派生的子会话/工具 / 主会话 cancel **一律级联、无弹框**；**正常 complete 不取消后台任务/子会话**（取消语义详见 [13-生命周期](../10-architecture/13-生命周期.md) §4.2）。
- **任务即树节点**：tasktree 为唯一权威（parent_node_id + top/parent 索引）；gateway 执行池（`execPool`）只持执行态。**唯一写者 = Task 层（`src/lib/task`，与 LLM/Data/Filesys 平级）**——llm `taskManager` 内存 `nodes` 降级为**运行态视图**、不再自写库；`data-tasktree-tasks` 由「双源」收敛为**单源（层落库行）**。
- ⚠️ tool_pair 与 tasktree 分开承载：主 chat 的工具记录点击 → 定位 tasktree 节点（CHAT-009）。

## 4. tasktree 写入时机与节点行

> 本节为原设计稿整体迁入，语义与现行实现一致（字段以 [61-消息一览](../60-reference/61-消息一览.md) `data-tasktree-upsert` 为准）。

### 4.1 写入时机

| 场景 | 动作 |
|------|------|
| 任务启动（命令 / 普通工具 / 异步注册 / `llm_run` 作业） | Upsert task 节点（`parent_node_id`=父任务或空；`session_id`；`top_session`；`task_id`=`tk-*`） |
| 子会话创建（`llm_run` 的 LLM 委派步骤） | session 节点（`kind=llm`，`node_type=session`，`session_id`=`sub-*`） |
| **`llm_run` 作业根节点（`kind=llm`）** | 建 task 节点（`kind=llm`，附带被调用的 `task_id` 冗余），其派生的子会话节点挂其下；parent：主会话直接调 → 空（顶层）；子会话内调 → 调用方会话节点 |
| 状态变化（`task-started` / `task-updated` / `task-done`） | 同步 `status` 字段（进程/输出仍在 TaskManager 内存态） |
| 手动关闭（前端 ✕） | `data-tasktree-delete` ~~**级联删除子树**~~ → **逻辑删除**（节点 + 级联子树标 `closed`/`deleted_at`，**行保留、历史可查**；视图默认过滤 closed） |

> `llm_run` 作业根节点（`kind=llm`）**不提供 item 粒度进度**；其每次 LLM 委派派生的子会话节点直接挂其下（原 `tasks_run` 容器节点统计详情已下线，见 TASK-013）。

### 4.2 节点行（node-header）统一组成（task 节点与 session 节点同款）

| 区域 | 内容 | 触发行为 |
|------|------|----------|
| 左 1 | 展开箭头（有子级）或占位（叶子） | 点击展开/折叠 |
| 左 2 | 状态图标：running=旋转 loading（accent）｜error=红叉｜done=绿勾 | 纯展示 |
| 中 | 标题（`title`，无则 `#id` 前 8 位） | 点击 → 右侧详情：session 节点=会话内容（TASK-011）；task 节点=任务详情（TASK-012） |
| 右 1 | **仅 kind=llm 节点**：🧠 耗时 + 红色 ▍终止 | 终止 → 取消语义（级联，TASK-006/008） |
| 右 2 | 进程 badge（该节点直接派生的 running command 数） | 点击 → 任务管理器 |
| 右 3 | 子树 cancel 图标（子树含任一活动任务时出现） | 点击 → 任务管理器 |

## 5. 异步任务场景矩阵（T1–T4 × 工具）

> 本节为原设计稿场景矩阵整体迁入，语义与现行实现一致。工具 → 节点映射：命令类（`script_run` 等）与文件类等普通工具 → `kind=tool`（`tk-*`）；`llm_run`（作业根 `kind=llm`）→ 每次 LLM 委派派生 `sub-*` 子会话节点（挂根节点下）。

### 5.1 四时间线（T1–T4）· 落库-显示-通知对照

| 时间线 | 前端（chat + 任务视图 + 通知） | LLM 视角 |
|--------|------------------------------|----------|
| T1 同步完成 | 结果气泡立即显示结果；任务行 running→done 保留可关 | 本 turn 直接拿到结果；历史 completed 拆 pair |
| T2 转后台 + 未查 | 转后台话术 + 提示条；行 running→done；轮末追加 🔔 通知 | 下一轮见「已转后台」话术 + 🔔 通知消息，可再查 |
| T3 转后台 + 查到结果 | 查询返回正式结果；**无通知**（已取走） | 历史仅话术 + 查询记录，无 🔔 |
| T4 转后台 + 查超时 | 显示「任务尚未结束」；**照常补发 🔔** | 同 T2 |

### 5.2 各工具要点（T1 / T2 / T3 / T4）

| 工具（节点） | T1 同步 | T2 转后台 + 未查 | T3 查到结果 | T4 查超时 |
|---|---|---|---|---|
| 命令类（tool） | 结果气泡立即显示 ✅ 输出；任务行 running（呼吸）→done（绿点）保留可关闭；无提示条 | 转后台话术 + 提示条；行 running→done；轮末 🔔 追加（同一 message_id） | 查询返回正式结果；无 🔔；行 running→done | 显示「任务尚未结束」；轮末 🔔 照发；**查询超时不取消任务** |
| 普通工具 grep（tool） | 同步快：结果气泡立即显示匹配行；行 running→done；无提示条 | 注册异步任务（`tk-*`）→ 完成冲刷；完成态保留展示，前端**不自动删**（TASK-002） | 同命令类：查询命中则无 🔔 | 同命令类：查询超时照发 🔔 |
| `llm_run`（llm 根 + `sub-*` 子会话） | 子回答摘要同步返回（作业汇总）；任务树=🧠 根节点 + 派生 🧠 子会话节点（右 1 叠加耗时+▍终止）running→done；选中=子会话聊天内容 | 子轮次完成 → 轮末 🔔 落调用方 turn；节点 running 时右 1 显示耗时+▍终止 | 查到子回答 → 无 🔔 | 查询超时 → 照发 🔔 |

### 5.3 完成通知（🔔）要点

> 完整范式、挂账-冲刷语义与前端待发送队列见 [01-端到端数据流](../00-overview/01-端到端数据流.md) §5.3。

- **挂账**：任务完成时调用方 turn 活跃 → 暂存（不落库、前端也不显示），**轮末立刻冲刷**（落库 + 前端同刻显示，同一 message_id）；系统 idle → 立即发送。
- **取消条件**：结果已被 `tool_result` 取走 → 不发通知。
- **多条并发**：按完成顺序依次写入。

## 7. ask_user 表单（chat 内联）

> **目标态**：**取代原「全局弹窗队列」**——原 7.1「前端队列状态机（queue/current/busy）」与 7.2「弹框 UI 规范」作废。落地状态：设计已定、代码待做。

### 7.1 形态

- **内联表单**：ask 在**所属 chat 窗口**的消息流中内联渲染（问题 + 选项按钮 + "其他"输入 + 提交），**不再集中弹框排队**。
- **一次 = 一表 N 问**：`ask_user` 入参 `questions[]`；同一 tool-call 的 N 问 = 一张表单卡。
- **跨批次 / 跨轮次各自独立卡片**（"属于哪个 chat 就在哪个 chat"）；LLM 同批发多条 `ask_user` 时 server **合并为一张表单**。

### 7.2 提交、持久化与回灌

| 环节 | 语义 |
|------|------|
| 提交 | `ask-user-reply {ask_id, answers:[{id, answer, custom?}]}`（**增量**：仅带本次作答的题） |
| 持久化 | 每次提交**写穿**（ask 节点 `content`，落点 = 方案 A）→ 支持**重启续答** |
| 回灌 | **N 问全部答齐**才把聚合答案作为**一个 tool_result** 喂回 LLM 续轮（满足"同批 tool 结果一次提交"） |
| 只读 | 单项提交后转只读 + 高亮已选；整表答齐后整体只读 |
| 超时 | `expires_at` 仅作 UI 提示，**不作废**、不自动应答（原"有推荐用推荐"行为作废） |

### 7.3 重启续答

- ask 等待期 turn 状态 = **`awaiting`**（非 `running`），免被 `data-session-cleanup-stale` 误标 `interrupted`。
- 重开 / 进入该会话：按落库的 ask 节点 `content`（questions + answers）**重播 `session-ask`**，前端回显"已答 / 待答"；答齐后续轮。
- 恢复路径复用 `recoverTurnCtx`（见 [21-llm-server](../20-modules/21-llm-server.md)），与 tool-retry 恢复同构。

### 7.4 会话树标注

- ask 期间 `kind=ask_user` 任务节点可辨（"等待回答"）；前端 `SessionTreeNode` 需补 `ask_user` kind 图标/颜色（现状落 `default` 灰色"其他工具"）。
