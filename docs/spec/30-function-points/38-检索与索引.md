## 3. 文档转换服务（`mcps/markitdown`）与 vfts 的关系

**为什么需要它**：vfts 只索引**可解码文本**（默认扩展名集 = 源码 + `.txt`/`.md`，前 8 KiB 含 NUL 的二进制一律跳过），
Office / PDF 因而拿不到内容。本组件负责**抽取**：把非文本格式转成 Markdown 文本（尽量附定位），
vfts 引擎据此把 Office/PDF 的 chunk 写入索引（**2026-09-29 已接入**：`vfts.docs` 开关 + 转换缓存 + loc 落库）。

**两个入口**（同一端口、同一进程，只监听 `127.0.0.1`）：

| 入口 | 端点 | 鉴权 | 用途 |
|------|------|------|------|
| MCP（Streamable HTTP） | `/mcp`，工具 `convert_to_markdown(uri_or_path)` | 无（本地规范；绑定回环即边界） | 供 LLM / 用户手动注册使用（**不预置**） |
| vfts 内部快通道 | `GET /vfts/health`、`POST /vfts/convert` | health 无 token；convert 需 `X-Chonk-Token` | 供 vfts 引擎直连，省掉 MCP 往返 |

- **状态文件**：`<installRoot>/mcps/markitdown/state.json`（与 exe 同目录；`{pid, port, token, version, started_at, exe_dir}`，优雅退出即删）；
  目录只读时回落 `<data-dir>/mcps/markitdown/state.json`（Windows = `%LOCALAPPDATA%\chonkpilot`）——**插件侧两处都探**，
  实际路径以 `/vfts/health` 的 `state_path` 为准。
- 端口默认 `7317`，被占自动另选（实际端口入状态文件）；token 每次启动随机（32 hex，只落状态文件）。

**`POST /vfts/convert` 契约** —— 成功：`{ok:true, text, loc_kind, locs?, truncated, parser_version, elapsed_ms}`：

| `loc_kind` | 格式 | `locs[].loc` |
|------------|------|--------------|
| `page` | PDF | 页码 |
| `sheet` | xlsx | sheet 名 |
| `slide` | pptx | slide 序号 |
| `none` | docx / 文本类 | — |

`locs[].offset` = 该定位在 `text` 中的**起始偏移**，口径 = **UTF-8 字节偏移**（与 Go 索引侧按字节切块一致；中文等多字节字符下与"字符偏移"相差数倍，故一律用字节）。索引侧按「chunk 首行起点字节偏移落在的最后一个 loc 区间」给 chunk 打 `loc`。

**降级行为** —— 失败：`{ok:false, error_code, message}`：

| `error_code` | 触发 | 降级语义 |
|--------------|------|----------|
| `unsupported_format` | 旧版 `.doc/.xls/.ppt`、扩展名不在支持集、缺转换依赖 | 不尝试转换（不猜测内容） |
| `scan_only` | PDF 无文本层（扫描件 / 图片 PDF） | **不做 OCR**，返回空内容 |
| `encrypted` | 加密 PDF / 加密 OOXML（实为 OLE/CFB 容器） | 不尝试解密 |
| `too_large` | 输入 > `max_bytes`（默认 50 MiB） | 拒绝；调用方可显式放大上限 |
| `timeout` | 单文件 > 60 s | 结果丢弃（底层转换线程无法真取消） |
| `parse_error` | 其余解析失败（含文件头与扩展名不符） | 报错 |
| `not_found` | 路径不存在 / 非受支持 URI | 报错 |

- `truncated=true` = 输出 Markdown 超 2 MiB（UTF-8）被截断；`401` 的 `error_code=unauthorized` 属传输层。
- **明确不做**：OCR、旧版二进制 Office、加密文档解密；docx 表格会补一行空表头（markdownify 既有行为，正文不受影响）。

## 4. 边界与待办

- **两类索引的区别**：代码索引（codegraph）面向 LLM 代码理解（符号 / 依赖 / 复杂度）；全文索引（**vfts**）按**文件内容**做关键字检索。两者均为**默认关闭**的独立门控（`enable-codegraph` / `enable-vfts`）。
- 🔁 **订正（2026-09-29）**：原「检索框 = codegraph 生成的内容 + 文件名；不再另造独立全文索引（D-12）」**作废** —— 全文索引由 **vfts** 承接；检索框（SRCH-001）仍为路径匹配占位，**待接通 vfts**。
- ⚠️ 索引进度对话框的"实时更新/失败项重试"待与 codegraph 状态面接通（🔵）。
- ✅ **vfts 索引非文本格式（Office / PDF）已接入**（2026-09-29）：`vfts.docs` 开关（默认关）+ 转换服务探测 + 转换缓存 + `loc` 落库；服务未运行（插件下发空 `doc_endpoint` → `docsAvailable=false`）→ 整批跳过文档类（不报错），并被**从 `file_list` 移除**；单文件失败 → 降级为「仅索引文件名」并保留在清单。**检索框（SRCH-001）仍未接通 vfts**。
- 组件契约 / 构建细节见 [03-构建与部署 §5.3](../00-overview/03-构建与部署.md) 与 `src/mcps/markitdown/README.md`。
