> **〔订正（2026-09-25，[25-MCP与场景分层模型](../10-architecture/25-MCP与场景分层模型.md) · [42 §2 (170)](../40-roadmap/42-决策记录.md)）—— 场景面口径（已拍板，🔵 待实施）〕**
> ① **场景独立根 `scenarios/`**（与 `capability/` **平级**），不再是 `capability/prompts/<场景目录>/`；三级仍 app/user/project。

> ④ **`SystemPrompt` 语义重定义**：由"派生 = 主 agent 的 prompt"改为 **= 场景层**（`scenario.description` + 代码按 agents 自动拼接的成员段）；**主 agent 的 prompt 归 agent 层**。
> ⑤ 用户侧 prompt（chat 面，用户输入框选择注入）**独立于场景面**。
> ⑥ **〔叠加（2026-09-26）〕三级场景（app/user/project）均可编辑**：app 级不再只读（出厂内容 = **磁盘目录**，源 `src/initdata/scenarios/`，构建脚本投放）→ app 级可**保存 / 删除**；`data-scenario-restore` 消息**已删除**（含门面 `ScenarioAPI.ScenarioRestore` 与实现）。〔**订正（2026-09-29）**：出厂内容**不再 embed、不再自动物化** —— app 初始化不写盘；根缺失即缺装（提示重新安装或用 `initial.zip` 恢复）。〕
> **〔叠加（2026-09-26 用户裁决，[42 §2 (175)](../40-roadmap/42-决策记录.md)）：同场景内 agent 重名必须报错、无法保存〕** —— 数据层 `capfs.WriteScenarioDir` **写盘前**校验（判定键 = agent **落盘文件名**、大小写不敏感）：同场景内 agent 同名（含**大小写等价** / **主 agent 与子 agent 撞名 `main`** / **空名**）→ 返回含「**场景 id + 重复 agent 名**」的错误并**拒绝写入**（**不得静默覆盖**）；覆盖**全部写入入口**（新建 / 编辑保存）。**既有数据不迁移**（③ 口径，见 [24 §3.2](../10-architecture/24-多窗口模型设计方案.md)）。
