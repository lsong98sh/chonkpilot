### `FT-016` 被索引排除条目灰显

- **说明**：文件树（目录树）中，**被当前已启用引擎的索引排除规则命中**的条目（文件/目录）**文本灰显**（`--fg-disabled`）——哪些条目「不会参与索引」一目了然。**只改文本颜色**：点击/双击/拖拽/右键等交互与布局均不变；并带原生 `title`（i18n `fileTree.index_ignored`：zh「已排除：不会参与索引」/ en「Excluded: not indexed」）。
  - **判据来源** = 只读数据面 `data-index-ignored`（[61 §3.6](../60-reference/61-消息一览.md)）：请求 = 当前**已加载节点**的 workdir 相对路径（`/` 分隔，一次批量、去重）；应答 = 每引擎 `{enabled, ignored}`。判定口径与 codegraph / vfts 引擎实际遍历**严格一致**（含祖先目录剪枝、`!` 同层反选、内置强制排除）。
  - **灰显规则**：仅统计 **`enabled=true`** 的引擎，两引擎 `ignored` 取**并集**（被任一已启用引擎排除即灰显）；两引擎皆未启用 → 无 `ignored` → **全不灰**。
  - **刷新时机**：① 树数据到手 / 每层目录加载完成 / `filesys.changed` 合并后（新增节点补判）；② 既有广播 `data-prj-config-refresh`（排除规则或引擎开关变化）→ 清缓存**重判已加载节点**（已灰的可恢复不灰）。请求克制：同一批路径只请求一次；`truncated=true`（入参超上限）时仅未判定节点不灰显、不报错。
  - **降级**：请求失败 / 主题不可用 / 应答异常 → **静默不灰显**（不报错、不打印 console.error），不影响文件树任何既有功能。
- **关联消息**：`data-index-ignored` · `data-prj-config-refresh`（既有广播）｜ **关联模块**：[20-gui](../20-modules/20-gui.md) · [38-检索与索引](38-检索与索引.md)

| ID | 场景 | 类型 | 前置 | 步骤 | 预期 | 穿透点 |
|----|------|------|------|------|------|--------|
| FT-016-S01 | 命中排除规则 | 正常 | 引擎启用 + `.gitignore`/用户排除规则 | 观察文件树 | 命中条目（含目录及其子项）文本灰显 + 原生 title | `data-index-ignored` → `.tree-row.is-ignored`（`--fg-disabled`） |
| FT-016-S02 | 引擎未启用 | 边界 | `enable-<引擎>=false` | 观察文件树 | **全不灰**（无任何灰显） | `enabled=false → ignored=[]` |

## 3. 前端树数据模型与刷新（本节为 2026-08/09 原设计稿整体迁入）

按现行实现口径整理：数据根 `.chonkpilot/chonkpilot.db`，路径统一正斜杠 `/`，目录列出走 `filesys.list`，变更推送走 `filesys.changed`。

### 节点结构

```typescript
interface TreeNode {
  label: string          // 显示名
  path: string           // 绝对路径（正斜杠 /）
  is_dir: boolean        // 是否目录
  children?: TreeNode[]  // 子节点（目录专用）
  expanded?: boolean     // 展开状态（目录专用）
  _loading?: boolean     // 加载中状态
  _loaded?: boolean      // 是否已加载过子节点
  _depth?: number        // 深度（flatNodes 计算属性注入）
}
```

### treeData（根数据）与根目录语义

treeData 是**项目工作目录的第一级子节点数组**，**根目录本身不在 treeData 中**——treeData 就是根目录的 children。

```text
treeData = [
  { label: 'assets',  path: 'E:/.../assets',  is_dir: true,  children: [], expanded: false },
  { label: 'src',     path: 'E:/.../src',     is_dir: true,  children: [...], expanded: true },
  { label: 'main.go', path: 'E:/.../main.go', is_dir: false },
  ...
]
```

因此 `findNode(treeData, workDir)` 恒为 null，根目录变更必须通过 `dir === workDir` 条件单独触发重建。

### 变更合并

收到目录变更推送（`filesys.changed` 目录批次 `{path, children}`）后，按下列规则合并：

| 情形 | 处理 |
|------|------|
| 找到 `dir` 节点 + 是目录 + 已展开 | 用推送的 `children` 替换 `node.children`；保留已展开子目录的 `expanded=true`；清除已不存在的子目录 |
| 找到 `dir` 节点 + 是目录 + 未展开 | 跳过（不刷新） |
| 未找到 + `dir === workDir` | 根目录变更 → 重建整棵 treeData（见下） |

合并/重建后触发快照持久化（防抖约 500ms）。

### 根目录变更的重建

treeData 不含根目录节点，故当 `dir === workDir` 时需：

1. `collectExpanded(treeData)` 收集当前所有展开目录路径；
2. 用推送的 `children` 重建 `treeData`（`treeData = children.map(treeNode)`）；
3. `restoreExpanded(treeData)` 恢复展开状态，对命中路径的目录立即加载其子节点。

```typescript
const expandedPaths = new Set<string>()
function collectExpanded(nodes: TreeNode[]) {
  for (const n of nodes) {
    if (n.is_dir && n.expanded) {
      expandedPaths.add(n.path)
      if (n.children) collectExpanded(n.children)
    }
  }
}
function restoreExpanded(nodes: TreeNode[]) {
  for (const n of nodes) {
    if (n.is_dir && expandedPaths.has(n.path)) {
      n.expanded = true
      loadDirChildren(n)   // 立即加载子节点
    }
    if (n.children) restoreExpanded(n.children)
  }
}
```

### 关键注意事项

1. **根目录不在 treeData 中**：`findNode(treeData, workDir)` 恒为 null，根目录变更须经 `dir === workDir` 触发重建。
2. **重建前必须 collectExpanded**：否则展开状态丢失；重建后用 restoreExpanded 恢复。
3. **Watcher 只推送已展开（watched）目录**：未展开的目录不会收到变更推送，折叠后再次展开需重新拉取最新内容。
