## 7. 配置类端到端覆盖口径（A + B，2026-09-17 立）

> 起因：配置类端到端此前只验"保存成功 / 回显正确"。用户口径（2026-09-17）：「**所有的配置，它的这个落库以及它的效果测试的确认，都需要补齐**」。
> 配置类端到端**必须同时有 A 与 B 两侧证据**才算覆盖：

| 侧 | 含义 | 判据（本波实例） |
|:--:|------|------|
| **A（落库）** | 值确实写进**目标层库**，且**回读一致** | `data-user-config-load` / `data-prj-config-list` 回读 == 写入值（含 `--data-dir` 非空时 prjusr == prj 的同库语义；重启后再回读可验"非内存态"） |
| **B（效果）** | 该值被**真实消费方**读走并产生**可观测**结果 | 请求体原文（mock `/last` 的 path / `system` / `authorization` / `max_tokens` / `reasoning_effort` / `n_requests`）· 工具面清单（`tools-list`）· 索引状态与落盘（`codegraph.status` + `index.json` 命中集合）· 磁盘文件（记忆 `memory/*.md` / 场景 `main.agent.md` / 原语 `*.tool.md`）· 子进程回显（cwd / env / argv / `process.execPath`）· 前端 DOM 落点（选中态 / 星标 / 标红） |

1. **不得**用"保存成功即算过"、"UI 回显正确"或"配置页显示正常"充当 B；B 必须是**独立于写入路径**的观测（真实 LLM 请求 / 真实工具调用 / 真实落盘 / 真实重启 / 真实子进程）。
2. **需重启 vs 保存即生效**必须写明：配置在 `instance-register` 期注入的（路径族 env / 解释器 / chrome）→ **B 证据在重启后采集**（同套件内采集"重启前未注入"基线为反例）；订阅既有 `data-*-refresh` 的（codegraph/vfts 开关与索引键、memory、compress、prj 执行参数、场景）→ **同实例内断言"保存即生效"，不写重启用例**。
3. **例外（如实标注，不算覆盖）**：后端**无读点**或**仅 UI 消费**的键（如 `security-*`、`memory.category-max-tokens`、prj 层路径键、prj `defaultLLM`/`defaultScenario` 覆盖层）→ 只能验 A 或仅验 UI，**必须在 [64-配置项一览](../60-reference/64-配置项一览.md) 标"产品待办"**，不得记为 A+B。
4. 覆盖状态**逐键标注**见 [64-配置项一览 §3–§7](../60-reference/64-配置项一览.md) 状态列的「**✅ A+B**」；本波落地明细见 §2（`run_llm_fields` / `run_mcp_fields` / `run_paths` / `run_index_gate` / `run_memory_ctx` / `run_session_active` / `run_scenario_prj` / `run_primitive_hot` + 3 套既有套件补 A 侧）。
