# 61 · 消息面命名重构规划（新旧对照表）

> 状态：📋 **规划稿（待评审）** —— 本文**不是**准则，仅用于评审命名方案；评审通过后按本文改写 [61-消息一览.md](61-消息一览.md) + [61-messages.schema.json](61-messages.schema.json)，再改代码。
> 关联：[61-消息一览.md](61-消息一览.md)（现行唯一准则） · [11-MQ与消息](../10-architecture/11-MQ与消息.md)
> 口径来源 = 2026-10-16 用户决定：
> ① **全量重构**（产品未发布，**不考虑向后兼容**）
> ② **主题一律单段连字符 kebab-case**（取消 `gui.*` / `filesys.*` / `vfts.*` 点分形态）
> ③ **拼写统一美式 + 读 `load` / 写 `save`**
> ④ **客户端 topic 与总线相对主题合并为一套**（删除 `mqTypeMap` / `domainTopics` / `frontMethodSubjects` 映射层）
> ⑤ `session-complete.status` **保留 `interrupted`**（仅 `complete` → `completed`）
> ⑥ **未被消费的主题 / 字段一律删除**（审计结论见 §11）

## 0. 目标命名规范

### 0.1 主题模板（强制）

```
<域>-<对象>[-<子对象>]-<动作>
```

| 项 | 约定 |
|----|------|
| 分隔 | **单段连字符**，全小写；**不用点分**（`gui.init-data` → `gui-init-data`） |
| 域 | 闭集，见 §4 命名空间注册表；新主题必须落域 |
| 动作 | 闭集，见 §0.2；**请求/查询用祈使动词，事件/结果用过去分词** |
| 对象 | 允许 1~2 段（`session` / `session-turn` / `window` / `dir` / `task-tree`） |

### 0.2 动作词表（闭集，统一）

| 动作 | 用途 | 取代 |
|------|------|------|
| `list` | 取集合 | — |
| `load` | 取单体 / 整体 | `get` / `read` / `content` / `history` / `latest` |
| `save` | 写入（含 upsert） | `set` / `put` / `upsert`(可选保留) |
| `delete` | 删除 | `remove` / `del` / `rmdir` |
| `create` | 新建 | `mkdir`（→ `*-dir-create` / `*-file-create`） |
| `detect` / `probe` | 探测（只读） | — |
| `-ed` 事件 | 已完成 | `-done`→`-finished`、`-changed` 保留、`-refresh` 保留（见 §5 决策点②） |
| `ready` / `failed` / `required` | 状态类事件 | `server-starting`→`server-ready` |

### 0.3 拼写规范

- 美式：`optimize` / `summarize` / `canceled`（**不写** `optimise` / `summarise` / `cancelled`）。
- **取消无意义前缀**：`zprompt-*` → `prompt-*`。
- **消除光杆词**：`gui.reveal` / `gui.open-with` 等补对象（`gui-explorer-reveal` / `gui-shell-open-with`）。

## 11. 零使用审计结论（2026-10-16）

> 按「⑥ 未被消费的主题 / 字段一律删除」口径，对 schema 全部 **193 个主题**逐条审计（排除 `src/test/**`、`*_test.go`、`msgkeys_gen.go`、`msgkeys.js`；`mcp-*` 按方法名字符串 + gateway 方法注册表判定；`gui.*` 按 `guiDo` action 分派判定）。

**结论：193 个主题中，零使用（可删）＝ 0 条。** 每个主题都至少有一处生产发送方或订阅方。

| 候选 | 复核结论 |
|---|---|
| `config-refresh` | **在用**（非死主题）—— 发送方 `kernel/conf.go`，订阅方前端 `ChatPanel.vue` / `useLLMSetup.js`；处理方式 = **合并进 `data-usr-config-refresh`**（重复广播去重） |
| `mcp-prompts-*` / `mcp-resources-*` | **在用** —— gateway 方法注册（`mcpgateway.go`）+ facade 暴露（`bus.go` / `call.go` / `ext.go`，作为 MCP server 对外原语面）+ 前端 `resources-list`（场景 agent 选资源） |
| `bridge/compat.go` 兼容事件族 | **仍被前端生产消费**（`llm-token` / `llm-error` / `tool-pair` / `complete` / `task-ended`）→ 需连带迁移后删（见 §7.3） |
| 客户端 topic `prompts-list` | **确证零前端发送方**（唯一一处；`tools-list` / `resources-list` 均有发送方）→ **本次删除**该客户端别名（`msgkeys.js` / `bridge.go` 白名单 / `httpapi/publish.go` 放行 / `capabilityListKeys`）。底层 `mcp-prompts-list` 仍在用，**保留** |
