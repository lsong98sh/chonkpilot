## 0. 总则（传输与消息分类）

### 0.1 传输
- **mq 仅进程内内存实现**（去 NATS）；多进程去中心化 mq 待功能稳定后自研（桥 = 传输门面，为将来预留）。
- 语义（Go/JS 对称 promise）：
  - `mq.publish / mq.emit(topic, payload)` = **唯一发送方式**（本地订阅者 + 经桥发后端）；返回 **Promise**，resolve 时携带各订阅者的写回与 errors。
  - 事件类：不等待（忽略 Promise，内部同步按 order 派发）。
  - 查询类：`await` Promise **收集回复**（"一疑问多答"：publish 后多个订阅者可各自处理并写回，发送方统一收集；errors 恒收集、恒 accept，发送端自查）。
  - `mq.on(topic, cb, order)` = 订阅（order 升序，同 order 按注册序）。
- **无独立的 request/RPC 方法**：请求 = publish + Promise 收集（`mq.request` 是 NATS 时代的旧方法，已废除）；Go 侧内核即 `Publish/Emit → *Future`。
  - **v1/v2 口径（T-17）**：**已全迁** —— 生产代码早已全部迁至 v2（`Emit` / `On`），剩余约 71 处**测试侧** v1 调用亦已按模块全迁（`Publish→Emit`、`Subscribe→On(...,0,...)`）；**除 `src/lib/core/mq/{promise_test,prefix_test}.go` 的 v1 自身测试外零残留**。v1 `Publish` / `Subscribe` 为**迁移期兼容面，暂保留、不废弃/删除**（等价 `Emit` 不 await / `On(subject,0,包装)`，不写回、order=0；见 [11-MQ与消息 §6/§7](../10-architecture/11-MQ与消息.md)）。
- **业务层 payload 不含 `req_id`**（Promise 内建关联）；**`instance_id` 一律必带**（不分单/多实例，单实例同样携带）——经桥业务消息由桥自动注入；gateway 内部协议（server⇄gateway，§5.1）为 server⇄gateway 方法面，显式携带必带 `instance_id`（表内已列，不再有"除外"）。
  - **`data-*` 数据面请求为例外：请求 payload 允许携带 `req_id` 用于应答关联**（应答载荷 `{req_id, ok, result}`），与 Promise 收集**共存、不冲突**——因 data 面为**同主题派发**（请求与应答同主题），Promise 本身无法唯一区分同主题的并发请求 → `req_id` 为必要关联键。代码证据：请求侧 `src/lib/task/store.go:42-93`（生成 `req_id` 并按 `req_id` 匹配应答）；应答侧 `src/lib/data/persist/persist.go:319-329`（`reply`/`fail` 回填 `req_id`）。本条**不改** §3 各行 payload 形状，仅明确该例外的既有实现。
- 主题命名 kebab-case；业务**相对主题**按域前缀隔离：`gui.` / `filesys.`（点分多段）与 `data-<domain>-*`（单段连字符一体，如 `data-session-list`）；总线命名空间前缀 `chonk.` 注入一次（全主题如 `chonk.data-session-list`）。**A2 正名：data-* 数据面不再挂 `chonk.srv.notify.` 遗留前缀**。gateway 内部方法面（server⇄gateway，§5）2026-09-06 统一 **mcp 域**：相对主题 `mcp-<组>-<动作>`（方法名 / → -，如 tools/list → `mcp-tools-list`），全主题经 chonk. 前缀注入 → `chonk.mcp-*`；方法名/主题/URL 一一对应（§5）。
- `/show/<path>` = 预览资源字节流（img/iframe/pdf/office），WebView 资源加载豁免（不走 mq）。
- **无 `/call` RPC**（清理目标；历史 `dataCalls` 已按 §1-§3 归位；`/call` 端点与后端 `bridge.Call` 已于 2026-09-11 随测试脚本清理批次确认不存在）。
- **实例消息**：instance-claim / instance-register / instance-heartbeat / instance-exit 归 §4.1 客户端实例生命周期（🆕 2026-09-20 增 `instance-claim`；`instance-heartbeat` **发布方改为前端**）；**认证域 `login-*` 见 §4.6**。

### 0.2 使用形态（同一发送方式 publish，区别只在收不收集）
| 使用形态 | 语义 | 发送 | 回复收集 |
|---------|------|------|---------|
| 事件（不收集） | 单向广播/驱动/流式内容，订阅者处理即可 | `mq.emit` | 忽略 Promise（无需回复） |
| 查询（收集回复） | **一疑问多答**：publish 后各订阅者（可多个）处理并写回，发送方 await 收集 | `mq.emit` + `await` | Promise resolve：{ok, result(集合), errors} |

> 例：**「多答」是 MQ 机制的**能力**，不等于每条消息真有多个应答方** —— `gui.init-data` 实际为**单应答**：GUI 桥本地**单点**处理（`src/lib/gui/bridge/guimsg.go` 的 `init-data` 分支），并在**桥内合并**布局/UI/已开文件/窗口等数据面后**一次写回 result**；前端 `src/api/file.js` 仅**请求**、**不订阅**该主题。**"多订阅"仅存在于事件面**，promise 面（查询类）无多应答方。

### 0.3 表列说明
统一列：**消息** | **触发时机与目的** | **payload** | **返回（publish Promise 收集的 result / 事件载荷）** | **备注**。`kind: app|user|project` = 三级 capability 根（app=`<exeDir>/capability`，user=`~/.chonkpilot/capability`，project=`<workDir>/.chonkpilot/capability`；见 [12-数据层](../10-architecture/12-数据层.md)），仅 `data-knowledge-root` 使用。表中"返回"即 await publish 后收集的结果（后端单处理方写回 result；多订阅者时各写回合并/集合）。

### 0.4 速记
| 项 | 约定 |
|----|------|
| 传输 | `mq.Bus` **仅进程内内存实现**（去 NATS）；桥 = 传输门面（为将来预留） |
| 唯一发送 | `publish / emit(topic, payload)`；不 await = 事件，`await` = 收集回复 |
| 回复收集 | Promise resolve = `{ok, result(集合), errors}`；**无 `-reply` 主题、payload 无 `req_id`** |
| 订阅 | `mq.on(topic, cb, order)`；order 升序，同 order 按注册序 |
| 实例字段 | 业务 payload **一律必带 `instance_id`**（单实例同样携带，桥自动注入） |
| 主题形态 | `gui.` / `filesys.`（点分）· `data-<domain>-*` / `mcp-<组>-<动作>`（连字符一体）；总线注入 `chonk.` 前缀 |
| 豁免 | `/show/<path>` = 预览资源字节流（不走 mq） |
| 已废除 | `/call` RPC、`mq.request`、`filemon.*`（→ `filesys.*`）、`srv.notify.` 前缀 |

> 特例：**`instance_id` 的唯一豁免 = `server-starting`**（服务器级就绪广播，发布时实例尚未注册）；`gui.devtools.open` 为**本地事件无返回**（devtool 按钮）；`gui.init-data` 为**单应答**（桥本地单点处理、**桥内合并**后一次写回）。**前端 `mq.emit` 统一注入 `instance_id`**（纯前端事件与路由到后端的消息都带；已存在不覆盖），桥上行 `injectInstance` 为幂等兜底。

### 0.5 字段命名与书写约定（本文全表统一）

| 约定 | 说明 |
|------|------|
| 字段名 | **snake_case**（`session_id`、`tool_call_id`、`work_dir`、`file_id`、`dirNode`…）为默认 |

| 枚举 | `a\|b\|c`（**不带引号**）；值为字符串时同样不写引号 |
| 容器 | 对象 `{...}`、数组 `[...]`（如 `keys:[...]`）、元组式并列表述用 `/` |

> 语义要点：
> - **零副作用**：不写配置/状态、不触发索引、不广播 `-refresh`。规则来源 = prj 配置 `enable-<引擎>` / `<引擎>.skip-dirs`（逗号/分号/换行分隔，**保序不去重**）/ `<引擎>.stack-gitignore`（`"true"` 才叠加 全局 ignore → `.git/info/exclude` → 逐级 `.gitignore` → 用户规则，低→高）。

> - 性能：单次请求**每引擎只构建一次规则集**（逐级 `.gitignore` 只解析一次），判定为 O(paths)。
> - 实现：判定库 = `src/lib/ignore`（`ConfigOptions` / `Options.Ignored`）；信封 + 逻辑 = `src/lib/data/persist` + `src/lib/data/internal/indexignored`。

### 4.6 认证域（客户端 → server；🆕 2026-09-20）

> **背景**：三形态 = `desktop` / `gui` / `browser`（**`gui` = 「GUI + 独立 server」**，且 **server 可运行在异地 → 不存在"本机信任"**，故 `gui` 与 `browser` **必须统一走认证**；`desktop` = 桌面单体（GUI 内嵌 server），本机单用户、免鉴权。**形态名 2026-09-21 重整**：原 `standalone` → `desktop`、原 `desktop`（≡ team）→ `gui`）。三者差异**只在客户端形态**（WebView2 ↔ 浏览器）与**令牌承载**（GUI = 桥注入 / browser = `Set-Cookie`）。
> **实现**：认证走**门面**（`Authenticator` 接口；可替换实现 = 本期本地库 / OS 账号 / LDAP / OIDC）。
> **元数据存储（🆕 2026-09-20 用户口径）**：**用户 · 项目 · 用户-项目关联 · 令牌** 四类元数据统一放**一个独立 auth 库**，位于 **app-server 的 exe 旁**（本期 = **bbolt 单文件**，如 `auth.db`；亦可用 CSV；名称不限）。它**属数据层**，且**与业务库分离** → 将来可整体替换为**远程数据库**而业务库不动。密码哈希用 **bcrypt**（**不用 MD5**）；令牌表独立存放、**可逐个吊销**。
> **业务数据**：**每用户一套库**（数据根 = `<用户数据根>/<uid>/`），放**实例侧** → **天然隔离，无需在任何表加 user 字段**。**自助注册**：用户名 + 密码；**一用户一 UUID**（UID）。
> **凭据**：登录成功签发令牌。**会话令牌**（browser）承载于 `Set-Cookie`（HttpOnly、**不设 `Max-Age`** = 关浏览器即失效）；**免登录令牌**（gui，存 `~/chonkpilot`）为**自证型** —— `{用户名, UID, 密码哈希}` 加盐加密成串（建议 AES-GCM 而非 DES），服务端解密即得身份；含密码哈希使其天然支持「**改密即踢下线**」。
> **硬前提**：① **HTTPS**（否则密码明文过网，哈希再强也无用；非 HTTPS 且非 localhost 建议启动即拒/强告警）；② **同源部署**（`/publish` `/events` `/show` 依赖 cookie 自动携带；跨域需 CORS + credentials，不在首版）。
> **首屏注入**：扩展既有 `injectBootstrap` → `window.__ck = {form, requireAuth, authed, instanceId}`（`form` ∈ `desktop` | `gui` | `browser`，由宿主/服务端按形态注入）；**`authed` 由服务端读凭证判定**（非客户端自称）→ 前端据此直接分派登录视图 / 主视图，**零额外往返**。**不使用 UA 判形态**（UA 客户端可伪造，不能作为鉴权依据，仅可作日志诊断）。

| 消息 | 触发时机与目的 | payload | 返回 |
|------|--------------|---------|------|
| login-register | 注册页提交：自助开户 → 服务端生成 UUID、写用户表、**建数据目录** `<用户数据根>/<uid>/` | {username, password} | {ok, user} + 令牌下发 |
| login-in | 登录页提交（用户名 + 密码） | {username, password} | {ok, user} + 令牌下发 |
| login-out | 登出：清令牌 + 清 cookie | {} | {ok} |

**错误码**（复用既有 `{ok, error}` 信封，**不新增字段**）：`login-failed`（用户名或密码错）· `login-username-taken`（注册重名）· `instance-unauthorized`（未登录 / 令牌失效 → 前端**跳登录**；gui 可先用免登录令牌重试）· `instance-forbidden`（已登录但**无权访问该 work_dir** → **不跳登录**，提示换目录）。
**配置**：`auth.allowRegister`（默认 true；**对外暴露必须关闭**）· `auth.projectRoots`（**允许根列表**，默认 = 用户数据根；`instance-claim` 的 `work_dir` 落在允许根之下且未登记为项目 → 视为**用户自建项目**，其余无权场景 → `instance-forbidden`；**属服务端配置项、非消息面**）· 登录会话闲置失效（建议 12h，可配）· `heartbeat` 30s / 回收 90s。
**流程**：`登录 → 选目录 → instance-claim{user?, work_dir?} → 校验 → claim 成功后服务端广播 instance-register → 前端起 heartbeat`。

#### 5.1.1 分组 register/unregister payload
> **scope（归属域，2026-09-06）**：四种 register/unregister 载荷统一可选顶层字段 `scope` —— 缺省 / `"global"` = **全局注册**（所有 instance 可见；静态接入、内嵌 capability、自持 meta、缺省注册均属此类）；**instance id（uuid，无前缀）** = **instance 级注册**（仅归属 instance 的请求可）。归属判断只看注册载荷 `scope`，**不取 mq 发起方/上下文 instance_id**（后者仅作请求侧过滤：请求以自身 instance 匹配可见集 = global ∪ 归属自己）。隔离覆盖 tools/list、tools/call、prompts/get、resources/read、mcp_find/mcp_load、prompts/list；同暴露名可属不同 instance（(scope, name) 独立名字空间互不冲突，scoped 命中遮蔽 global）；注销（unregister）须带与原注册一致的 `scope`。
> **origin**：可选顶层字段 `origin` = `builtin` | `user`，**缺省/未知 → `user`（安全默认）**。语义：`builtin` = 本仓自有/内置 server（内嵌 self/本仓 mcp-server、三级 capability dir 节点），gateway 向其透传内部调用上下文 `_meta["chonkpilot"]`（并最终 spawn executor 注入 `CHONKPILOT_*`）；`user` = 用户定义（第三方）server，**不注入 `_meta`、不给 `CHONKPILOT_*`**。dir 类型节点恒为 `builtin`（由本仓 `RegisterContracts` + 本仓 executor 提供）。
> **isolate（按 workdir 隔离，2026-09-16 新增，仅 servers/register 的 `mcp_server`）**：**可选**字段 `isolate`（bool；**缺省 null = 未设置**）。语义 = 该下游 server 是否**按调用上下文的 `work_dir` 各持独立连接/管道**（`isolate=true` 时同 server 不同项目各一条连接/子进程，互不阻塞；`isolate=false` 时全 server 共享一条连接）。**未设置（null）→ gateway 按 transport 推断：`stdio` → true / `http`·`sse` → false**。**旧发送方不带该字段 → 行为不变**（等同未设置）；隔离槽的空闲回收 TTL 复用既有 `Params.CallTimeout`，**零新增配置键**。见 [26-mcp-gateway §4.4](../20-modules/26-mcp-gateway.md) · [64 §6](64-配置项一览.md)。
> **sandbox / sandbox_dirs（agentbox 隔离，2026-09-19 新增，仅 servers/register 的 `mcp_server`）**：**可选**字段 `sandbox`（bool 三态；**缺省 null/未设置 = 不隔离**，与引入前行为一致）与 `sandbox_dirs`（**只读快照**，形如 `[{"dir":"<绝对目录>","writable":true}]`，由装配层按在线实例 prj `security-*` 并集注入）。语义 = gateway 在 **stdio** spawn 上游进程时追加环境变量 `CHONKPILOT_SANDBOX`（值 = `sandbox_dirs` 的 JSON）；**http/sse 不施加**；`sandbox=true` 但 `sandbox_dirs` 为空 → **不下发**（+ 日志）。**与 `isolate` 是两条独立轴**（`isolate` = 连接池按 `(instance, workdir)` 隔离；`sandbox` = 沙箱策略下发），互不替代。**上游进程是否遵守取决于其是否实现 agentbox 消费方**（第三方仅透传，不构成强制）。**旧发送方不带该字段 → 行为不变**。见 [14 §7](../10-architecture/14-安全域-agentbox.md) · [64 §6](64-配置项一览.md)。
> **path（内容来源，2026-09-22 新增，仅 prompts/register · resources/register）**：**可选**字段 `path` = 该资产的**运行时内容来源路径**（文件路径）。语义 = **内容不驻留**（RB-4 ①）：`mcp_load` / `prompts/get` 每次按 `path` **实时读盘**取内容；**与 `content` 二选一**——无 `path` 的内嵌资产（如 `//go:embed` 域 agent）仍随载荷携 `content`，作为**兼容兜底**。两者同时给出 → **以 `path` 为准**。**旧发送方不带该字段 → 行为不变**（等同无 path，走 `content`）。

  - `llm-error`（兼容名，**仅在 `session-complete{status:error}` 时由兼容层兼发**）payload = `{session_id, turn_id, code, message, retryable, retry_attempt, retry_count}`：
    - **`retryable` = 透传真实值**：来源 = `session-complete.retryable`（**单源**，2026-09-16 起该字段为该错误分类的唯一真实值，规则见 §4.3 注）；`session-complete` **缺该字段**（旧发布方 / 手工注入事件）→ 缺省 `false`（旧兼容契约语义）。

## 8. 边界与遗留

- **msg 冻结**：本节全部主题/payload 为唯一准则；增/改/删须用户确认（测试准则）。
