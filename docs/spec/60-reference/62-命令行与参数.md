# 62 · 命令行与参数

> 唯一形态 = **desktop（桌面单体）**，产物 `chonkpilot.exe`（宿主壳 = `src/desktop`，装配实现 = `src/lib/gui/host`），前端运行时形态标识 `window.__ck.form` 恒为 `desktop`。
> 仓库根构建脚本共 6 个：`build-desktop.ps1` · `build-plugins.ps1` · `build-mcp-server.ps1` · `build-mcp-gateway.ps1` · `build-codegraph.ps1` · `build-vfts.ps1`。
> 所有 exe 均用 Go `flag` 解析：单横线 `-x` 与双横线 `--x` **等价**；`-h` / `--help` 均可用。

## 1. chonkpilot.exe 参数

由 `.\build-desktop.ps1` 产出到 `dist/desktop\chonkpilot.exe`。

| 名称 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--work-dir` | string | 空 | 工作目录（前端文件树根）。未给出时依次解析：**最近项目**（存在即用）→ 默认工作目录 `%APPDATA%\chonkpilot\workspace`（首次启动自动创建）→ 当前 cwd |
| `--llm-base` | string | `http://127.0.0.1:8901/v1` | 内嵌会话服务的 OpenAI 兼容 base URL |
| `--llm-model` | string | `mock` | 内嵌会话服务默认使用的 LLM 模型名 |
| `--no-server` | bool | `false` | 不启动内嵌会话服务（UI 注入测试模式：回合完全由注入事件驱动，无真实 LLM）。该模式下 `data-*` 请求**快速失败返回空信封**（`{ok:false,error}`，不等待总线超时），调用方据 `errs` 回落缺省值 |
| `--ui-assets-addr` | string | `127.0.0.1:5670` | 只读静态资产端口：供非本仓 origin 的第三方页面 / 外部工具 include 公共前端资产。**仅 loopback**（非 loopback 拒启）· 只接受 `GET`/`HEAD`（其余 405）· 路径硬白名单 `/themes.css` 与 `/shared/{ck-theme.js,ck-theme.css,plugin-bridge.js}`（`/themes.css` 优先读 `<exeDir>/themes/themes.css`，缺失回落 embed）· 目录穿越（`..`/`%2e`/反斜杠）→ 403、未命中 → 404 · `Host` 仅 `127.0.0.1`/`localhost`/`[::1]` · 响应 `no-cache, no-store, must-revalidate`。空 / `off` / `-` = 关闭；启动失败（端口占用等）不阻断主程序。**不承载任何消息或动态接口**，能力面走插件桥 UDS |
| `--bridge-url` | string | 空 | bridge 对端地址（HTTP）。桌面单体内**不参与装配**，仅在启动日志中登记 |
| `--nats-url` | string | 空 | `--bridge-url` 的别名：仅在未显式给出 `--bridge-url` 时作为其值 |

`--test-port` 见 §3。

## 2. 启动示例

以下命令均在产物目录 `dist\desktop\` 下执行。

```powershell
# 默认启动（最近项目 → 默认工作目录）
.\chonkpilot.exe

# 指定工作目录
.\chonkpilot.exe --work-dir E:\work\demo

# 内嵌会话服务接本机 LLM 网关
.\chonkpilot.exe --llm-base http://127.0.0.1:8901/v1 --llm-model <模型名>

# 关闭只读静态资产端口
.\chonkpilot.exe --ui-assets-addr off

# UI 注入测试模式（不启动内嵌会话服务）
.\chonkpilot.exe --no-server

# 调试构建 + 测试通道
.\build-desktop.ps1 -Debug
.\chonkpilot.exe --work-dir E:\work\demo --test-port 2345
```

## 3. 仅在 `-Debug` 构建存在的测试参数

`.\build-desktop.ps1 -Debug` 以 `-tags debugport` 编译，编入测试通道（`src/lib/gui/debugport_on.go` + `testserver.go`）。默认发布构建**不注册**本参数，传入即 `unknown flag`。

| 名称 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--test-port` | int | `0` | 测试通道端口（`0` = 禁用；`>0` = 监听 `127.0.0.1:<port>` 供外部脚本驱动）。仅绑进程内**第一个**项目主窗口；`POST /quit` 走与托盘「退出」相同的收尾路径 |

测试通道端点与用例口径见 [50-测试体系](../50-testing/50-测试体系.md)。

## 4. 运行期约定（非参数）

- **数据根固定**：项目数据根（prj）= `<workDir>/.chonkpilot`；个人运行态（prjusr）= `<workDir>/.chonkpilot/users/<OS 用户名>/`，**不可经参数覆盖**。
- **插件桥**：UDS 前门，默认 `%LOCALAPPDATA%\chonkpilot\plugin.sock`，免认证、仅本机；可经 `CHONK_PLUGIN_LISTEN`（UDS 路径或 `tcp://127.0.0.1:<port>`）或 `CHONK_PLUGIN_UDS` 覆盖。
- **LLM 桥**：UDS 入口，默认 `%LOCALAPPDATA%\chonkpilot\llm.sock`（socket `0600` / 父目录 `0700`）；`CHONK_LLM_UDS` 覆盖路径，`off` / `-` 关闭。无 TCP 监听。
- **插件启动清单**：`<exeDir>\plugin.ini`（每行一个可执行命令行，行序 = 启动顺序）；缺失时回落 `enabled.json`。
- **日志**：`<prjusr>/logs/gui.log`（按大小滚动）；GUI 子系统下 stdout/stderr 不可见。
- **常驻**：进程常驻托盘（双击 / 「显示日志」唤出日志窗口；「打开项目」「项目列表」「退出」）；关闭项目主窗口只移除该项目，不结束进程。

## 5. 配套部署 exe

### 5.1 chonkpilot-mcp-server.exe

独立部署的 MCP server（`build-mcp-server.ps1` → `dist/other/`，与 gateway 同目录共用 `capability/`）。**必须显式指定一种运行形态**，否则打印用法并退出（码 2）。

| 名称 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `-http[=<addr>]` | string（可省值） | 裸 `-http` → `127.0.0.1:5700` | 前台 Streamable HTTP，端点 `/mcp` |
| `-stdio` | bool | `false` | stdio transport（由 MCP 客户端 spawn，stdin/stdout 只走 JSON-RPC）。与 `-service` 互斥，且不接受 `-http` |
| `-service install\|remove\|run` | string | 空 | Windows 服务（服务名 `chonkpilot-mcp-server`）；服务运行形态 = HTTP。`install` 可附 `-http=<addr>` 指定监听地址（缺省 RunArgs = `--service run`） |
| `-root` | string | `<exeDir>/capability` | 契约扫描根 |
| `-timeout` | int | `300` | 工具调用超时（秒）；`config.json` 的 `timeout_sec` 若给出则覆盖本参数 |
| `-config` | string | 空 | config.json 路径；未给出时自动探测 `<exeDir>/config.json` |

### 5.2 chonkpilot-core-mcp-server.exe

工具唯一前门（`build-mcp-server.ps1` 产出，`build-desktop.ps1` 置于 `dist/desktop/mcps/core-mcp/`），由宿主 `coretools.Supervisor` 拉起并监管。

| 名称 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--addr` | string | `127.0.0.1:0`（随机端口） | MCP Streamable HTTP 监听地址（`POST /mcp`） |
| `--root` | string | `<exeDir>/capability` | 契约根 |
| `--work-dir` | string | 空 | 请求未带 `X-Chonk-Work-Dir` 时的缺省工作目录 |
| `--data-dir` | string | 空 | 请求未带 `X-Chonk-Data-Dir` 时的缺省数据目录 |
| `--ready-file` | string | 空 | 就绪信息输出文件（JSON：`url` / `token` / `pid`，原子写入，权限 `0600`） |
| `--token` | string | 空 = 随机生成 | Bearer token（constant-time 校验）；随机生成时写入 `--ready-file` |
| `--config` | string | 空 | config.json；未给出时自动探测 `<root>/../config.json`（`--stdio` 形态不探测） |
| `--plugin-addr` | string | 空 | 插件桥地址（进程内 meta/domain 工具经 `plugin/v1/*` 取能力） |
| `--plugin-token` | string | 空 | 插件桥 HTTP token |
| `--stdio` | bool | `false` | 以 stdio MCP server 运行（stdin/stdout 仅 JSON-RPC，日志走 stderr）；用于 capability 目录节点接入 |

端点：`POST /mcp` · `GET /healthz` · `POST /internal/runtime`（运行期执行配置热更新）· `POST /internal/exec`（内部工具执行面，仅 `internal: true` 工具可调）。

### 5.3 chonkpilot-mcp-gateway.exe

网关 exe（`build-mcp-gateway.ps1` → `dist/other/`），以标准 MCP 协议对外提供聚合能力。

| 名称 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `-transport` | string | `stdio` | `stdio` / `http://<addr>` / `sse://<addr>`（http 挂 `/mcp` 与 `/`，sse 挂 `/sse` 与 `/`） |
| `-service install\|remove\|run` | string | 空 | Windows 服务（服务名 `chonkpilot-mcp-gateway`）；服务运行 = HTTP，`install` 缺省 `--transport=http://127.0.0.1:5556` |
| `-servers-file` | string | 空 | `servers.list` 接入列表（`mcp.alias=` 分组格式） |
| `-capability` | string | 空 | capability 契约根（未给出时探测 `<exeDir>/capability`）；以 `chonkpilot-core-mcp-server --stdio --root <dir>` 作为下游接入 |
| `-config` | string | 空 | config json（透传给 capability 下游 core-mcp-server） |
| `-call-timeout` | int | `60` | 默认调用超时（秒） |
| `-max-tasks` | int | `8` | 并发后台任务上限 |

无接入源（未给 `-capability` 且 `-servers-file` 为空）时照常启动，工具面为空。就绪 marker 打到 stderr：stdio → `GATEWAY_READY stdio`，http → `GATEWAY_READY http://<addr>`。

### 5.4 chonkpilot-codegraph-mcp-server.exe

代码索引引擎（`build-codegraph.ps1` → `dist/plugins/codegraph/`，发行时置于 `dist/desktop/mcps/codegraph/`）。**必须显式指定一种形态**（三者皆无则打印用法并退出，码 2）。

| 名称 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `-http[=<addr>]` | string（可省值） | `127.0.0.1:5701` | HTTP 端点 `/mcp` |
| `-stdio` | bool | `false` | stdio（由 codegraph 插件按 workdir 以子进程形态管理） |
| `-probe <dir>` | string | 空 | 自检：`Open` → `Initialize` → 打印 workdir/files/symbols/langs/stackGitignore/elapsedMs/store + 前 30 符号后退出（非 MCP 形态） |
| `-stack-gitignore` | bool | `false` | 自检附加项（仅与 `-probe` 同用）：按 gitignore 语义叠加各级 `.gitignore` / `.git/info/exclude` / 全局 ignore（见 [29 §4.1](../20-modules/29-codegraph.md)） |

## 6. 环境变量

| 变量 | 使用方 | 说明 |
|------|--------|------|
| `CHONK_UI_ASSETS_ADDR` | chonkpilot.exe | 覆盖 `--ui-assets-addr` 缺省值（仅命令行未显式给出该参数时生效） |
| `CHONK_PLUGIN_LISTEN` | chonkpilot.exe | 覆盖插件桥前门监听地址（UDS 路径或 `tcp://127.0.0.1:<port>`） |
| `CHONK_PLUGIN_UDS` | chonkpilot.exe（插件桥） | 覆盖插件前门默认 UDS 路径 `%LOCALAPPDATA%\chonkpilot\plugin.sock` |
| `CHONK_LLM_UDS` | chonkpilot.exe | 覆盖 LLM 桥 UDS 路径（默认 `%LOCALAPPDATA%\chonkpilot\llm.sock`）；`off` / `-` 关闭 |
| `CHONK_CHROME` | executor 子进程 | 覆盖 Chrome 路径（否则按配置 `chromePath` 注入 / 内置候选路径探测）。配置 `chromePath` 为空时**不注入**本键，保留宿主继承值（即设环境变量手动覆盖有效）；`chromePath` 非空时先剔除宿主旧值再回注 |
| `CODEGRAPH_EXE` | codegraph 插件 | 覆盖引擎 exe 路径（优先级：`Options.Exe` > `CODEGRAPH_EXE` > `<exeDir>/mcps/codegraph/`） |
| `VFTS_EXE` | vfts 插件 | 覆盖引擎 exe 路径（优先级：`Options.Exe` > `VFTS_EXE` > `<exeDir>/mcps/vfts/`） |
| `TEMP` / `TMP` | executor | 临时脚本 / 超长输出落盘位置 |
| `%VAR%` / `${VAR}` | gateway `servers.list` | 条目字段（env/headers/args 等）中的变量展开 |
