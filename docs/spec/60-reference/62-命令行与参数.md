- **连接（UDS）**：flash ↔ server 走 **UDS 本地 socket** —— 路径为**约定值** `%LOCALAPPDATA%\chonkpilot\server.sock`（server 与 flash 各自推导，**无 CLI 参数**；测试/多实例隔离经 `Options` 或环境变量覆盖）；目录 ACL 限当前用户；**instance ↔ 连接 1:1**（一条连接 = 一个实例；连接断开 = 该实例退出）。**UDS 前门 = 本机信任 → 免鉴权**；HTTP 前门（仅 browser 形态、`--http-addr` 显式开）仍走认证。**R7-B**：① `uds.Server.Start()` 在 `os.Remove` 旧 socket 前**先 dial 探测**该 socket 是否仍有活实例在监听（成功 → **拒绝启动第二实例**、不删既有 socket；仅探测失败才清理陈旧遗留并重绑）；② 同一实例被**新连接顶替**时改绑映射并**关闭旧连接**，旧连接断开**不再**误发 `instance-exit`（判据 = `IsCurrent`，仅当前绑定连接补发）；③ 同一连接改绑新实例 id 时清理旧 id 绑定；④ 单帧（行分隔 JSON）有**行长上限** `uds.MaxFrameBytes`（64 MiB），超限断连（防无换行大流吃爆内存）。**R8-B-1**：前门设**连接数上限** `uds.MaxConns` = 64（每条连接常驻 1 goroutine + 64 KiB reader）—— 超出则 Accept 后**立即关闭新连接并留痕**（不进入连接表、不起读循环；免鉴权本机 UDS 面防同用户进程耗尽 FD / 内存）。
- **单例**：server **全局一份** = **server exe 同目录独占文件锁**判定（`chonkpilot-lib/procsingleton` + `lockfile`，锁文件 = **`<server exe 同目录>/chonkpilot-server.lock`**；启动**最先**判定）—— 第二个实例**立即退出**（exit code = 2）、**不触碰** UDS socket / HTTP / DB；**否决**「UDS bind 失败兜底」（`uds.Server.Start()` 先 `os.Remove` 旧 socket 再 listen，Windows 下重复 bind **不失败**）。**R7-B-8**（保留）：单例判定失败改 **fail-closed**（拒绝启动，不再「按非单例继续」——否则与 `Start()` 无条件删旧 socket 组合，异常环境下第二实例可能删掉在跑实例的前门 socket）。**〔订正（2026-10-10）：原「命名互斥体」（`Local\` → `Global\ChonkPilotServer_<hash(user)>`，R7-B-3）已废弃，改文件锁——跨登录会话有效（同用户两登录会话共用同一把锁，不再各得一份）、无特殊权限、崩溃自动释放，见 [42 §2.28](../40-roadmap/42-决策记录.md)。〕**
- **存续**：flash 启动时探测 server（UDS 连通性），未运行则**拉起**（并传 `--autoexit`）；**flash 不自行发布 `instance-heartbeat`** —— 其**保活由 UDS 前门代发**（R7-B-1：前门按**仍持有连接的实例**代发 `instance-heartbeat{instance_id}` 续期，周期 = `heartbeat.Interval/2` = 15s，对 `heartbeat.Timeout`（90s）留 **6×** 裕量；连接断开即停止续期）→ **分离形态 90s sweep 不再误回收长会话**；HTTP 客户端（gui/browser）仍自持 30s / 90s 心跳用于资源清理。
- **打开语义（flash / flash-cli / 单体一致）**：无 `--work-dir` 启动 → 打开**最近关闭**的项目；若该项目**已打开**（本用户持锁）→ 依次取**次近**，都没有 → **让用户选目录**；显式 `--work-dir` → 以之为工作目录并**初始化**，若**已打开** → 让用户选目录。**"已打开"判定 + 持锁 = flash 侧**（`lockfile.AcquireWorkDir`，**per-user**：RDS 多用户同项目互不冲突）。
- **重复打开（同用户）**：flash 发现目标 `data_dir` 已打开 → 发 **`instance-bring-to-top{data_dir}`**（[61 §4.1](61-消息一览.md) ⑥）→ server 反查 `data_dir` 顶层实例并比对 `user`：一致 → 定向投递 **`instance-goto-top`**（同用户窗口置顶）；**不一致（其他用户）→ 返回 `instance-forbidden`**（前端提示换目录、继续选）。**R7-B-6**：定向投递**未命中**（目标实例无活动 UDS 连接）→ 同样返回 `instance-forbidden`（不再回 `{ok:true}` **假成功**）。
- **托盘**（server 侧；**无客户端接入时仅保留「退出」**）：**双击图标** = 打开**最近使用**实例（对该实例连接**定向发 `instance-goto-top`**；无实例 → spawn 新 flash）；**右键菜单** = 「退出」/「打开新窗口」/「列举实例」。
  - **「列举实例」收录规则（🆕 2026-10-10）**：① 仅**顶层实例**（**子窗口实例**——`parent_instance` 非空者——**不列入**）；② **排除 browser 形态**——判据 = 该实例**是否持有 UDS 前门连接**（browser 走 httpapi、**无 UDS 连接** → 不列；flash 经 UDS 前门接入 → 列）；③ **仅收录 `user == 当前用户`** 的实例（跨用户不列）。**双击「打开最近实例」与菜单共用同一份过滤**（口径一致）。纯函数 = `instance.MenuInstances`（输入：实例列表 + 当前用户 + 只读连接判据 `udsapi.Gateway.Connected`）。
  - **菜单交互修复（🆕 2026-10-10）**：`startTray` 原把「就绪」回报放在**永不返回**的消息循环之后 → **永远阻塞**，致其上/其下逻辑（`--autoexit` / `<-ctx.Done()` / 关闭流程 / 「退出」）全部失效；已拆为 `setup`（注册窗口类/建隐藏窗口/加图标）→ **立即回报就绪** → `loop`（GetMessage，锁定 OS 线程）→ `cleanup`，`startTray` 正常返回 `(stop, nil)`。`TrackPopupMenu` 后按 Win32 惯例补 `PostMessageW(hwnd, WM_NULL)` 使菜单立即消隐（保留 `SetForegroundWindow`）。见 [42 §2.24](../40-roadmap/42-决策记录.md)。
