> 2. **状态两份、归属分明**——任务树 = **DB 投影**（`data-tasktree-*`，任意进程可读）+ **内存句柄表** `task_id → {cancelFn, parentID}`（**每进程一张、不可序列化**；gateway 一张已有、server 一张待抽离）。取消按 `task_id` 路由到归属进程（gateway 任务 → `gc.TaskCancel`；server 侧 goroutine → server 自取消）。
> 3. **ask 需按会话标注**——ask 现为**阻塞式全局弹窗队列**（`askUserManager`），与"属于哪个 chat"矛盾；应改为**所属会话内联**并在**会话树节点**打标。数据侧其实已有：server 为每次 ask 建 `kind=ask_user` 任务节点且 reply 前恒 `running`（已落库、`full` 模式可见），缺的是前端标注（`SessionTreeNode` 的 `kindIcon`/`kindColor` 无 `ask_user` case → 落 `default` 灰色"其他工具"）。
>

## RB · 分层与责任边界收口（2026-09-21 定，🔵 待实施）

> **来源**：2026-09-21「分层与责任边界」专题讨论（逐项按代码核实，证据落到 file:line）。**本节即本批唯一登记处**（不另拆 [41](41-未决项登记.md) 条目；唯一例外 = **I-83** 为既有登记，本批做修复）。**编号空间 `RB-x`**（Responsibility Boundary），与 P-x / T-xx / D-xx / I-xx / G-xx 及历史 A–X 组**不冲突**。
> **实施约定**：每项都做成「**删掉新增路径即回现状**」的形态；**全批不涉 [61](../60-reference/61-消息一览.md) 消息面**（`dir` 字段保留原义，见 RB-2）。
> **目标**：让分层与责任边界**既清晰又合理**——各层不管闲事。

### 0. 六条原则（本批所有改法的公理）

1. **分层看责任，不看包名** —— 谁持有实现谁干活，谁持有「源」谁读。
2. **gateway lib 不读「源」、不做持久化** —— 只「接成品 + 路由 + 执行」。不读文件 / 目录 / DB；**纯解析函数可留 lib**（如 `ParseServersList` / `parseToolDoc`）；**spawn 进程属执行、不算读源**。
3. **索引只记 meta，内容按需取** —— 能力面（asset / resource）不得把正文常驻。
4. **能力面可共享，运行态必须按 instance** —— 只读快照可共享；`gateway.taskManager` / `llm.turns·busy·asks` 等**运行态一律不可共享**。
5. **静态装配归入口，动态装配归持有者** —— 启动期装配交入口/装配器；instance 级接入与热重扫留在持有实例视图的一方。
6. **跨层只有两个口** —— ① 方法面（`tools/*` · `servers/*` · `prompts/*` · `resources/*`）；② `ExecSink`（反向窄接口，依赖倒置）。

### 1. 模块定位与依赖方向

| 项 | 结论 |

### 1.1 router 边界与重试分层（**2026-09-22 用户定案**）

> **本节为口径唯一登记处**（本节细则与 [41](41-未决项登记.md) 条目描述冲突时，以本节为准并回改条目）。

**router 边界包含「发送」**：一次 `Call` = 编码 → 发送（HTTP）→ 流式读取 → 解析 → 出事件；router **持有连接生命周期**。

**重试分层（判据）**：

> **「透明重发」（对上层不可见、语义不变）→ router；「需要决策或可见的重试」（影响对话内容 / UI / 取消）→ llm。**

**router 透明重试的触发条件（唯一判据）**：

> **「尚未向上层输出过任何事件」** —— 一旦已输出任何事件（哪怕一个 `text_delta`），**绝不重发**；重发仅限连接层失败（DNS / 连接被拒 / TLS 握手失败）与「流已开始但中断 / 半包且**未输出过任何事件**」（此二者等价于「还没向上层输出」）。

**次数**：**router 的透明重试次数累计计入总次数**（不放大：router ≤1 次 + llm 侧 `retryCount` = 总额上限；**总量归 llm 掌管**，用现有 `retryCount` / `retryDelay` 四级配置语义不变）。

**归属表**：

| 场景 | 归属 |
|---|---|
| 连接失败 / 流中断且未输出任何事件 | **router**（透明重试 ≤1 次，毫秒级退避） |
| 超时（`responseTimeout` / `streamTimeout`） | llm |
| 已输出部分内容后失败 | llm（不得透明重发） |
| 上报「重试中」/ 响应 cancel / 次数用尽处置 | llm |
| 跨 provider fallback | **policy，暂不做**（本期仅同 provider 内重试） |
| 判定可重试性 + 退避值（`Retryable` / `RetryWait`） | router/adaptor 出，llm 决策 |

> **落地位置**：router 侧 = `src/lib/router/retry.go`（透明重试：判据 / 次数上限 / 毫秒级退避）+ `src/lib/router/router.go`（`Call` 接线）；llm 侧可视重试循环（`src/lib/llm/server/turn.go:427` / `:462`）**本轮不动**（归 [LR-11](40-演进计划.md) 收口）。

### 6. 风险与取舍

1. **流式 tool_call 增量拼装的常见错法**（现行 `llm.go:463` 即其一）：
   - ❌ **按 `ID` 聚合**：首 chunk 才有 `id`，后续 chunk `id` 为空 → 被当成**新调用**追加（参数被拆成多条、工具名丢失）。**必须按 `index` 聚合**。
   - ❌ **拿到 `arguments` 分片就 `json.Unmarshal`**：分片不是合法 JSON 边界；**必须等该调用流结束（`finish_reason=tool_calls` / `[DONE]` / `input_json_delta` 结束）再 parse**（parse 失败 → `Error{protocol}`，不可静默忽略）。
   - ❌ **空 `name` 分片覆盖已落位值**（部分厂商后续 chunk 带空 `function.name`）；`id`/`type` 同理——**只写非空**。
   - ❌ **默认 `index` 恒 0 / 忽略 `index` 缺失**：并行多调用时 `index` 交叉到达，须累积到 `map[index]*ToolCallDelta`，结束时按 `index` 升序输出。
2. **OpenAI 兼容端点的差异坑**：`reasoning_content` **非标准**（DeepSeek / Qwen / GLM / 代理各写各的：`reasoning` / `reasoning_content` / `thinking`）→ 适配器需按 provider 白名单兜底，且**不把未知字段当正文**；`max_tokens` vs `max_completion_tokens`；`reasoning_effort` 仅部分支持；`stream_options.include_usage` **不开则末 chunk 无 usage**；部分端**无 `data: [DONE]`**（直接关流；**兼容口径**：只要出现过 `finish_reason` 即以 EOF 正常收尾，`[DONE]` 与 `finish_reason` **都未见** → 判**断链** `network` 可重试）；SSE 行含前导空白 / 注释行 / 心跳；错误体可能是**纯文本或 HTML**（非 JSON）。
3. **与现有重试 / 超时 / 压缩的交互**：`probeBeforeRetry`（TCP 预检）+ `sleepCtx`（取消感知）+ `attempt` 计数在 llm —— **router 不得再叠一层「可视」自旋重试**（否则双层重试放大且丢失取消感知）；**唯一例外 = 连接层透明重发 ≤1 次**（判据「尚未向上层输出过任何事件」，见 §1.1）；首字节/流间隔语义**逐字保留**（120s/60s，usr 覆盖，下个 turn 生效）；`finish_reason=length` 必须原样透出（自动续写依赖）；`EMPTY_REPLY` 判定依赖「无 content 且无 calls」→ **router 不得替 llm 合成空文本**；compress 依赖 assistant 消息形状（`reasoning` 落库）不变。
4. **与 `gateway` 边界的重叠风险**：gateway 是**工具调用唯一入口（执行侧）**；router 只管 **LLM 出网** —— **router 绝不碰工具执行 / 工具注册 / 工具清单**；`toolsForLLM` 仍由 llm 从 gateway 取，router 只接收 `[]ToolDef`。**Naming 撞名风险**：gateway 的 `Provider`（工具提供方）与 router 的 provider（LLM 服务商）同名异义 → router 内建议用 `Spec`/`adapter`，**避免新增 `Provider` 标识符**（gateway 侧已有 RB-1 改名先例可循）。
5. **其他取舍**：canonical 类型不 import `data` → 换来**一层薄转换**（可测、单向）；Anthropic 适配是**统一接入而非互转**（保留原生语义，差异用 `Caps` 显式暴露）；router 无状态 → 「会话可复用」仍由 llm 层（`ensure-session`）管理；**不新增消息面**、**不引入 MQ**、**不加 facade**。
6. **DeepSeek 多协议（[D-29](41-未决项登记.md)）的取舍**：同一 provider 支持 **chat（OpenAI 兼容）** 与 **`/responses`（Responses API）** 两协议 → router 侧落**同族两个适配器**（`openai/` 包内 `openai.go` 与 `responses.go`），**不做协议互转**、**不新增 module**；两协议**字段差异 7 项**（端点 / `input` vs `messages` / `instructions` / 扁平 tools / `max_output_tokens` / `reasoning.effort` / `item_id` 聚合 + 终态事件）逐项在 `responses.go` 文件头列出并处置。**Responses 无 `[DONE]`** → 终态只能靠 `completed|incomplete|failed` 判定，缺其一即判**断链**（`network`，可重试）。

- **消息面**：预期**零变更**（复用 `llm` 参数）；若实现中发现必须新增/改字段，按 R-2 先确认。
