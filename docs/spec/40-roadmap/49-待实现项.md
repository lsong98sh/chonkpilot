**缺口（按风险从高到低）**

1. **解释器配置当前无执行侧消费面** ~~`script_run` 已随 core 契约退役…写了也不生效~~ **〔2026-10-28 已解决〕**：`task_run` 随 task 插件落地，解释器配置归插件（`plugins.task.interpreter-*`），消费点 = `chonkpilot-plugins/task/lib/scriptrun/exec.go`。**〔2026-10-28 用户拍板 · 已解阻塞〕**：见下方「P2-3 定案」——**以 `scriptrun` 为基座、对外工具名统一为 `task_run`**（`task` 是 `script` 的子集）；`file` / `requires` / `interpreter` 全部保留；`script_run` 不再作为独立工具名。
2. **无版本约束 / 锁定**：探测只回首行文本（如 `Python 3.12.10`），不解析语义版本、无 min/max/精确版本校验，无法「版本不匹配 → 告警/拒绝」。
3. **无安装 / 升级能力**：仅探测 + 手动填路径；无下载、校验、解压、静默安装，也无「一键写入探测结果」。
4. **探测结果不落库**：用户须手动在路径页保存；重复探测成本低但无缓存/无变化提示。
5. **docs 转换器未纳入工具链体系**：markitdown 的路径/端口无统一探测与配置项（仅有插件 `doc_endpoint`），安装引导缺失。

**建议方案（分层，按前置顺序）**

1. **先解阻塞**：确定 `script_run` 归属（若由插件承载，则解释器注入链改为随该插件 spawn 下发；若回归 core 契约，则补 `src/initdata/capability/tools/server/script_run.tool.md`）——**必须先于 2–5**。
2. **版本规范化（低风险，纯函数）**：`toolchainVersion` 增解析器（`name` + `semver` 抽取），仍只读展示；不改变探测协议（`{id,name,path,version}` 逐字段不变）。
3. **版本约束（契约新增字段，须用户确认）**：若要做「锁定」，建议在 usr 路径键旁增可选 `toolchain.<runtime>.minVersion`，或独立 `toolchain` JSON 键（不塞进既有 7 标量键），并只在**消费点**（executor 启动/工具调用）校验 + 明确错误文案。
4. **安装**：**不建议**宿主内置下载器（供应链/权限/代理复杂）；建议「探测 → 打开官方下载页 / 复用 winget 命令提示」的引导式方案，或做成独立插件（插件自持安装逻辑，宿主只提供能力面）。
5. **探测缓存**：前端内存缓存 + 路径页手动「重新探测」即可，不落库（与现值一致）。

### 2.4 SCOPE-1（已定案；2026-10-28 **运行态归属不变式已实施**）—— 组件实例粒度

> **〔2026-10-28 用户拍板（订正）〕**
> 1. **`Gateway` 保持单例** —— 「按 workdir（项目）一个」**作废**。理由：`mcp-tools-call` 等 gateway 方法面是全进程共享的 bus 面（chat / GUI 全局搜索 / 插件桥三个进程内调用方），多实例会变成「一条 Emit 多个订阅者 → 工具双执行」。单例下唯一订阅者，不存在该风险。
>    **已知代价（接受）**：`MaxTasks` / 池槽 / 下游连接 / sandbox 根仍**全局共享** —— 同一台机器开两个项目窗口时，一个项目跑满并发会挤另一个项目。
> 2. **组件间内部调用维持现状（不做直调改造）** —— `chat → gateway`（经 `mcp-tools-call`）与 `llm → data`（经 `data-*` / `dataRequest`）继续走进程内 bus；不做「`Deps.Tools` 直调 `s.gw` / `dataRequest` 改直连端口」。理由：收益仅是每次调用省一次进程内 Emit+Wait（数十 µs，相对 LLM 延迟可忽略），代价是审计面、实例定库语义、全量回归。
> 3. 因此本项剩余只有 **`Session` 按 dialog** 与「三作用域不复用字段」两条。
> 4. **「同一 dialog 不得在两个窗口打开」= 强制不变式**（2026-10-28 用户拍板；同一窗口内多个活动 dialog **允许**）。
>    - **归属表**：宿主内存 `session(= dialog 主会话) → 窗口`。释放有**两条**路径（用户 2026-10-28 追加第 2 条）：
>      (1) **窗口关闭 → 整窗释放**（用户原话：「释放必须是在关闭窗口」）；
>      (2) **空闲自动结束 → 只释放该 dialog**：判据 = **turn 完全结束 ∧ inbox 无 pending ∧ 无 async task**；释放后该 dialog 变「无主」，**下次用户选中即重新归属激活**。
>      两条之外的任何事件（切走 / 不显示 / 关标签）都**不释放**。
>    - **判据不是「显示」，视图不参与**（用户 2026-10-28）：「session 和视图没有必然联系 —— 不显示、没有 view 也可以有活动 session；view 只是订阅某个 session 的内容显示，换一个订阅即可」→ 归属**只由运行态决定**，视图可随意订阅/切换，不产生也不释放归属。
>    - **归属 = 运行态归属**：某 session 在某窗口实例上**有活动运行态**（turn 未结束 / inbox 有 pending / 有 async task）时，该实例是它的 owner；三者皆无 = 该 session「无主」（即上面第 2 条释放路径）。
>    - **数据来源**：`busy`/turns（键 `(instance, session)`）· inbox（`data-inbox-list{status:pending}`）· 任务树 async 节点——都已在 llm server / data 手上，**不需要 bridge 旁听 payload、不新增消息**。
>    - **纳入主窗口**：「主窗口不入表」只指 `window_id` / handle 不进 `byID`（那是列表 / 广播 / `--test-port` 路由用的），**归属判定照常纳入主窗口**（据此订正 [24 §4.3](../10-architecture/24-多窗口模型设计方案.md) 与 U-9 的「宿主不追踪主窗会话」）。
>    - **归属产生/转移点**：该 session 的**运行态产生处**（受理 `llm-start` / `llm-send`、inbox 消费、async task 登记）——owner 随之落到那个窗口实例；不需要额外旁路记录。**消息面零变更**。
>    - **执行点（两处，均不改消息面）**：① `gui.window.open-chat` —— 目标 session **有活动 owner** → **激活该窗口**并回 `{ok:true, window_id:<既有>, activated:true}`（主窗口 `window_id` 取空串，与 `--test-port` 既有约定一致）；**无主** → 照常建窗。② 运行态受理处 —— 已活动 session 被**另一实例**再发起 `llm-start`/`llm-send` → 拒（走既有 `ok:false` 应答）；空闲 session 发起来源即成为新 owner（「用户选择即激活」）。视图层不拦。

- **提权（2026-10-28 定）**：**不做 `elevated` 参数、不走 UAC**。契约里写明：工具以**调用方进程权限**运行；遇到必须以管理员身份执行的操作**不执行**，返回结果里附**可复制的命令行**并提示「请以管理员身份打开 PowerShell / CMD 后手动粘贴执行」。实现上：启动失败于 `ERROR_ELEVATION_REQUIRED`（740）或运行返回 `ERROR_ACCESS_DENIED`（5）→ 结果附该提示（`ok:false` + `error` 文案 + 原命令行），不重试、不弹框。
- **契约形态**：task 插件的工具契约改为 `*.tool.md`（照 `chonkpilot-plugins/file/tools/file/*.tool.md` 写法），文件 **`go:embed` 打进插件二进制**，**不放 `capability/` 目录**；工具扫描/声明由 task 插件自己完成（它是 MCP server，不依赖主仓 capability 扫描）。

#### 2.22.6 启动单例：UDS 探测替代命名互斥体（2026-10-29 定案，覆盖 TURNRUN-1 ⑥）

> **口径**：启动第一件事用**实例 UDS socket** 判定单例，**删除** `CreateMutexW` 判据；framework 只返回 typed error，**弹框与退出由主仓做**。

1. **删除**：`src/lib/core/procsingleton` **整包删除**（`mutex_windows.go` / `mutex_other.go` 的 `AcquireMutex`、`DesktopMutexName*`，以及已无生产调用点的文件锁 `Acquire` / `LockPath` / `fallbackLockPath`）——2026-10-29 用户定「1. 删除」；仅 `DataRootFingerprint` 算法**迁入** `framework/host/src/singleinstance`（新包自带同一指纹实现）。
2. **路径按数据根隔离**：`%LOCALAPPDATA%\chonkpilot\instance\<DataRootFingerprint>.sock`，保证 [23 §5](../10-architecture/23-工程与部署拓扑.md)「不同数据根可并存」不变量（L4 多实例套件依赖）。
3. **判定序列（三态；关键 = 不先删文件）**：
   1. `dial`（≤300ms）**成功** → 返回 `ErrAlreadyRunning`（已有实例）；
   2. `dial` 失败 → `listen`（**不 Remove 旧文件**）成功 → 本进程唯一，继续启动；
   3. `listen` 失败（地址占用）→ **再 dial 一次**：成功 → `ErrAlreadyRunning`；仍失败 → 判定崩溃残留 → `os.Remove` 后重试一次 listen；仍失败 → **硬错误 fail-closed**（拒绝启动 + `gui.log` 留痕）。
   - **不得复用** `uds.Server.Start()` 现行实现：它是「先 `os.Remove` 再 listen」，Windows 下重复 bind 不失败 → 第二进程会顶掉第一进程的前门。需新增 `ListenExclusive`（或 `ServerOptions.NoStaleRemove`）。
4. **分工**：framework 返回 `ErrAlreadyRunning`；主仓 `src/desktop/main.go` 捕获 → **`msgbox` 提示「已有实例在运行（数据根 …）」→ `os.Exit(0)`**；其它错误 → `os.Exit(1)`。framework **不弹框、不 exit**。
5. **连接语义（一期）**：accept 后**立即 Close**，仅作单例探针；**不做**激活/置顶（与 TURNRUN-1「不做 UDS 激活通道」一致），若后续要做激活，另立批次。
6. **测试**：L1 `singleinstance`（首启成功 / 二次 `ErrAlreadyRunning` / 残留文件可恢复 / 并发双启仅一个赢）；L4 真机（双击两次 → 第二份弹框退出；不同数据根两进程并存）。
7. **文档同步（P6）**：[19](../10-architecture/19-单进程形态与实例隔离.md) §8.11 · [23 §5](../10-architecture/23-工程与部署拓扑.md) · [62](../60-reference/62-命令行与参数.md) §3A · [41](41-未决项登记.md)；`procsingleton` 包注释中「UDS bind 不可作单例判据」的结论改写为「**不 Remove 的独占 listen** 可作判据」。

#### 2.22.7 MQ 分发出口：策略外置（workdir 路由属业务，不进 framework）· S1–S3 已落地 2026-10-29

> **用户口径（2026-10-29）**：`mq` 的**分发出口**按 `workdir` 决定投给谁 —— 这是**业务规则**，framework 只提供总线与投递机制，规则做成 **strategy** 由主仓注入。

**现状（改造前基线，2026-10-29 之前）**

- 总线实现已在 framework `runtime/bus`（主仓 [`core/mq`](../../../src/lib/core/mq/mq.go) 只是类型别名）。
- 出口 = **每个窗口桥各自订阅 `>`，本地过滤**（[bridge.go](../../../src/lib/gui/bridge/bridge.go#L304-L333)）：① 自己发布的事件（src 防环）丢弃；② `data-*` 的 persist 应答丢弃；③ 载荷 `instance_id` 非空且不等于本实例 → 丢弃；④ **载荷无 `instance_id`（`data-*` / `filesys.*` 等「按 workdir 管理」的事件）→ 放行给所有窗口**，实际隔离靠**前端按 workdir 过滤**。
- 结论：「按 workdir 分发」当时是**广播 + 前端自觉**，且 topic 家族判定（`data-` 前缀）与归属规则都写死在 `gui/bridge`（主仓）。
- 〔**2026-10-29 更新**〕上面三条已按本节 S1–S3 改造完毕（见下「S1/S2/S3 已落地」），此处仅作改造前基线留档。

**目标分层**

| 层 | 只做 | 不知道 |

**接口（framework 侧，已落地 `runtime/dispatch`）**

```go
type Sink struct { ID, WorkDir, Instance string; Kind SinkKind } // Kind = Window | Plugin；Instance 可选、仅透传
type Event struct { Topic string; Payload []byte; Src string }

type Policy interface {
    Deliver(evt Event, sinks []Sink) []Sink // 空 = 丢弃
}
func AllowAll() Policy // 默认策略：全投（保证 framework 可独立运行/测试）
```

- 插件 sink 由 `framework/plugin` 的 bridge 实现，订阅 pattern（`plugin.subscribe`）与 workdir 限定同样走 `Policy`。
- **类型归属（实际落地）**：`Sink` / `Event` / `Policy` / `Dispatcher` = framework **`runtime/dispatch`**（`plugin-framework` module，`host` 与 `plugin` 两个 module 共用，**禁止** `host` ↔ `plugin` 互相依赖）；业务策略 = 主仓 **`src/lib/gui/mqpolicy`**。

### 2.23 PLUGIN-ASSET-1 插件 UI 资源多模式返回（2026-10-29 定案 · 🔵 待实施）

> **触发**：插件**不全是 exe**。`demo-python` 的 `runtime.exe = python`、`args = ["-u","plugin.py"]`（[plugin.json](../../../src/initdata/capability/plugins/demo-python/plugin.json)），Node 插件同理；这类插件**无法把 webui embed 进二进制**，页面只能落盘或由插件自读盘回吐。单一「整块 base64」通道既不适用也不经济，故协议必须支持**多种来源**。
> **消息面**：只改**桥方法**（`plugin/v1/ui.asset.get` 与注册帧的 `assets` 段），**61 MQ 消息面零变更**；契约变更已获用户确认（2026-10-29）。

#### 2.23.1 三种来源模式

| 模式 | 适用 | 宿主如何取 | 桥调用 | 单文件上限 |
|---|---|---|---|---|
| `bytes`（默认 / 兼容） | 任意插件（现有 Go 插件即此） | 调 `plugin/v1/ui.asset.get`，插件回 `{size, data(base64)}` | 每文件 1 次 | ≤ 48 MiB（帧 64 MiB） |
| `dir` | **Python / Node**、任何落盘 webui | 注册期拿 `root`，之后**直接读盘** `<root>/<path>` | **0**（仅注册 1 次） | 无 |
| `resource` | 原生 exe（构建期 `.syso` 打 `RT_RCDATA`） | `LoadLibraryExW(exe,0,LOAD_LIBRARY_AS_DATAFILE)` + `FindResource/LoadResource` | 0 | 无 |

- **不提供 `proxy`**（插件自起 HTTP）：端口占用、防火墙提示、安全边界外扩；开发调试若需要，另设 debug 开关、不进生产协议。
- **不采用「解析 Go embed 符号」**：依赖编译器内部布局，`-ldflags -s` 即失效，不作为产品机制。

#### 2.23.2 声明与兼容

**注册期（主路径）** —— manifest `ui.assets`：

```json
"ui": {
  "selfServe": true,
  "assets": { "mode": "dir", "root": "webui", "version": "1.0.0", "sha256": "<可选清单>" }
}
```

- `root` **必须是相对插件安装目录（或宿主分配的 dataDir）的子路径**；`..` / 绝对路径 / 盘符 → manifest 校验期直接拒绝。
- **无 `assets` 段 → `mode = bytes`**，旧插件零改动。
- **请求期兜底**：`ui.asset.get` 响应新增**可选** `mode`（`bytes|resource`）与 `resource_id`，缺省 = `bytes`（允许插件对个别文件改走 resource）。

#### 2.23.3 安全约束

| 项 | 约束 |
|---|---|
| `dir` 越权 | 只接受宿主拼出的 `<root>/<path>`；`Clean` + `EvalSymlinks` 后必须仍在 `root` 内；`..` / `%2e` / 反斜杠 / 绝对路径 → **403**（沿用 [pluginassets.go](../../../src/lib/gui/pluginassets.go#L63-L73) 的穿越拒绝口径） |
| 任意路径 | **禁止**插件返回绝对路径让宿主读（否则插件可驱使宿主读用户任意文件）；`root` 由 manifest 声明且在插件目录内 |
| `resource` | 只以数据文件方式加载（**不执行**）；资源缺失 → 404 |
| MIME / 缓存头 | 不变：MIME 由宿主按扩展名推定；`no-cache, no-store, must-revalidate` + `nosniff` |
| 完整性（可选） | `assets.sha256` 清单用于 `dir` 模式防替换；未提供则不校验（插件本身可执行代码，威胁等级不变） |

#### 2.23.4 缓存键

`(plugin_id, path)` + 版本分量：
- `bytes` / `dir`：`manifest.version#运行代次`（现口径不变）；
- `dir` 追加 `root` 的 `mtime+size`（开发期改文件即时生效）；
- `resource` 追加 exe 的 `mtime+size`。

### 2.8 PLUGIN-INSTANCE-1（2026-10-27 登记 · **已落主体**，框架侧待发版）—— 插件 UI 的 instance 归属与定向投递

> 设计口径 = [28 §3A.7](../20-modules/28-plugins.md) + 专题稿 [插件边界与实例归属设计方案 §3.2/§3.3](../../plugin-platform/插件边界与实例归属设计方案.md)（本节为落地清单）。**未改动任何代码 / 未改消息面**。

**现状（问题）**

- `plugin.publish` 只允许固定 topic `plugin-ui-event`；广播载荷 `{id, topic, payload}` **顶层没有 `instance_id`**。
- GUI 桥 `forwardEvent` 只按**载荷顶层** `instance_id` 精确过滤（无该字段 = 放行）→ 插件事件投给**所有窗口**。
- `PluginPageHost` 仅按 `id` 过滤 → 同一插件页开在两个主窗口时**两边都收到**（串窗）。
- 插件 `sdk` / `runtime` 没有"`work_dir` → 主窗口实例"的解析能力；GUI 进程内虽有 `work_dir → 主窗口` 表，但未对插件暴露。
- 定时任务类插件（crontab 示例，主仓无定时任务实现）属于**无来源**消息，没有可复用的 `instance_id`。

**已定方案**

1. **插件 UI 的 instance = 承载它的窗口实例**：iframe URL 拼 `?instance_id=<currentInstanceId()>`，插件页首帧读取（插件进程自己的 instance 是另一命名空间，禁止混用）。
2. **定向投递**：`plugin.publish` 增可选 `instance_id`；宿主广播时提升到顶层 `{id, instance_id?, topic, payload}` → 复用 GUI 桥既有的实例过滤，缺省仍为广播。
3. **无来源消息**：`work_dir` → **同 workdir 且 `parent_instance` 为空**（顶层 = 主窗口）的实例；未命中 → **丢弃 + 记日志**（不回落广播）。

### CODEGRAPH-IDXDB-1（2026-10-26 登记 · **2026-10-28 主体已修**）

**现象**：codegraph 重建索引后，**落盘索引库**（`<workdir>/.chonkpilot/codegraph/index.db`）与
**插件上报状态**（prj 键 `codegraph.status.indexedFiles`）出现**条数不一致**——实测
`skip-dirs` 已生效（落盘 6 / status 5）。同一次「清除索引」后，落盘 `index.db` 已删除，
而 `codegraph.status` 可能仍短暂（或长期）保留旧快照。

**推断**：落盘集合与 `status` 由**两条读路径**分别产出（疑似引擎 workspace 双实例 / 路径键
大小写归一不一致），非测试侧问题。

**影响与当前测试口径**（`src/test/chonkpilot-gui/systest/run_index_gate.py` G4）：
重建/重试**以 `codegraph.status.indexedFiles` 为判据**；清除**以落盘产物（`index.db` 删除 +
命中集合为空）为判据**，不在同一用例里交叉硬断言两者相等。

**待做**：① 让 `status` 与落盘集合**由同一索引快照派生**（或清理历史 key / 路径键统一归一）；
② 补一条「status ↔ 落盘 index.db 双向一致」的 L2/L4 断言；③ 消除 clear 后 status 陈旧快照。

**已修（2026-10-28）**

- **①根因（双实例）**：进程内 Workspace 注册表 `wsReg` 以**原始绝对路径**为键，Windows 大小写不敏感 →
  同一 workdir 以不同大小写进入会被建成**两个** Workspace（两套内存索引各自 `saveIndexFull` 覆盖同一个
  `index.db`）→ 上报 status 的条数与落盘集合不一致。修复：treesitter / vfts 两引擎统一 `wsKey(abs)`
  （Windows 下 `strings.ToLower`）作为注册键（`Open` / `Drop` 同归一）。
- **②断言（L1）**：新增 `engines/treesitter/server/indexdb_consistency_test.go` ——
  `TestStatusMatchesDiskIndex`（Initialize 后 `status.indexedFiles` == `index.db` files bucket 条数；
  进程内缓存清空重开后仍相等且 `loaded=true`；Clear 后 status 归零 / 库被删 / `state=""`）+
  `TestOpenCaseInsensitiveReuse`（大小写翻转必须复用同一 Workspace）。
- **③clear 后陈旧**：Clear 已清零 meta + 删库；当时另加 `handleClear` 清除后**立即** `mirrorStatus`
