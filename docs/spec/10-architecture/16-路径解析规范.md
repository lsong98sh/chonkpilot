# 16 · 目录字符串解析统一规范

> 日期：2026-08-28（2026-09-11 移入 spec）｜ 状态：✅ 已落地（`--work-dir` / `--data-dir`）
> 关联：[24-lib](../20-modules/24-lib.md)（`paths` 包）· [14-安全域-agentbox](14-安全域-agentbox.md)（路径约束）· [62-命令行与参数](../60-reference/62-命令行与参数.md) · [03-构建与部署](../00-overview/03-构建与部署.md)
> 本文为**目录字符串解析的唯一规范**（原文整体迁入，来源见 [42-决策记录](../40-roadmap/42-决策记录.md) §3 B-6）。

## 1. 背景

CLI 参数中的**目录/路径**（`--work-dir`、`--data-dir` 等）存在多种写法：绝对路径、相对路径、`~` 开头（用户目录）、Windows 盘符/UNC 等。为避免各解析点各自为政，统一收敛到一个函数，并作为**项目对目录字符串解析的共同规范**——所有新增目录参数必须走同一入口。

## 2. 统一入口

```text
src/lib/paths/paths.go                # 唯一实现（mcp 体系 + llm_run + mcp-tools 共用）
  ExpandHome(p string) string                    # ~ / ~/x / ~\x → 用户 home（~foo 不展开）
  ResolvePath(raw, base string) (string, string) # 工具/DSL 参数路径解析（严格；base=="" 时相对报错）
  ResolveDir(raw, base string) string            # CLI 目录参数解析（--work-dir/--data-dir；允许相对，语义不变）
  SetTempRoot(instanceID string) (string, error) # 初始化/刷新 !/ 临时目录根；instance 空 → 错误（ErrNoInstance）
  TempRoot() (string, error)                     # 读取当前临时目录根；未设置 → 错误（ErrNoInstance）
  ErrNoInstance                                  # 「缺少 instance（宿主未注入调用上下文），无法解析 !/ 或注入 env」
  InvalidPathMessage(raw string) string          # 统一错误消息（单一实现）

src/gui/models/path.go                # GUI 侧 --work-dir/--data-dir（等价语义的 GUI 复刻）
  ExpandHome / ResolveDir
```

- **`ResolvePath`** 是工具/DSL 参数路径解析的**唯一入口**；**禁止在调用点裸写 `filepath.Join` / `filepath.IsAbs` 手搓路径解析**。
- **`ResolveDir`** 仅服务 CLI 目录参数（`--work-dir`/`--data-dir`），**允许相对路径**，语义与 R-11 前**完全一致**（§3）；mcp-tools **不得**再用 `ResolveDir`。
- mcp-tools 侧 `fileops.ValidateFilePath(raw)` == `paths.ResolvePath(raw, "")`（薄封装，见 §8.7）。
- `base` 是相对基准（见 §4、§8.2）；`raw` 为空返回空，由调用方决定缺省值。

## 3. 解析规则（ResolveDir）

按顺序执行，任一命中即返回：

| 步骤 | 规则 | 示例（Windows） |
|---|---|---|
| 1 | `~` → home；`~/x` 或 `~\x` → `<home>/x`（ExpandHome，跨平台） | `--data-dir=~/data` → `C:\Users\me\data` |
| 2 | `filepath.IsAbs`（盘符 `c:\`、`C:/`、`\`、`/`、UNC `\\`）→ 原样 `filepath.Clean` | `--data-dir=c:\tmp` → `c:\tmp` |
| 3 | 其余（含 `data`、`./data`、`../data`）→ `filepath.Clean(Join(base, raw))`，**可 `../` 跳出 base** | `--data-dir=data`（base=workDir）→ `<workDir>\data` |

约定：
- 重复参数：最后一个生效（与 executor `ParseArgs` 语义一致）。
- `~foo`（非 `~/` 前缀）**不展开**，按字面处理。
- 解析不校验目录是否存在（创建/探测由调用方语义决定）；不落盘任何配置。

## 4. 相对基准与缺省值

| 参数 | 相对基准（base） | 缺省值 |
|---|---|---|
| `--work-dir` | 当前工作目录（`os.Getwd()`） | 自动探测（GUI：recent → 文件夹选择；executor：cwd） |
| `--data-dir` | `workDir` | `<workDir>/.chonkpilot`（GUI 探测语义见 [62-命令行与参数](../60-reference/62-命令行与参数.md) §2；CLI 恒建临时数据根） |

## 7. 边界与注意

- Windows 大小写不敏感路径由 `filepath.Rel` / `filepath.Clean` 天然处理；`filepath.IsAbs` 覆盖 `\`、`/`、盘符、UNC。
- 数据根/工作目录分离（`--data-dir`）完整语义见 [62-命令行与参数](../60-reference/62-命令行与参数.md)。
- 相对路径可跳出 base（`../`）：属**有意行为**（用户显式指定），不做强制钳制。
- 🔵 **本文只定义「解析」；不定义「归属」**。服务端形态下 `work_dir` 需由**服务端下发**且必须做**目录归属校验**（`filesys` 目前直接采信请求 payload 的 `work_dir`，仅校验 path 在 wd 内）——见 [19-多租户服务端形态](19-多租户服务端形态.md) §3.4（**安全前置**）。

## 8. 工具/DSL 路径强约束（R-11；2026-09-12 二次升级：`!/` 临时目录 + DSL env，方案 A）

> 决策见 [42-决策记录](../40-roadmap/42-决策记录.md) §1 R-11 / §2 (18) / §2 时间线 **(20)**。这是**工具参数层**约束：`ResolveDir` 本身语义不变，仅限制工具/DSL 入参。动机：**防止路径写错位置产生垃圾文件**。

### 8.1 总规则（三种前缀，相对拒绝）

`src/mcp-tools` 与 `llm_run` 中**所有输入/输出文件与目录参数**——**含 DSL 内所有 `#"..."` 文件/目录引用**（数据源读取、落盘、目录操作）——必须是下列之一；**收到相对路径即失败**（顶层错误 + 明确消息），**不再按隐式 workDir 兜底解析**：

| 前缀 | 映射 | 示例（Windows） |
|---|---|---|
| 绝对路径 | `filepath.Clean` 原样 | `C:\work\proj\src\main.py`、`\\srv\share\a` |
| `~/`（`~\`、`~`） | 用户 home（`ExpandHome`；`~foo` 不展开） | `~/data/x.txt` → `C:\Users\me\data\x.txt` |
| `!/`（`!\`） | `<系统 temp>/chonkpilot/<instance>/...`（`paths.TempRoot()`，**按 instance 分目录**；缺 instance → 错误，不回落 default） | `!/tmp.csv` → `…\Temp\chonkpilot\ins-1\tmp.csv` |

### 8.2 唯一 API：`paths.ResolvePath(raw, base string) (abs, errMsg string)`

规则顺序（`src/lib/paths/paths.go`，**唯一实现**，不再叫 `ValidateAbs`）：

1. `raw == ""` → `("", "")`（空值交给调用方做必填校验）；
2. **`!/` 或 `!\` 前缀** → `filepath.Join(TempRoot(), rest)`（§8.3；`TempRoot()` 报错 → 返回该错误消息，不再 panic/回落）；
3. **`~` / `~/x` / `~\x`** → `ExpandHome`（`~foo` 不展开）；
4. `filepath.IsAbs` → `filepath.Clean` 原样；
5. 其余：`base != ""` → `filepath.Clean(Join(base, raw))`；**`base == ""` → 返回统一错误消息**。

- **`base` 的唯一合法用途 = CLI 参数解析**（把相对路径按 base 拼接）。工具/DSL 一律传 `base == ""`（相对即报错）；**唯一允许相对的场景 = 调用方显式传 base（CLI）**。
- `paths.InvalidPathMessage(raw)` 是统一错误消息的**单一实现**，含原值 + 三种前缀写法与示例 + DSL 场景提示，例如：
  `路径必须是绝对路径、以 ~/ 开头的用户目录、或以 !/ 开头的临时目录：<原值>（例：C:\work\proj\src\main.py、~/data/x.txt、!/tmp.csv；DSL 内可用 {{env.CHONKPILOT_WORKDIR}} 拼项目内路径）`
- **`ResolveDir` 语义不变**（CLI `--work-dir`/`--data-dir` 仍允许相对、base 为空时相对原样返回；§3），由 L2 测试锁定旧语义。

### 8.3 临时目录根（`!/` 映射，按 instance 分目录；instance 空 = 异常）

- `paths.SetTempRoot(instanceID string) (string, error)`：设置/刷新临时目录根并返回 `<os.TempDir()>/chonkpilot/<sanitize(instanceID)>`（仅保留 `[A-Za-z0-9._-]`，其余替换 `_`），按需 `MkdirAll`；**线程安全、幂等**。**instance 为空/平凡值 → `("", ErrNoInstance)`，不再回落 `default`**。
- `paths.TempRoot() (string, error)`：读取当前根；**未设置 → `("", ErrNoInstance)`**（不再惰性初始化 `default`）。
- **instance 不可能为空；为空即异常**（决策 R-11 二次升级，见 [42 §2](../40-roadmap/42-决策记录.md)）——三侧落地：
  - **llm server**：turn 请求 `InstanceID` 为空 → 顶层错误（`accepted:false`），不进 turn；`gwClient.Call` 的调用上下文 `InstanceID` 为空 → 直接返回错误，不下发。
  - **mcp-server**：调用上下文（协议 `_meta`）**存在但 instance 为空** → 工具执行失败（返回 `缺少 instance…`）；**完全无上下文**（外部直连 stdio/HTTP 客户端）→ 不注入、不报错（纯绝对路径调用照常）。
  - **executor**：缺 `CHONKPILOT_INSTANCE` 且本次调用需要 `!/` 或需要构造 DSL env → 顶层失败（消息见 `paths.ErrNoInstance`）；**纯绝对路径的非 DSL 调用不受影响**（直连 exe 的黑盒用例仍可跑）。
- **初始化时机（谁在何时 SetTempRoot）**：宿主在 **spawn executor 时注入子进程环境变量 `CHONKPILOT_INSTANCE`**；executor `cli.Run` 启动时以它调 `paths.SetTempRoot`（`fileops.HostEnv/BuildToolEnv` 同源、幂等）。llm_run（server 侧）在作业执行前以轮次 `req.InstanceID` 调 `paths.SetTempRoot`，并取其返回值为 `CHONKPILOT_TEMPDIR`（避免多实例并发时全局根被交叉覆盖）。

### 8.4 调用上下文传递与 DSL 注入变量 env（只读；方案 A）

**上下文不再进 `tool arguments`**，改由**调用上下文（协议 `_meta`）**承载，最终以**子进程环境变量**落到内部 executor：

```text
llm server ──mcp-tools-call payload(Context: instance_id/work_dir/data_dir/session/turn/tool_call_id)──▶ gateway
gateway    ──tools/call params._meta["chonkpilot"]{instance_id,work_dir,data_dir,...}──▶ 内嵌/self mcp-server（in-process）
mcp-server ──spawn executor 时注入子进程环境变量 CHONKPILOT_*(INSTANCE/WORKDIR/DATADIR/INTERPRETERS)+CHONK_CHROME──▶ executor
```

- **载体逐段**：server→gateway = mcp 消息 `Context`（`mcp-tools-call` payload，61 消息面**零变更**）；gateway→下游 mcp-server = MCP `tools/call` 的 **`params._meta`** 命名空间 `chonkpilot`（`src/mcp-server/server.CallContextMeta`；gateway `memNodeProvider`（self/dir 内置节点）与 `proxyProvider`（standalone 本仓下游）经 `CallToolParams.Meta` 透传）；mcp-server→executor = **子进程环境变量 `CHONKPILOT_*`**（`Config.executorEnv`）。
- **命名空间可扩展（2026-09-17，🔵 规划）**：`params._meta.chonkpilot` 是**逐调用上下文**（每次调用都不同 —— `instance_id`/`work_dir`/`data_dir`/…），**允许按需增字段**（用户口径「`_meta` 内可以增加任何需要的」，如 `task_id`）—— **61 消息面零变更**：`mcp-tools-call` payload 的 `Context` 已是既有载体、不改 61；实现时只更新**本节**（该 MCP 协议层命名空间说明），必要时同步 [25-mcp-server](../20-modules/25-mcp-server.md) / [26-mcp-gateway](../20-modules/26-mcp-gateway.md)。用途示例：若 go-sdk in-memory 传输不传递 client ctx cancel，则由 `task_id` + mcp-server 侧 in-flight 注册表承接终止（[18 §3.6 D](18-工具异步超时与取消.md)）。**注**：**`tools/list` 的 `_meta`（静态能力描述）不适用**「可增字段」口径 —— 那属工具契约面，见 [18 §1 非目标](18-工具异步超时与取消.md)。
- **来源边界（2026-09-12 起按来源判定，不再按是否 in-process）**：`ServerEntry.Origin` = `builtin`（本仓自有/内置：内嵌 self/本仓 mcp-server、三级 capability dir 节点）| `user`（用户定义/第三方，缺省安全默认）。**仅 `builtin` 注入 `_meta["chonkpilot"]` 与派生 `CHONKPILOT_*`**；**`user` 一律不注入**（gateway `proxyProvider.Call`/`memNodeProvider.Call` 的 `inject` 由 `entry.IsBuiltin()` 决定）。故第三方（用户定义）MCP 永远拿不到内部上下文，而 standalone 部署下的**自有** mcp-server 同样按 `builtin` 注入。
- **来源标注点**：gateway `connectSelf`（self）、`registerDirNode`（dir）、llm `mergeGatewayServers`（usr `mcps`→user；2026-09-14 起单体不再合并 exe 同目录 `config.json`）；运行时 `servers/register` 按载荷 `origin`（缺省 user，见 [61-消息一览](../60-reference/61-消息一览.md) §5.1.1）。

DSL **仍禁止相对路径**；宿主向 DSL 注入**只读**变量 `env`，LLM 用 **`{{env.*}}` 显式**拼绝对路径（**不得再依赖隐式 workDir 兜底**）：

| 变量 | 含义 |
|---|---|
| `CHONKPILOT_WORKDIR` | 项目工作目录（绝对） |
| `CHONKPILOT_DATADIR` | 数据目录（绝对） |
| `CHONKPILOT_TEMPDIR` | 临时目录根（`<temp>/chonkpilot/<instance>/`，`!/` 的落地目录） |
| `CHONKPILOT_EXEDIR` | 执行器/server 可执行文件所在目录（绝对） |
| `CHONKPILOT_PROJECT` | 项目目录（与 `CHONKPILOT_WORKDIR` 同值） |

- **只允许 `{{env.<NAME>}}`，无裸名**：根作用域**只**注入 `env` 一个对象；`{{WORKDIR}}`、`{{CHONKPILOT_WORKDIR}}` 等裸名**不存在**（兼容别名 `WORKDIR` 已删除）。见 [63-DSL语法](../60-reference/63-DSL语法.md)。
- **只读 + 保留字**：`env` 同时是 DSL **保留标识符**——脚本把它当变量名/绑定目标（`SET … => env`、`SET … => env.<字段>`、下标写、动作 `=> env`、TYPEOF/ENTRY/SPLIT/JOIN/PUSH 目标、`LOOP env=…` 绑定等脚本驱动赋值）→ 报错「env 是保留字（宿主注入的只读上下文），不能作为变量名」；实现 = `dsl.reservedVars` + `dsl.Options.Vars` 预置根作用域 + 引擎只读标记（见 [63-DSL语法](../60-reference/63-DSL语法.md)）。
- **注入链路**：executor 侧 `fileops.HostEnv()`（读本进程 `CHONKPILOT_WORKDIR/DATADIR/INSTANCE` + 自身 exe 目录 `CHONKPILOT_EXEDIR`）/ `fileops.BuildToolEnv()`（缺 instance → 顶层错误）；llm_run 侧 `jobEnvVars(workDir, dataDir, TempRoot, exeDir)`。两侧同名同值。
- **`script_run`** 另把同名变量注入**子进程环境**（`cmd.Env`，含 requires 安装子进程）；用户显式 `env` 同名优先；解释器解析额外读 `CHONKPILOT_INTERPRETERS`（宿主 spawn executor 注入的 `{runtime: 路径}` JSON）。

### 8.5 覆盖范围（穷尽）

- `file_read`（`files[].path`）· `file_find`（`path`）· `file_diff`（`file1`/`file2`/`files[].path`/`files[].path2`/`path[]`）
- `filesys_run`：动词文件句柄 `#"path"`；核心语句**所有**文件句柄（**LOOP/SET 数据源读取**、访问器 `.content/.lines/.array/.object/.range`、`IF exist` 路径、`=> #"file"` 目标）；顶层 `file`；顶层 `md5` 键
- `script_run`：`file`（脚本文件）、**`workdir`（运行目录）**、**`interpreter`（解释器/可执行文件路径）**
- `web_fetch`：`save_as`、`form_files[].path`
- `browser_run`：`file`；DSL 内 `SHT`/`DOM`/`DBG`/`UPF` 的最后一个参数、核心语句文件句柄（数据源/访问器/`IF exist`/`=> #"file"` 目标）；落盘参数 `dom_file`/`console_file`/`fail_shot`；**`chrome_path`**
- `desktop_run`：`file`；DSL 内 `SHT`、`WIN … SHT`、核心语句文件句柄（数据源/访问器/`IF exist`/`=> #"file"` 目标）
- `llm_run`：`file`（脚本文件）；**DSL 内所有 `#"path"` 句柄**（数据源读取、`=> 目标`、`IF exist` 等）
- **不受约束**：`args`/`env`/`filter`/`requires`（命令参数与依赖名）、runtime 内置命令默认（`cmd`/`bash`/`sh`，走 PATH 解析）、URL / 正则 / glob / locator 等非路径文本。

### 8.6 错误语义（两类不可混）

- **参数级违规（路径不合规）= 顶层错误**：整体失败（`cli.Err` / llm_run 工具错误，exit 非 0，stdout 输出错误消息），消息须含**原值**与**正确写法示例**，并指明是哪一个参数/指令（如 `files[0].path`、`第 3 行 RPL`、`第 2 行 SHT`、`第 1 行 LOOP 数据源`、`第 4 行 IF exist`、`第 1 行 => 目标`、`file`、`workdir`、`interpreter`、`chrome_path`、`md5["…"]`、`save_as`、`form_files[0].path`）；**不**降级为 `filesys_run` 的 `fails`。llm_run 的相对路径在**执行前**经 `dsl.CollectHandleRefs` 预校验（字面 `#"path"`；含 `{{}}` 的插值路径跳过、由运行时严格解析兜底）。
- **运行时冲突**（md5 不一致、lock 超时、未找到匹配等）保持原语义：记入 `filesys_run` 的 `fails`、整体不失败。

### 8.8 落地与残留（2026-09-12 R-11 边界收口）

- **standalone（gateway ↔ mcp-server over HTTP/stdio）`_meta` 已落地（按来源判定）**：gateway 以 `ServerEntry.Origin` 区分「自有/内置」与「第三方」——本仓自有 mcp-server（内嵌 self/dir 节点、standalone 自有部署）标注 `builtin` 并注入 `_meta`；第三方（用户定义）标注 `user` 一律不注入。判定**不再依赖是否 in-process**（`memNodeProvider.inject`/`proxyProvider.inject` 均来自 `entry.IsBuiltin()`）。
- **用户/项目级 capability 工具 = 内置**：其 `*.tool.md` + 同目录 executor 由本仓 spawn，dir 节点恒标 `builtin`，故**会**拿到 `CHONKPILOT_*`（不再列为未决）。
- **残留（已收敛）**：`servers.list` **静态条目缺省 `builtin`**（2026-09-12 定案：部署方文件视为本仓自有；第三方条目须显式 `<id>.origin=user`）；`servers/register` **动态接入**与裸构造 `ServerEntry` 缺省仍为 `user`（安全默认，须显式 `origin=builtin` 才注入）。已废弃字段 **`inject_context`**（`servers.list` 键 + `mcp_server.inject_context`）**已移除**——注入判定统一由 `origin` 承载。
