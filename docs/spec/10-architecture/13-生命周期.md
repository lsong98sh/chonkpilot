## 0. 三层生命周期

```text
进程 / 实例（instance）  ── GUI 存续期
   └─ 会话（session）      ── 长生命周期，跨多次启动

```

## 1. 实例生命周期

| 阶段 | 消息 | 行为 |
|------|------|------|
| 注册 | `instance-register {instance_id, work_dir, data_dir, client_type, user, parent_instance?, session_id?}` | `user` **必填**（跨用户判定）；`parent_instance` / `session_id` 可选（多窗口 / 群聊定向投递）。server 登记实例（`instance.Manager`）+ `data.Register` 绑定数据根；server 发现 `<workDir>/.chonkpilot/capability` → 经 gateway `servers/register`（`scope=instance_id`）动态接入（含 prjusr 级）。 |
| 保活 | `instance-heartbeat {instance_id}`（30s；唯一形态 desktop **不发布**） | 存活判定：心跳发布与超时判定**仅在编入 `-tags split` 时生效**；**唯一形态 desktop（默认构建）不发布、不据此判退出**（`heartbeatTimeout` 判定与 `plugin/instance.Sweep(timeout)` 不编入），实例失效由显式 `instance-exit` 收口。编入 `-tags split` 时 30s 发布 / 90s 判超时 → **判定侧消费方两处**：**llm-server 30s ticker → `Manager.Sweep(90s)` → 逐个走既有 `exitInstance`**（取消 running turn + 释放 `busy` 锁 + `unregisterCapabilityNodes`）、**persist 30s 扫描 → `LastBeat` ≥90s → 既有 `instanceGone`**（移除 `insts` 绑定 + `data.Unregister`）。见 [28-plugins §2](../20-modules/28-plugins.md) |
| 退出 | `instance-exit {instance_id}` | server 取消名下 running turn、清除进程内 `busy` 注册、`servers/unregister` 注销 capability 注册、`data.Unregister` |

**首次使用清理**：server 对某 instance 的**首个 `llm-start`** 触发（多 workdir 服务，启动时无从预知数据根）：

```text
data-session-cleanup-stale  → 遗留 running turn 标 interrupted（原「ask 等待态 awaiting 不在此列」**已作废**：awaiting 状态未落地，awaiting 仅存在于任务执行态）
data-tasktree-*（复用面；该清理并入 Task 层 `Recover`） → tasktree 遗留非终态（pending/running/awaiting/detached）→ interrupted（不自动重跑）
```

**实例边界**：单实例与多实例统一以 `instance_id` 标识；`work_dir`/`data_dir` 随注册绑定，后续 `llm-start` 不再传（取注册记录）。

## 1A. 项目（work_dir）生命周期与「隐藏打开」

> 口径定于 2026-11-03（SANDBOX-WRITE-1 P3 / [整改方案 §7·§8](../../sandbox/插件写隔离与定时任务整改方案.md)）；实现 = `chonkpilot-framework/host/src/gui`（窗口层）+ `src/lib/gui/host`（装配门面）。

**项目生命周期 = 项目主窗口的生命周期**（**未**与窗口解耦）：

| 阶段 | 触发 | 行为 |
|------|------|------|
| 打开 | 用户（托盘 / `gui.dir.open`）**或宿主隐藏打开**（定时任务，`plugin/v1/workdir.ensure`） | `env.OpenProject`：同 work_dir 唯一；建主窗口 → 桥发 `instance-register` → server 实例视图登记 → 工作区管理发 `workdir-opened`（各插件/索引照常） |
| 隐藏 | `ProjectConfig.Hidden=true`（仅差异 = 窗口不显示） | 窗口照常创建 + 导航 + 认领；`AutoFocus=false`、导航完成**不 Show**、**不套用**窗口几何（`SetWindowPlacement(SW_RESTORE)` 会把隐藏窗显示出来）；不参与「最近活动项目」判定 |
| 显形 | 托盘「项目列表」点选 → `ActivateProject` → `show()` | 变为普通可见项目（此后与用户自己打开的项目无差别） |
| 关闭 | 用户关闭该项目主窗口 / 托盘「退出」/ `/quit` → `env.Shutdown` | 既有 `finish`：关本项目全部小窗口 → `instance-exit` → server 注销实例（取消 running turn / 释放锁）→ 工作区管理发 `workdir-closed` |

**隐藏实例的关闭口径（不猜）**：

- **不**随「某次定时任务执行结束」退出，**也不**做使用者引用计数自动关窗（P3 不做，残留项 [41 G-98](../40-roadmap/41-未决项登记.md#2-已收口--历史只读不再待决)）；
- 常驻到**用户显式关闭该项目主窗口**或**进程退出**（与用户自己打开的项目完全一致）；
- 代价 = 一个常驻 WebView2（与正常打开同代价，C17）；
- 托盘「项目列表」照常列出（它就是已打开的项目），点选即显形。

## 3. 轮次（turn）生命周期

### 3.1 受理（`llm-start`）

```text
客户端（前端/桥）POST/Publish llm-start {session, turn, llm?, think?, effort?, scenario_id?}
  ├─ session/turn 必填（客户端分配；缺 turn 由桥补 t-<12hex>）
  ├─ instance 未注册 → Result{accepted:false, error:"instance not registered"}
  ├─ 首次使用该 instance → 清理遗留 running（§1）
  ├─ session busy（内存 busy 表；跨进程由 desktop 单例保证）→ Result{accepted:false, error:"session busy: <turn>"}
  ├─ continue=true 且未带 turn → 取该 session 最近一轮并复用（不重新分配）
  ├─ 落库：EnsureSession + EnsureTurn（幂等，不重新分配）
  ├─ 建 turn 状态机（turnCtx），登记 busy/turns
  ├─ 广播 turn-start（`session-turn-start {instance_id, session, turn, parents}`；主轮次 parents 空）
  └─ Result{accepted:true, session, turn}
```

### 3.2 驱动（`llm-send`）

调度核心按 `type` 喂给 turn 状态机：

| type | 行为 |
|------|------|
| `text-user` | 用户消息 → 构建上下文 → 调 LLM |
| `text-notify` | 后台任务通知 → 触发新一轮回复（含防循环） |
| `tool-result` | 工具结果回填 → 续轮 |

上下文构建（`data-session-context`）：有快照 → 快照前缀 + `snapshot_turn` 之后 turns；无快照 → 近端 summary 起点的历史。详见 [01-端到端数据流](../00-overview/01-端到端数据流.md) §2。

### 3.3 流式产出

- `session-receive {session, turn, type: reason|text|tool-call, payload}`（桥映射为 `llm-receive`）。
- 逐条落库：`data-session-append-message`（tool 结果、异步回填同面）。

### 3.4 终态（`finish`）

所有终态**收敛到 `session-complete`**（前端事件名 `llm-complete`；`llm-error` 仅错误状态由兼容层兼发）：

```text
finish(tc, status, finishReason, code?, message?, text?, retryable?)   # 原子终态：finishOnce 保证仅首个到达者落库/广播
  ├─ CompleteTurnTokens(turn, status, finish_reason, full_tokens?, brief_tokens?)  # 落库（含 token 预存）
  ├─ SetSnapshot(session, msgs, snapshot_turn=turn) # 唯一终态写快照
  ├─ 广播 session-complete {status, finish_reason, code?, message?, text?, parents, retryable?,
  │                          work_dir?, data_dir?, dialog_id?}   # 后三者只增字段
  └─（压缩 = 进程内后台、无 MQ 事件；`session-compress` 已于 2026-10-31 退出消息面）
```

> `retryable?`（可选）**仅 `status=error` 携带**：来源 = 该错误的 `*LLMError.Retryable`（超时/网络/429/5xx → `true`；鉴权/协议 → `false`；`EMPTY_REPLY` 等固定 `false`）。**2026-10-17（RETRY-1）口径**：重试中间态由 `session-retry` 承载（前端 `llm-retry`，可见「正在重试 n/N」）；终态 `session-complete{status:error}` 另带真实 `retry_attempt`/`retry_count`/`retry_wait_ms=0`；终态错误**只在下方提示条**显示（ERRUX-1），聊天流内不再渲染错误气泡。契约见 [61 §4.3](../60-reference/61-消息一览.md)。

| status | 触发 |
|--------|------|
| `complete` | 正常结束（`finish_reason=stop`；`length` → 续写） |
| `incomplete` | 未完成（可自动/手动继续） |
| `interrupted` | 用户取消 / 实例退出 / 启动清理 |
| `error` | LLM/链路错误（携带 `code`/`message` 与可选 `retryable`；可恢复者由前端自动/手动继续） |

> 终态完成后：清 `busy`/`turns` 注册、`tc.Close()`（含 ask 清理）。（2026-11-04 核对：无 session 文件锁可释放）

## 4. 取消

### 4.1 触发与定位

```text
chonk.llm-cancel {session, turn?} → {cancelled, turn}
  ├─ 有 turn → 直接定位
  └─ 无 turn → 按 session 回退运行中轮次（兼容旧 RPC CancelChat）
  └─ complete(tc, "interrupted", "interrupted", "") + tc.Close()
```

### 4.2 级联语义（一律级联，无弹框）

| 取消对象 | 行为 |
|----------|------|
| 任务根节点（工具派生子任务） | **必须级联**：停止自身 + 全部运行中派生任务/子会话 |
| 主会话 cancel | **必须级联**：停止当前 turn 相关任务 + 全部运行中工具/子 LLM |

**正常 complete 不取消任何后台工具/子 LLM**（继续后台运行，后续通知 / 结果消费）。

### 4.3 协作式取消

Go 不能安全 kill goroutine → 框架置 `args["cancel-flag"]`，长循环工具检查后尽早返回。浏览器等共享资源跨 turn 持久，不因单 turn 取消而关闭。

> ⚠️ **待核对（2026-11-04）**：全仓 `grep cancel-flag` **零命中**——该键的写入/读取未在现有代码中找到；实际取消经 `ctx` 取消 + gateway `provider.Invalidate` / `ExecSink.CancelExec` 完成。原设计保留于此，实现待确认。

## 6. 任务与子会话生命周期

- **tasktree 节点**：`chonk.task-started` / `chonk.task-updated` / `chonk.task-done`（**server 编排终态单源广播**，含 llm 子会话）；落库点 = **Task 层（`src/lib/task`）**——层订阅上述既有事件 + `mcp-tasks-report` + `task-deleted`，经既有 `data-tasktree-upsert` **同步落权威表 `tasktree`**（**唯一写者**；llm 侧落库调用已移除，内存 `nodes` 降级为运行态视图）。**零新增 MQ 主题**。见 [21-任务层设计方案 §9.2](../10-architecture/21-任务层设计方案.md)。
- **子轮次**：子聊天 / 子轮次（`subchat_*`）递归 `runChildTurn`，同样广播 `turn-start`（`parents` = 父会话链；history 插件据此判定主 session）。
- **网关异步任务**（执行态）：gateway 执行池（`execPool`，原 `TaskManager`）五态 `pending/running/done/error/cancelled`，完成回报 `mcp-tasks-report` → server 回填续轮；**gateway 只持执行态，树/重试/取消编排在 server**。
  > **2026-11-06（统一异步第一批）**：manual/never 到达超时点不再阻塞等待用户裁决——`tools/call` **立即返回** `structuredContent.status="awaiting"`，`mcp-tools-timeout` 照旧下发；用户 `wait` 仅确认继续等待，`detach`/`cancel` 经进程内 sink，终态统一由 `mcp-tasks-report` 交付一次。声明 `pre_hook_subject` 的工具同样立即返回 pending，钩子与执行在后台。**turn 仍未新增任何终态**：awaiting 只是单次调用的中间态。
  > **2026-11-06（第二批）**：gateway 的超时点「等待完成/解绑/到点」改由 `taskx` 外壳计时（成功优先），仍只推进单次调用的执行态；session/turn 生命周期语义零变更。
  > gateway 执行态（`started`/`detached`/`awaiting`/`error`）**经层内 API 直调**纳入任务层并落权威行 `tasktree`（`state` 可为 **`detached`/`awaiting`**，明细入 `exec_json`）→ 执行态**不再只存内存**；控制面**以层权威状态为准**；**实际打断仍在 gateway**（`onTaskCancel`→`provider.Invalidate`）。**不新增 MQ 主题**。`tasks/status|list|cancel` 与 HTTP `/mcp/tasks` **已移除** → 状态改为**层 `State(task_id)` 直读**、取消 / 转后台改经**进程内 sink**（`ExecSink.CancelExec` / `DetachExec`），**instance 归属校验随之取消**。见 [21 §9.3](../10-architecture/21-任务层设计方案.md)。
- **手动结束任务**：`task-stop` → 级联定位子树 → 节点标 `cancelled` + 广播 `task-done` → 经**进程内 sink**（`ExecSink.CancelExec`）执行取消。（`task-stop` 为 server 方法面主题，见 [61-消息一览](../60-reference/61-消息一览.md) §4.2）

## 8. 恢复与清理

- **权威状态只在数据层**：gateway/会话层/文件服务/插件仅持运行态，UI 持展示态 → 崩溃可从数据层重建。
- **启动/首次使用清理**：遗留 `running` turn → `interrupted`（`data-session-cleanup-stale`）+ tasktree 遗留 running 清理。**只改 DB 状态字段，历史拼接文本不变**（不破坏 LLM 前缀缓存）。tasktree 遗留清理**并入 Task 层 `Recover`**（取代 llm `cleanupStaleTasktree`），覆盖非终态 **`pending`/`running`/`awaiting`/`detached`** → 一律标 `interrupted`、**不自动重跑**。
- **关停收口（2026-11-06）**：`Server.Stop` 先置 `stopped` 闸门（拒绝新建轮次 / inbox 兜底消费）→ 关闭全部 turn → `turnWG` 等待 loop 收尾（上限 10s，超时只留痕）→ 再停任务层 / 数据服务；避免关停后后台写库与库句柄晚释放。轮次数量仍无生命周期终态语义（仅进程关停收口）。
- **工具重试**：`tool-retry` 只作用于**最后一条 interrupted 工具**（`lastInterruptedPair`）；进程重启/死 turn → 按库重建上下文续轮；历史 tool_pair 冻结不改。
- 实例退出清理 running turn + 清除 `busy` 注册 + 注销 capability 注册。
