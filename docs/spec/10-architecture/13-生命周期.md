# 13 · 生命周期

## 0. 三层生命周期

```text
进程 / 实例（instance）  ── GUI/CLI 存续期
   └─ 会话（session）      ── 长生命周期，跨多次启动
        └─ 轮次（turn）    ── 一次用户发送到终态
             └─ 任务 / 子会话（tasktree 节点）
```

## 1. 实例生命周期

| 阶段 | 消息 | 行为 |
|------|------|------|
| 注册 | `instance-register {instance_id, work_dir, data_dir, client_type}` | server 登记实例（`instance.Manager`）+ `data.Register` 绑定数据根；server 发现 `<workDir>/.chonkpilot/capability` → 经 gateway `servers/register`（`scope=instance_id`）动态接入 |
| 保活 | `instance-heartbeat {instance_id}`（GUI 30s；单体形态可免） | 存活判定：心跳由**编译开关** `split`（`-tags split`）编入 —— **单体默认构建不编入**（不据此判退出；`heartbeatTimeout` 判定与 `plugin/instance.Sweep(timeout)` 不编入）；**分离形态编入**后 30s 发布 / 90s 判超时 → **判定侧消费方两处**：**llm-server 30s ticker → `Manager.Sweep(90s)` → 逐个走既有 `exitInstance`**（取消 running turn + 释放 `busy` 锁 + `unregisterCapabilityNodes`）、**persist 30s 扫描 → `LastBeat` ≥90s → 既有 `instanceGone`**（移除 `insts` 绑定 + `data.Unregister`）。见 [28-plugins §2](../20-modules/28-plugins.md) |
| 退出 | `instance-exit {instance_id}` | server 取消名下 running turn、释放 session 锁、`servers/unregister` 注销 capability 注册、`data.Unregister` |

**首次使用清理**：server 对某 instance 的**首个 `llm-start`** 触发（多 workdir 服务，启动时无从预知数据根）：

```text
data-session-cleanup-stale  → 遗留 running turn 标 interrupted（**ask 等待态 `awaiting` 不在此列**，见 §5）
data-tasktree-*（复用面；该清理并入 Task 层 `Recover`） → tasktree 遗留非终态（pending/running/awaiting/detached）→ interrupted（不自动重跑）
```

**实例边界**：单实例与多实例统一以 `instance_id` 标识；`work_dir`/`data_dir` 随注册绑定，后续 `llm-start` 不再传（取注册记录）。

## 2. 会话生命周期

- **建会话**：`data-session-ensure-session`（幂等；已存在复用）。
- **活动会话**：`data-session-active-set` / `data-session-active-get`（UI 活动态，落 prjusr）。
- **启动恢复**：无活动会话 → `data-session-latest` 取最新。
- **重命名**：`data-session-title`。
- **删除**：`data-session-delete`（**先发 `llm-cancel` 取消运行中轮次**，再删）。
- **锁**：同 session 同时只能有一个活动 turn（跨进程文件锁 `lockSession`；崩溃由 OS 释放）。

## 3. 轮次（turn）生命周期

### 3.1 受理（`llm-start`）

```text
客户端（前端/桥）POST/Publish llm-start {session, turn, llm?, think?, effort?, scenario_id?}
  ├─ session/turn 必填（客户端分配；缺 turn 由桥补 t-<12hex>）
  ├─ instance 未注册 → Result{accepted:false, error:"instance not registered"}
  ├─ 首次使用该 instance → 清理遗留 running（§1）
  ├─ session busy（内存 busy 表）→ Result{accepted:false, error:"session busy: <turn>"}
  ├─ session 文件锁排他（lockSession）→ 失败 Result{accepted:false, ...}
  ├─ 落库：EnsureSession + EnsureTurn（幂等，不重新分配）
  ├─ 建 turn 状态机（turnCtx），登记 busy/turns
  ├─ 广播 turn-start（`session-turn-start {instance_id, session, turn, parents}`；主轮次 parents 空）
  └─ Result{accepted:true, session, turn}
```

### 3.2 驱动（`llm-send`）

调度核心按 `type` 喂给 turn 状态机：

| type | 行为 |
|------|------|
| `text-user` | 用户消息 → 构建上下文 → 调 LLM |
| `text-notify` | 后台任务通知 → 触发新一轮回复（含防循环） |
| `tool-result` | 工具结果回填 → 续轮 |

上下文构建（`data-session-context`）：有快照 → 快照前缀 + `snapshot_turn` 之后 turns；无快照 → 近端 summary 起点的历史。详见 [01-端到端数据流](../00-overview/01-端到端数据流.md) §2。

### 3.3 流式产出

- `session-receive {session, turn, type: reason|text|tool-call, payload}`（桥映射为 `llm-receive`）。
- 逐条落库：`data-session-append-message`（tool 结果、异步回填同面）。

### 3.4 终态（`finish`）

所有终态**收敛到 `session-complete`**（前端事件名 `llm-complete`；`llm-error` 仅错误状态由兼容层兼发）：

```text
finish(tc, status, finishReason, code?, message?, text?, retryable?)
  ├─ CompleteTurn(turn, status, finish_reason)     # 落库
  ├─ SetSnapshot(session, msgs, snapshot_turn=turn) # 唯一终态写快照
  ├─ 广播 session-complete {status, finish_reason, code?, message?, text?, parents, retryable?}
  └─ 广播 session-compress {…, last_turn, snapshot_turn} # 无订阅者 = 不压缩
```

> `retryable?`（可选）**仅 `status=error` 携带**：来源 = 该错误的 `*LLMError.Retryable`（超时/网络/429/5xx → `true`；鉴权/协议 → `false`；`EMPTY_REPLY` 等固定 `false`）。前端据此决定「静默自动续写」还是「错误气泡 + 手动继续」；正常/取消终态**不带该字段**。契约见 [61 §4.3](../60-reference/61-消息一览.md)。

| status | 触发 |
|--------|------|
| `complete` | 正常结束（`finish_reason=stop`；`length` → 续写） |
| `incomplete` | 未完成（可自动/手动继续） |
| `interrupted` | 用户取消 / 实例退出 / 启动清理 |
| `error` | LLM/链路错误（携带 `code`/`message` 与可选 `retryable`；可恢复者由前端自动/手动继续） |

> 终态完成后：清 `busy`/`turns`、释放 session 锁、`tc.Close()`（含 ask 清理）。

## 4. 取消

### 4.1 触发与定位

```text
chonk.llm-cancel {session, turn?} → {cancelled, turn}
  ├─ 有 turn → 直接定位
  └─ 无 turn → 按 session 回退运行中轮次（兼容旧 RPC CancelChat）
  └─ complete(tc, "interrupted", "interrupted", "") + tc.Close()
```

### 4.2 级联语义（一律级联，无弹框）

| 取消对象 | 行为 |
|----------|------|
| `llm_run`（作业根节点） | **必须级联**：停止自身 + 全部运行中派生任务/子会话 |
| 主会话 cancel | **必须级联**：停止当前 turn 相关任务 + 全部运行中工具/子 LLM |

**正常 complete 不取消任何后台工具/子 LLM**（继续后台运行，后续通知 / 结果消费）。

### 4.3 协作式取消

Go 不能安全 kill goroutine → 框架置 `args["cancel-flag"]`，长循环工具检查后尽早返回。浏览器等共享资源跨 turn 持久，不因单 turn 取消而关闭。

## 5. ask_user 生命周期

> **目标态**（见 [34 §7](../30-function-points/34-任务.md)）：由「阻塞弹框 + 前端超时」改为**chat 内联表单 + 增量写穿 + 重启续答**。

```text
工具命中 ask_user（入参 questions[] 一表 N 问）
  └─ 广播 session-ask {ask_id, session, turn, expires_at, questions:[{id,question,options?,multi?,recommended?(数组;字符串容错按单元素处理),custom?,answer?,answered?}]}
       前端在所属 chat 内联渲染表单
  └─ ask-user-reply {ask_id, answers:[{id,answer,custom?}]}（增量：仅本次作答的题）
       ├─ 写穿：ask 节点 content {questions, answers, state}（data-tasktree-upsert）
       ├─ 未答齐 → turn 停 awaiting，等后续提交（可跨重启）
       └─ 全部答齐 → task-done（若有 taskID）+ FeedToolResult(toolID, 聚合答案) → 继续 LLM 循环
```

- **不再有前端超时/自动应答**：`expires_at` 仅作 UI 提示，不作废、不选推荐。
- **重启续答**：ask 等待期 turn 状态 = `awaiting`（免被 `data-session-cleanup-stale` 误标 `interrupted`）；重开按落库 `content` 重播 `session-ask`（带已答态），重放路径复用 `recoverTurnCtx`。
- 子会话提问：表单落在子会话所属 chat，回答按 `turn_id` 路由回该轮。

## 6. 任务与子会话生命周期

- **tasktree 节点**：`chonk.task-started` / `chonk.task-updated` / `chonk.task-done`（**server 编排终态单源广播**，含 llm 子会话）；落库点 = **Task 层（`src/lib/task`）**——层订阅上述既有事件 + `mcp-tasks-report` + `task-deleted`，经既有 `data-tasktree-upsert` **同步落权威表 `tasktree`**（**唯一写者**；llm 侧落库调用已移除，内存 `nodes` 降级为运行态视图）。**零新增 MQ 主题**。见 [21-任务层设计方案 §9.2](../10-architecture/21-任务层设计方案.md)。
- **子轮次**：`llm_run` 的 LLM 委派步骤递归 `runChildTurn`，同样广播 `turn-start`（`parents` = 父会话链；history 插件据此判定主 session）。
- **网关异步任务**（执行态）：gateway 执行池（`execPool`，原 `TaskManager`）五态 `pending/running/done/error/cancelled`，完成回报 `mcp-tasks-report` → server 回填续轮；**gateway 只持执行态，树/重试/取消编排在 server**。
  > gateway 执行态（`started`/`detached`/`awaiting`/`error`）**经层内 API 直调**纳入任务层并落权威行 `tasktree`（`state` 可为 **`detached`/`awaiting`**，明细入 `exec_json`）→ 执行态**不再只存内存**；控制面**以层权威状态为准**；**实际打断仍在 gateway**（`onTaskCancel`→`provider.Invalidate`）。**不新增 MQ 主题**。`tasks/status|list|cancel` 与 HTTP `/mcp/tasks` **已移除** → 状态改为**层 `State(task_id)` 直读**、取消 / 转后台改经**进程内 sink**（`ExecSink.CancelExec` / `DetachExec`），**instance 归属校验随之取消**。见 [21 §9.3](../10-architecture/21-任务层设计方案.md)。
- **手动结束任务**：`task-stop` → 级联定位子树 → 节点标 `cancelled` + 广播 `task-done` → 经**进程内 sink**（`ExecSink.CancelExec`）执行取消。（`task-stop` 为 server 方法面主题，见 [61-消息一览](../60-reference/61-消息一览.md) §4.2）

## 7. 压缩与快照

```text
session-compress（终态后广播，无订阅者 = 不压缩）
  └─ src/plugins/plugin-compress：session-complete → 快照 → 摘要 → 回写
        ├─ data-session-set-summary {turn_id, summary}
        └─ data-snapshot-set {session_id, snapshot:{history, snapshot_turn}}
```

- 快照**唯一终态写**在 server `finish`；compress 写回为增量。
- 读：`data-snapshot-get`（无 → null，调用方回退全量 history）。

## 8. 恢复与清理

- **权威状态只在数据层**：gateway/会话层/文件服务/插件仅持运行态，UI/CLI 持展示态 → 崩溃可从数据层重建。
- **启动/首次使用清理**：遗留 `running` turn → `interrupted`（`data-session-cleanup-stale`）+ tasktree 遗留 running 清理。**只改 DB 状态字段，历史拼接文本不变**（不破坏 LLM 前缀缓存）。tasktree 遗留清理**并入 Task 层 `Recover`**（取代 llm `cleanupStaleTasktree`），覆盖非终态 **`pending`/`running`/`awaiting`/`detached`** → 一律标 `interrupted`、**不自动重跑**。
- **工具重试**：`tool-retry` 只作用于**最后一条 interrupted 工具**（`lastInterruptedPair`）；进程重启/死 turn → 按库重建上下文续轮；历史 tool_pair 冻结不改。
- 实例退出清理 running turn + 释放 session 锁 + 注销 capability 注册。
