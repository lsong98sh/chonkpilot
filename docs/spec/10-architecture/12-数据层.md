## 1. 定位与原则

统一数据层 = **三级 chonkpilot.db（usr / prj / prjusr）+ 一级资源（系统）**，加通用 DAO + 版本迁移 + 配置 fallback。承载当前 ChonkPilot 的全部落地数据。

| 原则 | 说明 |
|------|------|
| 三级一机制 | usr / prj / prjusr 同一套 DAO / schema / 迁移代码，仅**数据根不同** |
| 系统级不落库 | 系统级 = 代码常量 + `<exeDir>/capability/`（含出厂场景 `<exeDir>/capability/scenarios/`；源 `src/initdata/`） |
| 一 key 一决策 | config 表多为标量 / 极小 JSON；多记录集合走专用表或文件树 |
| 覆盖即可见 | 分层值 = **整值覆盖**（非深合并）；删本层 key = 恢复继承 |
| 内容库独立 | codegraph 索引保持独立目录（`<workDir>/.chonkpilot/codegraph/`） |
| 不做历史迁移 | 旧库/旧 `config.json` 不导入（如需另做一次性工具） |

> 级别归属、fallback、键粒度的完整规则见 [02-配置层级](../00-overview/02-配置层级.md)（不再本文重复）。

## 2. 引擎

**bbolt**（`go.etcd.io/bbolt`）：纯 Go、单文件、无 CGO（契合主模块 CGO 禁令）。

- 结构 = 单文件 COW B+ 树；**打开即独占 flock**（同进程内同一文件二次 `Open` 会互斥，故有 §5 的连接缓存）。
- 打开参数：文件 `0600`、目录 `0700`。
- 事务：`Update`（写，单写者）/ `View`（读，可并发）。
- **不是** WAL 引擎；跨进程并发不依赖 WAL，靠"允许的实例模型 + 连接缓存"（见 §5.4）。

## 4. 通用 DAO

### 4.1 Table（类 Hibernate）

`db.Table(name)` 返回表句柄；行 = `Record`（`map[string]any`，序列化为 JSON 存 value）：

| 方法 | 语义 |
|------|------|
| `Insert(key, rec)` | 已存在 → `ErrExists` |
| `Update(key, rec)` | 不存在 → `ErrNotFound` |
| `Upsert(key, rec)` | 不存在插入 / 存在覆盖；自动写 `updated_at` |
| `Get(key, *rec)` | 返回 `(found, err)`；回填 `_key` |
| `Delete(key)` | 不存在 → `ErrNotFound` |
| `ListKeys()` | 主键列表 |
| `ListPrefix(prefix)` | 按**主键前缀** `Cursor.Seek` 顺序返回主键列表（顺序 = 主键字典序；遇非前缀即止；空前缀 = `ListKeys`）。供「主键本身即复合键」的表（`memory_extract` 主键 `<session_id>\x00<category>`）做前缀读。**〔订正（2026-10-08 · Phase-1 索引改造）新增〕** |

约定：主键字段 `_key`（`KeyField`）不落 value。
> **〔订正（2026-10-08 · Phase-1 索引改造）〕**：`Insert` / `Update` / `Upsert` / `Delete` 在**同一 bolt 事务内**同步维护该表全部二级索引（删旧键 + 插新键，键随列值 `created_at` 等变更而迁移）——一致性内建，不散在各 facade。索引声明与查询路由见 §4.2 / §6.1；实现 `src/lib/data/{indexes.go,table.go}`。

### 4.2 Query（类 Criteria）

```go
type Query struct {
    Where     map[string]any // 等值过滤（支持点路径 a.b.c）
    OrderBy   string         // 排序字段（点路径）
    OrderDesc bool
    Limit     int  // 0 = 不限
    Offset    int  // 与 Cursor 互斥
    Cursor    string // 连续滚动游标（优先于 Offset）
}
recs, nextCursor, err := table.Query(q)
```

- 过滤：`Where` 逐项点路径等值；JSON 数值容错（float64 比较）。
- 排序：数值优先，其次字符串（RFC3339 时间可直接字典序）。
- 游标：`<orderByValue>|<primaryKey>` 的 URL-safe base64；`filterAfter` 按 (排序值, 主键) 保留游标之后记录 → 连续滚动分页。

> **〔订正（2026-10-08 · Phase-1 索引改造）〕**：`Query` **不再是「恒全表扫描 + 内存排序」**，新增**索引路由**：
> - **路由**：`Where` 覆盖某二级索引 `Fields` 的**最长等值前缀**（前缀列须连续命中、值均为**字符串**）→ 走该索引桶 `Cursor.Seek(前缀)` 顺序遍历；每个索引值 = **主键**，按主键**回表** `Get` 主行，再应用**剩余** `Where`（含前缀未覆盖项）与 `Cursor` 续查。
> - **跳过排序 / 提前退出**：遍历顺序即结果顺序时（`OrderBy==""` 按遍历序，或 `OrderBy` 命中索引 `Order` 的**升序**）**跳过内存排序**，并允许攒够 `Offset+Limit` 后**提前退出**（`next_cursor` 由窥见的 `more` 决定）；`OrderDesc` 或顺序不一致 → 收集完再内存排序分页。
> - **回落全表扫描**：无可用索引前缀（Where 为空 / 未覆盖首列 / 值为非字符串）、或 `Cursor` 续查与无 `OrderBy` 的不兼容组合、或无注册索引的表、或**索引桶整桶为空 / 桶缺失**（`Cursor().First()` O(1) 探测；视为「索引未就绪」→ 回落全桶扫描，避免升级后索引尚未写入时**静默返回空**）→ **回落全桶扫描**（行为与改前逐字节一致）。
> - **返回语义不变**：`_key`、`next_cursor` 编码、`Offset`/`Limit`/`Cursor`、坏行/脏索引跳过均与全桶扫描一致。
> - **索引声明/维护**：声明与键形态见 §6.1；写入口同事务维护见 §4.1 订正；实现 `src/lib/data/{indexes.go,query.go}`。

> **〔订正（2026-10-10 · R7-A 索引消费口径）〕**：索引路由（§4.2）落地后，**查询侧须按「无 `OrderBy` 禁索引路由」口径补齐 `OrderBy`**，否则退化全桶扫：
> - **按轮读消息**（`queryTurnMessages`，`session_facade.go`）`Where` **仅用 `turn_id`**（A-44）——若并带 `session_id`，`indexFor` 等长前缀平局会取先声明的 `messages_by_session` → 按轮读退化为 O(轮×会话消息)；单用 `turn_id` 直命中 `messages_by_turn`，有界流式（`Limit=messagePerTurnCap`）。口径同 `MessageLoad`。
> - **会话级级联查询**（`SessionDelete` 的 `turns`/`messages`；`FindToolMessageKey` 的 `{turn_id, tool_call_id}`）补 `OrderBy: "created_at"` → 分别命中 `turns_by_session`/`messages_by_session`/`messages_by_turn`（A-05）。**`FindToolMessageKey` 的 `Where` 已按 `role=tool` 收窄**（同轮同 `tool_call_id` 仅取工具行，避免误命中 assistant 的 `tool_calls` 行）。
> - **索引平局优先级 = 声明顺序**（A-6）：`tasktreeIndexes` 把更窄的 `_by_session` 声明在 `_by_top` 之前 —— 查询 `{top_session, session_id}` 等长命中两索引时取 `by_session`（更窄行集；correctness 由回表 `matchWhere` 兜底，两索引结果集恒等）。
> - **启动期陈旧 tool 对清理**（`cleanupStaleToolPairs`，A-5）：`tool_call_status` 无索引，原对 3 个非终态各 `Query` 一次 = 3 次全桶扫 → 改**单次流式扫描**（`Table.ForEach`，单事务、不整表物化）按状态分桶（各状态上限 500、桶序取前 500，与改前逐条等价），三状态均攒满即提前结束。
> - **读/删路径 symlink 越界复验**：`KnowledgeRead` 补**读前**实路径复验（与写入口同口径，A-32 同款 —— `SafeJoin` 仅纯词法校验，根内指向根外的 symlink 会被 `os.ReadFile` 跟随越界读）；`MemoryDelete` 补**删前**实路径复验（`os.Remove` 会跟随根内指向根外的 symlink，A-45 同族）。均经 `capfs.RealPathInside`（先解析 root 自身 symlink 再复判，见 `capfs/primitive.go`）。

### 4.4 写侧字段校验（INPUTVAL-1，2026-10-21）

**写侧 = 唯一可信边界**：前端约束只改善体验，数据层在**写库前**复验，超限/非法**整批拒绝**（返回明确错误，**不截断**、不静默丢弃），事务失败不破坏旧数据；读侧保持既有兜底（兼容存量脏数据）。

| 落点 | 校验内容 |
|---|---|
| `config.ValidateUserConfigPayload`（`UserConfigSet`） | usr 标量已知键（`responseTimeout`/`streamTimeout` **必须 >0**；`retryCount`/`retryBudgetSec`/`autoContinueDelaySec`/`turnEventLogRetentionDays`/`nextRunMax` 非负；`turnEventLog` 枚举；路径类绝对路径）+ `llms` 逐条（名称 ≤64/必填/不重名、模型 ≤128、baseUrl http(s) ≤2048、apiKey ≤512 无空白、temperature 0–2、maxOutputToken 0 或 256–1e6、maxContextToken / maxToolIterations 范围） |
| `config.ValidateConfigKV`（`ConfigKVSet`） | prompt 域正文 ≤256 KB 字符；prj-security 信任目录（绝对路径 + 存在 + `writable`）；`timeout_sec`/`max_concurrency`/`project-id`/`keep_full_*`/`pending_task_timeout_sec` 数值与格式 |
| 会话域（`session_facade`/`inbox_facade`） | 会话标题 ≤128；`turns.status` 白名单；消息 `role` 白名单 + 正文 ≤256 KB 字符 |
| 任务树（`tasktree`） | `status` 白名单（空/pending/running/done/error/cancelled/interrupted） |
| 实例登记（`persist.onInstanceRegister`） | `instance_id` 标识符 ≤64、`work_dir` 必填绝对路径 ≤512、`data_dir` 可选绝对路径、禁 `..`；失败不登记（告警留痕） |

字段基线常量 = `src/lib/data/internal/config/validate.go`；前端同源规则 = `src/frontend/src/utils/fieldRules.js`（基线口径见 [输入校验专题](../../input-validation/输入校验专题.md) §3）。

## 5. 多实例访问与连接缓存

### 5.1 instance 绑定

`server`/`persist` 订阅 `instance-register` → `data.Register(instance_id, work_dir, data_dir)`；`instance-exit` → `Unregister`。之后所有数据访问**以 `instance_id` 为入口**，路径解析在包内完成，调用方无感：

```text
data.Prj(instanceID)    → (*DB, release, error)：<workDir>/.chonkpilot/chonkpilot.db（**短开**，D-45）
data.PrjUsr(instanceID) → (*DB, error)：dataDir 非空：<dataDir>/chonkpilot.db（**与 prj 同文件**）
                          否则：~/.chonkpilot/data/<project-id>/chonkpilot.db（**常开**）
data.Usr()              → (*DB, release, error)：~/.chonkpilot/chonkpilot.db（全局单例，**短开**）
```

未注册的 instance → `ErrLayerUnavailable` / "instance not registered"。

### 5.2 连接缓存 + 引用计数（短开语义，D-45）

`OpenSharedLayer(path, layer)`：按 **db 文件最终路径**（非 data_dir）缓存连接并计数；`Release` 计数归零才真正 `Close`。理由：不同 data_dir / 不同项目可能解析到同一文件，按路径缓存保证同文件单连接（bbolt 独占）。

- **prj / usr = 短开**（D-45 ②，GUI 与 CLI 双方）：用则开、用完关 —— `Prj`/`Usr` 返回 `(*DB, release, error)`，调用方**必须 `defer release()`**；计数归零即真关，使 CLI 可与 GUI 并发打开同一项目配置。
- **prjusr = 常开**（D-45 ③）：会话/任务树/快照高频写，保持进程内常开（调用方无需管生命周期）；**打开冲突**（被另一进程持有）→ 明确报错退出（提示"可改用临时模式或关闭 GUI"）。
- **超时**：`bolt.Open` 一律带 `Options{Timeout: data.BoltOpenTimeout（3s）}`（`src/lib/data/db.go`；auth store 同）——bbolt 独占 flock 被持有不再无限等待，快速失败可诊断。
- **config 值缓存（不持句柄）**：`src/lib/data/internal/config/valuecache.go` 按 db 文件路径缓存 config 表平铺值，stamp = **读表之前的 stat**（mtime+size 双判据；stamp 相同 = 读到的是 stamp 之后状态 = 命中新鲜）——短开后高频配置读不再逐次开库；本进程写后主动 invalidate，跨进程靠 stat 失效。仅缓存 config 表 kv（`llms` 等集合表不缓存）。

### 5.3 `dataDir` 非空形态（CLI 临时）

`dataDir` 非空 → prj 与 prjusr **同文件**（`<dataDir>/chonkpilot.db`）。

- ~~**CLI**~~（**已删除 2026-10-21**）：原 `dataDir` = 临时目录（tmp 空根 + 复制三级配置、退出即弃，**GUI 不可见**）的语义随 CLI 移除；`--data-dir` 仅 desktop 用（缺省 = `<workDir>/.chonkpilot`）。**原文（历史）**：见 `2A-cli §9`（该规格稿已删除）。
- **desktop（B 方案前）**：`dataDir` = `models.DataDir(workDir)`（缺省 `<workDir>/.chonkpilot`，**恒非空**）→ 会话数据落在**项目目录内**。**B 方案**（[24 §3](24-多窗口模型设计方案.md)）**改为走 `dataDir == ""` 分支** → 会话数据落 `~/.chonkpilot/data/<prj-id>/`。

> **判据是 `dataDir != ""`，与"是否 CLI"无关**。

### 5.4 并发边界

- 同进程：连接缓存 + 引用计数，单连接串行事务。
- 跨进程（**D-45：CLI × GUI 并发访问同一项目库**）：prj/usr **短开**（§5.2）→ 双方可并发读同一项目配置；**prjusr 常开互斥** → 第二个实例启动准备期**试开即明确报错退出**（CLI：`src/lib/cli` `probePrjUsr`，提示"可改用临时模式或关闭 GUI"；临时隔离态不受限——复制配置进 tmp，不触碰真实 prjusr）。
- **work-dir 占用锁**（`LockFileEx` 模式，`src/lib/core/lockfile`）：GUI 与 CLI **真实根态**在启动入口校验（I-74），占用即明确报错；非 busy 设施故障仅告警放行（降级不持锁）→ bbolt 独占 flock 兜底，`bolt.Open` 带 3s `Timeout` 快速失败（§5.2）。
- 连接缓存键 = 最终路径，避免同文件重复 Open。

## 6. Schema 与迁移

### 6.1 三层同构桶

三层桶集合完全一致（全量 migration，空桶无妨）：

```text
_meta  _migrations  config  llms  mcps
sessions  turns  messages  tasktree  meta
sessions_by_top  turns_by_session  messages_by_session  messages_by_turn
tasktree_by_parent  tasktree_by_top  tasktree_by_session
task_shadow  task_shadow_by_top  task_shadow_by_parent  task_shadow_by_session
memory_extract
group_participants  group_round_targets
index_queue
turn_events
```

> **v11（2026-10-20 · MOD-1 M3）**：新增 prjusr 级 `turn_events`（TurnState 事件日志）。字段 `session_id / turn_id / seq / type / at / payload`；主键 `<turn_id>/<seq 12 位零填充>` → 同 turn 前缀扫描即重放；**不建二级索引**。写入 = llm-server（`data-turn-event-append`，同 turn+seq 幂等、type 冲突失败）；清理 = `data-turn-event-cleanup`（仅删**终态且超过 `turnEventLogRetentionDays`** 的 turn；`0` = 永久；running 永不按时间删）。
>
> **v10（2026-10-19 · resident indexer）**：新增 prjusr 级 `index_queue`（待索引队列；字段 `work_dir / path / operation / state / attempts / last_error / created_at / updated_at`，**2026-10-19 P5 增 `consumer`**）。查询模式 = 按 `work_dir` + `state` + `consumer` 过滤、`created_at` 升序；**不建二级索引**（队列量小）。写入方 = filesys（经 inline 门面，**不新增 MQ 主题**）；消费方 = resident indexer（vfts / codegraph）。
>
> **consumer 扇出（2026-10-19，P5）**：同一文件变更按 `indexkind.All`（`vfts` / `codegraph`）各写一行，两个 indexer 各自 `take/ack/pending`，互不影响；同 `(work_dir, path, consumer)` pending 去重。旧行无 `consumer` 字段 → 视为 legacy（任意 consumer 可见、任一方可回执）。`Append` 不传 `Consumers` = 旧单行行为。见 [插件桥设计稿 §11.8.6](../../bridge-plugin/插件桥接端口设计方案.md)。

> 〔订正（2026-10-08 · schema 7→8）**：`sessions_by_created` / `turns_by_session` / `messages_by_turn` / `tool_pair_by_turn` / `tool_pair_by_task` 五个索引桶曾按「**建而不用**」（全仓零写零读，属 schema 债务）删除。**本轮（Phase-1 索引改造）按查询模式重建/新增二级索引桶**（清单见下条注）：新增 `sessions_by_top` / `messages_by_session` / `turns_by_session` / `messages_by_turn` / `tasktree_by_session` / `task_shadow_by_session`，**移除** `task_shadow_by_instance`（已无写方、由 `task_shadow_by_session` 取代）；`sessions_by_created` / `tool_pair_by_turn` / `tool_pair_by_task` 三桶**保持删除**。既有库中的多余空桶**无害、不主动清理**；本轮**无任何回填/迁移逻辑**（**不考虑存量**，索引随新写入自然建立）。**原「本层 `Query` 仍为全表扫描 + 内存排序」表述作废** —— `Query` 现支持**索引路由**（+ 前缀 Seek + 提前退出，无可用索引前缀时回落全桶扫描），见 §4.2 订正。〕
>
> **二级索引（Phase-1「按查询模式建索引」）**：键 = **前缀列值 +（可选）排序字段值 + 主键**，各段以 `\x00` 分隔（前缀恒以分隔符结尾 → `Cursor.Seek(前缀)` 落区段起点）；**索引值 = 主键**（查询时回表取主行，见 §4.2）。声明见 `src/lib/data/indexes.go`，**由 `Table` 写入口在同一事务内维护**（§4.1 订正；tasktree 原手写索引维护 `shadowIndexPut`/`shadowIndexDelete`/`indexDelete` 已收敛删除）。清单：
> - `messages_by_session`：`<session_id>\x00<created_at>\x00<主键>`
> - `messages_by_turn`：`<turn_id>\x00<created_at>\x00<主键>`
> - `turns_by_session`：`<session_id>\x00<created_at>\x00<主键>`
> - `sessions_by_top`：`<parent_id>\x00<created_at>\x00<主键>`（**顶层会话 = `parent_id` 为空串** → 前缀 `"\x00"` 命中）。**`LatestTopSession`（最近活动的顶层会话）**：`Where{parent_id:""}` + `OrderBy created_at desc` 仅供命中该索引路由；**选中口径 = `SessionActivity`（`last_activity` 优先、回落 `updated_at`），与索引排序列 `created_at` 不一致** → 必然全量物化顶层集合并内存扫描取最大（**复杂度 O(N)，N = 顶层会话数**），且**不能加 `Limit` 截断**（O(1) 首行 ≠ 最近活动行，截断会选错）——与 `SessionList` 排序口径一致。
> - `tasktree_by_top`：`<top_session>\x00<created_at>\x00<主键>` · `tasktree_by_session`：`<session_id>\x00<created_at>\x00<主键>`
> - `tasktree_by_parent`：`<parent_node_id>\x00<主键>`（**列名 `parent_node_id`**；无排序段，供级联子树前缀递归）
> - `task_shadow_by_top` / `task_shadow_by_session` / `task_shadow_by_parent`：影子表 `task_shadow` 孪生（键形态同 `tasktree_*`）
> 注：场景**不落库**（历史空桶 `scenarios` / `permission` 已从 schema 移除、不再创建；无任何读写）。场景 = `<级别根>/capability/scenarios/<场景目录>/` 文件树（见 §7），原 `scenario_list` 不再作主数据。**不允许同名场景**（id **全局唯一**，跨级亦然）→ **"覆盖"语义整体不存在**（`list` 无需去重、`load` 直接按 id 命中）、`ScenarioSave` 需**新增跨级重名校验**；级别语义 = **存放位置/归属**（**四级均可写**），**不是优先级链**；既有重名数据**不迁移**（见 [25 §6](../10-architecture/25-MCP与场景分层模型.md)）。
> **任务影子域（Task 层 P1）**：末行 `task_shadow` + 三个索引桶（`task_shadow_by_top` / `task_shadow_by_parent` / `task_shadow_by_session`；原 `task_shadow_by_instance` **已移除**，见上条订正）由 schema 迁移统一建立，**不改动** `tasktree` 表与 `data-tasktree-*` 默认语义——影子读写经载荷 **`shadow: true`** 显式路由（见 §7 任务树域行）。
> **记忆提取进度表（OP-05/06）**：`memory_extract` 桶由 schema 迁移建立（三层同构、仅 prjusr 实际使用）——**记忆提取进度专用表**：记录 `{session_id, category, last_turn_id, updated_at}`，主键 `<session_id>\x00<category>`（每 (会话, 类别) 一行「最后已成功提取的 turn」）。读写经 `data-memory-extract-{load,save,delete}`（[61 §3.1](../60-reference/61-消息一览.md)）；取代此前 prjusr config 键 `memory-extract.<会话>.<类别>`（**进度是记录不是配置**，旧键已废、零兼容）。
> **群聊两表（SUBCHAT-3 阶段 E，2026-10-16）**：`group_participants` / `group_round_targets` 两桶由 schema 迁移建立（三层同构、仅 prjusr 实际使用）——**① 参与者名单 + 角色**（`{session_id, agent, role, seq, created_at, updated_at}`，主键 `<session_id>\x00<agent>`；`seq` = **名单固定顺序**，见 [群聊方案 D3](../../agent-chat/群聊会话设计方案.md)）；**② 每【大轮次】的投递对象**（`{session_id, round, agents[], created_at, updated_at}`，主键 `<session_id>\x00<round 6 位零填充>` → 主键字典序 = 轮次数值序）。两表**逻辑外键 = `session_id`**（关联 `sessions.kind == group_chat` 的行）；**无二级索引**（查询 = 单前缀 Seek）；读写经 `data-session-group-{participants,round-targets}-{load,save}`（[61 §3.2c](../60-reference/61-消息一览.md)），**不广播 -refresh**。设计见 [群聊会话设计方案 §5 · D44](../../agent-chat/群聊会话设计方案.md)。

### 6.2 迁移与 seed

- **单条最新版 schema**：`migrations` 仅一条（**`Version: 8, Name: "schema"`**）——一次建出全量桶；未发布期**无旧库**，故**不留增量史**（原 v1/v3/v4/v5/v6 已压平）。**〔订正（2026-10-08 · Phase-1 索引改造）**：版本 7→8，`ensureBucket` 幂等建出新增二级索引桶、不再建 `task_shadow_by_instance`；**不写任何回填逻辑**（索引随新写入自然建立，**不考虑存量**）。〕
