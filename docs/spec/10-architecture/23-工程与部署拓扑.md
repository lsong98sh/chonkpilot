## 1. 总原则：层 ≠ 工程

> **层 = 职责角色；工程 / exe = 宿主（打包方式）。** 层的定义**不随部署方式变化**。

1. 新增一个能力 = **加包 + 装配处注册一行**，而不是「新增 module + 新增 exe + 新增消息面」。
2. 目录搬迁 = **零行为变更、零消息面变更**。
3. **层间通信仍在进程内**（MQ 总线 / 门面）；工程位置变化不改通信方式。
4. **只有一种运行形态**（desktop 单进程），不存在按形态分叉的宿主工程。

## 2. 工程构成（`src/`）

| 工程 | 角色 | 产物 / 落点 |
|------|------|------------|
| `src/desktop` | **唯一外壳·宿主**：WebView2 薄壳（`//go:embed all:frontend/dist` + `FormDesktop`）→ `lib/gui/host.Main` | `dist/desktop/chonkpilot.exe` |
| `src/frontend` | 前端源码工程（Vue3，单入口 `index.html`）：**业务 UI**（视图 / api / 业务 utils / 视图登记表）+ `main.js`（composition root）。**平台基座前端机制包 = 同级仓 `chonkpilot-framework/host/web/src`**（窗口 chrome / 布局引擎与档案 / 通用控件 / MQ 客户端），以 vite alias `@ckfw` **源码级**编译（不产 dist、不引第二套 node_modules） | vite 直投 `src/desktop/frontend/dist`（`go:embed`） |
| `src/lib` | **业务库**：服务层（`data` / `filesys` / `task` / `llm` / `mcp-server`）+ `mcp-tools`（executor）+ `gui/{host,bridge,mqpolicy}`（装配 / 业务 MQ 桥）+ 适配层（`appwire` / `assembly` / `gwadapter` / `ignore` / `workspace`）。**平台基座（原 `core` + 窗口层）与插件对接面（原 `pluginhost`）已迁至同级仓 `chonkpilot-framework`**（TOPO-1，2026-10-29） | 编入 exe |
| `src/initdata` | **出厂数据唯一源**：`capability/{prompts,resources,skills,agents,scenarios,system,plugins}` + `themes/`（**工具契约不在此**：server 域 = `src/lib/llm/contracts/tools/`；插件域 = 插件仓 `<plugin>/tools/`） | 覆盖式同步进发行目录 / 出厂包 |
| `src/others` | 对外协议外壳：MCP server / MCP gateway | `dist/other/chonkpilot-mcp-server.exe` · `chonkpilot-mcp-gateway.exe` |
| ~~`src/plugins`~~ | **已整体迁出主仓（2026-10-24，PLUGIN-SPLIT-1）**：全部业务插件源码在同级仓 `chonkpilot-plugins/<id>/{src,doc}`（9 个：codegraph/browser/desktop/file/task/mcp/web/memory/history；主仓零业务插件） | `dist/plugins/{codegraph,vfts}`；插件 staging `dist/plugin-apps` |
| `src/mcps` | 可选文档转换器（markitdown） | `dist/desktop/mcps/markitdown` |
| `src/test` | 测试工程（`unittest` / `systest` / `llmproxy`） | — |
| `src/tools` | 构建辅助（`genmsg`：消息键常量生成） | 生成 `msgkeys`（勿手改） |
| ~~`src/server`~~ | **已删除**（独立 server 形态不存在；`chonkpilot.exe` 即宿主 + server） | — |

```text
src/
├── desktop/          # 唯一壳（main.go 薄壳 + frontend/dist embed 落点）
├── frontend/         # 前端源码（vite：src / public / test / index.html；机制包经 @ckfw → framework/host/web/src）
├── lib/
│   ├── data/         # 数据面（facade / persist / internal 内核）
│   ├── filesys/      # 文件服务（含 watcher）
│   ├── task/         # 任务层
│   ├── llm/          # 会话服务（server）+ LLM 桥（llmbridge）+ 契约
│   ├── mcp-server/   # MCP server 库 + 契约执行面（进程内注册；独立 gateway 用 stdio 下游）
│   ├── mcp-tools/    # 工具进程实现（cmd 外壳 + internal 实现）
│   ├── gui/          # 业务侧：host（单体装配）/ bridge（业务 MQ 桥）/ models / mqpolicy
│   ├── appwire/      # 共用脊柱装配（bus → facade → filesys → server）
│   ├── assembly/     # 装配实现
│   ├── gwadapter/    # 外部 gateway 模块适配
│   ├── workspace/    # 工作区管理（PM）+ layout（物理布局唯一算法，可被 filesys/data 单独依赖）
│   └── ignore/
├── initdata/         # 出厂数据唯一源（capability / themes）
├── others/           # mcp-server / mcp-gateway 两个 exe 外壳
├── mcps/             # 可选文档转换器
├── test/             # unittest / systest / llmproxy
└── tools/            # genmsg（输出 = framework host/core/msgkeys + 前端 events/msgkeys.js）

（同级仓：`chonkpilot-framework/{host,plugin}`（平台基座 + 插件对接面）· `chonkpilot-agent`（组件各独立 module、`<组件>/{src,doc}`：chat / router / session / gateway / types；sandbox / winproc / internal 留在仓根 module）·
`chonkpilot-plugins/<id>/{src,doc}`（业务插件）· `chonkpilot-util` · `chonkpilot-webview2`。主仓不再有 `plugins/`、`server/`、`lib/core/`、`lib/pluginhost/`。）
```

**Lib 内部分层**

- 依赖方向：`chonkpilot-framework/host`（**平台基座：mq / paths / uds / transport / lockfile / tray / winlog / 窗口层**）← 服务层（`data` / `filesys` / `task` / `llm` / `mcp-server`）+ 适配/装配层（`appwire` / `assembly` / `gwadapter` / `workspace`）。`chonkpilot-framework/plugin` 只被**插件侧**与主仓插件桥依赖，`host` 与 `plugin` 不互相依赖。
- **实例视图单源（P5 / C15）**：`workspace`（PM）与 `llm/server` 共用**同一份** `framework/plugin/runtime/instance.Manager`（入口装配器先建、后分别注入）；`workspace/layout` 子包是物理布局唯一算法，`filesys` / `data` 只依赖它。
- 隔离：非门面的一切下沉 `<组件>/internal/`，由编译器强制（`internal` 之外不可 import）。
- 门面 = 翻译层（存储模型 → 领域模型），不是管道：不交解析器、不交路径规则。

## 3. 构建脚本与产物

**构建脚本共 6 个**，一律无形态参数（`build-desktop.ps1` 支持 `-Debug`：编入 `--test-port` 测试通道）。

| 脚本 | 产物 |
|------|------|
| `build-desktop.ps1` | `dist/desktop/`：`chonkpilot.exe` + `capability/` + `mcps/` + `themes/`；并调用下述 mcp-server / plugins / codegraph / vfts 脚本 |
| `build-plugins.ps1` | `dist/plugin-apps/<id>/`（插件 staging）→ 由 `build-desktop.ps1` 拷入 `dist/desktop/capability/plugins/<id>/` |
| `build-mcp-server.ps1` | `dist/other/`：`chonkpilot-mcp-server.exe` + `capability/`（契约 + executor）+ `config.json` |
| `build-mcp-gateway.ps1` | `dist/other/chonkpilot-mcp-gateway.exe`（与 mcp-server 同目录，共用 `capability/`） |
| `build-codegraph.ps1` | `dist/plugins/codegraph/`（引擎 exe + 查询工具一工具一 exe） |
| `build-vfts.ps1` | `dist/plugins/vfts/`（引擎 exe + 查询 executor + `zvec_c_api.dll`） |

> 契约同步：`src/initdata/capability/` 是 LLM 识别工具 / 提示词 / 技能的**唯一契约源**；构建时覆盖式同步到发行目录与 mcp-server 的 embed 兜底副本（生成物勿手改）。

## 4. 发行目录 `dist/`

| 目录 | 内容 | 是否随发行 |
|------|------|:---:|
| `dist/` | **唯一发行根**（2026-11-02 扁平化）：`chonkpilot.exe` · `chonkpilot-remote-server.exe`(+`.db`) · `capability/` · `plugins/` · `themes/themes.css` | ✅ |
| `dist/other/` | 独立 MCP 部署（可选，单独跑 `build-mcp-server.ps1`）：`chonkpilot-mcp-server.exe` · `chonkpilot-mcp-gateway.exe` · `capability/` · `config.json` | 独立部署 |
| `dist/plugins/` | 引擎构建区：`codegraph/` · `vfts/`（需内置引擎时手工投放） | 中间产物 |
| `build/plugin-apps/` | 插件 staging（manifest 插件 exe，`build-plugins.ps1` 产出） | 中间产物 |
| `dist/initdata/` | 出厂数据包（默认不产；需要时单独打包）：`capability-<时间戳>.zip` + `initial.zip` | 可选 |

**`dist/` 发行根（2026-11-02 扁平化）**

```text
dist/
├── chonkpilot.exe
├── chonkpilot-remote-server.exe + .db    # 远端服务（H5 + 后台管理 embed；SQLite）
├── capability/
│   ├── tools/ prompts/ resources/ skills/ agents/ system/
│   └── scenarios/<场景id>/
├── plugins/<id>/plugin.json + <exe>      # 与 capability 同级（不再有 capability/plugins）
└── themes/themes.css
```

> 运行期产物（WebView2 profile、日志、数据库）落在数据根，**不进发行目录**。
> 内置引擎（codegraph/vfts `mcps/`）与文档转换器默认不投放；`self-tools` 已退役。

## 5. 运行期部署拓扑（单机）

```text
安装目录（可只读）                   项目目录（work_dir）
dist/desktop/                       <workDir>/
├─ chonkpilot.exe                   ├─ .chonkpilot/
├─ capability/                      │   ├─ chonkpilot.db          # prj 库
├─ mcps/                            │   ├─ users/<OS 用户名>/     # prjusr（会话/任务树/快照/日志/附件）
└─ themes/                          │   └─ capability/            # 项目级能力
                                    └─ （用户工程文件）
用户级数据（跨项目）
~/.chonkpilot/
├─ chonkpilot.db                    # usr 库（全局配置）
└─ webview2/<instance_id>/          # 每窗口一份 WebView2 profile
本机通道
%LOCALAPPDATA%\chonkpilot\plugin.sock   # 插件前门（UDS）
%LOCALAPPDATA%\chonkpilot\llm.sock      # LLM 桥（UDS）
```

**要点**

1. **单机单进程**：只有「安装目录 / 项目目录 / 用户目录」三处落点，业务不经网络。
2. **安装目录可只读**：exe 只从 `<exeDir>` 读 `capability/` / `mcps/` / `themes/`；所有写入落项目目录或用户目录。
3. **数据随项目走**：`prj` 与 `prjusr` 都在 `<workDir>/.chonkpilot` 下；复制项目目录即复制该项目的本机历史。
4. **数据根内进程唯一**：实例 UDS socket 独占 listen（`%LOCALAPPDATA%\chonkpilot\instance\<数据根指纹>.sock`；作用域 = `<workDir>/.chonkpilot`；不同数据根可并存，见 [19 §2](19-单进程形态与实例隔离.md)）。第二实例不建窗，只经该 socket 发 `activate`：既有实例前置一个 workdir 窗口，没有窗口则打开该 workdir（49 §2.22.6-5）。
5. **UDS 仅本机**：目录 ACL 限当前用户；不监听业务 TCP 端口。
6. **文件到应用区**：executor / 工具直接读写项目目录；filesys 负责监听 / 变更通知 / 前端文件树（不承担全部文件 IO）。

## 6. 路径解析

| 前缀 / 形式 | 含义 |
|------|------|
| 绝对路径 | 直接使用（须在允许根内） |
| `~/` | OS 用户目录（`C:\Users\<name>`） |
| `!/` | **本实例**临时根（`paths.TempRootFor(instance_id)`） |
| 相对路径 | **一律拒绝** |

- 规则细节见 [16-路径解析规范](16-路径解析规范.md)；文件操作的基目录由实例绑定（`instance-register` 的 `work_dir`）决定，不采信请求自报。
- DB 中保存路径的形态沿用数据层既有口径（见 [12-数据层](12-数据层.md)）。

## 7. 外壳边界

**外壳只应有**

1. 进程入口与生命周期（`main` / 参数 / 退出 / `instance-claim`·`instance-exit`）
2. 宿主环境适配（读 env、定 `work_dir` / `data_dir`、注入）
3. 宿主装配（WebView2 窗口 / 静态资源 / 内嵌 server / 插件平台接线）
4. 装配选择（装哪些层、注册哪些契约、开哪些插件）—— **只「选」，不「装」**
5. 协议适配（对外 MCP ↔ 内部 MQ，见 `src/others`）
6. 身份与作用域（实例认领 + 实例绑定下发）

**外壳不该有**：业务规则 · 领域判断（名字 / 类型 / 树）· 状态机 · 持久化 · 层间协调逻辑。

**判据**

- **换宿主测试**：换成另一个外壳还成立吗？成立 → 归 `lib`。
- **去 I/O 测试**：把 stdin/stdout/网络/窗口/文件/时钟都 mock 掉还能跑吗？能 → 归 `lib`。

> **独立能力体例外**：`mcp-tools`（executor）与引擎（codegraph / vfts）不是外壳，是「被 spawn 的执行体 / 独立部署」→ 不得依赖 `lib` 服务层。
