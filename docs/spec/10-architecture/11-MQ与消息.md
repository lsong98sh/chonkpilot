## 1. 定位

**MQ 是组件间唯一的跨组件通道**（单体形态亦然）：

- 抽象掉物理边界——同一份业务代码在"同进程内存总线"与将来"跨进程/多机"下语义一致。
- 所有交互 = 事件（fire-and-forget）+ 请求-响应（publish + promise 收集），**无独立 RPC**。
- 唯一豁免：GUI↔server 的 `/show` 字节流、测试端口端点白名单。

当前实现 = **进程内内存总线**（**去掉 NATS**；去中心化 MQ 留待自研，见 §7）。

> 目标形态：**客户端 = 前端 + GUI**；**服务端 = llm + gateway + filesys + data 等合并为一个 exe（服务）**；**消息经 HTTP 在 GUI 与 llm server 之间直接路由**。
> 落地原则 =「**内部采用内存，外部用 bridge**」：**进程内用内存总线**（沿用本文门面），**跨端（GUI↔服务端）用 bridge(HTTP) 路由**。**当前实现仍为单体合并（同进程内存总线）**，上述分离为**演进方向**；消息面（主题/payload）不变。见 [40 T-24](../40-roadmap/40-演进计划.md)。

## 2. 门面接口（Go）

包：`chonkpilot-framework/host/src/core/mq`（**别名转发** → `chonkpilot-framework/plugin/src/runtime/bus`）。核心是两个方法 + 一个共享值 + 一个 promise：

```go
type Bus interface {
    Prefix() string
    Emit(ctx context.Context, subject string, payload any) *Future // 唯一发送入口
    On(subject string, order int, h VHandler) (Sub, error)         // 唯一订阅入口
    // v1 兼容（迁移期兼容面；生产/测试已全迁，暂保留，仅 v1 自身测试使用）
    Publish(subject string, payload []byte) error
    Subscribe(subject string, h Handler) (Sub, error)
    Close() error
}

type Value struct { Subject string; Payload []byte; Result any; Errors []error }
type VHandler func(ctx context.Context, subject string, v *Value) error
```

语义要点：

| 要点 | 说明 |
|------|------|
| **不 Await = 事件**；**Await = 请求-响应** | `Emit` 同步派发全部订阅者后 resolve；订阅者把结果写进 `v.Result`，发起方 `f.Wait()` 取回 |
| **errors 恒收集、不 reject** | handler 返回 error / panic → 追加 `v.Errors`，**不中断后续订阅者**；发送端自查 `v.Err()` |
| **order 升序** | `On(subject, order, h)`；同 order 按注册序（`(order, id)` 稳定排序） |
| **通配** | `*` 匹配单段、`>` 匹配剩余多段（NATS 约定，按 `.` 分段） |
| **payload** | `[]byte` / `string` 原样；其他类型 `json.Marshal` |
| **并发** | `sync.RWMutex` 保护订阅表；派发在锁外执行 |

> v1 `Publish/Subscribe` 为迁移期兼容（等价 `Emit` 不 await / `On(subject,0,包装)`），**不写回、order=0**。

## 3. 主题命名

### 3.1 前缀注入（业务不写 `chonk.`）

- 宿主在 `mq.New(Options{Prefix: "chonk."})` **注入一次**；业务一律写**相对主题**。
- 总线内部 `fullSubject` 补前缀用于注册/匹配；**下发给 handler 的 subject 统一去前缀**（相对形式）。
- 兼容保护：主题**已带**该前缀则原样透传、不重复加（遗留全主题调用方可继续工作）。

### 3.2 相对主题形态

| 形态 | 示例 | 分段 |
|------|------|------|
| 域-动作（kebab，单段） | `session-start`、`task-done`、`instance-register`、`data-prj-security-list` | 1 段 |
| 点分主题（多段，供通配） | `filesys.changed`、`mcp-tools-list`（域前缀 `mcp-`） | ≥2 段 |

- 全主题示例：`chonk.session-start`、`chonk.filesys.changed`。

### 3.3 主题空间归属

| 主题空间 | 交互方 | 承载 |

- **实现**：`chonkpilot-framework/plugin/src/runtime/topics`（`Registry`）；总线经 `mq.Options.Registry` 接入，未注入时行为与旧版完全一致。
- **启动预注册**：`appwire.Build` 以 `topics.BuiltinSpecs` 预注册 61 契约全集（243 条，登记键 = **实际总线相对主题**：schema `busTopic` 优先，如 `llm-start` → `session-start`、`llm-inbox-add` → `inbox-add`；scope 来自 schema `x-chonk`，优先级 `topics[topic] > 最长匹配 prefix > defaults`）。生成物：`runtime/topics/builtin_gen.go`（Go）与 `src/frontend/src/events/topic-specs.generated.js`（JS），由 `src/tools/genmsg` 生成。
- **注册载荷**：`{topic, scope, schema?}`。`scope` 必填（`global | workdir | instance | session | local`）；**不含** Kind / Direction / Owner（owner 仅为内部注册来源，插件销毁清理用）。
- **预置控制主题**（registry 内置，owner=`system`，scope=`global`，不可被普通 owner 覆盖/反注册）：`topic-register` / `topic-unregister` / `topic-seal` / `topic-registered` / `topic-unregistered` / `topic-register-error` / `topic-validation`。
- **订阅语义（不校验存在性）**：`On` / `Subscribe` 成功即把**相对主题** pattern 记入注册表；此时不校验 topic 是否存在。所有插件加载后由宿主/前端触发 `topic-seal`：精确 pattern 必须已注册，含 `*` / `>` 的 pattern 必须至少命中一个已注册主题；空 / 非法 pattern 报错。
- **发布语义**：未 seal → 一律放行（启动期）；sealed 且未注册 → `Emit` 收集错误并**不派发**、`Publish` 返回错误。
- **插件生命周期**：插件 manifest 可声明 `topics[]`（纯元数据，**不强制拦截** publish/subscribe）；hello 后以 owner=`plugin:<id>` 登记，插件停用/退出时按 owner 注销其 topic，**既有订阅保留**；重新启用/重新登记后投递恢复。`topic-unregistered` 供订阅者自行决定是否退订。
- **范围边界**：本阶段只做注册表与 scope/seal 校验，**不做通用授权 / 权限拦截**。

### 3.5 前端本地镜像注册表（阶段 3b，2026-11-19）

实现：`chonkpilot-framework/host/web/src/utils/mq.js`（挂在 `mq` 对象上，**不改** on/emit 既有语义，**不改**后端注册表）。

| API | 口径 |
|---|---|
| `installTopicSpecs(specs, { owner='builtin' })` | 批量登记内置 specs（主仓 `main.js` 装载 `TOPIC_SPECS` 243 条）；**不向后端发注册**；已存在跳过、不覆盖；非法条目 warn 跳过 |
| `installLocalEventTopics(eventNames)` | 前端本地事件（`EventNames` 的值，去重）以 `scope='local'`、`localOnly=true`、`owner='frontend'` 登记；已属 61 契约的 topic 不覆盖 |
| `registerTopic(topicOrSpec, opts)` | `registerTopic('x', {scope})` 或 `registerTopic({topic, scope, schema})`；scope 必填（string 形式缺省 `local`），仅允许 `global/workdir/instance/session/local`；topic 非空且不含 `*`/`>`；同 owner+scope 幂等 true，冲突 warn false；成功后非 local 以 **fire-and-forget** 发 `topic-register`（owner 由后端按 instance_id 派生） |
| `unregisterTopic(topic, opts)` | 只删本地条目并（非 local）fire-and-forget 发 `topic-unregister`；**订阅表不删除**（与后端一致，既有订阅保留）；builtin/system 拒绝 |
| `sealTopics()` | 置 sealed + `validateTopics()`；向 `topic-seal` 发一条（不 await，返回 Promise）；校验失败逐条 `console.error`；幂等 |
| `validateTopics()` | 精确 pattern 必须已登记；含 `*`/`>` 的 pattern 必须至少匹配一个已登记 topic；空/非法 pattern 报错；返回 `[{pattern, error}]` |
| `listTopics()` / `topicSpec(topic)` / `isTopicRegistered(topic)` | 查询本地登记表 |
| `resetTopicRegistry()` | 测试用：清空登记表 / 订阅 pattern 计数 / seal / 校验结果并重装控制主题；**不碰** on 回调 |

行为要点：

- **控制主题内置**：`topic-register` / `topic-unregister` / `topic-seal` / `topic-registered` / `topic-unregistered` / `topic-register-error` / `topic-validation` 在模块初始化时以 `scope='global'`、`owner='system'` 登记。
- **订阅追踪**：`pre/on/post/error/final` 实际新增回调时累加 pattern 计数，退订 / `clear(topic)` 递减；同一 callback 重复 `on` 只更新 order，不重复计数。
- **sealed 后发布**：未登记 topic 的 `emit` 返回 `{payload, results: [], backend: null, errors: ['[mq] topic 未注册（已 sealed）: …']}`，**不发后端、不本地派发**（每 topic 只 `console.error` 一次）；已登记 topic 走原逻辑。
- **后端事件不丢**：`emitRemote` 遇到未登记 type 只 `console.warn` 一次并照常 dispatch（后端已校验），`llm-receive.<type>` 动态子主题行为不变。
- **装配**：`main.js` 在 `installGlobalCkStore` 之后、`setupLayoutEngine` 之前装载 specs / local events；`App.vue#waitPluginsReady`（插件就绪或 20s 超时）触发一次 `mq.sealTopics()`，不阻塞 UI；插件 `host.mq` 暴露 `registerTopic/unregisterTopic/topicSpec/listTopics`。
- **边界**：本阶段仍**不做通用授权 / 权限拦截**；scope 仅为归属元数据，不参与授权 / 路由拦截。

## 4. 前端对称实现（`chonkpilot-framework/host/web/src/utils/mq.js`）

> 2026-11-04 核对：文件已随 framework 迁出主仓（原 `src/frontend/src/utils/mq.js` 不存在）；前端经 `@ckfw` 别名 import（`src/frontend/vite.config.js`）。

前后端**同一套 publish/on promise 语义**：

### 4.1 后端 → 前端（唯一入口）

Go 侧经 WebView2 `Eval` 直调 `window.mq.emitRemote(envelope)`，信封：

```json
{ "type": "<前端事件 type>", "payload": "<JSON 字符串>", "src": "mq|gui" }
```

- `emitRemote` 解析 payload（字符串 → JSON 对象）后按 `type` **本地 dispatch**（同 order 有序）；
- **只做本地分发，不回发后端（防环）**；
- 特殊：`llm-receive` 主主题分发后，再按 `payload.type` 二次分发子主题 `llm-receive.<type>`。

### 4.2 前端 → 后端（唯一发送）

```js
mq.emit(topic, payload)   // 本地按 order 分发 pre/on/post|error/final + fetch POST /publish
```

- HTTP 响应信封 `{ ok, result, errors }`（errors 收集、恒 accept，发送端自查）；
- `await mq.emit(...)` → `{ payload, results, backend }`（**收集**）；不 await → **事件**；
- 无 `request/RPC` 方法。

### 4.3 本地操作生命周期

`pre → on(main) → post | error → final`（本地请求-响应；`on` 支持 `order`）。Vue 指令：

```text
v-mq:[topic].[phase].[domEvent].[stop].[prevent].[once]="handler"
  · 订阅模式：v-mq:topic.on="fn"（挂载注册 / 卸载取消）
  · 触发模式：v-mq:topic.click="payload"（DOM 事件 → mq.emit(topic, payload)）
```

> 业务交互一律 `v-mq` / `mq.emit`；`@click` 仅限组件内部纯本地动作。

### 5.1 分发出口 = framework 分发器 + 主仓 Policy（策略外置）

> 依据：[49 §2.22.7](../40-roadmap/49-待实现项.md#1-引用迁移与历史索引2026-11-04)。**workdir / instance 路由属业务，不进 framework**。

| 层 | 组件 | 只做 | 不知道 |
|----|------|------|--------|
| framework | `runtime/dispatch`（`Dispatcher`） | 单订阅 `>` → 组装 `Event{Topic, Payload, Src}` → 问 `Policy.Deliver` → 按**注册序**逐个调 sink 的 `SendFunc`；sink 注册表 `RegisterSink/UnregisterSink/Sinks`；`Sink{ID, WorkDir, Kind, Instance}` 字段由注册方提供（`Instance` 为**可选**实例归属，framework 仅透传） | `data-*` / `filesys.*` 等主题家族、`instance_id` / `work_dir` 语义、前端 type 映射、compat 事件 |
| 主仓 | `mqpolicy.WorkDirPolicy`（`src/lib/gui/mqpolicy`） | ① 自发布丢弃（指纹口径）② `data-*` 的 persist 应答丢弃 ③ 载荷 `instance_id` 非空 → 只投该实例的 sink（窗口看 `Sink.ID`、插件看 `Sink.Instance`）④ **workdir 级主题 → 只投同 workdir 的 sink**（S2/S3）⑤ 其余 → 全投 | 总线实现、传输、前端 type |
| 主仓 | `gui/bridge` | 只**注册为 window sink**：`SendFunc` = 现有 `Eval window.mq.emitRemote` 链路（topic→type 映射、compat 事件、测试 waiter） | 过滤规则（已上移到策略） |
| 主仓 | `pluginhost/bridge` → **`chonkpilot-framework/plugin/src/bridge`** | 只**注册为 plugin sink**（每个插件会话一个，`plugin.hello` 后注册、会话关闭注销）：`SendFunc` = 会话内 `Subscription.Pattern/Filter` 过滤 → 帧下发 | 过滤规则（分配目标由策略决定） |

- **Hub 粒度 = 总线**（`mqpolicy.HubFor(bus)`）：同一进程多窗口共享**一个** `>` 订阅，窗口开关只做 sink 注册/注销（替代改造前「N 个窗口各订阅 `>` + 各自 JSON 解析」）。
- **Policy 未注入** → framework 用 `AllowAll()`（全投），保证 framework 可独立运行/测试。
- **S1 = 零行为变化**（等价性用例 `TestDeliverEquivalentToLegacy`）；**S2 = workdir 级主题只投同 workdir**；**S3 = 插件 sink 接入同一分发器**（见下「主题级别（唯一口径）」[49 §2.22.7](../40-roadmap/49-待实现项.md#1-引用迁移与历史索引2026-11-04)）。
- **插件 sink 与窗口 sink 同规则**（S3，2026-10-29）：插件桥不再自订阅 `>`；每个插件会话在 `plugin.hello` 后注册 `Sink{Kind: Plugin, WorkDir: 会话声明的 work_dir}`，**workdir 级事件由宿主强制隔离**（只投同 workdir），`instance` 级与 server 级同样按上表判定。插件 sink 的 `Instance` 默认**为空**（未标识 → 放行）：插件连接的 `instance_id` 属**插件命名空间**（`plugin:<id>:<hex>`），不参与窗口实例级判定；插件需按实例收窄时用订阅 `Filter.instance_id`。未注入分发器的宿主（L2 单测 / 无总线形态）仍走桥自有 `>` + `fanout` 兜底，行为与改造前一致。

#### 主题级别（三档 + 显式清单，**唯一维护口径**）

判定顺序（`WorkDirPolicy.Deliver`，短路语义自上而下）：

1. `data-*` 的 persist **应答**（`{req_id, ok, result|error}` 信封）→ **整条丢弃**；
2. sink 级**自发布**回环（发布方实例 id + 主题 + 载荷指纹，1s 窗口）→ 该 sink 吞掉；
3. **instance 级**（载荷 `instance_id` 非空）→ 只投**该实例的 sink**（窗口看 `Sink.ID`、插件看
   `Sink.Instance`；sink 未标识 → 放行）；
4. **workdir 级**（下表 `workDirTopics`，**事件 workdir 已知**时）→ 只投**同 workdir** 的 sink
   （窗口与插件同规则；事件 workdir 取值顺序：载荷 `work_dir` → 否则按 `instance_id` 反查 framework
   `instance.Manager` 视图；两者都拿不到 = **未知 → 保守全投**并记 Debug；sink 侧 workdir 未知 → 放行）；
5. 其余（**server 级**）→ 全投。

收紧**只会缩小**投递集合：instance 级仍按精确相等，workdir 判定不会放大回去。

**level = workdir 级（`workDirTopics`，显式清单，不靠前缀猜；唯一实现在 `src/lib/workspace/router.go`，`src/lib/gui/mqpolicy/topics.go` 仅为只读别名）**

| 主题 | 为什么是 workdir 级 |
|------|--------------------|
| `filesys.changed` · `filesys.watch-error` | 61 §2.4：载荷带 `work_dir`，语义 = **某工作目录内**的文件变化；dirWatcher **无 watch 声明者**时**不带 `instance_id`** 直接广播（`src/lib/filesys/watcher.go` 的 `emit`）→ 必须由 workdir 把关 |
| `data-prj-config-refresh` · `data-prj-security-refresh` · `data-prompt-refresh` · `data-mcp-refresh` · `data-scenario-refresh` · `data-memory-refresh` | 61 §3.1：「保存后变更广播」，落点 = **项目（work_dir）级**或「项目优先」四级合并；当前 persist 带 `instance_id` 逐实例下发（prj-config 按 `InstancesByWorkDir` 扇出），列入清单是**兜底**（将来漏带 `instance_id` 仍按 workdir 收口） |

**level = server 级（显式列白，不得收紧）**

| 主题 | 为什么必须跨窗 |
|------|--------------|
| `data-user-config-changed` | 61 §3.1：**不带 `instance_id`** 的 usr 配置下行广播 → 全局；用途 = 多窗口 theme / locale **即时同步**（24 §6.5 · WIN-021；真机用例 `run_mw.py` MW-T27） |
| `data-session-title-changed` | 61 §3.2：**不带 `instance_id`** 的会话标题下行广播 → 全局；用途 = 主窗改标题 → 已开对话窗口标题跟随（MW-T29） |
| `data-user-config-refresh` · `config-refresh` | usr 级（**跨项目**）配置刷新，按实例下发；不做 workdir 收口，避免「同一用户其它项目窗口」漏刷新 |

其余主题（`session-*` / `task-*` / `mcp-*` / `subchat-*` / `instance-*` / `plugin-*` 等）**未列入**上两表 = server 级，全投（其中带 `instance_id` 的由第 3 条精确投递）。

> 维护约定：新增/改名 `filesys.*` 或 `data-*` 变更（非应答）主题时，必须在上表**显式登记**级别；增删本表须同步 **`src/lib/workspace/router.go`**（`mqpolicy/topics.go` 为只读别名；单测 `TestWorkDirTopicTable` / `TestServerTopicWhitelistNotNarrowed` 覆盖）。**消息面零变更**：路由用的 `work_dir` / `instance_id` 均为 61 既有字段。（2026-11-04 核对）

## 6. 设计约束与边界

1. **`instance_id` 由信封/前端 mq 统一注入**（跨端信封与不可变元数据必带；`instance-register` 事件自身带；**不是每个 payload 字段都显式携带**）——多实例/多项目隔离的依据。（2026-11-04 核对）
2. **跨端 payload 为 JSON 字符串**（信封约定），接收端自行解析。
3. **无 `/call` RPC、无 `/events`、无 `req_id`（v2）**：请求-响应靠 promise 结果写回，回执 = 同一次派发的 `v.Result`。
4. **errors 恒 accept**：不因订阅者报错而 reject；发送端必须自查。
5. **订阅方可多答**（一疑问多答）：多个订阅者各自写回 `Result`，前端 `results` 为数组。
6. **消息冻结**：主题/payload 的增删改须用户确认（见 [50-测试体系 §1](../50-testing/50-测试体系.md)）。
