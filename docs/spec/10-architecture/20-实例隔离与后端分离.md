## 1. 隔离边界

desktop 单进程内同时运行多个窗口实例（多项目主窗口 + 多对话/群聊窗口），因此各层状态**必须能按实例或项目区分**，否则会出现跨窗口串扰（取消他人任务、看到他人事件、临时目录互相覆盖等）。

**三类键，用途不同**

| 键 | 作用域 | 用途 |
|----|--------|------|
| `instance_id` | **窗口实例** | 执行池分桶、运行态（回合/占用/待答）分桶、事件归属过滤、临时根分桶 |
| `work_dir` | **项目** | 数据根（prj / prjusr）、filesys 基目录、任务树与任务管理单位 |
| `session_id` / `top_session` | **会话** | 任务树视图切分（同一 workdir 下多实例同域，视图按主会话切分） |

**管理单位分工**

| 层 | 管理单位 |
|----|---------|
| data / filesys / taskManager | **`work_dir`** |
| llm 运行态 / gateway 执行池 / gui 桥 | **`instance_id`** |

> 契约前提：业务 payload 一律带 `instance_id`（[61 §0](../60-reference/61-消息一览.md)）；前端 → 后端的 `instance_id` 由各窗口的桥自动注入。

## 2. 每实例状态清单

### 2.1 生命周期与绑定

| 项 | 事实 |
|----|------|
| 注册 | 窗口桥 `Start()` 发 `instance-register{instance_id, work_dir, data_dir, user, parent_instance?, session_id?}` |
| 数据面绑定 | `persist` 订阅 `instance-register/-exit` 维护 `instance_id → {work_dir, data_dir}`，据此解析 prj / prjusr 库 |
| 文件面绑定 | `filesys` 自持同一实例视图；**基目录只取登记值**（不采信请求 payload 的 `work_dir`），越界路径由 `withinWorkDirReal`（词法 + 真实路径）拒绝 |
| 注销 | 窗口关闭发 `instance-exit` → 释放该实例的库连接与登记（日志窗口不注册） |

### 2.2 llm 运行态

| 状态 | 隔离键 | 规则 |
|------|--------|------|
| `turns` / `busy` / `continuePending` / `asks` | `instKey(instance_id, id)` = `<instance>\x00<id>` | instance 空 → 原键（旧语义）；同 session 的活动回合互斥按 `(instance, session)` 判定 |
| 任务树节点 `InstanceID` | 归属过滤 | 查找 / 取消 / 重试 / 子树遍历一律校验节点归属；instance 空 = 旧语义等价 |
| 记忆指引 / 能力节点缓存 | `instance_id` | 按实例分桶（多实例/多工作区不串味） |

### 2.3 gateway 执行池

- 执行池按 `instance_id` 分桶：`map[instance_id]map[task_id]*Task`；容量上限为**每实例**上限；定位 / 取消 / 等待 / 异步上报全部带实例归属。
- 下游连接池键 = `(instance_id, work_dir)`：同 workdir 的不同实例不共享下游子进程/会话，取消走**作用域作废**（不误伤他实例）。
- 控制面方法（`CancelExec` / `DetachExec`）为**进程内接口**，带 instance 参数（非 MQ 面）。

### 2.4 临时根

- `paths` 的 `!/` 临时根按实例分桶：`TempRootFor(instance_id)` / `ResolvePathFor(instance_id, …)`。
- 任务脚本与工具环境按实例取根，**不再写进程级「当前根」**（避免多实例互相覆盖）。

### 2.5 实例额度

- 实例视图有数量上限；`instance-claim` / 登记超限 → **明确失败**（`instance-forbidden`），不静默成功。
- 窗口层面另有分类额度（普通对话窗口 / 群聊窗口），由窗口注册表在**占位时**判定，避免并发越限。

### 2.6 事件与前端

| 环节 | 规则 |
|------|------|
| 桥下行 | `forwardEvent` 先按载荷 `instance_id` 过滤：非空且 ≠ 本窗口实例 → **丢弃**；无归属 / 本实例未标识 → 放行（单实例逐字节等价） |
| 前端二次防线 | `utils/instanceScope.js` 的 `eventBelongsToInstance` 用于 `tasks.*` / `llm-complete` 等入口，判据与桥一致 |
| 任务树视图 | 视图按 `top_session` 切分，`instance_id` 仅作来源标注（任务侧不以 instance 为隔离键） |

## 3. 共享与例外（设计如此，非缺陷）

| 项 | 说明 |
|----|------|
| usr 级数据 | `usr` 库与 `user-config` 等全局域跨项目共享（本机单用户）。 |
| self 能力源 / usr mcps | 全局能力面**有意**共享（scope = global），不按实例复制。 |
| 任务树同域 | 同一 `work_dir` 下多实例的任务同属一棵树，**按主会话切分视图**，不按 instance 切树。 |

## 4. 无 `instance_id` 消息的入站校验

> 依据：`61 §0` 硬规则（业务 payload 一律带 `instance_id`，由桥自动注入；唯一豁免 `server-starting`）。本节约束的是**旁路发送方**（插件 / 脚本 / 内部直发）可能缺字段的情况。

**data 面入站校验**：`persist.handle` 按主题域白名单校验 —— 白名单内允许无 `instance_id`；**白名单外缺 `instance_id` → 明确失败**（`{ok:false, error: 缺 instance_id}`），不再静默走「唯一实例回退」。

| 主题（家族） | 需 `instance_id` | 说明 |
|------|:---:|------|
| `user-config`（list/load/save/delete） | 否 | usr 全局域 |
| `scenario` / `mcp` / `knowledge` | 否 | 四级根域；缺实例 = 仅 app + user 级（宽松语义） |
| `prj-config` / `prj-security` / `prompt` | **是** | 项目严格作用域（经实例绑定解析 prj 库） |
| `memory` / `snapshot` | **是** | 落 prjusr / prj |
| `session-*`（含 turn / message / context） | **是** | 会话数据层 = prjusr |
| `tasktree-*`（list/tasks/delete） | **是** | 任务树落 prjusr |
| `filesys.*` | 否（按 `work_dir` 定位） | 基目录取实例登记值；点分主题经桥幂等注入 instance |
| `gui.*`（宿主本地面） | 否 | 执行对象 = 调用来源窗口（每窗口一桥） |
| `task-started/updated/done` | 否（按 `work_dir`） | instance 仅来源标注 |
| `server-starting` | 否 | 服务器级就绪广播 |

**相关守卫**

- `data.Register` 拒绝空 `instance_id` 登记（防空键被静默解析到某个数据根）。
- 容错探测走 `ResolveQuiet`（不刷「未带 instance_id」告警）；严格路径仍用告警版 `Resolve`，让遗漏显式暴露。

## 5. 兼容与失败语义

- **实例为空 → 旧行为逐字节等价**：执行池空键桶、`instKey` 原键、归属过滤恒真、作用域作废回落全量。
- **消息面零增删**：instance 维度早已在 `Context` / payload 中承载；隔离改造不新增主题或字段。
- **失败只告警**：作用域作废失败 / no-op 仅记 warn；实例超限与对外方法面错误返回**明确错误**。
- **不改 data / filesys 语义**：二者和任务层仍以 `work_dir` 为管理单位；安全责任 = 「实例绑定 `work_dir`」+「gateway 进程级 Low IL 写隔离（仅 stdio 下游）」+「路径 R-11 强校验」（[14](14-安全域-agentbox.md)）。
