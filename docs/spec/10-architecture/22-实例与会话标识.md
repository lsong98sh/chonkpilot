# 22 · 实例与会话标识

> **〔实例口径 · 2026-11-04 核对〕** `instance-claim` 语义 = 「**项目主窗口启动 → `work_dir` 提议 → 任意非空提议即绑定（提议优先；空则回落入口/实例绑定）**；**提议与绑定皆空 → `instance-forbidden`**」；**无验签 / 无令牌校验**（全仓无签名 / HMAC；`RequireAuth()` 恒 false，仅保留入口进程内绑定 + `__local` 布尔信任标记）。`instance-heartbeat` 在唯一形态 desktop 下**不发布**（gating 恒 false，主题/判定侧保留）；`instance-goto-top` **当前无消费方**（主题保留，框架已有 `bringMainToTop` helper 但未接线，待 registry / H5 接入）。`form` / `client_type` **产品唯一取值 = `desktop`**（代码仍保留 gui/browser 历史分支）。**无本地认证**（将来由 registry 承担）。**`instance-unauthorized` 已随本地认证面删除，代码不产出该错误码**。详见 [61 §0](../60-reference/61-消息一览.md)。

> **定位**：定义 `instance` 的**认领、承载、续期、失效与作用域**，并确立「**作用域与身份标识一律由服务端绑定（当前无验签实现）**」总原则。

## 1. 总原则：客户端不自称

> **凡客户端可自称的标识（`instance_id` / `work_dir` / `user` / 形态），都不得作为作用域或身份依据。**
> payload 中这些字段的语义 = **「自述 / 提议」**；服务端**以连接层（入口绑定 / 凭证）为准并校验**。

四处同类问题：

| 场景 | 表现 | 归属 |
|------|------|------|
| filesys 请求 | 采信 payload 的 `work_dir` → 可声明任意目录（真越权） | G-21 ✅ 已实施 |
| 多实例 | `instance_id` 客户端可自称（单实例无害，多实例可跨实例越权） | 本条 |
| claim payload | `user` 由客户端携带（desktop 可省略，服务端回落 OS 用户名） | G-28 ✅ 已闭 |
| 形态判定 | **UA 客户端可伪造** → 不可作鉴权依据，**仅可作日志诊断** | 本条 |

**统一链路**：

```text
连接层（入口绑定）→ 服务端解析 → 内存实例表
   → instance（已校验上下文句柄）→ 注入各层
```

> **〔2026-11-04 核对〕「校验」的现状**：只有**入口进程内绑定**（桥 / 前门注入 `instance_id`）与 `__local` 布尔信任标记；**没有签名 / HMAC / 令牌校验**。`work_dir` 在 desktop / local 分支是「提议优先、非空即绑定」，**不校验归属**（见 §3.1）。

## 2. 术语与硬规则

| 术语 | 定义 |
|------|------|
| **token** | 当前**不存在**本地认证，无 token / cookie 签发（将来由 registry 承担） |
| **instance** | **已校验的上下文句柄** = `{instance_id, work_dir, data_dir}` 的绑定；**不是**「服务端进程」 |
| **instance-id** | instance 的标识；**由服务端绑定 / 生成**（客户端自述者不采信）。对前端**可见**（`window.__ck.instanceId` + payload `instance_id`），但**不构成凭据** |
| **client_type** | 客户端形态 = `desktop`（**产品唯一取值**）；代码仍保留 `gui` / `browser` 历史分支（`Form()`），但构建产物只有 desktop |

**硬规则**

1. **客户端不自称**（§1）：身份与作用域由入口绑定后注入；前端不携带、不判定。
2. **`work_dir` 由服务端在 claim 时确定** → 绑定 `instance → work_dir`，后续各层按 instance 查绑定、**忽略 payload**。**〔2026-11-04 核对〕当前 desktop / local 分支不校验提议归属**：非空提议优先（`claim_test.go::TestInstanceClaimWorkDirProposalWins`），空则回落入口/实例绑定；只有「提议与绑定皆空」才 `forbidden`。这是 PRODSIM-1 多项目主窗口的有意口径，**不是**「命中登记才绑定」。
3. **形态不由 UA 判定**：`window.__ck.form` 恒为 `desktop`。

## 3. 实例生命周期

### 3.1 认领：`instance-claim`（请求-响应）

项目主窗口启动即发起（无登录、本机单用户）。

| 形态 | 请求 payload | 服务端取值 |
|------|------|------|
| **desktop / 本地前门** | `{work_dir}`（`work_dir` = 客户端提议；`user` 可省略） | **提议非空 → 直接采用（提议优先）**；提议空 → 回落**实例已绑定 `work_dir`**；两者皆空 → `instance-forbidden`；本机单用户、**免鉴权**（`claim.go` 的 `resolveClaimTarget`） |
| 其他形态 | — | 当前不存在实际形态；代码对非 desktop / local 一律返回 `instance-forbidden` |

### 3.2 服务端行为（claim 成功后）

1. 生成 / 绑定 `instance_id`（见下）
2. 写**服务端内存实例表**：`{instance_id, work_dir, data_dir, user, lastBeat, client_type}` —— **进程重启即清**
3. **广播既有 `instance-register`**（主题不变；payload = `{instance_id, work_dir, data_dir?, user, client_type?}`），供 `src/lib/data` / `src/lib/filesys`（经工作区管理 `workspace.Manager`）登记 `instance → work_dir`（G-21 依赖它）
4. 应答**发起者** `{instance_id, work_dir, data_dir}`

> **〔2026-11-04 核对〕payload 已非「一字不改」**：为满足 61 §4.1 ⑤，`user` 为**必填**（客户端提议为空时回落本机 OS 用户名）；`client_type` 由实例既有登记回填。原「主题与 payload 一字不改」的表述仅对**主题**成立。

> **入口绑定**：入口（GUI 桥）**已在启动时自生成并注入 `instance_id`**（供 `/show` URL 等**首屏前**即需使用）。claim 采「**入口绑定优先、缺省服务端生成 uuid v4**」，避免同进程出现**双 id 源**。

### 3.3 心跳与回收

- **发布方 = 客户端**：前端 SPA（claim 成功后起定时器）。唯一形态 `desktop` 下**不发布**。
- 周期 **30s**，payload `{instance_id}`；**语义 = 客户端续期**（「该实例仍在使用」），**非**「服务端存活证明」。
- 服务端 **90s** 未收 → **回收该实例 + 数据根绑定**（仅分离形态判定；desktop 不判超时），sweep **补发 `instance-exit`**。**〔2026-11-04 核对〕回收后不产出 `instance-unauthorized`**（该错误码随本地认证面删除）；旧 id 在内存表查不到时，后续 claim 按「提议 / 实例绑定 / 两者皆空 → forbidden」收敛。
- **`instance-heartbeat` 在唯一形态 desktop 下不发布、不判超时**（gating 恒 false）：主题与判定侧保留，实例失效由显式 `instance-exit` 收口。见 [28-plugins §2](../20-modules/28-plugins.md)。

### 3.4 错误码（复用既有 `{ok, error}` 信封，**不新增字段**）

| 码 | 触发 | 前端动作 |
|------|------|------|
| `instance-unauthorized` | 🗄 **历史错误码，当前不产生**（本地认证面已整体删除，`claim.go` 只定义 `claimErrForbidden`） | 前端仍保留占位提示分支（兼容读数） |
| `instance-forbidden` | **提议与实例绑定皆空**（desktop / local），或非 desktop / local 形态；实例数超上限的登记失败也复用此码 | 提示换目录（**不跳登录**） |

## 4. 失效与重建

```text
服务端重启 → 内存实例表清空 → 客户端旧 `instance_id` 查不到记录
  ├─ 携非空 work_dir 提议（desktop/local）→ 直接绑定该提议，claim 成功
  └─ 无提议且无实例绑定 → instance-forbidden（不是 instance-unauthorized）
```

> **〔2026-11-04 核对〕** 原文「无法解析 → `instance-unauthorized`」与代码相反：`claim.go` 对未登记 id 只做 `Lookup`（空记录），随后按提议 / 绑定 / forbidden 收敛；代码中**无 `instance-unauthorized` 产出方**（全仓仅注释 / 前端兼容读数 / 测试夹具）。
> ⚠️ **历史约束（不再触发）**：「未认证」曾要求走消息面错误码（不能是 HTTP 401）——GUI 走 MQ。现无本地认证，故无该错误路径。

## 5. 承载：前端零身份逻辑

| 形态 | 凭据 / 令牌承载 | 前端是否读 |
|------|-----------|:---:|
| desktop | **桥在转发时注入**（进程内） | ❌ 不读 |

**前端零身份逻辑**

- 前端**不参与身份判定**；**但持有 `instance_id`**（`window.__ck.instanceId` 与服务端注入的 payload 字段），仅用于消息面携带
- 页面所需元信息（形态）由**入口注入**（同现有 `injectBootstrap`）
- 服务端在**入口处**注入 `{instance_id, user, work_dir, data_dir}` 给后续各层
- **下行事件按「连接」过滤**，不依赖 payload

**兼容口径（61 零变更）**：payload 中的 `instance_id` **保留但语义降级**为「请求方自述、服务端不采信，**以入口绑定为准**」。

## 6. 认证（无本地认证）

> **当前无本地认证域**：本机单用户、免鉴权。认证将来统一由 **registry（注册服务器）** 承担（H5 APP / 外部 WebView 壳接入时再落地），不在本篇实施。
> **首屏注入**：`window.__ck = {form, requireAuth, authed, instanceId}`；`form` 产品恒 `desktop`、`requireAuth` 恒 `false`、`authed` 恒 `true`；**不使用 UA 判形态**（§1）。
> **〔2026-11-04 核对〕无「验签」实现**：全仓无签名 / HMAC / 令牌校验；`RequireAuth()` 恒 false，信任来源仅 = **入口进程内注入 `instance_id`** + `__local` 布尔标记（`claim.go` 的 `claimReq.Local`）。代码仍保留 `FormGui` / `FormBrowser` 分支与前端 `FORMS` 三态，但**构建产物只有 desktop**（`build-desktop.ps1` 仅 `debugport` tag）。

## 7. 与 `filesys` 的关系（G-21 根治点）

三层现状（**已实施**）：

| 层 | 现状 |
|------|------|
| GUI 桥（desktop） | ✅ 统一注入 `instance_id`（`injectInstance`）；`work_dir` **无需覆盖**（组件层已按绑定解析） |
| **filesys 组件** | ✅ **根治**：**不自持** `instance_id → work_dir`；订阅工作区生命周期 `workdir-opened` / `workdir-closed`，解析经工作区管理 `workspace.Manager.Resolve(instanceID)`；**忽略 payload 的 `work_dir`**（未登记 / 未绑定 → `forbidden`，**不回落载荷**；`src/lib/filesys/filesys.go`） |

- **未订阅 `instance-register` / `instance-exit` / `instance-heartbeat`**：filesys 不再自行维护实例表；`instance → work_dir` 唯一来源 = `workspace.Manager`（PM）。绑定生命周期由 `workdir-open/close` 驱动。
- **〔2026-11-04 核对〕** 原文「订阅 `instance-register` / `instance-exit`、自持 `instance_id → work_dir`」已过时；现订阅清单 = `filesys.*` + `workdir-opened/closed` + `data-prj-config-refresh`（见 `filesys.Start`）。
- `allowedDirs()`（原经非 MQ 路由 `/dirs` 暴露，**该路由已删 2026-10-10**；主仓 grep 已无该符号）= 「服务端限定作用域、客户端不得自报路径」的**历史参考实现**；现前端经 `gui.show-dialog.options` 消费（`useGuiShowDialog`），生产方不在本仓。
- **关联缺口 [G-29]**：~~sweep 超时回收时不补发 `instance-exit`~~ → **✅ 已修**：llm 与 persist 的 sweep 回收时**补发 `instance-exit`**（主题与 payload 不变）→ 其它订阅方解绑；**filesys 现由 `workdir-closed` 释放监听**，不再依赖 `instance-exit`。
