# 22 · 实例与会话标识

> **〔实例口径〕** `instance-claim` 语义 = 「**项目主窗口启动 → `work_dir` 提议 → 命中实例登记即绑定 / 否则 `instance-forbidden`**」；`instance-heartbeat` 在唯一形态 desktop 下**不发布**（gating 恒 false，主题/判定侧保留）；`instance-goto-top` **当前无消费方**（主题保留，待 registry / H5 接入）。`form` / `client_type` 唯一取值 = `desktop`；**无本地认证**（将来由 registry 承担）。详见 [61 §0](../60-reference/61-消息一览.md)。

> **定位**：定义 `instance` 的**认领、承载、续期、失效与作用域**，并确立「**作用域与身份标识一律由服务端绑定或验签**」总原则。

## 1. 总原则：客户端不自称

> **凡客户端可自称的标识（`instance_id` / `work_dir` / `user` / 形态），都不得作为作用域或身份依据。**
> payload 中这些字段的语义 = **「自述 / 提议」**；服务端**以连接层（入口绑定 / 凭证）为准并校验**。

四处同类问题：

| 场景 | 表现 | 归属 |
|------|------|------|
| filesys 请求 | 采信 payload 的 `work_dir` → 可声明任意目录（真越权） | G-21 ✅ 已实施 |
| 多实例 | `instance_id` 客户端可自称（单实例无害，多实例可跨实例越权） | 本条 |
| claim payload | `user` 由客户端携带（当前 `desktop` 省略该参数） | G-28 |
| 形态判定 | **UA 客户端可伪造** → 不可作鉴权依据，**仅可作日志诊断** | 本条 |

**统一链路**：

```text
连接层（入口绑定）→ 服务端解析 → 内存实例表
   → instance（已校验上下文句柄）→ 注入各层
```

## 2. 术语与硬规则

| 术语 | 定义 |
|------|------|
| **token** | 当前**不存在**本地认证，无 token / cookie 签发（将来由 registry 承担） |
| **instance** | **已校验的上下文句柄** = `{instance_id, work_dir, data_dir}` 的绑定；**不是**「服务端进程」 |
| **instance-id** | instance 的标识；**由服务端绑定 / 生成**（客户端自述者不采信）。对前端**可见**（`window.__ck.instanceId` + payload `instance_id`），但**不构成凭据** |
| **client_type** | 客户端形态 = `desktop`（**唯一取值**），由服务端按入口判定（非客户端自报、非 UA） |

**硬规则**

1. **客户端不自称**（§1）：身份与作用域由入口绑定后注入；前端不携带、不判定。
2. **`work_dir` 必须服务端校验归属** → 校验通过后绑定 `instance → work_dir`，后续各层按 instance 查绑定、**忽略 payload**。
3. **形态不由 UA 判定**：`window.__ck.form` 恒为 `desktop`。

## 3. 实例生命周期

### 3.1 认领：`instance-claim`（请求-响应）

项目主窗口启动即发起（无登录、本机单用户）。

| 形态 | 请求 payload | 服务端取值 |
|------|------|------|
| **desktop** | `{work_dir}`（`work_dir` = 客户端提议；`user` 省略） | `work_dir` 命中实例登记 → 绑定；否则 `instance-forbidden`；本机单用户、**免鉴权** |

### 3.2 服务端行为（claim 成功后）

1. 生成 / 绑定 `instance_id`（见下）
2. 写**服务端内存实例表**：`{instance_id, work_dir, data_dir, lastBeat, client_type}` —— **进程重启即清**
3. **广播既有 `instance-register`**（主题与 payload **一字不改**：`{instance_id, work_dir, data_dir?, client_type?}`），供 `src/lib/data` / `src/lib/filesys` 登记 `instance → work_dir`（G-21 依赖它）
4. 应答**发起者** `{instance_id, work_dir, data_dir}`

> **入口绑定**：入口（GUI 桥）**已在启动时自生成并注入 `instance_id`**（供 `/show` URL 等**首屏前**即需使用）。claim 采「**入口绑定优先、缺省服务端生成 uuid v4**」，避免同进程出现**双 id 源**。

### 3.3 心跳与回收

- **发布方 = 客户端**：前端 SPA（claim 成功后起定时器）。唯一形态 `desktop` 下**不发布**。
- 周期 **30s**，payload `{instance_id}`；**语义 = 客户端续期**（「该实例仍在使用」），**非**「服务端存活证明」。
- 服务端 **90s** 未收 → **回收该实例 + 数据根绑定** → 后续请求 `instance-unauthorized`。
- **`instance-heartbeat` 在唯一形态 desktop 下不发布、不判超时**（gating 恒 false）：主题与判定侧保留，实例失效由显式 `instance-exit` 收口。见 [28-plugins §2](../20-modules/28-plugins.md)。

### 3.4 错误码（复用既有 `{ok, error}` 信封，**不新增字段**）

| 码 | 触发 | 前端动作 |
|------|------|------|
| `instance-unauthorized` | 未登录 / 令牌失效 / 90s 未续期被回收（当前不产生） | 显示明确占位提示 |
| `instance-forbidden` | 该 `work_dir` 未被实例登记 | 提示换目录 |

## 4. 失效与重建

```text
服务端重启 → 内存实例表清空 → 客户端旧 `instance_id` → 无法解析 → instance-unauthorized
  └─ desktop → 项目主窗口重新 claim（`work_dir` 提议）
```

> ⚠️ **「未认证」必须是消息面错误码**（如 `{ok:false, error:"instance-unauthorized"}`），**不能是 HTTP 401** —— GUI 走 MQ，没有 HTTP 状态码。

## 5. 承载：前端零身份逻辑

| 形态 | 凭据 / 令牌承载 | 前端是否读 |
|------|-----------|:---:|
| desktop | **桥在转发时注入**（进程内） | ❌ 不读 |

**前端零身份逻辑**

- 前端**不参与身份判定**；**但持有 `instance_id`**（`window.__ck.instanceId` 与服务端注入的 payload 字段），仅用于消息面携带
- 页面所需元信息（形态）由**入口注入**（同现有 `injectBootstrap`）
- 服务端在**入口处**注入 `{instance_id, user, work_dir, data_dir}` 给后续各层
- **下行事件按「连接」过滤**，不依赖 payload

**兼容口径（61 零变更）**：payload 中的 `instance_id` **保留但语义降级**为「请求方自述、服务端不采信，**以入口绑定为准**」。

## 6. 认证（无本地认证）

> **当前无本地认证域**：本机单用户、免鉴权。认证将来统一由 **registry（注册服务器）** 承担（H5 APP / 外部 WebView 壳接入时再落地），不在本篇实施。
> **首屏注入**：`window.__ck = {form, requireAuth, authed, instanceId}`；`form` 恒 `desktop`、`requireAuth` 恒 `false`、`authed` 恒 `true`；**不使用 UA 判形态**（§1）。

## 7. 与 `filesys` 的关系（G-21 根治点）

三层现状（**已实施**）：

| 层 | 现状 |
|------|------|
| GUI 桥（desktop） | ✅ 统一注入 `instance_id`（`injectInstance`）；`work_dir` **无需覆盖**（组件层已按绑定解析） |
| **filesys 组件** | ✅ **根治**：订阅 `instance-register` / `instance-exit`，自持 `instance_id → work_dir`，**忽略 payload 的 `work_dir`**（未登记 / 未绑定 → `forbidden`，**不回落载荷**） |

- **未订阅 `instance-heartbeat`**：filesys 与发布方恒**同进程同总线**，绑定生命周期 = 进程生命周期 → 心跳在 filesys 侧**无消费方**（与 persist 的一处有意差异）。
- `allowedDirs()`（原经非 MQ 路由 `/dirs` 暴露，**该路由已删 2026-10-10**；现经 `gui.show-dialog.options` 下发）= 「服务端限定作用域、客户端不得自报路径」的**参考实现**。
- **关联缺口 [G-29]**：~~sweep 超时回收时不补发 `instance-exit`~~ → **✅ 已修**：llm 与 persist 的 sweep 回收时**补发 `instance-exit`**（主题与 payload 不变）→ filesys 等订阅方解绑。见 G-29。
