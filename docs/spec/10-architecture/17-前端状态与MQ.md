# 17 · 前端状态管理与 MQ

> 日期：2026-08-26（2026-09-11 移入 spec）｜ 状态：🔵 草案（**规范为现行强制**：禁止 `watch`/`watchEffect`，用 `useXxx` composable，见 [20-gui §12](../20-modules/20-gui.md)）
> 关联：[11-MQ与消息](11-MQ与消息.md)（MQ 机制）· [20-gui](../20-modules/20-gui.md)（前端落点）· [2C-UI插件](../20-modules/2C-UI插件.md)（插件 UI 用此模式）· [61-消息一览](../60-reference/61-消息一览.md)（主题/payload 准则）
>
> **通用前端状态管理模式（与插件无关）**：适用于整个前端——主应用组件与插件 UI 一致。核心：**MQ 事件链 + 响应式 state，无 watch、无 computed**。

---

## 1. 模型

```text
MQ 事件 ──写入──▶ state（响应式 ref/reactive，唯一真相源） ──绑定──▶ 渲染
                   ▲
   域级共享状态：事件处理器写入；域内局部状态：域模块 setter 写入
```

**状态流转 = 事件链**：每步是一个事件处理器（异步拉数据 → 写 state → 发下一消息）。所有变更显式可见，消息链即状态机。

## 2. 核心原则

| 原则 | 说明 |
|------|------|
| 想改变状态 = 发 MQ 事件 | UI/组件不直接写 state（域级共享状态），意图经消息表达 |
| 状态有明确写入点 | 域级共享状态只经事件处理器；域内局部状态只经域模块导出的 setter——均不散落在组件内部 |
| 异步只在处理器里 | `mq.call` 的结果写回 state，不进 computed、不在模板 |
| ref/reactive 本身响应式 | 模板绑定 state 自动更新，无需 computed 派生 |
| 消息即日志 | 每个状态转换由一条消息显式触发，全链路可追踪 |

## 3. 无 watch、无 computed

| 该去掉的 | 原因 | 替代 |
|---------|------|------|
| watch / watchEffect | 监听变化再执行副作用：隐式依赖、命令式、难追踪 | 变化由消息主动写入 state |
| computed 派生 | 隐式重算，调试不透明；ref 已够响应式 | 普通函数（每次渲染重算，量小无开销）；状态显式逐级写入 |

> computed getter 内本就**不可写 state、不可发 MQ/异步**（纯函数约束）——与其受约束，不如直接不用，状态流转全走显式事件链。

## 4. 级联消息链（标准示例）

状态流转 = **事件链**：每步处理器「异步拉数据 → 写 state → 发下一消息」（伪代码中 `state` 指当前域模块的响应式单例，写 `state.x` 或 `state.value.x` 等价）：

```js
// ① session-changed → 拉 tasklist → 发 tasklist-changed
mq.on("session-changed", async ({ session }) => {
  state.session = session
  state.tasklist = await mq.call("GetTasks", [session.id])   // 异步拉数据 → 写 state
  mq.emit("tasklist-changed", {})                            // 显式发下一步
})
// ② tasklist-changed → 默认选中第一条 → 发 activetask-changed
mq.on("tasklist-changed", () => {
  state.activeTask = state.tasklist[0] ?? null               // 默认选中第一条
  mq.emit("activetask-changed", { task: state.activeTask })
})
// ③ activetask-changed → 拉详情 → 写 state（链终点）
mq.on("activetask-changed", async ({ task }) => {
  if (!task) return
  state.activeTask = task
  state.taskDetail = await mq.call("GetTaskDetail", [task.id])
})
// 用户手动点选：复用同一条链（发 activetask-changed）
function onSelectTask(task) { mq.emit("activetask-changed", { task }) }
```

```vue
<!-- template：直接绑定 state -->
<TaskList :items="state.tasklist" @select="onSelectTask" />
<TaskDetail :data="state.taskDetail" />
```

## 5. 可重用性（链上每步可重入）

```text
activetask-changed ←──────────┐
  ├─ tasklist-changed 触发      │（自动选中第一条）
  ├─ 用户点选 onSelectTask ─────┘（同一消息）
  └─ 其他域/插件/外部事件也可复用  （外部切任务）
```

- **单一通道**：`activetask-changed` 是唯一入口，自动/用户/外部走同一条处理逻辑，零重复代码
- **可重入**：任何来源发该消息，处理结果一致（状态机语义）
- **扩展性**：新入口（其他面板/插件）直接发同一消息，无需新增路径

## 6. 约定

| 项 | 约定 |
|----|------|
| 消息命名 | kebab-case（`-` 分隔），如 `session-changed` / `tasklist-changed` |
| 订阅清理 | `mq.on` 返回取消函数，`onUnmounted` 统一回收 |
| state 命名 | 与消息对应：`session` / `tasklist` / `activeTask` / `taskDetail` |
| 状态字段 | 显式（每级由事件链写入），不搞派生缓存 |
| composable | 组件门面：`useXxx` 内部引用对应域 state 模块（`useTaskPanel` 等），组件零逻辑 |

### 6.1 状态组织（按域，保留局部 state）

**问题**：组件私有 state（`<script setup>` 内 ref）对插件不可见——插件是独立进程，无法访问前端 js 模块内部。

**方案**：按**业务域**组织 state 模块，域内分两级：

- **域级共享**：跨组件引用 / 需被插件感知的状态 → 导出 + **变更必发消息**（对外窗口）
- **域内局部**：插件绝对用不到的纯内部状态 → 私有，直接改，**不发消息**（零消息开销）

```text
src/state/
  sessionState.js    // 会话域：session / turns / activeSession
  taskState.js       // 任务域：tasks / nodes / activeTask
  fileState.js       // 文件域：filetree / activeFile / codebase 索引
  chatState.js       // 聊天域：inputText / sendQueue / draft
  configState.js     // 配置域：场景 / LLM 配置 / 工具开关
```

```js
// chatState.js
// 域级共享：导出 + 变更发消息（插件可感知）
export const chatState = ref({ inputText: '', sending: false })
export function setInputText(text) {
  chatState.value.inputText = text
  mq.emit("chat-input-changed", { text })    // 对外窗口
}
// 域内局部：不发消息（插件用不到，零开销）
const composing = ref('')                     // 输入法组合态等内部细节，直接改
```

**消息边界判据**：状态是否会被"域外"感知（其他域组件 / 插件）？
- 是 → 域级共享：导出 + 变更发消息
- 否 → 域内局部：私有，直接改

**插件访问**：只经域级共享的消息/context；局部 state 不对外，插件拿不到也不需要。

**生命周期**：域模块常驻；域内一次性状态显式清理（`resetXxx()` 由事件链触发）。

**代价**：域模块文件；换取：跨域可引用 + 插件可访问（共享级）+ 局部零消息开销。**按需消息化**——只有"对外窗口"状态付出消息成本，优于"全部模块化全发消息"。

## 7. 适用边界

- **适用**：状态流转、异步数据（会话/任务/配置）、需可追踪的状态变更、多入口触发的状态（自动/用户/外部）
- **注意**：超大列表的渲染过滤若每次重算开销大，可用普通函数 + 记忆化（memo）兜底，仍不引入 watch/computed 隐式依赖

> **迁移说明**：现有散落在 `composables/`、`stores/`、`utils/` 的共享状态（useTaskView、sessionStats、codebaseStatus、sendQueue、fileTree 等）统一迁入 `state/` 目录对应域模块；按 §6.1 判据划分域级共享（保留消息化）与域内局部（不发消息）。

## 8. 目标态 state 模块规划（按功能域）

> 基于当前功能要求整理的目标态。★ = **域级共享**（发消息，插件可感知）；其余 = **域内局部**（不发消息，零开销）。

| 域模块 | 状态 | 级别 | 说明 |
|--------|------|------|------|
| **sessionState.js**（会话域） | `sessions` / `activeSession` / `sessionStats` | ★ 共享 | 会话列表、当前会话、token 统计、标题（data-session-title 重命名） |
| **chatState.js**（聊天域） | `turns` / `messages` / `sendQueue` / `inputText` / `sending` | ★ 共享 | 当前对话内容、发送队列、输入与发送状态 |
| | `composing` / `draft` / `scrollPos` | 局部 | 输入法组合、草稿、滚动位置 |
| **taskState.js**（任务域） | `tasks` / `nodes` / `activeTask` / `taskDetail` | ★ 共享 | 任务运行态、任务树节点、选中任务、详情 |
| **fileState.js**（文件域） | `filetree` / `activeFile` / `openTabs` / `codebaseIndex` | ★ 共享 | 文件树、当前文件、打开页签、codebase 索引状态 |
| | `treeLoading` / `expandedDirs` / `filter` | 局部 | 树加载态、展开、筛选 |
| **configState.js**（配置域） | `llmConfig` / `scenario` / `tools` / `userPrefs` | ★ 共享 | LLM 配置、当前场景、工具开关、用户偏好 |
| **kbState.js**（知识域） | `knowledgeList` / `activeKnowledge` | ★ 共享 | 知识库、当前知识 |
| **uiState.js**（UI 域） | `windowState` / `layout` | ★ 共享 | 窗口几何、布局（SaveWindowState/LayoutState） |
| | `sidebarOpen` / `panelSizes` | 局部 | 侧栏开合、面板尺寸 |
| **statusState.js**（状态域） | `workdir` / `runtimeStatus` | ★ 共享 | 工作目录、运行状态摘要（状态栏） |

> 粒度可再细分（如预览状态独立 `previewState`），但**域边界以功能为准、域级共享以"是否被域外/插件感知"为准**——判据见 §6.1。
