# 17 · 前端状态管理与 MQ

>
> **通用前端状态管理模式（与插件无关）**：适用于整个前端——主应用组件与插件 UI 一致。核心：**MQ 事件链 + 响应式 state；禁 watch；computed 仅用于纯派生（无副作用）**。

## 1. 模型

```text
MQ 事件 ──写入──▶ state（响应式 ref/reactive，唯一真相源） ──绑定──▶ 渲染
                   ▲
   域级共享状态：事件处理器写入；域内局部状态：域模块 setter 写入
```

**状态流转 = 事件链**：每步是一个事件处理器（异步拉数据 → 写 state → 发下一消息）。所有变更显式可见，消息链即状态机。

## 2. 核心原则

| 原则 | 说明 |
|------|------|
| 想改变状态 = 发 MQ 事件 | UI/组件不直接写 state（域级共享状态），意图经消息表达 |
| 状态有明确写入点 | 域级共享状态只经事件处理器；域内局部状态只经域模块导出的 setter——均不散落在组件内部 |
| 异步只在处理器里 | `mq.emit` 驱动的处理器内异步拉数据，结果写回 state，不进模板 |
| ref/reactive 本身响应式 | 模板绑定 state 自动更新；只读派生允许 `computed`（纯函数、无副作用），写操作仍必须走事件链 |
| 消息即日志 | 每个状态转换由一条消息显式触发，全链路可追踪 |

## 3. 禁 watch；computed 仅纯派生

| 项 | 规则 | 原因 |
|---|---|---|
| watch / watchEffect | **禁止** | 监听变化再执行副作用：隐式依赖、命令式、难追踪；变化由消息主动写入 state |
| computed | **允许，但仅限纯派生** | 不得在 getter 内写 state / 发 MQ / 异步；实测主仓前端 **316 处** `computed(`，是现行普遍用法 |
| `$subscribe` | **禁止** | Pinia store 变化同样只由事件链驱动 |

> 原文「无 computed / 用普通函数替代」**作废**（2026-11-04 核对）：与代码 316 处使用、[20-gui §12](../20-modules/20-gui.md) 的 computed 派生要求冲突。现行口径 = **禁 watch / `$subscribe`；computed 只能是只读派生**。
> 禁 watch 的验证：`src/frontend/src` 内 `watch(` / `watchEffect` / `$subscribe` 仅 5 处注释命中，无真实调用。

## 4. 现行事件链（示例）

> 🗄 **原文 §4 / §5 的 `tasklist-changed` / `activetask-changed` / `mq.call("GetTasks" / "GetTaskDetail")` 均为虚构**（全仓 0 命中；`mq` 封装只有 `emit` / `on` / `pre` / `post` / `error` / `final`，没有 `call`）。以下替换为现行主题。

现行核心主题（`src/frontend/src/events/event-names.js`）：

| 主题 | 语义 | 现行用途 |
|---|---|---|
| `session-changed` | 当前会话变化 | 会话切换 → 更新 `activeSession` |
| `subsession-changed` | 子会话变化 | 子会话切换（群聊/子代理） |
| `task-detail-open` | 打开任务详情 | 任务详情面板 |
| `data-prj-security-refresh` 等 `data-*` | 数据域刷新 | 既有主题，非新增 |

```js
// 处理器：读事件 → 写 state / 调既有接口 → 发下一步（只在处理器内异步）
mq.on("session-changed", async ({ session }) => {
  state.activeSession = session
  // 数据通过既有 MQ 请求/应答或 api 层获取，不假设存在 mq.call
})

mq.on("task-detail-open", ({ task }) => {
  state.activeTask = task
})
```

```vue
<!-- template：直接绑定 state 或纯派生 computed -->
<TaskDetail :data="state.activeTask" />
```

## 5. 可重用性（链上每步可重入）

```text
session-changed ←───────┐
  ├─ 会话树点选          │
  ├─ 快捷键 / 托盘激活   ┘（同一主题）
  └─ 其他域/插件复用
```

- **单一通道**：`session-changed`（同类还有 `subsession-changed`）是入口，自动/用户/外部走同一处理逻辑，零重复代码。
- **可重入**：任何来源发该主题，处理结果一致（状态机语义）。
- **扩展性**：新入口直接发同一主题，无需新增路径。
- 🗄 原文以 `activetask-changed` 为单一通道的示例作废（主题不存在）。

## 6. 约定

| 项 | 约定 |
|----|------|
| 消息命名 | kebab-case（`-` 分隔），如 `session-changed` / `subsession-changed` / `task-detail-open` |
| 订阅清理 | `mq.on` 返回取消函数，`onUnmounted` 统一回收（`framework/host/web/src/utils/mq.js`） |
| state 命名 | 与消息对应：`activeSession` / `activeTask` / `taskDetail` |
| 状态字段 | 显式（每级由事件链写入）；只读派生可用 computed |
| composable | 组件门面：`useXxx` 内部引用对应域状态（`useTaskView` / `useToolSandbox` 等） |

### 6.1 状态组织（按域，保留局部 state）——🔵 目标态

> **2026-11-04 核对：`src/state/` 目录不存在、未实施**。本节与 §8 均为规划；现行域状态在 `composables/`（31 个 `useXxx.js`，模块级单例）与 Pinia `stores/selection.js`。

**问题**：组件私有 state（`<script setup>` 内 ref）对插件不可见——插件是独立进程，无法访问前端 js 模块内部。

**方案**：按**业务域**组织 state 模块，域内分两级：

- **域级共享**：跨组件引用 / 需被插件感知的状态 → 导出 + **变更必发消息**（对外窗口）
- **域内局部**：插件绝对用不到的纯内部状态 → 私有，直接改，**不发消息**（零消息开销）

```text
src/state/
  sessionState.js    // 会话域：session / turns / activeSession
  taskState.js       // 任务域：tasks / nodes / activeTask
  fileState.js       // 文件域：filetree / activeFile / codegraph 索引
  chatState.js       // 聊天域：inputText / sendQueue / draft
  configState.js     // 配置域：场景 / LLM 配置 / 工具开关
```

```js
// chatState.js
// 域级共享：导出 + 变更发消息（插件可感知）
export const chatState = ref({ inputText: '', sending: false })
export function setInputText(text) {
  chatState.value.inputText = text
  mq.emit("chat-input-changed", { text })    // 对外窗口
}
// 域内局部：不发消息（插件用不到，零开销）
const composing = ref('')                     // 输入法组合态等内部细节，直接改
```

**消息边界判据**：状态是否会被"域外"感知（其他域组件 / 插件）？
- 是 → 域级共享：导出 + 变更发消息
- 否 → 域内局部：私有，直接改

**插件访问**：只经域级共享的消息/context；局部 state 不对外，插件拿不到也不需要。

**生命周期**：域模块常驻；域内一次性状态显式清理（`resetXxx()` 由事件链触发）。

**代价**：域模块文件；换取：跨域可引用 + 插件可访问（共享级）+ 局部零消息开销。**按需消息化**——只有"对外窗口"状态付出消息成本，优于"全部模块化全发消息"。

## 7. 适用边界

- **适用**：状态流转、异步数据（会话/任务/配置）、需可追踪的状态变更、多入口触发的状态（自动/用户/外部）
- **注意**：超大列表的渲染过滤若每次重算开销大，可用普通函数 + 记忆化（memo）兜底；仍**不引入 watch**，computed 只做纯派生。

> **迁移说明**：现有散落在 `composables/`、`stores/`、`utils/` 的共享状态（useTaskView、sendQueue、fileTree 等）统一迁入 `state/` 目录对应域模块；按 §6.1 判据划分域级共享（保留消息化）与域内局部（不发消息）。

**口径**

1. **唯一真相源 + 订阅者模式（部分成立）**：`selectionSubscribers.js` 只订阅 `session-changed` / `subsession-changed` / `task-detail-open` 三个既有主题（**零新增主题**）。代码注释已自列上述 **4 个额外写入点**（`workDir`、`activeFile`、`explorerMode`、`activeSelection`），故「写入点唯一」**不成立**；应表述为「跨 view 状态集中在 store，订阅者覆盖会话/任务，其余由对应组件或接口显式写入」。
2. **Pinia 边界**：Pinia **只**放「被 ≥2 个 view 读 / 写」的状态（上面 6 项 + 布局域 `layout-free/stores/*`）；**单 view 私有状态留组件内**（`ref`），**不**进 Pinia。
3. **禁 `watch` / `watchEffect` / `$subscribe`（现行强制）**：读取方靠**事件链重渲染**（组件模板读 store 反应式值即可），**禁止**用 watch 监听 props / store 变化（§3 + [71 §7.1](../70-conventions/71-编程规范.md)）；Pinia 的 `$subscribe` **同样禁止**（主仓前端 0 命中）。computed 仅纯派生。
4. **布局域 store**（`layout-free/stores/{config,edit,runtime,keys}.js`）由自由布局容器子系统**内部**持有；未找到 `layout-free/engine.js`，现行门面 = `layout/index.js#setupLayoutEngine`（主仓 `main.js` 调用）。**不并入** `selection.js`。
5. **组件门面（偏差如实记录）**：约定组件优先用 `useXxx` composables，**不直连** store 细节；但实测 **7 个 `.vue`、共 14 处**直接 `useSelectionStore()`（`CodeView.vue` / `ChatPanel.vue` / `ExplorerPane.vue` / `SessionChat.vue` / `SessionTree.vue` / `SessionsPane.vue` / `App.vue`）。该偏差可接受，但不得再表述为「组件零直连」。

## 11. 前端状态注册 v1（阶段1，2026-11-19）

`src/frontend/src/utils/ckStore.js` 在既有 getter 仓库（`register` / `get` / `listKeys`，**兼容不变**）之上新增**状态注册表**；主程序 canonical key 在 `src/frontend/src/stores/hostState.js` 登记。

| API | 口径 |
|---|---|
| `create(key, options)` / `create({ key, ...options })` | 注册状态，返回 handle `{ key, ref, value, set(), get(), destroy() }`；options = `{ initial, owner='host', scope='window', persist:'none' \| 'session', label, description, defaultValue, schema }`。重复注册保留先注册者并告警（幂等返回已有 handle） |
| `ref(key)` | **消费者入口**：稳定、**只读** Vue ref；同一 key 多次调用返回同一对象；未注册 → `null` |
| `getSync(key)` | 同步读取状态；key 不是已注册状态 → `undefined` |
| `set(key, value)` | owner 写入；不存在 → `false`。写后：`persist='session'` 写 `localStorage['chonkpilot.state.<key>']` → 手动通知 listeners（**不使用 watch**） |
| `destroy(key)` | 幂等删除；既有只读 ref 不崩，保留 ref 并把值置 `undefined` |
| `alias(aliasKey, targetKey)` | 兼容旧 key；不持有独立值，`ref` / `getSync` / `set` / `onChange` 解引用到目标 |
| `definitions()` | 返回 `{ key, label, description, defaultValue, scope, owner, persist, aliasOf?, hidden? }`；layout-free 下拉过滤 `hidden` |
| `onChange(key, cb)` / `offChange` | 只由 `set` 触发；`onChange` 返回退订函数 |

**owner / 消费者边界**

- `selection.js` 是 `workdir` / `selected-session` / `active-file-path` / `active-task-id` / `explorer-mode` 的 owner；各 setter 经 `publishHostState()` 把值投影到注册表。
- 消费者（组件 / layout-free / 测试）只读 `ref(key)`；要写必须走 owner 的 setter（或明确的 `set`）。
- 兼容 alias：`project` → `workdir`、`sessionId` → `selected-session`、`filePath` → `active-file-path`、`taskId` → `active-task-id`；alias 标记 `hidden`，不出现在 layout-free 变量下拉，但读取 / 写入仍可用。

**与既有 getter 仓库的兼容**

- `get(key)` 仍是 Promise，且**状态优先**：已注册状态 → 返回当前值；否则走旧 getter；两者都没有 → `null`。
- `listKeys()` 仍只列 getter key；新增 `listStateKeys()` 列状态 key（含 alias）。
- `installGlobalCkStore()` 暴露的对象自然包含全部新 API（`window.ckStore`）。

**layout-free 动态 key**

- 主仓 `main.js` 经 `setHostDeps({ state: ckStore })` 注入；`layout-free/stores/keys.js` 在注入时从 `definitions()` 动态生成变量下拉（过滤 `hidden`），值读 `ref(key)`，写回走 `set(key, value)`。
- 未注入（standalone / 测试）继续使用 `config/keys.js#KEY_DEFINITIONS` fallback，`keys.list` 返回 shape 不变。

**边界**：本阶段不做跨窗口 / 跨 iframe 的 ref 传递 —— 插件 iframe 仍用 `await window.top.ckStore.get(key)`。**禁 `watch` / `watchEffect` / `$subscribe` 仍成立**；状态通知由 `set` 内部手动触发。
