## 1. 目标与结论

### 1.1 目标

在一个进程内支持**多个窗口**：

| 窗口 | 形态 | 内容 | 几何 |
|------|------|------|------|
| **项目主窗口**（每 `work_dir` 一个） | 现状不变 | 完整布局（toolbar/文件树/预览/任务/session 列表/主 chat/状态栏） | 持久化（`window.*` / `layout.*`） |
| **对话窗口**（每项目 0..N） | 新增 | **仅 chat**（可跑 tools） | **不持久化**；仅需原生最大化 / 最小化 / resize |

> **多项目（PRODSIM-1，2026-11-04 核对）**：「主窗口唯一」已过时 —— 同一进程内按 `work_dir` 可打开**多个项目主窗口**（`hostapi.go OpenProject` 同 work_dir 幂等、不同 work_dir 新建），各自带一组小窗口；日志窗口仍为**进程唯一**。

对话窗口由 URL 路由承载，形如：

```
https://app.localhost/?session-id=<session-id>#chat
```

要点：
- **原生标题栏**（`Frameless: false`）→ 最大化 / 最小化 / 关闭 / 拖动 / 八方向 resize **全部由系统提供，零代码**。
- **不记录几何**：每次按默认位置打开（同项目内避开主窗口、级联避让其它对话窗）。
- **不变量 I-1（一个 session 只允许一个窗口）**：任意时刻，一个 `session_id` **最多绑定一个窗口**（主窗口**或**某个对话窗口）。判定优先级：
  1. 该 session = **主窗口当前活动会话** → **不可**开新窗口（入口**置灰**）；
  2. 该 session = **某对话窗口已绑定的 session** → **不可重复建窗**，改为**激活**该窗口（`ShowWindow(SW_RESTORE)` + `SetForegroundWindow`），**不切主窗口**；
  3. 其余 → 建新对话窗口并绑定该 session。
  推论：**主窗口也不得切换到"已被对话窗口绑定的 session"** → 点击此类 session 时**激活对应窗口**（否则违反 I-1，出现一 session 多窗口）。
- **对话窗口不提供会话切换**：窗口**绑定** URL 里的 `session-id`（固定）；要看别的会话 → 从 session 列表**另开**一个对话窗口。

### 1.2 结论（本轮拍板）

| # | 结论 | 依据 |
|---|------|------|
| C1 | **路由模型 = 每窗口一 instance**（窗口 ↔ instance 1:1） | §2 |
| C2 | **不采用「单 instance + `eval` 扇出 + `window_id`」** | §2.3 |
| C3 | **每窗口一桥**（各自 `eval` → 各自窗口）；隔离由**既有 instance 过滤**免费提供 | §2.2 |
| C4 | **数据层取 B 方案**：desktop 走 `dataDir == ""` → prjusr 落到 `<workDir>/.chonkpilot/users/<OS 用户名>/` | §3 |
| C5 | 对话窗口**不写** `active_session_id`、**不写** `window.*`/`layout.*` | §3.3 |
| C6 | 前端按 URL 分派，新增 `ChatOnlyView`（不走主布局、不参与 `instance-claim` 之外的主流程） | §6 |

## 2. 模型（三轴与路由）

### 2.1 三个正交轴

| 轴 | 决定什么 | 落地键 / 机制 |
|----|---------|--------------|
| **`work_dir`** | **业务数据分区**：会话 / 消息 / 任务树 | prjusr 库路径（见 §3） |
| **`instance_id`** | **运行态分区**（turns / busy / asks）+ **消息归属过滤** + 数据根绑定 | `instKey` · `acceptEventInstance` |
| **窗口** | **视口**：窗口几何、面板布局 | 主窗口：`window.*`；对话窗口：无 |

> **关键澄清（易错）**：`instance` **不做业务隔离**。同 `work_dir` 的两个 instance 共用同一个 prjusr 库 → **会话列表/历史是共享的**。instance 只隔离「运行态 + 消息投递」。

### 2.2 路由：每窗口一 instance + 每窗口一桥

```text
进程（desktop 单体）
├─ bus（进程内内存 MQ，唯一）
├─ server 生态（persist / gateway / mcp-server / filesys / 插件，唯一）
├─ 主窗口：instance_id=A · bridge A（eval → 主窗口）
└─ 对话窗口：instance_id=B · bridge B（eval → 对话窗口）
```

- **后端 → 各前端**：每个桥只把**本 instance 的事件**转发给**本窗口**（[acceptEventInstance](../../../src/lib/gui/bridge/bridge.go) 按 `instance_id` 过滤）→ 天然满足「后端消息到达每个前端」，**无需改 `eval` 扇出**。
- **前端 → 前端**：A 窗口 publish 的事件带 `instance_id=A`，B 桥按归属过滤丢弃 → **前端之间不互通**（符合要求）。
- **窗口定向命令**：`gui.window.status` / 截图 / DevTools 的 `hwnd` 由**每窗口自己的 `appHandler`** 提供 → 天然只作用于本窗口，**无需 `window_id`**。
- **桥级防环**（`published`，1s 窗口）语义不变：仅抑制"自己刚发布的事件"回环。

### 2.3 为什么不走「单 instance + 扇出 + `window_id`」

| | 每窗口一 instance（**采用**） | 单 instance + 扇出 |
|---|---|---|
| 后端 → 各前端 | 各自 instance 到各自窗口（现成） | 需改 `eval` 单目标 → 多目标扇出 |
| 前端隔离 | instance 过滤（现成） | 桥级防环（现成） |
| 窗口定向 | 桥 = 窗口（现成） | 需 `window_id` 贯穿消息面 |
| 新增机制 | **≈0** | `eval` 扇出 + `window_id` |
| 跨窗口观察同一会话 | ❌ 运行态分桶，不可见 | ✅ 广播可见 |

本项目**不需要**跨窗口观察同一会话（每窗口独立对话），故取左列。

### 2.4 与既有规格的关系（**必须同步**）

[20-实例隔离与后端分离 §2](20-实例隔离与后端分离.md) 现声明：

> **desktop = 1 进程 = 1 instance**；「split 下 gui 与 instance 是绑定的，无需分割」；「**不存在**「gui 侧多 instance 同进程」问题」。

**本方案打破了该不变量**（desktop 进程内将出现 ≥1 个 instance）。**结论：desktop 的 instance 数 = 主窗口数 + 各项目对话小窗数**（PRODSIM-1 同进程多项目时主窗口也可 > 1）；服务端侧的「同进程多 instance」隔离能力（[20](20-实例隔离与后端分离.md) 缺口 1/2/3/4/5/8 已实施）**正好承接**，无需新增服务端能力。

## 3. 数据层（B 方案）

### 3.1 现状（实测）

`dataDir != ""` 时，prj 与 prjusr **同文件**；而 desktop 的 `data_dir` **恒非空**（`models.DataDir(workDir)` 缺省 `<workDir>/.chonkpilot`，永不返回 `""`）→ **desktop 的会话数据实际写在 `<workDir>/.chonkpilot/chonkpilot.db`**，`~/.chonkpilot/data/<prj-id>/` 从未生成（实测该目录不存在）。

### 3.2 目标态（B 方案）

desktop 走 `dataDir == ""` 分支：

| 库 | 路径 | 内容 |
|----|------|------|
| `usr` | `~/.chonkpilot/chonkpilot.db` | 用户级（LLM/MCP 定义、偏好、凭据） |
| `prj` | `<workDir>/.chonkpilot/chonkpilot.db` | **项目级**：团队共享配置（无会话数据） |
| `prjusr` | `<workDir>/.chonkpilot/users/<OS 用户名>/chonkpilot.db` | **个人运行态**：会话 / 轮次 / 消息 / 任务树 / 快照 / `window.*` / `layout.*` / `active_session_id` |

**动机**：个人运行态**不应落在项目目录内**（项目目录可能入库/共享）。这正是 `prjusr` 分层的原意。

> **⚠️ 影响面（需在实施时逐条处理）**：`models.DataDir(workDir)` 还被用于 **日志目录**（`<dataDir>/logs`）、**截图/附件落盘**（`<dataDir>/<dir>`，`dir` 缺省 `tmp/uploads`）、`fileserver` 白名单。
> - **日志**：✅ **跟随数据根** → `<workDir>/.chonkpilot/users/<OS 用户名>/logs/`（与 prjusr 同根；`gui.init-data` 的 `logDir` 随之指向该处）。
> - **截图/附件**：✅ 属**会话数据** → 随 prjusr 落 `<workDir>/.chonkpilot/users/<OS 用户名>/<dir>/`（按 prjusr 数据根解析；`dir` 由 `gui.upload` 决定，缺省 `tmp/uploads`、截图 `screenshot`）。
> - **`fileserver` 白名单**：✅ 需同时可达 **workDir**（`<workDir>/.chonkpilot`）与 **prjusr 数据根**（`<workDir>/.chonkpilot/users/<OS 用户名>`）。
>
> **⚠️ 实施注意（prjusr 根 ≠ `models.DataDir(workDir)`）**：`models.DataDir(workDir)` 是 **data-dir 访问器**（[models/consts.go](../../../../chonkpilot-framework/host/src/models/consts.go)），缺省求值 = **`<workDir>/.chonkpilot`（项目目录内）**，**不是** prjusr 根。prjusr 根由 `data.PrjUsrDir(workDir, dataDir)` 唯一解析 = **`<workDir>/.chonkpilot/users/<OS 用户名>/`** → **日志/上传目录一律按 prjusr 根解析**。
>
> **✅ 实现方式已定（取 (a)，§8 U-7）**：**`data_dir = ""`** → 数据层自动把 prjusr 落到 `<workDir>/.chonkpilot/users/<OS 用户名>/`；**日志/上传/截图显式按 prjusr 根解析**。**不动数据层语义**。~~(b) 保留 `data_dir` 可配 + 改数据层让 `prj` 恒落项目内~~ → **已否决**。
>
> **✅ 旧数据处置已定：不迁移，视为重建**。切换 B 方案后**历史会话在 UI 中不再显示**（数据**仍留在**旧文件 `<workDir>/.chonkpilot/chonkpilot.db`，**不删除**）；**不写迁移逻辑**、**不做兼容回落读取**。属开发期口径；发布前如需再另立迁移项。

### 3.3 与多窗口的交互（C5 的来源）

prjusr 库**按 `work_dir` 共享**（同 work_dir 的所有窗口 → 同一个 prjusr 文件），因此以下键**两窗会互相覆盖**：

| 键 | 是否会撞 | 处置 |
|----|---------|------|
| `active_session_id`（prj config / prjusr） | 若对话窗口写则撞 | ✅ **对话窗口不调用 `session-active-set`/`-get`**（它绑定固定 session-id） |
| `window.*` / `layout.*` | 两窗都写则撞 | ✅ **对话窗口不持久化几何**、不写 layout |

## 4. 宿主改造（`chonkpilot-framework/host/src/gui` + 主仓装配）

> **落点（2026-11-04 核对）**：窗口工厂 / 注册表 / owner 镜像 / 宿主消息处理均在同级仓 `chonkpilot-framework/host/src/gui/`；主仓 `src/lib/gui/host/main.go` 负责 `gui.NewEnv`、`OpenProject` 与各子系统接线。下文 `main.go` 均指框架仓该目录下的文件，除非显式写 `src/lib/gui/host/main.go`。

### 4.1 窗口工厂（技术路径已 POC 验证）

每个窗口创建时：**独占一个 OS 线程** + **在该线程上 `CoInitializeEx(STA)`** + **独立 WebView2 `DataPath`**，随后 `Run()` 阻塞在该线程。

- 已实测（附录 A）：同进程 4 窗口全绿、消息泵互不干扰、关闭一个不影响其它。
- fork（同级仓 `chonkpilot-webview2`）的 `package init()` 只把 STA 钉在主线程 → **每窗口线程必须自行 STA**（宿主侧实现，**不改 vendored fork**）。
- **`Terminate()` 不可跨线程调用**（`PostQuitMessage` 投到调用线程）；关闭窗口**一律用 `Destroy()`**（投 `WM_CLOSE` 给窗口自身线程）。

### 4.2 每窗口一个 `appHandler`

`appHandler`（`main.go`）当前是单例，字段 `hwnd`/`destroy`/`br` 为进程级。改为**每窗口各建一个**：

- 拦截器 `SetWebResourceRequestedCallback` 本就是 **per-webview** → 每窗口的 `/publish`、`/show/`、静态资源**天然绑定到来源窗口**。
- 新增字段 `role`（`main` / `chat`）与 `sessionID`（对话窗口的绑定会话）。
- **窗口定向事件**：`window-maximized-changed` 等**窗口状态类下行事件**由**本窗口** appHandler 经**本窗口的桥**发出 → **只到该窗口**；**不再进程广播**（否则多个窗口的最大化图标会互改）。**载荷 = `{maximized, instance_id}`**（`chonkpilot-framework/host/src/gui/main.go` 的 `appHandler` 广播处，2026-11-04 核对；与「业务 payload 必带 `instance_id`」一致；见 [61 §1](../60-reference/61-消息一览.md)）。
- **不注入** `window.__ck.view`（视图判定以 URL 为准，见 §6.1 · U-2 已决）。

### 4.3 窗口注册表（session ↔ 窗口一对一）

每项目一个注册表（`projectCtx.windows`；PRODSIM-1 多项目隔离，2026-11-04 核对）—— **只登记对话窗口**（主窗口与 Ask 中心**不入表**）：

```text
registry: windowID -> { hwnd, sessionID, destroy }
反向索引: sessionID -> windowID
```

职责：
- `open-chat(session)` **幂等**：已存在该 session 的对话窗口 → **激活**（`ShowWindow(SW_RESTORE)` + `SetForegroundWindow`）；不存在 → 建窗；**已达上限（5 个对话窗口）** → 拒绝。
- 窗口关闭 → 双向移除（解除占用）。
- **主窗口不入表**：主窗口"当前活动会话"由**主窗口前端自知** → T-3 置灰、T-5 禁切均由**前端本地判断** + `gui.window.list`（仅 chat 集合）。对应地 `gui.window.list`（见 §5）**只返回 chat 窗口**（见 §5 / §8 U-9）。Ask 中心窗口（§6.8）同样不入 `byID`/`bySession`、不占对话窗额度。

#### 4.3.1 运行态归属（SCOPE-1 强制不变式，2026-10-28）

> 决策依据：[49-待实现项 §2.4 订正块第 4 条](../40-roadmap/49-待实现项.md#1-引用迁移与历史索引2026-11-04)。**主窗口不入 `byID`/列表，但纳入归属判定**（本订正取代原「宿主不追踪主窗会话」）。

- **不变式**：**同一 dialog 不得在两个窗口打开**（同一窗口内多个活动 dialog **允许**）。
- **判据不是「显示」，视图不参与**：session 与 view 没有必然联系 —— 不显示、没有 view 也可以有活动 session；view 只是订阅某个 session 的内容。归属**只由运行态决定**。
- **归属定义**：某 session 在某窗口实例上**有活动运行态**（turn 未结束 / inbox 有 pending / 有 async task）→ 该实例是它的 owner；三者皆无 = 该 session「无主」。
- **两条释放路径**（其余事件——切走 / 不显示 / 关标签——**都不释放**）：
  1. **窗口关闭 → 整窗释放**（本窗口实例名下的全部归属清空）；
  2. **空闲自动结束 → 只释放该 dialog**（turn 结束 ∧ inbox 无 pending ∧ 无 async task）；释放后变「无主」，下次用户选中即重新归属激活。
- **归属产生**：运行态产生处 —— 受理 `llm-start` / `llm-send`（「用户选择即激活」）、inbox 消费、async task 登记。`(instance, session)` 运行态键**不改**（不变式成立时它语义上即「按 dialog」）。
- **执行点（两处，均不改消息面）**：
  1. `gui.window.open-chat`：目标 session 有活动 owner → **激活该窗口**并回 `{ok:true, window_id:<既有>, activated:true}`（**主窗口 `window_id` = 空串**，与 `--test-port` 既有约定一致），**不新建**；无主 → 维持既有行为（`bySession` 幂等 / 上限判定）。
  2. 运行态受理处（llm server）：已活动 session 被**另一实例**再发起 `llm-start` / `llm-send` → 拒（走既有 `accepted:false` 应答，文案 `session is running in another window: <owner>`）；空闲 session 谁发起谁成为新 owner。
- **实现**：llm server 内存归属表（权威侧，`src/lib/llm/server/owner.go`：busy / inbox 索引 / 任务树三源判定）+ 宿主镜像（`chonkpilot-framework/host/src/gui/owner.go`：订阅既有 `session-turn-start` / `session-complete` 维护 `session → {instance, turn}`，空闲复核经既有只读 `data-inbox-list{status:pending}` + `data-tasktree-list`；查不到按「无活动」处理，宁放不挡）。**消息面零变更**。

### 4.4 关闭与退出语义（2026-11-04 核对）

- 关闭**任一**窗口 → 仅销毁该窗口 + 移除注册表项 + 发该实例的 `instance-exit`。
- **关闭项目主窗口** → **终止该项目全部小窗口会话并销毁该项目注册表**（`projectCtx.windows.shutdown()` + `removeProject`）→ 发对应 `instance-exit`；**进程不退出**，日志窗口 + 托盘常驻（PRODSIM-1）。测试脚本 `run_mw.py case_t03` 明确断言关主窗后进程仍存活。
- **退出进程只走托盘菜单 / `/quit`**（`Env.Shutdown()` 关闭所有项目主窗与小窗、强制销毁日志窗口）。
- 日志窗口关闭 = **收起（hide）**，不销毁、不退出。
- **不得**因任一窗口关闭就注销**其它项目或其它**实例。

### 6.5 主题 / 语言跨窗口**即时同步**

✅ **已落地**：主窗口切换 theme/locale → **已打开的对话窗口立即跟随**（无需重启、无需重开窗）。实现 = 服务端在 `data-user-config-save` / `delete` 成功后广播**下行事件** `data-user-config-changed`（**不带 `instance_id` → 全局**；前端每窗口订阅并应用）。

- **原瓶颈（落地前）**：`data-user-config-save` 是**请求-响应**（写入 usr 库 + 回 `{ok,id}`），原**没有任何变更广播** → 其它窗口无从得知。
- **方案（已落地）**：新增**下行广播事件** `data-user-config-changed`
  - payload `{data:{...}}`（与 `save` 的 payload **同形**，前端可复用同一应用逻辑）；已登记于 [61 §3.1](../60-reference/61-消息一览.md)
  - 触发点：`data-user-config-save` / `delete` **成功后**
  - 投递：**不带 `instance_id`** → 每个窗口的桥各自转发 → **所有窗口都收到**；发起窗口重复应用（**幂等**）
- 前端：theme/locale 的 composable 订阅该事件 → 立即应用（**禁用 `watch` 监听 store/props**，遵守前端规则）。
- **落地实况**：服务端新增 `Base.UserConfigChanged` + `config/config_facade.go` 在 `UserConfigSave/Delete` 成功后广播（**不带 `instance_id` → 全局**）；前端新增 `composables/useUserConfigSync.js` / `utils/userConfigApply.js`（**每个窗口**含对话窗入口订阅、**不回写 DB** 防自激），`plugins/i18n.js` 拆出 `applyLocale`。该主题 `data-user-config-changed` **已登记于 [61 §3.1](../60-reference/61-消息一览.md)** → 无须走 R-2 新增。
- 测试：[MW-T27](#93-触发位置-t-1t-5) **✅ 已通过**（判据按 [61 §3.1](../60-reference/61-消息一览.md)：校验 `{data:{theme:'dark'}}`、**不得带 `instance_id`**、并验「对话窗已应用」）。本项对应 [31 WIN-021](../30-function-points/31-窗口与布局.md)。

### 6.6 单聊（子聊天）窗口（**SUBCHAT-2 · 2026-10-16 并入**）

单聊窗口 = **对话窗口的一种**（URL `?session-id=<子聊天 session>&#chat`），复用上文本节全部既有能力（一 session 一窗口 I-1 / 上限 5 / `open-chat` 幂等 + 前置 / 关窗广播 `gui.window.closed`）。其**特有点**：

| 项 | 规格 |
|----|------|
| **开窗入口** | **自动**：父窗口（主会话窗口）订阅 **`subchat-opened`**（自带 `parent_session_id`）→ 比较「本窗口绑定会话 == `parent_session_id`」→ 命中即 `gui.window.open-chat{session_id}`；不匹配忽略。**不再依赖通用 `session-new`**（[61 §4.3](../60-reference/61-消息一览.md)）。手动入口 = 会话列表主会话行下挂的子聊天子节点 + 输入框上方状态条「继续」（[61 §4.2](../60-reference/61-消息一览.md)） |
| **固定参数** | 子聊天会话**锁定** `agent` / `scenario_id` / `llm`（**落会话行**，非 URL、非请求参数；[22 §5](../20-modules/22-data-persist.md)）→ 窗口内**隐藏场景切换入口**（前端 F1），服务端 `resolveTurnScenario` **以会话固定参数为准**（会话 > 请求，见 [21 §4.5](../20-modules/21-llm-server.md)）→ **重启恢复轮同口径**，人格与第五层不丢 |
| **生命周期** | 只有三态（**会话行** `lifecycle`，非窗口态）：`chatting`（进行中）/ `ready`（子 agent 自报建议）/ `finished`（用户拍板）。**窗口开/关不是状态**——关窗 = 用户暂离，`lifecycle` 不变、**不上报服务端**（宿主只广播已有的 `gui.window.closed` 供父窗口刷新状态条） |
| **状态实时同步** | 状态变化经 **`subchat-state`**（`{session_id, parent_session_id, lifecycle}`）下发：`ready` 点亮「结束」按钮 / `finished` 消失 / 新一轮 `ready → chatting` 撤销点亮。**当前取广播退化路径**（不带 `instance_id`；llm-server 不持有 session→instance 映射）→ 前端按 `parent_session_id` / `session_id` **归属过滤**（见 [61 §4.3](../60-reference/61-消息一览.md) · 单聊设计 §12.4/§5.3） |
| **回切语义** | 用户在**子聊天窗口内**点「结束」→ 前端发 `subchat-finish{session_id}` → 服务端置 `finished` + 发 `subchat-state` → 该窗口**自关**（`gui.window.status{close}`，执行对象恒为来源窗口）→ 宿主广播 `gui.window.closed` → **父窗口**按状态条列表（`subchat-list{parent_id}`）判定归属后**回切原会话**。**结果不回流**：主会话不写消息、不起轮、不改历史（单聊设计 §3.4.3） |
| **只读窗口** | `lifecycle == finished` 的子聊天窗口**不渲染输入框**；进入 `finished` 时若窗口开着 → 立即变只读（终态稳定，不"悄悄复活"）。父窗口状态条上的「强制结束」**只收口、不打开窗口** |

> **不进任务树**：单聊（`kind=sub_chat`）走会话列表 / 状态条视图，**不建任务节点、不并入任务执行树**；`dsl_run` 的 `LLM` 步骤派生的子会话（`sub_session`）**不受影响**（见 [21-任务层设计方案 §4](21-任务层设计方案.md)）。`sessions.parent_id` 保留，作两处技术关联：① 状态条过滤依据；② 关窗回切依据。
