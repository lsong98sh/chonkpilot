## 1. 开发一个工具需要改哪些文件

每个执行层工具由 4 个组成部分构成：

```
┌──────────────────────────────────────────────────────────────┐
│  1. 契约（*.tool.md，分区式）                                │
│     internal/contracts/tools/<cat>/<name>.tool.md            │
│     → [meta] + [description] + [parameters]                  │
│     → LLM 看到的参数签名 + 前端/框架所需元信息               │
├──────────────────────────────────────────────────────────────┤
│  2. Handler 实现                                             │
│     internal/{fileops,browser,desktop,scriptrun,fetch}/*.go  │
│     → HandleXxx() 函数，返回 *cli.Result                     │
├──────────────────────────────────────────────────────────────┤
│  3. 注册到 dispatcher                                        │
│     core/main.go · browser/main.go · desktop/main.go         │
│     → dispatch switch 中绑定 handler                         │
├──────────────────────────────────────────────────────────────┤
│  4. 测试                                                     │
│     internal/<pkg>/*_test.go                                 │
│     → 测试 Handler 功能                                      │
└──────────────────────────────────────────────────────────────┘
```

> 契约文件名（不含 `.tool.md`）**必须等于工具 name**（原语名 = 文件名，见 [25-mcp-server](../20-modules/25-mcp-server.md)）。

## 2. 契约字段完整说明（*.tool.md）

**路径：** `src/mcp-tools/internal/contracts/tools/<cat>/<name>.tool.md`（`<cat>` ∈ `core` / `browser` / `desktop`）

**完整格式（分区式）**——首行 `# H1` 可读标题，其后为 `[meta]` / `[description]` / `[parameters]` 分区：

```text
# 读取文件

[meta]
runtime=chonkpilot-core-executor.exe
hot=true
category=core
async=auto
async-threshold=30
timeout=60
args=file_read --input={RAW-INPUT-FILE}
output=stdout

[description]
<给 LLM 看的完整说明>

[parameters]
<YAML 形态 JSON Schema>
```

### [meta] 字段明细（key=value）

| 字段 | 给谁用 | 说明 |
|------|--------|------|
| `title` | 前端 / MCP | 一句话标题（MCP Tool.title），独立编写、非 description 截断 |
| `category` | 前端过滤器 | 分类声明；缺省由契约根目录名派生 |
| `hot` | 框架 | 固定暴露标志（吸收旧 `llm`） |
| `async` | 框架 | `auto`\|`always`\|`never`\|`manual`（缺省 auto） |
| `async-threshold` | 框架 | 秒；`async=auto` 下超时自动转后台 |
| `timeout` | 框架 | 秒；fail 语义，仅 `async=never` 下生效，0 = 用 cfg.TimeoutSec |
| `runtime` | 执行器 | 执行器 exe / PATH 名，或解释器（python/node） |
| `args` | 执行器 | 命令行模板（`{param}` / `{RAW-INPUT-FILE}` / `{RESULT-OUTPUT-FILE}`） |
| `output` | 执行器 | `stdout`\|`code`\|`file`（缺省 stdout） |

> **已删除死 meta（2026-09-14）**：`runtime-version` · `version` · `find`（解析与 `_meta` 透出均已移除，不再书写，见 [41 I-71](../40-roadmap/41-未决项登记.md)）。

### 分区明细

| 分区 | 给谁用 | 说明 |
|------|--------|------|
| `# <H1>` | 前端 / MCP | 可读标题（原语名 = 文件名，不由 H1 决定） |
| `[description]` | LLM | LLM 决定是否调用的依据，要详细 |
| `[parameters]` | LLM | YAML 形态 JSON Schema 参数签名（顶层 `type: object`） |

### 现行分类清单（按契约根目录）

| 分类 | 执行器 | 现有工具 |
|------|--------|---------|
| `core` | `chonkpilot-core-executor.exe` | `file_find`、`file_read`、`file_diff`、`filesys_run`、`script_run`、`web_fetch` |
| `browser` | `chonkpilot-browser-executor.exe` | `browser_run`（chromedp，需 Chrome） |
| `desktop` | `chonkpilot-desktop-executor.exe` | `desktop_run`（Win32） |

### 命名规则

**强制规则：名词_动词**

所有新工具名必须遵循名词在前、动词在后的格式：

| ✅ 正确 | ❌ 错误 |
|---------|---------|
| `file_read` | `read_file` |
| `web_fetch` | `fetch_web` |
| `browser_run` | `run_browser` |

规则详解：
- 全小写 snake_case
- 第一个单词是名词（操作对象/领域）
- 第二个单词是动词（操作动作）
- 同一功能组共享名词前缀（如 `file_*`, `browser_*`）

**例外：** 已有工具名保持不动，避免破坏兼容性。

## 3. 实现 Handler

### 工具结果结构（cli.Result）

定义于 `src/mcp-tools/internal/cli/cli.go`：

```go
type Result struct {
    Success   bool
    Output    string      // 给 LLM 的摘要（executor 原样透出 stdout）
    Error     string
    Tool      string
    RawResult interface{} // 结构化数据
}
```

> `Result` 是 executor 的中间产物、无 JSON tag；`cli.Run` 把 `Output`（或 `Error`）原样写到 stdout，由上层 mcp-server 统一判定 JSON / 封装，退出码表达成败（0 成功 / 1 失败）。

### Handler 签名

```go
func HandleXxx(workDir string, args map[string]interface{}) *cli.Result  // core（带项目目录）
func HandleXxx(args map[string]interface{}) *cli.Result                  // browser / desktop（不依赖项目目录）
```

### 路径参数（R-11）

工具/DSL 的**所有输入/输出文件与目录参数**（含 DSL 内所有 `#"..."` 引用——数据源读取、落盘、目录操作）**必须是绝对路径、以 `~/` 开头的用户目录路径或以 `!/` 开头的临时目录路径**（`!/` → `<系统 temp>/chonkpilot/<instance>/`，按 instance 分目录）；相对路径 → 工具**整体失败**（错误状态，消息含原值、位置与示例）。

- **唯一实现**：`src/lib/paths.ResolvePath(raw, "")` + `InvalidPathMessage`（`ResolveDir` 仅供 CLI 目录参数）。
- mcp-tools 侧薄封装 `internal/fileops/pathcheck.go` 的 `ValidateFilePath`/`ValidateField`/`ResolveLocalPath`；executor 经 `fileops.HostEnv`/`BuildToolEnv`（读**自身进程环境** `CHONKPILOT_INSTANCE/WORKDIR/DATADIR`）`paths.SetTempRoot` 并注入**只读** DSL `env`（`{{env.CHONKPILOT_WORKDIR}}` 等 5 变量，**无裸名别名**），`script_run` 同时注入子进程环境并读 `CHONKPILOT_INTERPRETERS`。缺 `CHONKPILOT_INSTANCE` 且需要 `!/` 或 DSL env → **顶层失败**（`ErrNoInstance`，不回落 `default`）。**上下文经协议 `_meta` 从调用链透传、`CHONKPILOT_*` 仅内部 executor 进程可见（第三方 MCP server 无效）**。
- **唯一允许相对处** = CLI 命令行目录参数解析（`src/lib/paths.ResolveDir`，服务 `--work-dir`/`--data-dir`）。
- 新增工具/参数时一并遵守并写入契约 `[description]`；**DSL 类工具**（filesys_run/browser_run/desktop_run/llm_run）同步补 `env` 变量表与 `{{env.CHONKPILOT_WORKDIR}}` 显式拼接示例。详见 [16-路径解析规范](../10-architecture/16-路径解析规范.md) §8。

### Output 与 RawResult 设计原则

| 字段 | 设计原则 |
|------|---------|
| Output | 一句话摘要，不要 dump 大量数据 |
| RawResult | 结构化 JSON，供调用方程序化使用 |

### Handler 放哪里

| 位置 | 适用场景 |
|------|---------|
| `internal/fileops/` | 文件查找 / 读取 / diff / 批量编排（DSL） |
| `internal/scriptrun/` | 脚本执行 |
| `internal/fetch/` | web_fetch |
| `internal/browser/` | 浏览器自动化 |
| `internal/desktop/` | 桌面自动化 |
| 新建包 | 复杂独立逻辑 |

## 4. 注册到 dispatch table

在对应执行器主程的 `dispatch` switch 中绑定「工具名 → handler」（`core/main.go`、`browser/main.go`、`desktop/main.go`）：

```go
func dispatch(workDir, tool string, args map[string]interface{}) *cli.Result {
    switch tool {
    case "file_read":
        return fileops.HandleReadFile(workDir, args)
    default:
        return nil   // nil → cli.Run 归「unknown tool」
    }
}
```

> 不再有 `types.Wrap` / `types.DepthAware` 包装与深度参数；工具是否异步由契约 `[meta] async` 声明、gateway TaskManager 承担。

## 5. 写测试

```go
func TestHandleReadFile(t *testing.T) {
    // R-11：文件操作参数须为绝对路径或以 ~/ 开头（相对路径会被拒绝）
    abs := filepath.Join(t.TempDir(), "x.txt")
    os.WriteFile(abs, []byte("x"), 0o644)
    res := fileops.HandleReadFile("", map[string]interface{}{
        "files": []map[string]interface{}{{"path": abs}},
    })
    if !res.Success {
        t.Fatalf("file_read failed: %s", res.Error)
    }
}
```

测试文件与被测包同目录（`src/mcp-tools/internal/<pkg>/*_test.go`）。

## 6. 同步 / 异步 / 超时 / 取消 — 架构分层

### 6.1 核心理念

**工具 Handler 只需要做两件事：**
1. 解析参数并执行操作
2. 返回 `*cli.Result`

**框架负责：**
- 管理同步/异步分发（gateway TaskManager，按契约 `[meta] async` / `async-threshold`）
- 写库持久化（任务树）
- 返回结果给 LLM / 推送事件
- 超时判定与取消

### 6.2 完整的工具执行流程

```
LLM 发出 tool-call
    │
    ▼
① gateway Registry 路由 → mcp-server callTool
    │
    ▼
② mcp-server spawn 执行器 exe：<exe> <tool> --input=<params.json>
    │
    ▼
③ executor cli.Run：读 JSON → dispatch → handler
    │
    ▼
④ Handler 返回 *cli.Result
    │
    ▼
⑤ executor 把 Output（或 Error）原样写 stdout，退出码 0/1
    │
    ▼
⑥ mcp-server 判定 JSON / 封装 → gateway 回结果
    │
    ▼
⑦ 结果分发
    ├─ 同步：tool-result 事件返回 LLM
    └─ async（always / auto 超 async-threshold）：返回 pending{task_id}，
       后台经 task-started / task-updated / task-done 广播；
       LLM 用 tool_result(id) 取回
```

### 6.3 取消机制

- 异步任务登记在 gateway TaskManager，取消 = 触发其 `context.CancelFunc`（**2026-09-18 起经进程内 sink**：`ExecSink.CancelExec`，原 `tasks/cancel` 方法面已移除）
- 上层经 server 域工具 `tool_stop(task_id)` 级联取消子树；前端发 `task-stop` 消息
- 执行器 spawn-on-call、零状态；被取消时对应进程终止，任务状态置 `cancelled`
- **不存在**循环内 `args["cancel-flag"]` 协作式取消

### 6.4 工具 Handler 边界

| 该做的 | 不该做的 |
|--------|---------|
| ✅ 解析参数并执行操作 | ❌ 启动 goroutine 做后台任务 |
| ✅ 纯函数式：入参→出参 | ❌ 管理 task_id |
| ✅ 单次调用内完成并返回 | ❌ 处理超时回调 |
| ✅ 错误经 `Error` / 退出码表达 | ❌ 区分同步/异步模式 |

### 6.5 异步通知

- 异步任务终态经 `task-done` 广播（在 `task-started` / `task-updated` 之后）
- LLM 用域工具 `tool_result(id, timeout)` 获取完整结果（超时返回「任务尚未结束」，可再调）
- task_id / 任务节点持久化在库中，重启可恢复（tool-retry）

### 6.6 async-threshold 参考值

| 场景 | 建议值 |
|------|--------|
| 即时操作（读文件、搜索、截图） | 3-10 秒 |
| 中等耗时（编译、测试） | 30-120 秒 |
| 不确定耗时（下载、API 调用） | 10-30 秒 |
| 长驻进程（开发服务器） | 0（始终异步） |

## 7. 常见陷阱

### 陷阱 1：Output 太大
**解决：** Output 只放摘要，完整数据放 RawResult。

### 陷阱 2：RawResult 是空结构
**解决：** RawResult 包含调用方需要的所有结构化数据。

### 陷阱 3：忘记写契约
**解决：** 每个工具必须有对应的 `<name>.tool.md`，且 `[description]` 非空（否则 mcp-server 加载报错）。

### 陷阱 4：文件名与 tool name 不一致
**解决：** 文件名（不含 `.tool.md`）必须等于工具名（原语名 = 文件名）。

### 陷阱 5：CRLF 文件导致 replace 失败
**解决：** 用 Python 脚本处理，或使用 Write 工具重写整个文件。

### 陷阱 6：title 写成了 description 截断
**解决：** `title` 是独立编写的一句话标题，不是截断！

### 陷阱 7：忘了声明 runtime / args
**解决：** 执行层工具 `[meta]` 必须声明 `runtime` 与 `args`，否则执行器无法定位命令。

### 陷阱 8：Handler 里处理异步/超时
**解决：** 这些是框架层（gateway）的职责，Handler 只做「入参 → `*cli.Result`」。
