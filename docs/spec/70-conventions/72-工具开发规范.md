## 1. 开发一个工具需要改哪些文件

> 〔2026-11-04 核对：D-72 后口径〕内置 executor（`src/lib/mcp-tools/*`、`cmd/web-exec`、`cmd/script-exec`）与 `cli.Result` 已全部退场。现行工具 = **契约 + 实现 + MCP 注册 + 测试**；除 server 域 6 个由 core-mcp-server 内置外，出厂工具均由插件 MCP server 执行。

每个执行层工具由 4 个组成部分构成：

```
┌──────────────────────────────────────────────────────────────────┐
│  1. 契约（*.tool.md，H1 分区 v2）                                 │
│     （core 已无 server 域契约；仅插件域）                            │
│     插件域: chonkpilot-plugins/<plugin>/src/tools/<cat>/<name>.tool.md │
│     → # 基本信息(yaml) + # 摘要 + # 参数(json)                    │
│     → LLM 看到的参数签名 + 前端/框架所需元信息                     │
├──────────────────────────────────────────────────────────────────┤
│  2. Handler 实现（插件内）                                        │
│     <plugin>/src/...（实现包，如 file/src/lib/toolset、task 的 main.go）│
│     → 签名 pluginsdk.ToolFunc(ctx, args, cx) (any, error)         │
├──────────────────────────────────────────────────────────────────┤
│  3. 注册到插件 MCP server                                        │
│     p.Tool(name, desc, schema, handler) + p.HotTool(name)        │
│     或 file 插件：contract.Register(srv, tools, call) + p.MCPHot  │
├──────────────────────────────────────────────────────────────────┤
│  4. 测试                                                         │
│     <plugin>/src/**/*_test.go（同包/同目录）                       │
└──────────────────────────────────────────────────────────────────┘
```

> 契约文件名（不含 `.tool.md`）**必须等于工具 name**（原语名 = 文件名，见 [25-mcp-server](../20-modules/25-mcp-server.md)）。
>
> **现行完整例子** = `chonkpilot-plugins/task/src/tools/task/task_run.tool.md` + `task/src/main.go`（脚本执行实现已上收 `chonkpilot-util/scriptrun`，见 `task/src/main.go:191`）；`file` 插件（11 契约 + `contract.Register`）为另一标准形态。
>
> **已退场（D-72，2026-10-31）**：`chonkpilot-script-executor.exe` / `script_run`、`internal/{fileops,fetch}`、`internal/cli`、`cmd/web-exec`、executor stdout 协议。下文涉及处均标注「历史」。

## 2. 契约字段完整说明（*.tool.md）

**路径（2026-11-08 核对）：** 契约唯一源 = **插件域** —— core 侧 `src/lib/llm/contracts/` 已删除（2026-11-08；`ask_user` / `next_run` / `subchat_open` / `subchat_finish` 迁 task 插件，`tool_result` 删除，`tool_stop` 已于 2026-11-04 删除）。插件域 = `chonkpilot-plugins/<plugin>/src/tools/<cat>/<name>.tool.md`（**25 个**：crontab 6 / file 11 / task 8）。构建铺设：`build-desktop.ps1` / `build-mcp-server.ps1` **不再**投放 `capability/tools/server`（并清理旧产物）；`build-plugins.ps1` 仅将 `file` 契约拷到 `<pluginRoot>/tools/file/`，而 `task` / `crontab` 契约经 `//go:embed all:tools` 打进插件二进制（`task/src/main.go:37`、`crontab/src/main.go:32`）。

**完整格式（H1 分区 + 代码块，v2，2026-10-14）**——契约名 = 文件名去 `.tool.md`；`# 基本信息` 的 yaml 块承载 `name`/`title` 与类型专属键，`# 摘要` = 描述，`# 参数` = JSON Schema（详见 [25-mcp-server §3.1](../20-modules/25-mcp-server.md)）：

````text
# 基本信息
```yaml
name: file_read
title: 读取文件
runtime: builtin
hot: true
category: file
async: never
timeout: 120
idempotent: true
args: file_read --input={RAW-INPUT-FILE}
output: stdout
```

# 摘要
<给 LLM 看的完整说明>

# 参数
```json
{"type":"object","properties":{},"required":[]}
```

# 返回值
<可选：file_* / task_run 等使用；不是固定必需分区>
````

> 历史示例中的 `script_run` / `runtime: ../../executors/...exe` / `# 正文` 均为 D-72 前形态，保留仅作格式参考；新增工具按现行 `runtime: builtin|plugin` 与插件注册写法。

### 基本信息 yaml 字段明细

| 字段 | 给谁用 | 说明 |
|------|--------|------|
| `name` | 框架 / MCP | **必填且不可删**；= 文件名去 `.tool.md`；保存时校验**同级同类型唯一**。注册为工具名（契约名） |
| `title` | 前端 / MCP | 可读标题（MCP `Tool.Title`）。v2 起写在「基本信息」yaml 块（**原「首行 H1」**） |
| `category` | 前端过滤器 | 分类声明；缺省由契约根目录名派生。现行取值：`crontab` / `file` / `server` / `task` |
| `hot` | 框架 | 固定暴露标志（吸收旧 `llm`）；插件契约按 manifest 设为 `true`（task 插件 8 个工具均 `hot`）；core 已无契约 |
| `async` | 框架 | `auto`\|`always`\|`never`\|`manual`（缺省 auto）。**现状（2026-11-04 核对）：27 个契约全部 `never`**，异步档位暂无实际使用 |
| `async-threshold` | 框架 | 秒；`async=auto` 下超时自动转后台（当前契约未使用） |
| `idempotent` | 框架 | **可重试性声明位**：`true` = 该工具**可安全自动重试**（只读或幂等）；缺省 / `false` = **不可安全自动重试**（**安全默认**，如 `file_write`/`file_delete`/`task_run`/`web_fetch` POST）。透出为暴露 `_meta.idempotent=true`（**仅声明 `true` 时写**，缺失即 false）；将来若要加重试，判据 = `_meta.idempotent == true`。**声明优先**：只读/幂等工具显式声明 `true`（如 `file_read`/`file_find`）；有副作用工具写 `false`（与缺省等价，仅自文档化）。现行 10 true / 11 false（server 6 缺省=false） |
| `timeout` | 框架 / gateway | 秒；**执行硬上限**，并作为 **gateway 超时裁决点**的来源（`auto` 档未声明 `async-threshold` 时阈值回落它；`manual`/`never` 到点发 `mcp-tools-timeout` 交用户裁决）。**取值语义**：键**未设置**（缺失 / 空串）→ **回落**全局（prj `timeout_sec` / 内置 300s；gateway 回落全局 `CallTimeout`）；显式 **`0` / `-1` = 无上限**（永不超时、不设裁决点，永远等待、用户可取消）；正数 = 该值。**「无上限」绝对优先**：工具显式 `0`/`-1` 时，**调用级 / server 级 / 全局超时均不得覆盖**（该调用永不设裁决点）；仅**正数**时才保留「调用级 > server 级 > 工具 > 全局」链。**系统工具（`category=server`）不单独设执行硬上限** → 契约写 `timeout=0`（**`0` = 无上限**，**非**"回落"；`_meta.timeout=0` 显式透出，现行 6/6 server 契约如此）。权威口径见 [18 §3.8](../10-architecture/18-工具异步超时与取消.md) |
| `runtime` | 框架 / 插件 | **现行仅两种取值（27/27）**：`builtin`（17，进程内执行） / `plugin`（10，插件执行）。D-72 起内置 executor 已全部退场（`src/lib/mcp-tools` 为空壳），出厂工具均由插件 MCP server 或 core-mcp-server 执行；原「executor exe / PATH 名 / 解释器」写法已无契约使用，不得用于新增工具 |
| `args` | 执行器 / 插件 | 命令行模板（`{param}` / `{RAW-INPUT-FILE}` / `{RESULT-OUTPUT-FILE}`）；插件形态下保留声明但由插件解析 |
| `output` | 执行器 | `stdout`（21）\|`json`（6 server）\|`code`\|`file`（缺省 stdout） |
| `core-only` | 框架 | `true` = 只在 core-mcp-server 外部工具模式注册（现行仅 6 个 server 契约） |
| `entry` / `internal` | 框架 | 兼容读取字段：`entry` 已废弃（解释器类遗留）；`internal=true` = 仅作 core-mcp-server 内部执行器、不进 MCP `tools/list`。现行 27 契约均未使用 |

> **已删除死 meta**：`runtime-version` · `version` · `find`（解析与 `_meta` 透出均已移除，不再书写）。**标题链路 = 「基本信息」`title` → `Tool.Title`**。

### 命名规则

**强制规则：名词_动词**

所有新工具名必须遵循名词在前、动词在后的格式：

| ✅ 正确 | ❌ 错误 |
|---------|---------|
| `file_read` | `read_file` |
| `web_fetch` | `fetch_web` |
| `file_delete` | `delete_file` |

规则详解：
- 全小写 snake_case
- 第一个单词是名词（操作对象/领域）
- 第二个单词是动词（操作动作）
- 同一功能组共享名词前缀（如 `file_*`, `browser_*`）

**例外：** 已有工具名保持不动，避免破坏兼容性。

## 3. 实现 Handler

> 〔2026-11-04 核对〕`*cli.Result` 与 `src/lib/mcp-tools/internal/cli` **已不存在**（`src/lib/mcp-tools` 现为 0 文件空壳）。现行结果直接由插件 SDK 返回，不再有 executor 中间结构。

### 工具结果（插件 SDK）

现行插件工具签名为 `pluginsdk.ToolFunc`（`chonkpilot-framework/plugin/src/sdk/plugin.go:83`）：

```go
type ToolFunc func(ctx context.Context, args map[string]any, cx CallContext) (any, error)
```

- 返回 `(any, error)`：`any` 为工具结果（文本 / 结构化 JSON，由插件 MCP server 封装为 MCP content）；`error` 非 nil 表示工具失败。
- `CallContext` 携带 `instance_id` / `work_dir` / `data_dir` / `session` / `turn` / `tool_call_id` / `parent` / `purpose` / `sandbox` 等调用链上下文（JSON tag 为 snake_case）。
- `file` 插件内部中间层为 `call(ctx, name, args) (string, bool, error)`（文本 + 是否错误 + 错误），再经 `contract.Register` 适配为 MCP 工具；这是插件内部形态，不是跨插件契约。

### Handler 签名

```go
// 插件 SDK（现行统一签名）
func(ctx context.Context, args map[string]any, cx pluginsdk.CallContext) (any, error)

// file 插件内部（示例：业务分派）
func (f *filePlugin) call(ctx context.Context, name string, args map[string]any) (string, bool, error)
```

> 历史：`func HandleXxx(workDir string, args map[string]interface{}) *cli.Result` 为 D-72 前 executor 写法，已废止。

### 路径参数（R-11）

工具/DSL 的**所有输入/输出文件与目录参数**（含 DSL 内所有 `#"..."` 引用——数据源读取、落盘、目录操作）**必须是绝对路径、以 `~/` 开头的用户目录路径或以 `!/` 开头的临时目录路径**（`!/` → `<系统 temp>/chonkpilot/<instance>/`，按 instance 分目录）；相对路径 → 工具**整体失败**（错误状态，消息含原值、位置与示例）。

- **唯一实现**：`chonkpilot-framework/host/src/core/paths.ResolvePath(raw, "")` + `InvalidPathMessage`（底层 `chonkpilot-util/pathx`；`ResolveDir` 仅供宿主目录参数）。原 `src/lib/paths` 已不存在。
- 插件侧薄封装：`chonkpilot-plugins/file/src/lib/fileops/pathcheck.go` 的 `ValidateFilePath`/`ValidateField`/`ResolveLocalPath`；插件内 `file/src/lib/paths` 为 framework/core 的薄封装。执行期上下文经协议 `_meta`（`_meta.chonkpilot`）从调用链透传，`CallContext` 读取 `instance_id`/`work_dir`/`data_dir` 等；`CHONKPILOT_*` 环境变量仅内部进程可见（第三方 MCP server 无效）。
- **唯一允许相对处** = 宿主命令行目录参数解析（`core/paths.ResolveDir`，服务 `--work-dir`）。
- 新增工具/参数时一并遵守并写入契约「# 摘要」；带路径参数的工具（`file_*` / `task_run`）同步补 `env` 变量表与 `{{env.CHONKPILOT_WORKDIR}}` 显式拼接示例。详见 [16-路径解析规范](../10-architecture/16-路径解析规范.md) §8。

> 历史（已退场）：`internal/fileops`、`fileops.HostEnv`/`BuildToolEnv`、`CHONKPILOT_INTERPRETERS` 注入均为 executor 时代实现；`task_run` 的解释器解析现由 `chonkpilot-util/scriptrun` 自持。

### Output 与结构化结果设计原则

| 字段 | 设计原则 |
|------|---------|
| 文本结果 | 一句话摘要，不要 dump 大量数据（对应历史 `Output`） |
| 结构化结果 | 完整 JSON，供调用方程序化使用（对应历史 `RawResult`；脚本执行工具可另行落盘） |

### Handler 放哪里

| 位置 | 适用场景 |
|------|---------|
| 插件实现包，如 `chonkpilot-plugins/file/src/lib/toolset/` | 文件原语（同插件共享） |
| 插件 `src/main.go` | 胶水层：契约加载 → `p.Tool` / `contract.Register` 注册；轻量工具可直接在 main 内实现（如 `browser` / `desktop` / `mcp`） |
| `chonkpilot-util/*` | 可复用纯逻辑（如 `scriptrun`、`pathx`）；插件依赖，不反向依赖插件 |
| 新建插件 | 复杂独立能力（如 `crontab` / `task`） |

> 历史落点 `src/lib/mcp-tools/internal/{fileops,fetch}` 已退场；`fileops`/`fetch` 现位于插件仓或 util。

## 6. 同步 / 异步 / 超时 / 取消 — 架构分层

### 6.1 核心理念

**工具 Handler 只需要做两件事：**
1. 解析参数并执行操作
2. 返回结果 `(any, error)`（插件 SDK `ToolFunc`）

**框架负责：**
- 管理同步/异步分发（gateway 执行池 `execPool`，按契约「基本信息」`async` / `async-threshold`）
- 写库持久化（任务树）
- 返回结果给 LLM / 推送事件
- 超时判定与取消

> 〔2026-11-04 核对〕当前 27 个契约全部 `async: never`；异步能力由 gateway `execPool` 保留，待后续工具显式启用 `auto/always/manual`。

### 6.2 完整的工具执行流程（现行）

```
LLM 发出 tool-call
    │
    ▼
① gateway Registry 路由 → 插件 MCP server callTool
    │
    ▼
② 插件进程内：contract 取 schema → ToolFunc(ctx, args, cx)
    │
    ▼
③ Handler 执行并返回 (any, error)
    │
    ▼
④ 插件 MCP server 封装 MCP content → gateway 回结果
    │
    ▼
⑤ 结果分发
    ├─ 同步（现行全部）：tool-result 事件返回 LLM
    └─ async（auto/always/manual，契约显式声明时）：返回 pending{task_id}，
       后台经 task-started / task-updated / task-done 广播；
       LLM 用 task_status(task_id=…) 取回
```

> 历史（已退场）：`mcp-server spawn 执行器 exe：<exe> <tool> --input=...` → `executor cli.Run` → stdout JSON → mcp-server 封装。D-72 后无 process-per-call executor。

### 6.3 取消机制

- 异步任务登记在 gateway 执行池（`execPool`），取消 = 触发其 `context.CancelFunc`（`ExecSink.CancelExec`，原 `tasks/cancel` 方法面已移除；见 `chonkpilot-agent/gateway/src`）
- 上层经 `task-stop` 消息面级联取消子树（**`tool_stop` 已删除（2026-11-04，`task_stop` 为唯一停止入口）**）；前端发 `task-stop` 消息
- 插件调用随 context 取消；任务状态置 `cancelled`
- **不存在**循环内 `args["cancel-flag"]` 协作式取消

### 6.4 工具 Handler 边界

| 该做的 | 不该做的 |
|--------|---------|
| ✅ 解析参数并执行操作 | ❌ 启动 goroutine 做后台任务 |
| ✅ 纯函数式：入参→出参 | ❌ 管理 task_id |
| ✅ 单次调用内完成并返回 | ❌ 处理超时回调 |
| ✅ 错误经返回 `error` 表达 | ❌ 区分同步/异步模式 |

### 6.5 异步通知

- 异步任务终态经 `task-done` 广播（在 `task-started` / `task-updated` 之后）
- LLM 用 `task_status(task_id=…, waitSec=…)` 获取完整结果（运行中返回状态 + 已产出部分输出）
- task_id / 任务节点持久化在库中，重启可恢复（tool-retry）

### 6.6 async-threshold 参考值

> 现行契约全部 `async: never`，下表为启用异步时的建议值（框架能力保留）。

| 场景 | 建议值 |
|------|--------|
| 即时操作（读文件、搜索、截图） | 3-10 秒 |
| 中等耗时（编译、测试） | 30-120 秒 |
| 不确定耗时（下载、API 调用） | 10-30 秒 |
| 长驻进程（开发服务器） | 0（始终异步） |

## 7. 常见陷阱

### 陷阱 1：结果太大
**解决：** 文本结果只放摘要，完整数据以结构化结果返回或落盘。

### 陷阱 2：结构化结果为空
**解决：** 结构化结果包含调用方需要的所有数据。

### 陷阱 3：忘记写契约
**解决：** 出厂分类工具必须有对应的 `<name>.tool.md`，且「# 摘要」非空（否则加载报错）。`browser` / `desktop` / `mcp` 现无契约（历史欠账），新增同类工具不得再缺。

### 陷阱 4：文件名与 tool name 不一致
**解决：** 文件名（不含 `.tool.md`）必须等于工具名（原语名 = 文件名）。

### 陷阱 5：CRLF 文件导致 replace 失败
**解决：** 用 Python 脚本处理，或使用 Write 工具重写整个文件。

### 陷阱 6：标题写错位置 / 与原语名相同
**解决：** 工具标题（`Tool.Title`）= 「**基本信息**」yaml 块的 `title` 键；**不再**用旧 `[meta] title` 键或首行 H1。标题要与原语名区分。**现状（2026-11-04 核对）：6 个 server 契约 `title == name`**，属待改存量。

### 陷阱 7：忘了声明 runtime / args / timeout
**解决：** 契约「基本信息」必须声明 `runtime`（现行 `builtin|plugin`）、`args`、`timeout`（server 域 `0` = 无上限），否则框架无法正确调度。

### 陷阱 8：Handler 里处理异步/超时
**解决：** 这些是框架层（gateway）的职责，Handler 只做「入参 → `(any, error)`」。
