## 2. 视角清单（17）

### 2.1 固定视角（①~⑦，§2.11 建立）

| # | 视角 | 检查要点 | 典型问题类别 |
|---|---|---|---|
| ① | **安全** | 注入、越权、路径穿越、敏感信息泄漏、不安全反序列化、免鉴权面、脚本注入 | 越界读写、可伪造身份、token 落日志 |
| ② | **性能** | N+1 查询、无界内存、锁竞争、热路径分配、重复计算、全量扫描 | 串行往返放大、全链重放、强制布局 |
| ③ | **架构/分层/耦合/边界/依赖方向** | 层间越界、循环依赖、依赖方向倒置、边界职责不清 | 上层依赖下层实现、旁路绕过门面 |
| ④ | **冗余/无用/相似代码** | 重复实现、死代码、相似分叉未收敛、注释与实现不符 | 同构逻辑两处各写一份 |
| ⑤ | **潜在缺陷** | 并发竞态、错误处理、边界条件、空指针/越界、锁序 | 无锁读写、切片越界 panic |
| ⑥ | **用户体验** | 错误提示可见性、状态一致性、误导性空态、失败无反馈 | 静默失败、状态不回滚 |
| ⑦ | **生命周期管理正确性** | 配对创建/关闭、订阅/退订对称、启停对称、收尾清理、泄漏检测、context 取消传播 | 句柄/map 只增不删、订阅残留 |

### 2.2 深化视角（⑧~⑬，§2.12 建立）

| # | 视角 | 检查要点 | 典型问题类别 |
|---|---|---|---|
| ⑧ | **前端配置项后端未使用** | 前端可改但后端从不读的悬空配置 | 改了不生效的开关 |
| ⑨ | **后端配置值无编辑修改入口** | 有默认值/读取点但无写入入口的硬编码配置 | 死配置字段 |
| ⑩ | **高并发引起的阻塞和错误** | 锁争用、串行瓶颈、队列积压、超时、持锁跨 I/O | 持锁期间做总线往返 |
| ⑪ | **调用链路精简度** | 跨层链路过长、多余中转、重复查询、可合并往返 | 同一配置源重复读 |
| ⑫ | **错误及异常吞没** | err 被忽略/仅 log 不处理/静默 return/错误被覆盖 | `_ =` 吞掉失败 |
| ⑬ | **错误异常后继续处理致数据完整性破坏** | 出错后未中止而继续写/推进状态，产生半成品、字段错乱、跨表不一致 | 落库失败仍起状态机 |

### 2.3 新增视角（⑭~⑰，2026-10-09 用户拍板）

| # | 视角 | 检查要点 | 典型问题类别 |
|---|---|---|---|

## 3. 使用方法

1. **分区并行**：按模块分区（A~F 或按需），每区在各视角上过一遍；新增视角 ⑭~⑰ 建议**专项**做（不必每轮全跑，以免稀释）。
2. **排除基线**：先读 42-决策记录相关小节（§2.9~最新）与新近 `git diff`，已修/保留口径/豁免/剔除项**不得重报**；61 消息面的 msg/payload 不得增删改（「建议改消息面」判误报，「代码未按 61 实现」可报）。
3. **双校验**：候选经 2 名独立校验员逐条实读复核（存在性/严重度/误报/口径冲突），主控仲裁分歧。
4. **实读为凭**：每个候选必须给路径 + 行号 + ≤5 行代码摘录；禁止臆测。

## 4. 级别定义

| 级别 | 含义 |
|---|---|
| **P1** | 致命：数据丢失/损坏、崩溃、安全漏洞 |
| **P2** | 一般：功能缺陷、明确泄漏、竞态、可靠性问题 |
| **P3** | 轻微：健壮性/一致性/可维护性 |

---

## 5. 收敛判据

「每轮都有问题」不等于未收敛。应看的指标：

1. **P1 数量逐轮归零**；
2. **P2 数量单调下降**；
3. **新增视角不再检出 P1/P2**（若新视角持续检出 P1/P2，说明该面确实此前未覆盖）；
4. **修复回归率下降**（修复引入的新问题 / 修复项数）。

> **收敛公式**：`整体收敛 = ∀视角各自收敛 ∧ 修复零回归 ∧ 同族全扫`
> 单纯增减视角数**都达不到收敛**——真正的杠杆是「修一处必扫同族」与「修复后必跑全量验证」。

## 6. 配套纪律（每轮必做）

- **同族扫描**：每修一处，按该问题的**模式**全仓扫同族（如：修了 A 域的 symlink 复验 → 扫全部写路径；修了 B 处的探测收尾 → 扫全部同类调用点）。同族漏网是历轮重复检出的首要来源。
- **修复后全量验证**：全仓 `go test` + 前端 `npm test` + `build-*.ps1`。这是唯一有效的回归防线（历轮已捕获多处修复引入的回归）。
- **文档同步**：行为/契约变更须同步 42-决策记录、61（如涉及消息面）、对应模块文档。
- **P3 两档**：区分「必修」与「仅登记」，避免轻微项淹没收敛信号。
