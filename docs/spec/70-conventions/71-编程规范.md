## 1. Constants & 配置规范

### 1.1 常量优先原则

所有魔数（magic number）和魔字符串（magic string）必须定义为命名常量。

**❌ 禁止：**
```go
workDir := filepath.Join(a.workDir, ".chonkpilot")
```

**✅ 正确：**
```go
const UserConfigDirName = ".chonkpilot"
workDir := filepath.Join(a.workDir, UserConfigDirName)
```

**例外：** 单次使用的 `fmt.Errorf` 错误消息字符串、`log.Println` 调试输出。

### 1.2 路径常量的集中管理

- 文件系统路径常量统一放在 `src/lib/gui/models/consts.go`（如 `UserConfigDirName`）或各模块 `consts.go`
- 不要分散在 `main.go`、`bridge/*.go`、`config.go` 等各处定义
- 命名规则：`Dir<Name>`（目录名）、`File<Name>`（文件名）、`Path<Name>`（完整路径）

### 1.3 超时/限制常量

```go
// 单轮工具循环上限（provider 未显式配置时生效）
const defaultMaxToolIterations = 20   // src/lib/llm/server/turn.go
```

- 各工具的超时 / 异步阈值不走全局常量，而在契约 `[meta]` 中声明：`timeout`（秒）、`async-threshold`（秒，`async=auto` 下超时自动转后台）。

## 2. 包组织结构

### 2.1 多模块结构（单体 exe = 多模块串联）

```text
chonkpilot/                 # monorepo，每模块独立 go.mod，一律 replace ../
├── src/frontend/    # 前端源码工程（Vue3，仓库级）
├── src/lib/         # 库：core（mq/dsl/paths/winlog/winsvc/exedir，零本仓库依赖）+ gui（宿主实现）
│                    #     + data / filesys / task / llm / gateway / mcp-server / mcp-tools
├── src/desktop/     # 桌面单体宿主壳（main.go 薄壳 → lib/gui.Main；cli/ = CLI 单体）
├── src/gui/         # GUI 客户端宿主壳（main.go 薄壳，-tags split；frontend/dist = 客户端 embed 落点）
├── src/server/      # 独立 server 外壳（gui / browser 共用）
├── src/others/      # 协议外壳：mcp-server / mcp-gateway 两个 exe
├── src/plugins/     # 插件与引擎：plugin* + codegraph / vfts
└── src/test/        # 测试工程（unittest / systest / llmproxy）
```

> 〔D-28 结构重整：旧 `src/{gui(宿主),cli,llm,data,filesys,task,mcp-server,mcp-tools,gateway,plugin*,codegraph,vfts}` 已归位为 `src/{lib/*,plugins/*,others/*}`；宿主壳拆为 `src/desktop`（单体）+ `src/gui`（客户端），实现唯一一份在 `src/lib/gui`。〕

### 2.2 依赖方向（单向）

```text
src/{desktop,gui,server,others} 壳 → src/lib/gui（宿主实现）→ src/lib/llm → src/lib/gateway → src/lib/mcp-server
                                                                 → src/lib/data / src/lib/core / src/lib/filesys
所有模块 → src/lib/core   # 零本仓库依赖的公共底座
```

- 依赖方向全部单向（**壳 → lib**），模块依赖矩阵见 [10-分层与依赖](../10-architecture/10-分层与依赖.md) §1/§3
- **禁止** `src/lib/data` 引用 `src/lib/llm`（反向依赖）
- **禁止** 会话层绕过 gateway 直调 executor / 工具实现（跨组件一律 MQ）

## 3. 错误处理规范

### 3.1 错误包装

```go
// ✅ 正确：使用 fmt.Errorf + %w 包装上下文
if err != nil {
    return nil, fmt.Errorf("open chonkpilot.db: %w", err)
}

// ❌ 禁止：裸返回
return err

// ❌ 禁止：只加前缀不加 %w
return fmt.Errorf("open chonkpilot.db: %v", err)  // 丢失错误链
```

### 3.2 哨兵错误（Sentinel Errors）

```go
var (
    ErrScenarioNotFound = errors.New("scenario not found")
    ErrInvalidConfig    = errors.New("invalid configuration")
)

// 使用 errors.Is() 判断
if errors.Is(err, ErrScenarioNotFound) { ... }
```

## 4. 命名规范

### 4.1 Go 命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 包名 | 小写，单数 | `data`, `mq`, `models` |
| 文件命名 | `snake_case.go` | `project_config.go` |
| 导出的类型/函数 | `PascalCase` | `ScenarioConfig`, `GetAllScenarios()` |
| 未导出 | `camelCase` | `handleReadFile()` |
| 常量 | `PascalCase` | `UserConfigDirName` |
| 接口 | `PascalCase` + `er` 后缀 | `StorageProvider` |
| JSON 标签 | `camelCase` | `json:"systemPrompt"` |
| 测试文件 | `_test.go` | `db_test.go` |

### 4.2 Vue 前端命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 组件名 | `PascalCase.vue` | `MemoryPane.vue` |
| 文件名 | `PascalCase.vue` | `AgentEditor.vue` |
| props | `camelCase` | `:isMain="true"` |
| 事件 | `kebab-case` | `@update:agent` |
| CSS class | `kebab-case` | `.agent-list-panel` |
| 目录名 | `kebab-case` | `filetree/`, `codeview/` |

### 4.3 数据库命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 表（桶）名 | `snake_case`，复数 | `scenarios`, `sessions`, `turns`, `messages` |
| 列名 | `snake_case` | `session_id`, `created_at` |
| 主键 | 记录主键（桶内 key） | `data.KeyField`（`_key`） |
| 外键 | `<表名>_id` | `session_id`, `turn_id` |
| 时间戳 | `created_at`, `updated_at` | RFC3339 字符串（固定 9 位纳秒保序） |

## 5. 数据库规范

> 引擎为 **bbolt**（纯 Go、单文件、无 CGO），非 SQL：`src/lib/data` 的 `DB` / `Table`（通用 DAO）。

### 5.1 连接管理

```go
// ✅ 正确：Open 一次，传入 *data.DB / *data.Table
db, err := data.OpenLayer(path, data.LayerPrj)
if err != nil {
    return err
}
defer db.Close()
sessions := db.Table("sessions")   // 业务经 Table DAO 读写

// ❌ 禁止：每次 DAO 操作里自 Open/Close
func ListSessions(workDir string) {
    db, _ := data.OpenLayer(...)   // 谁调用的？连接生命周期不清晰
    defer db.Close()
}
```

### 5.2 Migration 策略

- 所有迁移集中定义在 `src/lib/data/migrate.go` 的 `migrations`（版本号 + `Up(tx)`）
- `OpenLayer` 按 `readSchemaVersion` 依次执行未应用迁移
- 建表（建桶）统一走迁移 / `ensureBucket`，禁止在业务代码中混入建表逻辑

## 6. 事件/通信规范

### 6.1 主题命名（MQ）

相对主题 = `<域>-<动作>`，全小写 **kebab-case**（宿主注入前缀 `chonk.` 后成全主题）；文件域为多段 `filesys.*`。

```text
session-start       session-cancel      task-done
instance-register   session-ask         prompt-optimise
data-prj-security-list                  filesys.changed（多段）
```

### 6.2 通信方向

```text
前端 ──mq.emit(topic,payload)（本地按 order 分发 + POST /publish）──→ Go 后端
Go 后端 ──WebView2 Eval：window.mq.emitRemote(envelope)──→ 前端（mq.on 订阅）
executor exe ──stdout 统一 JSON──→ mcp-server（spawn-on-call）
Go 组件间 ──src/lib/mq──→ Go 组件
```

> 消息全量清单与 payload 明细以 [61-消息一览](../60-reference/61-消息一览.md) 为唯一准则；**不存在 Wails**。

## 7. 前端状态管理

### 7.1 组件通信

- 父子通信：`props` ⬇ + `emits` ⬆
- 跨层通信：MQ 总线 `utils/mq.js`（`mq.emit` / `mq.on`），事件名清单集中在 `src/events/event-names.js`
- 状态逻辑：优先用 `useXxx` composables（`src/composables/`）封装；**禁止**在组件中用 `watch`/`watchEffect` 监听 props 或 store
- 全局状态：单例 Manager（`utils/askUserManager.js`、`utils/sessionMessages.js`）
- 禁止：`provide/inject` 乱用，必须注释说明 why

### 7.2 API 调用

- 所有后端调用通过 `src/api/` 下的模块封装（内部经 `utils/mq.js` / `utils/dataClient.js`）
- 禁止在组件中直调 `window.go.*`，或直接拼 `POST /publish`

## 8. 代码组织规约

### 8.1 文件职责（`src/lib/gui` 宿主实现 / `bridge/`；两个壳 `src/desktop` / `src/gui` 只嵌 dist + 传形态）

| 文件 | 职责 |
|------|------|
| `main.go` | 宿主入口 `Main(distFS, Options{Form})`：WebView2 启动、静态资源、`POST /publish` 接线 |
| `bridge/bridge.go` | MQ 桥接：宿主→前端 `Eval(emitRemote)`、前端→后端 publish 分发 |
| `bridge/guimsg.go` | `gui.*` / `system.*` 宿主级消息处理 |
| `bridge/data.go` | 数据层转发（`data-*` 消息） |
| `bridge/builtins.go` | 系统内置 MCP 项（exe 同目录 `config.json` 的 `mcpServers`） |
| `bridge/upload.go` | 文件上传 / 下载 |
| `bridge/{capture,local,compat,optimize,toolchain}.go` | 抓屏、本地文件、兼容事件、优化、工具链 |
| `models/*.go` | 数据模型与常量（`models/consts.go` 等） |

- **每个文件不超过 500 行**，超出则考虑拆分子包
- **每个函数不超过 80 行**，超出则拆内部辅助函数

### 8.2 前端组件组织

```text
src/frontend/src/     # 〔订正：原 frontend/src/ —— 前端工程已独立为 src/frontend，路径迁移〕
├── views/         # 页面级视图（chat/ scenario/ config/ settings/ filetree/ codeview/ tasks/ …）
├── components/    # 通用组件（ui/ common/ dialog/ tabs/ split/ task/ icon/）
├── composables/   # useXxx 状态 composables
├── utils/         # mq / dataClient / fileTree / askUserManager / sessionMessages
├── events/        # event-names.js（事件名清单）
├── api/           # 后端调用封装
├── locales/       # 前端多语言资源
└── plugins/       # i18n 等
```

## 9. 安全规范

### 9.1 API Key 管理

- API Key 存 usr 库 `llms` 表（password 输入）；**不再**存 `config.json`
- 禁止硬编码在代码中
- 禁止存入 `<workDir>/.chonkpilot/chonkpilot.db`（项目级别共享 DB）
- 禁止 log 中输出完整 key（只允许显示 `sk-****`）

### 9.2 文件路径安全

- 所有路径拼接使用 `filepath.Join()`，禁止字符串拼接
- 路径遍历攻击防护：用户传入路径必须 `filepath.Clean` + 检查是否在 workDir 内

## 10. 测试规范

- 数据库操作测试使用 `t.TempDir()` 创建临时目录
- 避免对外部 LLM API 的真实调用（mock）
- 测试文件与被测文件同目录，命名 `*_test.go`
- 关键路径必须有测试：db CRUD、Turn 循环、工具 Dispatch

## 11. 禁止清单

| # | 禁止行为 | 原因 | 替代方案 |
|---|---------|------|---------|
| 1 | 魔字符串作为路径/配置值 | 改一处漏十处 | 定义为包级别常量 |
| 2 | 裸 return err | 丢失调用栈上下文 | `fmt.Errorf("...: %w", err)` |
| 3 | 变量名拼音（如 `xingming`） | 不可读 | 英文全称 |
| 4 | 组件超过 500 行 | 难以维护 | 拆分子组件 |
| 5 | 在前端组件中直调 `window.go.*` 或直接拼 `POST /publish` | 不可测试、紧耦合 | 通过 `src/api/`（内部 mq）封装 |
| 6 | 多个文件定义同一常量 | 不一致 | 集中到 `consts.go` |
| 7 | 在 DAO 中自 Open/Close | 连接泄露 | 传入 `*data.DB` / `*data.Table` |
| 8 | 混用 snake_case 和 camelCase 做 JSON tag | 前端对接混乱 | 统一 camelCase |

## 12. 开发环境与文件修改

### 12.1 Go 编译环境

```powershell
$env:GOROOT="e:\GoDev\go1.26"
$env:Path = "e:\GoDev\go1.26\bin;" + $env:Path
$env:GOPROXY="https://goproxy.cn,direct"
```

> 与根目录 4 个 `build-*.ps1` 保持一致（脚本内统一用 `e:\GoDev\go1.26`）。

### 12.2 文件内容修改（严禁违规）

- **禁止**用 PowerShell 的 `>`、`Set-Content`、`Out-File`、`-replace` 修改代码文件；必须用编辑器工具（Write / Edit / SearchReplace）。
- 含非 ASCII 字符的文件写入必须 `[System.IO.File]::WriteAllText` + **显式 UTF8**（无 BOM）。
- **例外 —— 根目录 `build-*.ps1` 构建脚本**：必须保存为 **UTF-8 with BOM**（`EF BB BF`，PowerShell 5.1 兼容）。无 BOM 时 PowerShell 5.1 按 GBK 解码，脚本内中文引号被吞 → 报「字符串缺少终止符」并中断构建。
