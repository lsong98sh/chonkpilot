## 1. Constants & 配置规范

### 1.1 常量优先原则

所有魔数（magic number）和魔字符串（magic string）必须定义为命名常量。

**❌ 禁止：**
```go
workDir := filepath.Join(a.workDir, ".chonkpilot")
```

**✅ 正确：**
```go
const UserConfigDirName = ".chonkpilot"
workDir := filepath.Join(a.workDir, UserConfigDirName)
```

**例外：** 单次使用的 `fmt.Errorf` 错误消息字符串、`log.Println` 调试输出。

### 1.2 路径常量的集中管理

- 公共路径常量统一放在 `chonkpilot-framework/host/src/models/consts.go`（如 `UserConfigDirName`，其字面量来源 = `lockfile.ProjectDataDirName`）或各模块 `consts.go`；包内专用目录名就近放在包内（如 `src/lib/data/internal/capfs` 的 `DirMcps` / `DirSystem`）
- 不要分散在 `main.go`、`bridge/*.go`、`config.go` 等各处定义
- 命名规则：`Dir<Name>`（目录名）、`File<Name>`（文件名）、`Path<Name>`（完整路径）
- **现状 / 待改进（2026-11-04 核对）**：主仓 `src/lib` 下已无 `consts.go`（原 `src/lib/gui/models` 已迁出）；`.chonkpilot` 字面量仍有约 62 处、公共路径常量尚未完全收口。此项为**目标规范**，不表示现状已达成。

### 1.3 超时/限制常量

```go
// 单轮工具循环上限（provider 未显式配置时生效）
const defaultMaxToolIterations = 20   // src/lib/llm/server/turn.go
```

- 各工具的超时 / 异步阈值不走全局常量，而在契约「基本信息」yaml 中声明：`timeout`（秒）、`async-threshold`（秒，`async=auto` 下超时自动转后台）。

## 3. 错误处理规范

### 3.1 错误包装

```go
// ✅ 正确：使用 fmt.Errorf + %w 包装上下文
if err != nil {
    return nil, fmt.Errorf("open chonkpilot.db: %w", err)
}

// ❌ 禁止：裸返回
return err

// ❌ 禁止：只加前缀不加 %w
return fmt.Errorf("open chonkpilot.db: %v", err)  // 丢失错误链
```

> **现状 / 待改进（2026-11-04 核对）**：`%w` 包装约 89 处，但裸 `return err` 仍有约 160 处（如 `src/lib/data/backup.go`）。本规范仍为要求项，现状未普遍遵守，按待改进登记。

### 3.2 哨兵错误（Sentinel Errors）

```go
var (
    ErrScenarioNotFound = errors.New("scenario not found")
    ErrInvalidConfig    = errors.New("invalid configuration")
)

// 使用 errors.Is() 判断
if errors.Is(err, ErrScenarioNotFound) { ... }
```

### 3.3 异常与重启恢复（强制设计项）

> **规则级别：强制。** 异常与重启恢复是**需求的一部分**，不是实现细节。任何**有状态**的功能（会话 / 轮次 / 工具执行 / 异步任务 / 队列 / 缓存 / 插件 worker），在需求与设计阶段都必须同时给出「异常」与「重启恢复」两节；缺失视为设计未完成。

设计时必须逐条回答：

| # | 必答问题 | 不合格示例 |
|---|---|---|
| 1 | 状态落在哪：哪些在内存、哪些已持久化？崩溃瞬间会丢什么？ | 「存在 map 里就行」 |
| 2 | 用户输入是否**受理即持久化**？ | 只放内存 channel / 队列，崩溃即丢 |
| 3 | 非终态（`pending` / `running` / `provisional`）由谁收口？ | 崩溃后留下悬挂的 running |
| 4 | 重启后是**重建内存态**还是**收敛到终态后继续**？ | 含糊其辞，「应该能恢复」 |
| 5 | 副作用语义：至少一次 / 至多一次？重复回执或重试会不会重复执行？ | 不定义，导致重复写 / 重复发 |

配套硬约束：

- 每个新增的持久化状态字段，必须有**明确的收口 / 清理路径**（启动清理、看门狗、或显式恢复）。
- 每条异步链路必须有**超时兜底**，且兜底动作**幂等**。
- **禁止**用纯内存队列承载「不可丢」输入（用户消息、工具结果、插话）。
- 「异常中断 → 重启 → 恢复」必须至少有一条 L1 / L2 测试（mq 驱动 + mq 断言）。
- 设计文档必须包含「边界与异常」「重启恢复」两节；缺失即不通过设计评审。

#### 3.3.1 有状态能力：turn / 帧栈 / ask / inbox / 事件日志

> 落地答案见 [21-llm-server §12 恢复](../20-modules/21-llm-server.md)（MOD-1，2026-10-20）。**五问必须逐条回答，不得以「已收敛」「应该能恢复」代替。**

| 能力 | 持久化落点 | 收口 / 恢复路径 |
|------|-----------|----------------|
| turn 运行态 | 内存（`turnCtx` / 引擎 `TurnState`）；事件游标落 `turn_events`（prjusr，`data-turn-event-append`） | 启动 `CleanupStaleTurns` → 非终态收敛 `interrupted`；事件日志按 `turnEventLogRetentionDays` 清理 |
| 插话帧栈 | 内存帧栈（LIFO / 深度 5）+ `inbox_items`（pending 拉回、不自动发送） | 崩溃不重建帧栈；inbox `pending` 保留，`consumed`/`discarded` 按 7 天清理 |
| ask_user | `messages.ask_id`（**仅 ask 行**，**不建 ask 表**）+ `data-ask-pending` 回查 | 启动扫描未答 ask；未知/失效 `ask_id` 回执**不静默**（已终态明确失败 / 非终态转普通 user 消息开新轮）；答案即 tool result（回填即落库，不重问） |
| inbox 消费 | `data-inbox-commit`：消息 + `consumed` **同事务**；主键 `M-INBOX-<inbox_id>` | 重试幂等（至多一次）；`discarded` 拒绝；消除「消息已落、inbox 未消费」重复窗口 |
| 事件日志 | `turn_events`（schema v11；`none`/`minimal` 不可重放） | 写入同 `turn_id`+`seq` 幂等；仅删**终态且超保留期**的 turn |

- **副作用语义**：inbox 至多一次；ask 答案即 tool result（落库后重启可续）；工具按 `tool_call_id` 幂等回填，不重派发已完成工具。
- **当前边界（如实）**：生产仍走 `turnCtx`；帧栈「继续」与跨进程重建随 chat 引擎生产切换启用，当前崩溃语义 = 收敛到终态 + 保留已落库消息。

### 5.2 建桶策略（**无迁移体系**）

- **现状事实（2026-10-25 决策，2026-11-04 核对）**：本项目**没有版本迁移体系**。不存在 `src/lib/data/migrate.go`，也不存在 `readSchemaVersion`；打开库时由 `src/lib/data/buckets.go` 的 `bucketsFor` 按层**直接建桶**，缺桶即建。
- 表 / 索引的写入口自身走 `CreateBucketIfNotExists`，运行期新增表也能自愈；因此不需要「版本号 + Up」的迁移框架。

## 7. 前端状态管理

### 7.1 组件通信

- 父子通信：`props` ⬇ + `emits` ⬆
- 跨层通信：MQ 总线 `@ckfw/utils/mq.js`（实际文件 `chonkpilot-framework/host/web/src/utils/mq.js`；主仓前端经 `src/main.js:9` 别名引用，`vite.config.js` 同步 alias），`mq.emit` / `mq.on`；事件名清单集中在 `src/frontend/src/events/event-names.js`
- 状态逻辑：优先用 `useXxx` composables（`src/composables/`）封装；**禁止**在组件中用 `watch`/`watchEffect` 监听 props 或 store
- 全局状态：单例 Manager（`src/frontend/src/utils/askUserManager.js`、`src/frontend/src/utils/sessionMessages.js`）
- 禁止：`provide/inject` 乱用，必须注释说明 why

### 7.2 API 调用

- 所有后端调用通过 `src/api/` 下的模块封装（内部经 `utils/mq.js` / `utils/dataClient.js`）
- 禁止在组件中直调 `window.go.*`，或直接拼 `POST /publish`

### 7.3 函数式 ref / 量测写入（**禁自触发渲染**）

**约束（2026-10-16，UILAYOUT-1 P4 阻断修复）**：函数式模板 ref（`:ref="fn"`）**不是只在挂载/卸载时调用** —— Vue 在 `renderer#patch` 末尾对每个被 patch 的 vnode 无条件 `setRef`，函数式 ref **每轮重渲染都会重入**。因此：

- ref 回调里的量测（`getBoundingClientRect()` 等）写 reactive 状态时**必须幂等**：值未变**不得**写（先比较再赋值）。否则「渲染 → ref 回调 → 写 reactive → 触发渲染」形成**微任务级无限更新循环**：开发版 Vue 会抛 `Maximum recursive updates exceeded`，而**生产版无该守卫 → 页面主线程永久卡死**（WebView2 下 `ExecuteScript` 一律超时、窗口无响应）。同口径参考实现：`chonkpilot-framework/host/web/src/layout-free/components/ui/LfDropdown.vue#measure`（比较后写）、`.../tabs/LfTabbedContainer.vue#computeMorePop`（主仓 `src/frontend/src/layout-free` 已不存在，布局机制层随 framework 迁出）。
- 「挂载即量测（替代 `watch(打开态)`）」本身仍是正确做法（§4.2 禁 `watch`）；问题只在**写入不幂等**。

### 7.4 `v-mq` 载荷协议（宿主指令 ≡ 机制层指令）

- 宿主指令（`chonkpilot-framework/host/web/src/utils/mq.js`，主仓经 `@ckfw/utils/mq.js` 引用）与机制层内置指令（`chonkpilot-framework/host/web/src/layout-free/utils/mq.js`）**同协议**：触发模式下绑定值为**函数**时，在事件时刻求值 `(e, instance)` 并以其返回值作为载荷；非函数则原样作载荷；载荷从**最新** binding 读取（`updated` 刷新，避免 v-for 复用节点的 stale payload）。
- `layout-free/engine.js#install`（framework 内）判定「宿主已装 `v-mq` → 复用」即建立在此协议等价之上；**改动任一侧的载荷语义必须两侧同步**，否则机制层模板的 `v-mq:[t].click="() => payload"` 会把**函数对象**当载荷发出（订阅方读字段全为空 → 「点了没反应」）。

## 9. 安全规范

### 9.1 API Key 管理

- API Key 存 usr 库 `llms` 表（password 输入）；**不再**存 `config.json`
- 禁止硬编码在代码中
- 禁止存入 `<workDir>/.chonkpilot/chonkpilot.db`（项目级别共享 DB）
- 禁止 log 中输出完整 key（只允许显示 `sk-****`）
- **现状 / 待改进（2026-11-04 核对）**：`chonkpilot-util/redact`（`Mask` / `Text` / `IsSecretName`）已存在，但全仓暂无 import，日志脱敏尚未统一接入。

### 9.2 文件路径安全

- 所有路径拼接使用 `filepath.Join()`，禁止字符串拼接
- 路径遍历攻击防护：用户传入路径必须 `filepath.Clean` + 检查是否在 workDir 内

### 9.3 输入校验（写侧复验，INPUTVAL-1）

- **任何落库 / 落盘的输入都必须后端写侧复验**（前端 `maxlength` / 提示只改善体验，不构成信任边界）。
- 超限 / 非法 → **整批拒绝**并返回明确错误（含字段名与上限定值），**禁止截断、禁止静默丢弃**；事务失败不得破坏旧数据。
- 字段基线常量**单一来源**：后端 `src/lib/data/internal/config/validate.go`（`MaxNameChars=64` / `MaxTitleChars=128` / `MaxURLChars=2048` / `MaxPathChars=512` / `MaxTextChars=262144` 等）；前端同源规则 `src/frontend/src/utils/fieldRules.js`。新增字段必须同时补两处 + 测试。
- 空值语义按字段显式定义（如 LLM `model`/`baseUrl` 空 = 继承系统默认、`maxOutputToken=0` = 显式未设置、`responseTimeout/streamTimeout` 必须 >0），并在 [64-配置项一览](../60-reference/64-配置项一览.md) / [12 §4.4](../10-architecture/12-数据层.md) 留痕。
- 读侧保持既有兜底（兼容存量脏数据），**不得**因新增写侧校验而让历史数据不可读。

## 11. 禁止清单

| # | 禁止行为 | 原因 | 替代方案 |
|---|---------|------|---------|
| 1 | 魔字符串作为路径/配置值 | 改一处漏十处 | 定义为包级别常量 |
| 2 | 裸 return err | 丢失调用栈上下文 | `fmt.Errorf("...: %w", err)` |
| 3 | 变量名拼音（如 `xingming`） | 不可读 | 英文全称 |
| 4 | 组件超过 500 行 | 难以维护 | 拆分子组件 |
| 5 | 在前端组件中直调 `window.go.*` 或直接拼 `POST /publish` | 不可测试、紧耦合 | 通过 `src/api/`（内部 mq）封装 |
| 6 | 多个文件定义同一常量 | 不一致 | 集中到 `consts.go` |
| 7 | 在 DAO 中自 Open/Close | 连接泄露 | 传入 `*data.DB` / `*data.Table` |
| 8 | 混用 snake_case 和 camelCase 做 JSON tag | 前端对接混乱 | 消息面/落库统一 snake_case（61 为唯一准则；UI 个别结构另议） |

### 12.2 文件内容修改（严禁违规）

- 含非 ASCII 字符的文件写入必须 `[System.IO.File]::WriteAllText` + **显式 UTF8**（无 BOM）。
- **例外 —— 根目录 `build-*.ps1` 构建脚本**：必须保存为 **UTF-8 with BOM**（`EF BB BF`，PowerShell 5.1 兼容）。无 BOM 时 PowerShell 5.1 按 GBK 解码，脚本内中文引号被吞 → 报「字符串缺少终止符」并中断构建。
