# 动作

> 正样例：`samples/` 三份文件合起来应全部通过 `check.mjs`（所有计数归零）。

### ACT-001 · 创建并提交申请单

- 所属对象：OBJ-001
- 谁发起：需求部门
- 前置状态：STA-001
- 输入对象：—
- 输出对象：
  - OBJ-001
- 改了哪些字段：申请数量、需求日期
- 变成什么状态：STA-002
- 来源去向：—
- 可否撤销：可撤
- 业务理由：申请单创建后直接提交，进入待集采

### ACT-002 · 集采（聚合）

- 所属对象：OBJ-002
- 谁发起：采购员
- 前置状态：STA-004
- 输入对象：
  - OBJ-001 申请单（部门 A）
  - OBJ-001 申请单（部门 B）
- 输出对象：
  - OBJ-002 集采单
- 变成什么状态：STA-005
- 数量守恒：输入数量之和 = 集采单数量（可自动校验）
- 一起成功：集采单 + 明细
- 来源去向：集采单.source_ids → 输入的各张申请单
- 可否撤销：仅红冲（下游已分发时）
- 业务理由：多张申请合并采购，拿批量价

### ACT-003 · 分发（分解）

- 所属对象：OBJ-002
- 谁发起：采购员
- 前置状态：STA-005
- 输入对象：
  - OBJ-002 集采单
- 输出对象：
  - OBJ-003 分发记录
- 变成什么状态：STA-006
- 数量守恒：分发数量之和 = 集采单数量
- 一起成功：集采单 + 全部分发记录
- 来源去向：分发记录.parent_id → 集采单
- 可否撤销：仅红冲
- 业务理由：集采到货后按申请分发给需求部门

### ACT-004 · 确认收货

- 所属对象：OBJ-003
- 谁发起：需求部门
- 前置状态：STA-007
- 输入对象：
  - OBJ-003 分发记录
- 输出对象：
  - OBJ-003 分发记录
- 改了哪些字段：收货日期、收货数量
- 变成什么状态：STA-008
- 来源去向：—
- 可否撤销：不可撤
- 业务理由：需求部门确认收到分发物资，作为集采结算依据

### ACT-005 · 生成对账单

- 所属对象：OBJ-004
- 谁发起：财务
- 前置状态：—
- 输入对象：—
- 输出对象：
  - OBJ-004 对账单
- 变成什么状态：STA-009
- 来源去向：对账单.source_ids → 本期入库记录
- 可否撤销：仅红冲
- 业务理由：按供应商汇总月度入库，形成可对账的账期
