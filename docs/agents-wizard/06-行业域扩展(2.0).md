## 1. 为什么要泛化

1.0 的向导假设「域 = 软件开发」。但同一套机制（**探测 → 模式 → 选项 → 摘要 → 生成一组 agent**）对其它**知识密集型工作**同样成立：

- **量化炒股**：行情数据 → 策略研究 → 回测 → 风控 → 执行。
- **财务处理**：账务数据 → 合规校验 → 报表 → 审计。
- 其它候选：法律文书、市场调研、内容运营、科研实验。

**结论**：2.0 引入**行业域（domain）**抽象，把「域」做成可注册项；1.0 只实现 `dev` 域，其余域后置。

## 2. 域抽象模型

```text
Domain（域）
 ├─ id / name / icon
 ├─ detect        # 该域的目录/输入探测规则（判据可不同：dev 探测源码，quant 探测数据集/notebook）
 ├─ modes         # 顶层模式（dev: 新构建/迭代/重构；quant: 新策略/优化/复现）
 ├─ optionGroups  # 该域的选项菜单（各自的「技术栈」类比物）
 ├─ agentCatalog  # 预置 agent 目录（域专属）
 ├─ skills        # 域专属 skill（如因子分析、报表校验）
 └─ specSchema    # 该域的 project_spec 扩展字段
```

**共享内核**（1.0 已具备 ✅）：触发/检测机制（GUI 桥 `os.Stat`）、分步向导 UI（5 步）、摘要确认、提示词合成（`agent-wizard-compose` 纯字符串）、引用式 agent 落盘（`ProjectAgentWrite`）。
**域专属**（🔵 全部未实现）：探测规则、模式与选项、agent/skill 目录、spec 扩展 —— 当前全部硬编码 dev 语义。

## 3. 示例：量化炒股（quant）

| 维度 | 取值（示例） |
|------|-------------|
| 探测 | 是否存在数据集（csv/parquet）、notebook（`.ipynb`）、回测框架（backtrader/vectorbt/qlib） |
| 模式 | 新策略构建 / 策略优化 / 策略复现 / 其他 |
| 选项 | 市场（A股/美股/期货）· 频率（日/分钟/tick）· 数据源 · 回测框架 · 执行方式（回测/模拟/实盘）· 风控约束 |
| 预置 agent | 主协调者 · 数据工程师 · 因子研究员 · 策略开发 · 回测工程师 · 风控审查 · 绩效分析师 |
| skill | 因子计算、过拟合检验、绩效归因、仓位管理 |
| spec 扩展 | `market` / `frequency` / `data_source` / `risk_constraints` |

## 4. 示例：财务处理（finance）

| 维度 | 取值（示例） |
|------|-------------|
| 探测 | 是否存在账套/凭证/报表文件（xlsx/csv）、会计科目表 |
| 模式 | 建账 / 记账 / 结账 / 报表 / 审计 / 其他 |
| 选项 | 会计准则（企业/小企业/IFRS）· 币种 · 期间 · 科目体系 · 输出格式 |
| 预置 agent | 主协调者 · 凭证录入 · 科目校验 · 报表生成 · 合规审查 · 审计复核 |
| skill | 借贷平衡校验、科目对应、报表勾稽、异常分录识别 |
| spec 扩展 | `accounting_standard` / `currency` / `period` / `chart_of_accounts` |
