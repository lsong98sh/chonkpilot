> 关联：[README](./README.md) · [03-提示词合成](./03-提示词合成设计.md) · [prompts-ref](file:///e:/BizWorks/chonkpilot/prompts-ref)
> 落盘：出厂预置 = `src/initdata/capability/agents/<名>.agent.md`（app 级，构建时投放到 `<exeDir>/capability/agents/`）。场景以**引用**方式使用。

## 1. 文件格式（严格沿用）

```markdown
# <名>

[meta]
roletag=<角色标签>

[description]
<一句话职责>

[content]
<提示词正文>
```

> 主 agent 额外带 `ismain=true`，固定文件名 `main.agent.md`，**内联**在场景目录（不引用）。

## 3. 已有预置（内容，保持不动）

| 名 | roletag | description | content |
|----|---------|-------------|---------|
| 需求分析师 | 需求 | 澄清需求细节，深挖客户没有写明的需求，用于理解需求并和用户深度沟通 | 梳理业务模块，找出所有模糊/缺失/矛盾/隐含假设，按优先级提问，绝不替用户做假设；充分后输出《需求规格说明书》（功能/数据/非功能/验收），写入 `.chonkpilot/tmp/`，回复只给摘要。 |
| 架构设计师 | 架构 | 系统架构设计与技术方案规划 | 先理解功能/非功能需求与约束，对比 2-3 候选后给推荐方案与 ADR；输出架构概览、技术选型与理由、模块职责与接口、核心流程/状态、数据模型、风险与迁移方案；改造现有系统须给向后兼容方案。 |
| 前端开发 | 前端 | 前端 UI 组件与页面开发 | 遵循项目现有组件风格/UI 库/CSS，不引入新依赖；接口按契约调用；组件单一职责、Props 不可变、状态提升；异步三态；注意可访问性与渲染性能。 |
| 后端开发 | 后端 | 后端 API 与服务端开发 | 严格按契约实现（不自行设计 API，变更先知会主 LLM）；输入校验、参数化防注入、事务管理；错误区分业务/系统并统一响应；优先复用已有实现。 |
| 代码审查 | 审查 | 代码质量审查与改进建议 | 优先级 正确性→安全→性能→可维护→运维→风格；每问题给严重度（critical/major/minor/nit）、位置、描述、修复建议；结论 通过/条件通过/不通过。 |
| 前端测试工程师 | 前端测试 | 前端组件、交互、可访问性与视觉验证 | 组件行为（渲染/Props/事件）、异步三态、交互与状态（悬停/按下/禁用/聚焦/键盘可达）、可访问性（语义/对比度/焦点顺序）、视觉一致性（响应式断点/主题）、浏览器自动化（跨页流程/失败截图）。 |
| 后端测试工程师 | 后端测试 | 后端单元与集成测试（规范驱动） | 源自 [`unittest.txt`](../../prompts-ref/unittest.txt) 的语言无关规范：是否值得测过滤 → 依赖处理（Mock/Stub/Fake、纯函数不 Mock、禁时间等待）→ 测行为而非实现 → 边界与异常三类路径 → 断言标准（逐字段/副作用前后差/异常类型+消息/逆运算/幂等）→ AI 生成约束 → 断言反模式清单。 |
| 系统测试工程师 | 系统测试 | 端到端 / 集成 / 跨模块验收测试 | 端到端链路（外部入口→全链路→可观察输出）、集成与契约（跨模块/消息契约双向断言）、验收标准可追溯、非功能（性能基线/可靠性/并发）、环境隔离与数据清理、回归失败即阻断。 |
| UI 测试工程师 | UI测试 | 自动化的 UI 布局审查与交互验证 | 交互状态、可访问性、响应式与视觉一致性验证。 |
| UX 设计师 | UX | 以设计判断交付高质量界面：原型、线框、设计系统与可访问性 | 交互流程与体验设计，产出线框/状态说明。 |

## 5. 选项 → 团队成员（按信号定向增补）

> 团队以**成员清单**呈现，**不按「规模」数字**选择（见 [01 §6](./01-交互流程与界面设计.md)）。

| 信号 | 追加成员 |
|------|-----------|
| 基线（恒在） | 主协调者（默认 Leader）+ 代码审查 + **系统测试工程师** |
| 新构建(A) | 需求分析师、架构设计师、<按平台>前端/后端/移动 |
| 有数据库 | 数据工程师 |
| 含前端/多端 | 前端开发 / 移动端开发 / UX 设计师 / UI 测试工程师 / **前端测试工程师** |
| 含后端 | 后端开发 / **后端测试工程师** |
| 迭代(B) | 侦察工程师（**不预设任务类型**；专项角色 调试/性能/依赖 改为 Step4 按需手选） |
| 重构(C) | 侦察工程师 + 遗留分析员 / 兼容守护 / 迁移规划师 |

| 涉及构建/部署 | DevOps 工程师 |

### 5.1 架构形态 → 团队层（硬约束）

> 见 [01 §5.2](./01-交互流程与界面设计.md)。选中「三层」**必须**追加数据访问层角色，避免「选了三层却只有前后端」。

| 架构 | 追加成员 |
|------|----------|
| 两层结构 | 前端开发、后端开发 |
| 三层结构 | 前端开发、后端开发、数据工程师 |
| 微服务 | 前端开发、后端开发（按服务）、集成协调者、数据工程师 |
| Serverless | 前端开发、后端开发（函数）、DevOps 工程师 |

### 5.2 语言多选 → 开发角色

- 前端语言多选（TS / JS）→ 前端开发（多语言视为同一角色能力，不重复建卡）。
- 后端语言多选（Go / Node / Python / Java / Rust）→ 后端开发（同上；**仅当用户显式要求按语言拆服务时**才拆多个开发者）。

### 5.3 项目类型 → 侧重

| 类型 | 侧重成员 |
|------|----------|
| 业务型 | 前端开发 / 后端开发 / 数据工程师 |
| 组件型 | 架构设计师 / 后端开发 / 文档撰写者 / 系统测试工程师 |
| 基建型 | DevOps 工程师 / 后端开发 / 安全审查员 / 性能优化师 |
| 游戏 | 前端开发 / UX 设计师 /（图形向预置待扩展） |
| 其他 | 用户手选 |

> 平台为**多选可组合**（前端/后端/Web/移动端/小程序）；选 Web/移动端/小程序**自动含「前端」**。详见 [01 §5](./01-交互流程与界面设计.md)。
