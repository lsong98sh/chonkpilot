## 1. 现状：系统提示词三层拼接（沿用）

| 层 | 内容 | 载体 |
|---|------|------|
| 全局 | 身份/运行环境（代码写死，如「你是 {agent名}…」） | 代码 |
| 场景 | `scenario.description` + 代码按 agents 自动拼接的**团队段** | 向导生成 |
| agent | 当前 agent 的 `[content]` | 向导生成/引用 |

> **向导只产出「场景层 + agent 层」**，不改全局层。

## 2. 合成的五类输入

1. **项目信息（Step1，最先）**：目的 / 概要 / 预算 / 背景 / 要求 —— 新建由用户填写、有项目由扫描预填；~~LLM 据此先给出推荐~~ ⚠️（2026-11-04 核对：**无任何 LLM 推荐调用**；扫描仅预填 `summary`/`deploy`，`goal/background/requirement` 不预填）。
2. **预置 agent 基底**：[02](./02-预置智能体目录.md) 中各 `<名>.agent.md` 的 `description` + `content`。（✅ 经 `readAgentArchetype` 读取）
3. **目录探测结果**（有项目）：语言、框架、包管理、构建/测试命令、风格、结构（见 [04](./04-目录探测与project_spec.md)）。（✅ `probe` 原样透传给合成器）
4. **用户确认后的选择 + 摘要**：模式、平台、技术栈（含【其他】自定义值）、数据层、架构、成员清单、自治级别。（⚠️ 实际 compose 只收到 `choices=sel` + `team`；Step4 摘要编辑 `summaryEdits` 不传、【其他】自定义文本不传、**无「自治级别」字段**）
5. **公认标准**（对齐 [提示词内容纲要](../提示词内容纲要.md) 十维）：身份、行为准则、工具规范、编辑策略、安全边界、任务规划、上下文管理、输出风格、分层、评估。（⚠️ 实际输出以【身份】【职责与方法】【项目上下文】【协作】【约束】【输出契约】近似覆盖，见 §8）

> **推荐先行**：🔵 **规划（未实现，2026-11-04 核对）** —— Step2 / Step3 的默认值来自「项目信息 + 探测」的 LLM 推荐，用户仅调整偏离项。自定义技术（【其他】输入值，如 `Zig` / `JPA`）**原样**进入 §6 的「项目适配」槽。（实际默认值硬编码；自定义值不随 `choices` 发送）

## 3. 合成流水线

```text
摘要确认(Step4) ─┐
探测结果 ────────┤→ ① 场景蓝图（scenario_plan）
预置基底 ────────┘      ② 成员裁剪（team ⊆ 预置目录；缺则生成新 agent）
                        ③ 场景层渲染（description + 团队段）
                        ④ 主 agent 渲染（默认 Leader 模板，见 §5）
                        ⑤ 子 agent 渲染（基底 + 项目槽位 + 团队协作段）
                        ⑥ 落盘（scenario.json / main.agent.md / 引用 agents）
```

> **2026-11-04 核对（实现口径）**：实际流水线 = ③❌（`description` 由前端 `composeDescription()` 拼好，后端不渲染场景层）→ ①🔵（无独立 `scenario_plan`）→ ②⚠️（成员由前端 `deriveTeam()` 决定，后端不裁剪）→ ⑤✅（`composeAgentPrompt` 逐成员纯字符串组装）→ ④⚠️（主 agent 也走同一骨架，默认 Leader 模板被覆盖）→ ⑥✅（`agent-wizard-generate` 经 `ProjectAgentWrite` 落文件 + 引用）。**「缺则生成新 agent」为 🔵 规划，未实现**。

## 4. 场景层模板

```text
scenario.description =
  「我们是一个 <平台> <架构形态> 的研发团队，技术栈 <前端/后端/数据>。
   项目概要：<Step4 项目概要>。
   当前模式为 <模式名>（<模式说明>）。项目约定：构建 `<build>`，测试 `<test>`，风格 `<lint>`。」

团队段（代码自动拼接，无需写死）= 遍历 agents：
  - <名>（<roletag>）：<description>
```

> ⚠️ **2026-11-04 核对**：实际 `composeDescription()`（前端 `ScenarioWizardDialog.vue`）只拼 平台/架构/前端栈/后端栈/目标（A 模式）或 `stack`/`target`/`keep`（B/C 模式）+ `goal`；**未包含 `build` / `test` / `lint`**，也无独立「当前模式为…（模式说明）」分句。构建/测试/风格只出现在**子 agent** 的【项目上下文】（`composeAgentPrompt` 读 `probe.build_tool/test_tool/lint_tool`）。

## 5. 主 agent（默认 Leader）模板 — 不由用户选择

> 主 agent = `main.agent.md`（`ismain=true`），**使用固定的默认 Leader 提示词**；向导不提供 Leader 选择项。

```markdown
# 主协调者

[meta]
ismain=true
roletag=主

[description]
团队编排、任务拆解、决策与委派

[content]
你是 <场景名> 的编排者与决策者：规划 → 委派 → 检查结果 → 决策 → 循环。
先对齐再动手：需求不明先说明你的理解与执行标准，获认可后再开工。
信息密集的工具调用委派给【团队成员】中的合适角色：直接从上下文【团队成员】里选角色，
再用 llm_run 的 LLM "<agent名>" "<prompt>" "<目的>" 指令委派（agent 名照团队列表所写，可能带场景前缀；三参均必填，"目的" = 子任务展示名、建议 10–20 字）。
项目上下文：<项目概要 + 语言/框架/构建/测试/风格>。
工作模式：<新构建|迭代|重构>；自治级别：<每步确认|关键节点确认|全自动>。
安全约束：<按模式：如重构=严格行为保持、所有现有测试须通过>。
中间产物写入 .chonkpilot/tmp/，不污染项目根目录。
```

> ⚠️ **2026-11-04 核对（与实现不符）**：向导未提供 Leader 选择项 ✅，但**默认 Leader 模板并未生效**：前端默认提示词仅两句（`defaultMainPrompt()`，无 `llm_run` 三方委派/工作模式/自治级别/安全约束），且 `agent-wizard-compose` 会对「主协调者」也返回自建角色骨架并覆盖 `a.prompt`（`applyComposed`）。上述模板仅在**合成失败**回落时保留默认串；`default/main.agent.md` 的 Loop Engineer 范式未被注入。**「自治级别」字段在前端/后端均不存在（🔵）**。

## 9. 落盘结构（✅ 已实现 · 方案 C：合成结果**落文件后引用**）

> 合成由后端方法面 **`agent-wizard-compose`** 完成（`src/lib/llm/server/wizard_compose.go`）：**纯字符串组装（确定性模板，不调 LLM、不写文件、无副作用）** ✅；读 archetype 基底（`<exeDir>/capability/agents/<名>.agent.md` 的 `description`+`content`，经门面 `KnowledgeRoot`(app)+`KnowledgeRead`）✅ → 按维度框架 + 项目槽位组装 ✅ → 前端可编辑 / AI 优化（`useCase=agent`）✅ → 由 **`agent-wizard-generate`**（`wizard.go`）经 data 门面 **`ProjectAgentWrite`** 落为**项目级 capability agent 文件** ✅，再把 `ref` 设为引用路径后 `ScenarioSave` ✅。

```text
<workDir>/.chonkpilot/
├── capability/agents/                 # 合成结果落此（每成员一个 *.agent.md）
│   ├── 架构设计师.agent.md
│   ├── 前端开发.agent.md
│   └── …（用户自建角色同样落此）
└── capability/scenarios/<场景id>/
    ├── scenario.json                  # agents: ["${workDir}/.chonkpilot/capability/agents/<名>.agent.md", …]
    └── main.agent.md                  # 主协调者（内联）
```

> **为什么落文件 + 引用（唯一形态）**：**子 agent 唯一形态 = 引用** —— `scenario.json.agents` 存引用路径（`${exeDir}`/`${usrDir}`/`${workDir}`/`${dataDir}` 前缀 + 相对路径），场景目录内**不放** `*.agent.md` 子文件；加载端（`ReadScenarioDir`）只按引用展开（悬空引用静默删除）。**非主 agent 无 `ref` 保存即拒绝**（内联子 agent 形态已废除）。合成结果落**项目级 capability agent 文件**后引用之 → 场景文件精简、agent 资产可跨场景复用、可在「扩展 · 智能体」页统一编辑。**主 agent 仍内联** `main.agent.md`。
> **`{{path.*}}` 四根路径**：合成文本末以 `{{path.exeDir}}` / `{{path.userDir}}` / `{{path.dataDir}}` / `{{path.workDir}}` 占位符给出能力目录（`…/capability/skills/`），**组装系统提示词时**渲染为绝对路径，指示 LLM 用文件工具自读；**不再走 `mcp_load kind=skill`**（LLM 经 mcp_find/mcp_load 读不到能力面 `capability/skills/*`）。
> **archetype 仍复用**：出厂 `agents/*.agent.md` 作为**基底素材**被合成器读取（`source:"archetype"`），而非运行时引用；读不到（自建角色）回落通用骨架并标 `source:"自建"`。预置升级 → 重新生成场景即生效（非自动热更）。
> **失败回落**：合成失败/超时 → 主 agent 用默认提示词、子 agent 回落 `${exeDir}` 引用（`agentRef`），不阻断生成。
