# 03 · 提示词合成设计

> 关联：[提示词内容纲要](../提示词内容纲要.md) · [25-MCP与场景分层模型](../../docs/spec/10-architecture/25-MCP与场景分层模型.md) §3 · [02-预置智能体目录](./02-预置智能体目录.md) · [prompts-ref](file:///e:/BizWorks/chonkpilot/prompts-ref)

## 1. 现状：系统提示词三层拼接（沿用）

| 层 | 内容 | 载体 |
|---|------|------|
| 全局 | 身份/运行环境（代码写死，如「你是 {agent名}…」） | 代码 |
| 场景 | `scenario.description` + 代码按 agents 自动拼接的**团队段** | 向导生成 |
| agent | 当前 agent 的 `[content]` | 向导生成/引用 |

> **向导只产出「场景层 + agent 层」**，不改全局层。

## 2. 合成的五类输入

1. **项目信息（Step1，最先）**：目的 / 概要 / 预算 / 背景 / 要求 —— 新建由用户填写、有项目由扫描预填；**LLM 据此先给出推荐**。
2. **预置 agent 基底**：[02](./02-预置智能体目录.md) 中各 `<名>.agent.md` 的 `description` + `content`。
3. **目录探测结果**（有项目）：语言、框架、包管理、构建/测试命令、风格、结构（见 [04](./04-目录探测与project_spec.md)）。
4. **用户确认后的选择 + 摘要**：模式、平台、技术栈（含【其他】自定义值）、数据层、架构、成员清单、自治级别。
5. **公认标准**（对齐 [提示词内容纲要](../提示词内容纲要.md) 十维）：身份、行为准则、工具规范、编辑策略、安全边界、任务规划、上下文管理、输出风格、分层、评估。

> **推荐先行**：Step2 / Step3 的默认值来自「项目信息 + 探测」的 LLM 推荐，用户仅调整偏离项。自定义技术（【其他】输入值，如 `Zig` / `JPA`）**原样**进入 §6 的「项目适配」槽。

## 3. 合成流水线

```text
摘要确认(Step4) ─┐
探测结果 ────────┤→ ① 场景蓝图（scenario_plan）
预置基底 ────────┘      ② 成员裁剪（team ⊆ 预置目录；缺则生成新 agent）
                        ③ 场景层渲染（description + 团队段）
                        ④ 主 agent 渲染（默认 Leader 模板，见 §5）
                        ⑤ 子 agent 渲染（基底 + 项目槽位 + 团队协作段）
                        ⑥ 落盘（scenario.json / main.agent.md / 引用 agents）
```

## 4. 场景层模板

```text
scenario.description =
  「我们是一个 <平台> <架构形态> 的研发团队，技术栈 <前端/后端/数据>。
   项目概要：<Step4 项目概要>。
   当前模式为 <模式名>（<模式说明>）。项目约定：构建 `<build>`，测试 `<test>`，风格 `<lint>`。」

团队段（代码自动拼接，无需写死）= 遍历 agents：
  - <名>（<roletag>）：<description>
```

## 5. 主 agent（默认 Leader）模板 — 不由用户选择

> 主 agent = `main.agent.md`（`ismain=true`），**使用固定的默认 Leader 提示词**；向导不提供 Leader 选择项。

```markdown
# 主协调者

[meta]
ismain=true
roletag=主

[description]
团队编排、任务拆解、决策与委派

[content]
你是 <场景名> 的编排者与决策者：规划 → 委派 → 检查结果 → 决策 → 循环。
先对齐再动手：需求不明先说明你的理解与执行标准，获认可后再开工。
信息密集的工具调用委派给【团队成员】中的合适角色：直接从上下文【团队成员】里选角色，
再用 llm_run 的 LLM "<agent名>" "<prompt>" "<目的>" 指令委派（agent 名照团队列表所写，可能带场景前缀；三参均必填，"目的" = 子任务展示名、建议 10–20 字）。
项目上下文：<项目概要 + 语言/框架/构建/测试/风格>。
工作模式：<新构建|迭代|重构>；自治级别：<每步确认|关键节点确认|全自动>。
安全约束：<按模式：如重构=严格行为保持、所有现有测试须通过>。
中间产物写入 .chonkpilot/tmp/，不污染项目根目录。
```

> 默认 Leader 提示词沿用现有 `src/initdata/capability/scenarios/default/main.agent.md`（Loop Engineer）范式，仅注入项目槽位。

## 6. 子 agent 模板（基底 + 项目槽 + 团队协作段）

```markdown
# <名>

[meta]
roletag=<roletag>

[description]
<基底 description>

[content]
<基底 content>

【项目适配】
- 技术栈：<与本角色相关的选型>
- 命令：构建 `<build>`；测试 `<test>`；lint `<lint>`
- 约定：<探测到的代码风格/目录约定>
【本任务约束】
- <按模式注入：迭代=允许修改范围/回归测试；重构=行为保持/验证方式>
【团队协作】
- 你是团队中的代理；你的产出交回主协调者，不直接面向用户。
```

> 「团队协作」段提炼自 [prompts-ref `teammatePromptAddendum`](file:///e:/BizWorks/chonkpilot/prompts-ref/prompts/utils/swarm/teammatePromptAddendum.ts.md)（去工具名后改写）。

## 7. 无匹配预置时：LLM 生成新 agent（元提示词）

当摘要确认的某成员在预置目录中不存在（如「量化策略研究员」）时，由 LLM 依**元提示词**生成一个新的 `*.agent.md`，落到项目级 `capability/agents/` 并在 `scenario.json.agents` 引用。

元提示词基底 = 提炼自 [prompts-ref `generateAgent.ts`](file:///e:/BizWorks/chonkpilot/prompts-ref/prompts/components/agents/generateAgent.ts.md) 的 `AGENT_CREATION_SYSTEM_PROMPT`，改写为 ChonkPilot 口径：

```text
你是资深的智能体架构师。根据「角色意图 + 项目上下文（project_spec 摘要）」产出一个 ChonkPilot agent 定义。
输出严格为 JSON：{ "name": "...", "roletag": "...", "description": "一句话职责", "content": "第二人称、结构化、含质量自检与边界处理的完整提示词" }
要求：具体而非泛化；含可执行方法论；含异常/边界处理；对齐项目既有模式与命令。
```

> 生成后仍套用 §6 的【项目适配】/【团队协作】段再落盘。

## 8. 「公认标准」映射（纲要十维 → 向导落点）

| 纲维 | 向导落点 |
|------|----------|
| ① 身份与角色 | 全局层（代码）+ 各 agent `description` |
| ② 行为准则 | 主 agent 模板（先读后改、最小变更、根因修复） |
| ③ 工具使用规范 | 由 `agent.tools` 白名单 + 现有工具契约承载，向导只设白名单 |
| ④ 编辑与调试策略 | 子 agent 基底（复现→根因→最小修复→验证） |
| ⑤ 安全与权限 | 主 agent「安全约束」槽 + 安全审查员基底 |
| ⑥ 任务规划 | 主 agent 模板（规划→委派→循环） |
| ⑦ 上下文管理 | 全局层（环境信息）+ 项目概要注入 |
| ⑧ 语气与输出 | 子 agent 基底（简洁、Markdown、产出落 `.chonkpilot/tmp/`） |
| ⑨ 分层架构 | 三层拼接 + 引用式 agent |
| ⑩ 评估与迭代 | 生成后在 `project_spec.md` 记录 `wizard_version`，供后续 A/B |

## 9. 落盘结构（✅ 已实现 · 方案 C：合成结果**落文件后引用**）

> 合成由后端方法面 **`agent-wizard-compose`** 完成（`src/lib/llm/server/wizard_compose.go`）：读 archetype 基底（`<exeDir>/capability/agents/<名>.agent.md` 的 `[description]`+`[content]`）→ 按维度框架 + 项目槽位组装 → 前端可编辑 / AI 优化 → 由 **`agent-wizard-generate`**（`wizard.go`）经 data 门面 **`ProjectAgentWrite`** 落为**项目级 capability agent 文件**，再把 `ref` 设为引用路径后 `ScenarioSave`。

```text
<workDir>/.chonkpilot/
├── capability/agents/                 # 合成结果落此（每成员一个 *.agent.md）
│   ├── 架构设计师.agent.md
│   ├── 前端开发.agent.md
│   └── …（用户自建角色同样落此）
└── capability/scenarios/<场景id>/
    ├── scenario.json                  # agents: ["${workDir}/.chonkpilot/capability/agents/<名>.agent.md", …]
    └── main.agent.md                  # 主协调者（内联）
```

> **为什么落文件 + 引用（唯一形态）**：**子 agent 唯一形态 = 引用** —— `scenario.json.agents` 存引用路径（`${exeDir}`/`${usrDir}`/`${workDir}`/`${dataDir}` 前缀 + 相对路径），场景目录内**不放** `*.agent.md` 子文件；加载端（`ReadScenarioDir`）只按引用展开（悬空引用静默删除）。**非主 agent 无 `ref` 保存即拒绝**（内联子 agent 形态已废除）。合成结果落**项目级 capability agent 文件**后引用之 → 场景文件精简、agent 资产可跨场景复用、可在「扩展 · 智能体」页统一编辑。**主 agent 仍内联** `main.agent.md`。
> **`{{path.*}}` 四根路径**：合成文本末以 `{{path.exeDir}}` / `{{path.userDir}}` / `{{path.dataDir}}` / `{{path.workDir}}` 占位符给出能力目录（`…/capability/skills/`），**组装系统提示词时**渲染为绝对路径，指示 LLM 用文件工具自读；**不再走 `mcp_load kind=skill`**（LLM 经 mcp_find/mcp_load 读不到能力面 `capability/skills/*`）。
> **archetype 仍复用**：出厂 `agents/*.agent.md` 作为**基底素材**被合成器读取（`source:"archetype"`），而非运行时引用；读不到（自建角色）回落通用骨架并标 `source:"自建"`。预置升级 → 重新生成场景即生效（非自动热更）。
> **失败回落**：合成失败/超时 → 主 agent 用默认提示词、子 agent 回落 `${exeDir}` 引用（`agentRef`），不阻断生成。
