## 1. 结论先行

> ⚠️ **2026-11-04 核对**：本节为 2026-10-04 的决策记录；其中「B+A」实际落地为 **仅 A**（B 已废弃，见 §3）。

**「接收 ready → 检测 → 发出 agent-wizard 激活」可以做成插件**（原选 **方案 B+A**），但需明确三点：

1. **插件只负责「检测 + 触发」**：内嵌后端插件（`plugin.Hook`）无 UI；向导本体（对话框 + 步骤 + 生成逻辑）仍须落在**前端 + 服务端（llm-server/gui）**。
2. **新增主题已授权**（2026-10-04）：`agent-wizard*` **4 个方法面主题**（+1 事件，共 **5 个**；含 `agent-wizard-compose`）**可以加**，但须**配套门面**（§4.4）并同步 [61-消息一览](../../docs/spec/60-reference/61-消息一览.md) + 补齐测试。
3. **ready 时序**：`server-starting` 广播时实例尚未注册 → **workdir 可能未知**；更稳妥的钩子是 `instance-register`（携带 `work_dir`）。（🔵 未被采用：实际触发为 `gui.init-data`）

> **〔实现口径（2026-10-04 实施完成，覆盖上文 B 方案）〕** 本轮**未建 `plugin-wizard`**：检测落在 **GUI 桥**（`src/lib/gui/bridge/guimsg.go` 的 `gui.init-data`：缺 `.chonkpilot/project_spec.md` → 下发 `agent-wizard` + 只增字段 `wizard_required`），等价达成「就绪后检测并激活」；**B 方案（瘦插件）不做 —— A 已覆盖全部功能，用户 2026-10-04 拍板**（[41 D-44](../../docs/spec/40-roadmap/41-未决项登记.md#2-已收口--历史只读不再待决) ✅ 已闭环）。
> **probe / compose / generate / skip** 由 **llm-server** handler 实现（`src/lib/llm/server/wizard.go`、`wizard_compose.go`），**直接调 data 门面 `facade.ProjectAPI`（inline）** → **不新增 `data-*` 主题**；辅助选项经 `ConfigKVSet`（`prj-config`）写入并广播 `data-prj-config-refresh`。消息面以 [61](../../docs/spec/60-reference/61-消息一览.md) 为准（已同步，实际 **5 个主题**）。

## 4. 消息面提案（仅增，逐条授权）

### 4.1 后端 → 前端（事件）

| 消息 | 触发 | payload | 说明 |
|------|------|---------|------|
| `agent-wizard` | **GUI 桥**在 `gui.init-data` 检测到 `project_spec.md` 缺失（❌ 非插件） | `{reason:"missing_spec", work_dir, spec_path}` | 前端订阅 → 打开向导（`MainLayout.vue` → `openScenarioWizard`） |

### 4.2 前端 → 后端（方法面）

| 消息 | 触发 | payload | 返回 |
|------|------|---------|------|
| `agent-wizard-probe` | 向导挂载 / 「重新扫描」 | 前端 `mq.emit(...,{})`；**契约层**桥注入 `{instance_id}` | `{ok, probe}`（`probe` = `ProjectProbeResponse`：`work_dir/empty/has_code/has_git/has_readme/file_count/languages[]/frameworks[]/package_manager/build_tool/test_tool/lint_tool/top_dirs[]`） |
| `agent-wizard-compose` | 进入 Step5 预览（团队签名变化时） | `{instance_id, mode, description, probe{}, choices{}, team:[{name, roletag}]}`（`mode ∈ A\|B\|C\|custom`） | `{ok, agents:[{name, roletag, prompt, source}]}`（`source ∈ archetype\|自建`；`ok:false` → `{ok:false, error}`） |
| `agent-wizard-generate` | 向导 Step5「生成」 | `{instance_id, scenario_id, scene_name, description, agents:[{name, roletag, is_main, prompt, ref, skills, resources}], memory:[{category, content}], project_spec, config{}, init_git}` | `{ok, scenario_id, spec_path, memory_saved[], errors, config_saved[], git_initialized}`（场景保存失败 = `{ok:false, error}`） |
| `agent-wizard-skip` | 【关闭】/「稍后」 | 前端 `{}`；契约层桥注入 `{instance_id}` | `{ok}`（**后端无抑制逻辑**；「本会话不再自动弹」由前端 `scenarioWizard.js` 模块级 `_autoOpened` 实现） |

> ❌ **旧稿「复用 `data-scenario-save`」不实（2026-11-04 核对）**：`wizard.go:144` 直接调门面 `s.cfg.ScenarioSave(...)`，**不经** `data-scenario-save` 主题。generate 另调 `ProjectAgentWrite` / `MemorySave` / `ConfigKVSet` / `ProjectSpecWrite`，可选 `git init`。

### 4.4 门面（facade）设计（新增主题的配套）

> **原则**（[28-plugins](../../docs/spec/20-modules/28-plugins.md)）：插件**不直开库** —— 进程内 Hook 经 data 门面 `facade.API`（宿主 inline 绑定），进程外插件经**插件桥**（`plugin/v1/data.*`，宿主侧再走门面）。新增能力**不得绕过门面 / 插件桥**。

| 新消息 | 落点（2026-11-04 核对） | 实际调用的门面/接口 |
|--------|--------------------------|---------------------|
| `agent-wizard`（事件） | **GUI 桥** `guimsg.go`：`b.EmitFrontend(messages.MsgAgentWizard, …)`（❌ 非瘦插件 `Deps.Bus`） | 仅 `os.Stat` + 发事件（无库访问） |
| `agent-wizard-probe` | server `wizard.go`；只读探测 | ✅ `facade.ProjectProbe`（解析 workdir + 只读探测） |
| `agent-wizard-compose` | server `wizard_compose.go`；纯字符串组装 | ✅ 知识库 `KnowledgeRoot`(kind=app) + `KnowledgeRead`（只读 archetype） |
| `agent-wizard-generate` | server `wizard.go`；写 agent 文件 + 场景 + 记忆 + 配置 + spec（+ git） | ✅ `ProjectAgentWrite` + `ScenarioSave`(Level=project) + `MemorySave` + `ConfigKVSet`(域 prj-config) + `ProjectSpecWrite` + 可选 `os/exec git init` |
| `agent-wizard-skip` | 前端会话级标记（后端空操作） | —（不落库） |

**数据层门面（project 域）现状**：

- `ProjectSpecExists(instanceID)` —— ✅ 已在 `facade/project.go` + `internal/project` 实现；⚠️ **仓内无生产调用方**（仅单测），启动检测实际是 GUI 桥 `os.Stat`。
- `ProjectSpecRead(instanceID)` —— ✅ 已实现；⚠️ **无调用方**（重跑向导不回填 spec）。
- `ProjectSpecWrite(instanceID, content)` —— ✅ 被 `agent-wizard-generate` 使用（整份覆盖、自动建父目录）。
- `ProjectProbe` / `ProjectAgentWrite` —— ✅ 被 probe / generate 使用。

> 门面方法经 `facade.API` 的 **inline 绑定**注入（与既有 data 门面同构）；server **只经门面**访问，不持库句柄。实现须同步 `src/lib/data` 门面契约与 [12-数据层](../../docs/spec/10-architecture/12-数据层.md)。

## 5. 时序 · 🔵 方案 B（已废弃，仅存档）

> ⚠️ **2026-11-04 核对**：下述插件时序未实现（无 `plugin-wizard`）。实际时序 = 前端 `gui.init-data` → 桥 `os.Stat` → `EmitFrontend('agent-wizard')` + 应答 `wizard_required` → `MainLayout` 打开向导。

```text
server.Start → 插件 Start(订阅 instance-register) → 广播 server-starting
客户端连接 → instance-register{work_dir}
   └─ detector 插件：读 <work_dir>/.chonkpilot/project_spec.md
        ├─ 存在 → 静默
        └─ 缺失 → bus.Publish('agent-wizard', {reason, work_dir, spec_path})
             └─ 桥 forwardEvent → emitRemote → 前端 mq.on('agent-wizard')
                  └─ dialog.open(ScenarioWizardDialog)
                       ├─ mq.emit('agent-wizard-probe') → 判定空目录 + 渲染探测卡
                       ├─ Step2/3 选择 → Step4 摘要确认（可编辑）
                       └─ Step5 mq.emit('agent-wizard-generate') → 写场景 + project_spec.md
```

**实际时序（A 方案）**：

```text
前端 MainLayout 启动 → mq.emit('gui.init-data')
   └─ GUI 桥 stat <workDir>/.chonkpilot/project_spec.md
        ├─ 存在 → wizard_required=false，静默
        └─ 缺失 → EmitFrontend('agent-wizard', {reason, work_dir, spec_path}) + 应答 wizard_required=true
             └─ 前端 openScenarioWizard（模块级 _autoOpened 去重）
                  └─ ScenarioWizardDialog 挂载 → mq.emit('agent-wizard-probe')
                       └─ Step5 进入预览 → mq.emit('agent-wizard-compose')
                            └─「生成」→ mq.emit('agent-wizard-generate')
```

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| workdir 未知 / 多实例 | 以 `instance-register` 的 `work_dir` 为准；多实例各自检测、按 instance 归属过滤 |
| 越层直访数据 | 新增能力一律经 `facade.API`（§4.4），插件不直开库 |
| 重复弹窗打扰 | ⚠️ 文件存在即不再弹 ✅；「本会话不再弹」由前端 `scenarioWizard.js` 模块级 `_autoOpened` 去重实现，**`agent-wizard-skip` 后端为空操作**（不参与判定） |
| 与 `gui.init-data` 争抢首屏 | 向导**非阻塞**，主界面就绪后异步弹出 |
| 误判「空目录」 | 采用分层判定（见 [04 §2](./04-目录探测与project_spec.md)），准空时二次确认 |
