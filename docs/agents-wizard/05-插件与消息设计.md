# 05 · 插件与消息设计（含可行性结论）

> 关联：[28-plugins](../../docs/spec/20-modules/28-plugins.md) · [61-消息一览](../../docs/spec/60-reference/61-消息一览.md) · [2C-UI插件](../../docs/spec/20-modules/2C-UI插件.md) · [bridge.go](file:///e:/BizWorks/chonkpilot/src/lib/gui/bridge/bridge.go) · [ScenarioEditDialog.vue](file:///e:/BizWorks/chonkpilot/src/frontend/src/views/scenario/ScenarioEditDialog.vue)

## 1. 结论先行

**「接收 ready → 检测 → 发出 agent-wizard 激活」可以做成插件**（选 **方案 B+A**），但需明确三点：

1. **插件只负责「检测 + 触发」**：内嵌后端插件（`plugin.Hook`）无 UI；向导本体（对话框 + 步骤 + 生成逻辑）仍须落在**前端 + 服务端（llm-server/gui）**。
2. **新增主题已授权**（2026-10-04）：`agent-wizard*` 4 个主题**可以加**，但须**配套门面**（§4.4）并同步 [61-消息一览](../../docs/spec/60-reference/61-消息一览.md) + 补齐测试。
3. **ready 时序**：`server-starting` 广播时实例尚未注册 → **workdir 可能未知**；更稳妥的钩子是 `instance-register`（携带 `work_dir`）。

> **〔实现口径（2026-10-04 实施完成，覆盖上文 B 方案）〕** 本轮**未建 `plugin-wizard`**：检测落在 **GUI 桥**（`src/lib/gui/bridge/guimsg.go` 的 `gui.init-data`：缺 `.chonkpilot/project_spec.md` → 下发 `agent-wizard` + 只增字段 `wizard_required`），等价达成「就绪后检测并激活」；**B 方案（瘦插件）不做 —— A 已覆盖全部功能，用户 2026-10-04 拍板**（[41 D-44](../../docs/spec/40-roadmap/41-未决项登记.md) ✅ 已闭环）；**browser 形态不自动弹**（设计口径）。
> **probe / generate / skip** 由 **llm-server** handler 实现（`src/lib/llm/server/wizard.go`），**直接调 data 门面 `facade.ProjectAPI`（inline）** → **不新增 `data-*` 主题**；辅助选项经 `ConfigKVSet`（`prj-config`）写入并广播 `data-prj-config-refresh`。消息面以 [61](../../docs/spec/60-reference/61-消息一览.md) 为准（已同步）。

## 3. 方案：B+A（已选）

| 方案 | 触发点 | 是否新增主题 | 说明 |
|------|--------|:---:|------|
| **A · 核心内置（兜底）** | `gui.init-data` 应答带 add-only 字段 `wizard_required` | ❌ | 零主题改动、最简单 |

## 4. 消息面提案（仅增，逐条授权）

### 4.1 后端 → 前端（事件）

| 消息 | 触发 | payload | 说明 |
|------|------|---------|------|
| `agent-wizard` | 插件检测到 `project_spec.md` 缺失 | `{reason:"missing_spec", work_dir, spec_path}` | 前端订阅 → 打开向导 |

### 4.2 前端 → 后端（方法面）

| 消息 | 触发 | payload | 返回 |
|------|------|---------|------|
| `agent-wizard-probe` | 向导 Step1 | `{}` | `{empty:bool, probe:{…}}`（空目录判定 + 探测结果） |
| `agent-wizard-generate` | 向导 Step5「生成」 | `{mode, summary, choices, agents:[…], scenario_id, project_spec}` | `{ok, scenario_id, files:[…]}` |
| `agent-wizard-skip` | 「稍后」 | `{}` | `{ok}`（本会话不再自动弹） |

> **复用**：场景落盘沿用既有 `data-scenario-save`（reply `{ok, id}`）——**零新增**；仅「探测 / 生成编排 / 触发」为新增。

### 4.3 新主题授权（✅ 已获授权 2026-10-04）

- [x] `agent-wizard`（后端→前端事件）
- [x] `agent-wizard-probe`（前端→后端）
- [x] `agent-wizard-generate`（前端→后端）
- [x] `agent-wizard-skip`（前端→后端）

> 授权口径：**可以加**，但必须**配套做门面**（§4.4），并同步 [61-消息一览](../../docs/spec/60-reference/61-消息一览.md) 与测试。

### 4.4 门面（facade）设计（新增主题的配套）

> **原则**（[28-plugins](../../docs/spec/20-modules/28-plugins.md)）：内嵌插件**不直开库**，数据访问一律**经 data 门面** `facade.API`（宿主 inline 绑定）。新增能力**不得绕过门面**。

| 新消息 | 落点 | 需要的门面/接口 |
|--------|------|----------------|
| `agent-wizard`（事件） | 瘦插件 `plugin-wizard` · 经 `Deps.Bus` 发布 | 仅读 workdir + 发事件（无库访问） |
| `agent-wizard-probe` | server 处理；只读探测 | **`facade.API.ProjectProbe(instanceID)`**（解析 workdir + 只读探测） |
| `agent-wizard-generate` | server 处理；写场景 + 写 spec | **`facade.API.ProjectSpecWrite(instanceID, content)`**（+ 复用既有 `data-scenario-save` 落场景） |
| `agent-wizard-skip` | 会话级记忆（内存） | —（不落库） |

**数据层门面最小集（新增）**：

- `ProjectSpecExists(instanceID) (bool, error)` —— 判定 `<workDir>/.chonkpilot/project_spec.md` 是否存在（插件检测用）。
- `ProjectSpecRead(instanceID) (string, error)` —— 读取（重跑向导时回填）。
- `ProjectSpecWrite(instanceID, content) error` —— 写入（生成后落盘，含目录创建）。

> 门面方法经 `facade.API` 的 **inline 绑定**注入（与既有 data 门面同构）；插件与 server **只经门面**访问，不持库句柄。实现须同步 `src/lib/data` 门面契约与 [12-数据层](../../docs/spec/10-architecture/12-数据层.md)。

## 5. 时序（方案 B）

```text
server.Start → 插件 Start(订阅 instance-register) → 广播 server-starting
客户端连接 → instance-register{work_dir}
   └─ detector 插件：读 <work_dir>/.chonkpilot/project_spec.md
        ├─ 存在 → 静默
        └─ 缺失 → bus.Publish('agent-wizard', {reason, work_dir, spec_path})
             └─ 桥 forwardEvent → emitRemote → 前端 mq.on('agent-wizard')
                  └─ dialog.open(ScenarioWizardDialog)
                       ├─ mq.emit('agent-wizard-probe') → 判定空目录 + 渲染探测卡
                       ├─ Step2/3 选择 → Step4 摘要确认（可编辑）
                       └─ Step5 mq.emit('agent-wizard-generate') → 写场景 + project_spec.md
```

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| workdir 未知 / 多实例 | 以 `instance-register` 的 `work_dir` 为准；多实例各自检测、按 instance 归属过滤 |
| 越层直访数据 | 新增能力一律经 `facade.API`（§4.4），插件不直开库 |
| 重复弹窗打扰 | 会话内 `agent-wizard-skip` 记忆；文件存在即不再弹 |
| 与 `gui.init-data` 争抢首屏 | 向导**非阻塞**，主界面就绪后异步弹出 |
| 误判「空目录」 | 采用分层判定（见 [04 §2](./04-目录探测与project_spec.md)），准空时二次确认 |
