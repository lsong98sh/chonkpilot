# 01 · 交互流程与界面设计

> 关联：[README](./README.md) · [模式选项详细](../模式选项详细.md) · [04-目录探测](./04-目录探测与project_spec.md) · [assets/wizard-mockup.html](./assets/wizard-mockup.html)

## 1. 启动检测时序

```text
GUI 启动
  server.Start → 插件按序 Start → 广播 server-starting          （就绪信号）
  前端首屏 → mq.emit('gui.init-data') → 桥返回 {work_dir,...}
  ── 触发点（B+A，见 05）──
  A. 桥在 init-data 应答中带 add-only 字段 wizard_required（兜底）
  B. 瘦插件订阅 instance-register → 拿到 work_dir → 检测 project_spec.md
  缺失 → 前端 mq.on('agent-wizard') → dialog.open(ScenarioWizardDialog)
```

**判定文件**：`<workDir>/.chonkpilot/project_spec.md`
- 存在 → 不自动弹；场景编辑页提供【向导】按钮可手动重跑。
- 缺失 → 自动弹（可「稍后」；本会话不再自动弹）。

## 2. 向导步骤（共 5 步）

| 步 | 名称 | 说明 |
|----|------|------|
| **Step1** | **项目信息 ★** | **先输入意图**（目的/概要/预算/背景/要求）；有项目时由**扫描预填**、可改 |
| Step2 | 模式选择 | 由 LLM 依据项目信息**预选**；空目录→{新构建/其他}；有代码→{重构/迭代/其他} |
| Step3 | **模式专属选项** | 由 LLM **预填推荐**；**按模式分叉**：新建=脚手架选择 / 迭代=上下文采集 / 重构=约束定义（见 §5） |
| Step4 | 摘要确认 | **可编辑**汇总：项目概要、架构、开发语言、团队成员… |
| **Step5** | **预览与生成 ★** | 同「场景编辑」布局 + **记忆编辑 tab**；确认后写 场景 + **项目记忆** + `project_spec.md`（见 §7） |

> **核心转变**：不再让用户「一开始就逐项选技术」。**新建** = 用户只描述**项目目的/概要/预算/背景/要求** → **LLM 先给推荐**；**有项目** = **LLM 扫描识别并预填**部分内容。用户仅在偏离推荐时手动调整。

## 3. Step1 · 项目信息（★ 新增）

| 字段 | 新建 | 有项目 | 提示（Label 旁 **tooltip**） |
|------|------|--------|------------------------------|
| 项目目的（必填） | 用户填写 | 扫描预填 + 补充 | 为谁解决什么问题，一句话 |
| 项目概要 | 用户填写 | 扫描预填 + 补充 | 主要功能、目标用户、期望形态 |
| 预算 | 用户填写 | 可留空 | 如：无预算 / 10 万以内 / 已有云资源 |
| 部署 | 用户填写 | 扫描预填 | 如：云部署 / 私有部署 / 混合 |
| 周期 | 用户填写 | 可留空 | 如：未知 / 2 周 / 1 个月 |
| 背景 | 用户填写 | 扫描预填 | 团队现状、已有系统、时间要求 |
| 要求 | 用户填写（硬性约束） | 扫描预填 + 补充 | 必用语言/框架、合规、性能、部署 |

> **提示以 Label 旁的 `?` 图标（悬停 tooltip）呈现**；输入框**保持空白、不预填实际文本**。

- **新建**：由用户输入；填写后 → **LLM 依此推荐** 模式（Step2）与技术栈（Step3）。
- **有项目**：进入本步前**自动只读探测**（见 [04](./04-目录探测与project_spec.md)），把探测结果**预填**进这些字段，用户可改。
- **空目录**判定（[04 §2](./04-目录探测与project_spec.md)）决定 Step2 默认模式。
- **优先级**：「要求」中的硬约束**最高**，LLM 推荐不得违背；「预算」用于约束选型（Serverless 免运维 vs 自建集群）。

## 4. Step2 · 模式分流

| 探测结论 | 可选模式 |
|----------|----------|
| 空目录 | **新构建（A）** · 其他 |
| 有代码 | **重构（C）** · **迭代（B）** · 其他 |

- 默认高亮推断项。

### 4.1 「其他」（自定义逃生舱）

选「其他」= **不做 LLM 模板推荐**，**直接复用既有「场景编辑」**：

1. Step2 出现自定义输入：**场景名** + 一句话说明（可选）。
2. **跳过 Step3/4/5 模板**（Step3 仅显示「自定义模式：跳过模板」提示）。
3. 底部主按钮变为【**进入场景编辑**】→ 打开既有 **`ScenarioEditDialog`**（新建态），用户手动配置名称 / 级别 / agents / 主 agent。
4. 保存生成场景后，向导**补写 `project_spec.md`**（`mode: custom`，记录 Step1 `info` + `scenario_id` + `agents`），完成初始化。

> **不重造编辑 UI**：自定义路径复用 `ScenarioEditDialog`（落点见 [05 §6](./05-插件与消息设计.md)），向导只额外补写 spec。
> —— 即：**「其他」的「下一步」就是场景编辑**（不再逐帧走模板）。

## 5. Step3 · 模式专属选项（★ 按模式分叉）

> **Step3 不是一个通用页**：三个模式的选项组不同（下表）。Step1/2/4/5 结构通用，**只有 Step3 按模式切换内容**。样张 [assets/wizard-mockup.html](./assets/wizard-mockup.html) 已做成**随 Step2 模式切换**（点模式卡即换 Step3）。

| 模式 | Step3 选项组（顺序） | 技术栈来源 |
|------|----------------------|-----------|
| **A 新构建** | 项目类型 → 目标平台 → 前端语言/框架/UI/状态/构建 → 后端语言/框架/API → 数据层 → 架构形态 | **用户选择**（LLM 推荐预填） |
| **B 迭代** | 代码库接入 → 侦察预览 → 影响范围与风险 → 迭代节奏 | **扫描所得**（默认只读，可修正） |
| **C 重构** | 重构目标类型 → 当前技术栈(扫描) + 目标技术栈(迁移时) → 行为保持策略 → 范围与验证方式 → 特殊角色 | **扫描所得** + 迁移时选**目标** |

**三点共性**：
1. 三个模式都遵循 §5.1 控件规范（单选/多选 + 其他/自定义）；
2. 都先由 LLM 依 Step1「项目信息」预填推荐；
3. **B/C 的语言/框架/架构取自扫描、默认只读**——只做「确认 / 修正」，不做「从零选择」，避免与既有代码冲突。

> **B 不设「迭代任务类型」**：迭代是**持续**的、各类情况都会遇到，无法在初始化时预设一种任务类型。相应专项角色（调试工程师 / 性能优化师 / 依赖审计员）改为在 **Step4 摘要按需手选**（预置仍保留）。

> **为什么 C 不一样**：重构的核心约束是「不改变外部行为」，重心在**行为保持策略 / 验证方式 / 特殊角色**，而非技术栈。选项全集见 [模式选项详细](../模式选项详细.md) 第三、四章；样张见 [assets/wizard-mockup.html](./assets/wizard-mockup.html)。

### 5.1 控件规范（统一构造 + 其他/自建，适用于三个模式）

> **原则**：所有可枚举选项**只允许两种构造**——**单选**（radio chips / 单选卡）与**多选**（chips）；**不使用裸下拉**（下拉无法表达「列表里没有这个」）。**每一组末尾必须有【其他】**，选中后出现**自定义输入框**（如语言填 `Zig`/`MoonBit`、ORM 填 `JPA`）。

| 选项 | 构造 | 说明 |
|------|------|------|
| 项目类型 | **单选卡 + 其他** | 业务型 / 组件型 / 基建型 / 游戏 / 其他（见 5.3） |
| 目标平台 | **多选 chips + 其他** | 前端 / 后端 / Web / 移动端 / 小程序；**可组合**，选 Web / 移动端 / 小程序**自动勾选「前端」** |
| 架构形态 | **单选卡 + 其他** | 每项 = 标题 + 一句定义 + 「典型团队」（见 5.2） |
| 前端语言 / 后端语言 | **多选 chips + 其他** | **前端、后端各自独立**一组，可多选 |
| 框架 / UI / 状态 / 构建 / ORM / 数据库 / API 风格 | **单选 chips + 其他** | 从属选择，随平台/语言解锁；缺项走「其他」 |
| 自治级别 | 分段控件 | 单选 |
| 自定义技术 | 「其他」→ 输入框 | 值进入对应角色的「项目适配」槽（见 [03 §6](./03-提示词合成设计.md)） |

**核心修正**：
1. 架构、平台**逐项带详细说明**（单选卡 / chips），不做无解释的枚举。
2. **目标平台 = 多选可组合**（前端 / 后端 / Web / 移动端 / 小程序）：选 Web/移动端/小程序**自动勾选「前端」**；前端语言 / 后端语言**分开且可多选**。
3. **架构形态 → 团队层** 显式映射（见 5.2）：选中「三层」**必须**产出数据访问层角色，杜绝「选了三层却只有前后端」。
4. **兜底**：任一组**必有【其他】+ 自定义输入**，覆盖非主流/私有技术（Zig、MoonBit、JPA…），避免「列表没有就无法选」。

### 5.2 架构形态 → 团队层映射（模式 A）

| 架构 | 层 / 拆分 | 追加成员 |
|------|----------|----------|
| 两层结构 | 表现层 ←→ 服务端 | 前端开发、后端开发 |
| 三层结构 | 表现层 / 业务逻辑层 / 数据访问层 | 前端开发、后端开发、**数据工程师** |
| 微服务 | 表现层 + 多服务 + 网关 | 前端开发、后端开发（按服务）、**集成协调者**、数据工程师 |
| Serverless | 表现层 + 函数 + BaaS | 前端开发、后端开发（函数）、**DevOps 工程师** |

> 该映射为「选项 → 编排」的硬约束：预览（右栏）与生成的 `scenario.json.agents` **必须**体现对应层角色。

### 5.3 项目类型 → 团队侧重（模式 A）

| 类型 | 说明 | 侧重成员 |
|------|------|----------|
| 业务型 | 以增删改查为主 | 前端开发 / 后端开发 / 数据工程师 |
| 组件型 | 流程引擎、决策引擎等可复用组件 | 架构设计师 / 后端开发 / 文档撰写者 / 测试工程师 |
| 基建型 | Redis、容器等基础设施 | DevOps 工程师 / 后端开发 / 安全审查员 / 性能优化师 |
| 游戏 | 游戏 / 互动内容 | 前端开发 / UX 设计师 /（图形向预置待扩展） |
| 其他 | 自定义（按摘要手选成员） | 用户手选 |

## 6. Step4 · 摘要确认（可编辑，预览前置）

> **本步是「扫描总结 / 用户选择总结」的合流点**：新建时空白待填（**用户必须给出项目概要**）；有项目时由扫描预填，用户可逐项修改。**确认后**进入 Step5 预览与生成。

摘要字段（分组呈现，均可编辑）：

| 分组 | 字段 | 新建(A) | 有项目(B/C) |
|------|------|---------|-------------|
| 项目概要 | 名称、一句话目标、业务背景 | **用户填写**（必填） | 扫描 + 用户补充 |
| 架构 | 架构形态、分层、关键约束 | 由选项推导 | 扫描预填，可改 |
| 开发语言 | 主语言、框架、包管理 | 由选项推导 | 扫描预填，可改 |
| 数据 | 数据库、ORM、缓存 | 由选项推导 | 扫描预填，可改 |
| 命令 | 构建 / 测试 / lint | 由选项推导 | 扫描预填，可改 |
| **团队成员** | **成员清单（名词）** | 依据模式+选项推导，可增删 | 同左 |
| 协作 | 自治级别 | 用户选择 | 用户选择 |

> 团队以**成员清单（名词）**呈现，**不出现「规模」数字**；用户通过勾选/增删成员调整（可选项来自 [02](./02-预置智能体目录.md) 预置目录）。
> **Leader 不由用户选**（用默认 Leader，见 [03 §5](./03-提示词合成设计.md)）；**不暴露委派深度**。
> **团队可增删**：Step4 摘要 与 Step5 预览 **两处都**可添加 / 移除成员（**推荐在预览**操作）。

### 6.1 辅助选项（项目配置预设）

> 均为**预设**，写入项目配置；生成后可在「设置」页随时修改；默认值由探测决定。

| 项 | 默认 | 既有配置键 | 说明 |
|----|------|-----------|------|
| 记忆库 | 开 | `memory.enabled` | 关则团队不沉淀 / 不注入记忆 |
| 用户偏好 | 开 | `memory.category.用户偏好` | 唯一用户级类别 |
| 代码索引 codegraph | 关 | `enable-codegraph` | **仅现有项目**可选 |
| 全文索引 vfts | 关 | `enable-vfts` | **仅现有项目**可选 |
| 初始化 git | 仅**未检测到 git** 时提供 | （执行 `git init`） | 现有项目已有 git → 不显示 |
| 文件历史检查点 | 随 git 可用 | `history.enabled` | 有 git 才可选；默认关 |

## 7. Step5 · 预览与生成（★ 含记忆编辑）

> **预览页 = 「场景编辑」同构 + 项目记忆**（单一编辑面，避免同一份记忆两处编辑）。
> 与既有 [`ScenarioEditDialog`](../../src/frontend/src/views/scenario/ScenarioEditDialog.vue) 对齐：顶部工具条 + 左右分栏 + 页签；**多一个「项目记忆」tab**。

**布局**（顶部工具条 + 选项卡 + 底部生成栏）：

```text
┌ 场景名 [input]  项目级        将写入：场景目录 · 项目记忆 · project_spec.md ┐
├ [ 场景 ] [ 组合提示词 ] [ 项目记忆 (8) ] ────────────────────────────────────┤
│ 场景 tab（同场景编辑）：                                                     │
│   左：主 agent + 子 agent(5) 引用列表（可增删）                              │
│   右：选中 agent 详情（名称 / 角色 / 引用 / 提示词）                          │
│ 组合提示词 tab：三层只读（全局层 / 场景层 / agent 层，见 03 §1）             │
│ 项目记忆 tab：左类别列表（预置8/自定义）+ 右 tab（记忆内容 / 沉淀提示词）      │
├ [上一步] [生成] [存为预设] [稍后] ──────────────────────────────────────────┤
```

- **场景 tab**：与 `ScenarioEditDialog` 同构（左列表 + 右详情）；子 agent 为**引用**，内容编辑仍在「扩展 · 智能体」页。
- **组合提示词 tab**：只读展示三层拼接结果。
- **项目记忆 tab**：与「场景 tab」**同构**（**左类别列表 + 右详情**）。右详情 = 两 tab：【**记忆内容**】/【**沉淀提示词**】；左列表 = 预置 8 类（可启停·**不可删**）+ 自定义类（**可增删**）。落点 `<workDir>/.chonkpilot/memory/<类别>.md`。
  > ⚠️ **向导时项目尚无真实记忆**：右栏文本框是 **LLM 依项目内容预填的「初始种子内容」**，生成时才写为 `memory/<类别>.md` 的**起点**，此后由记忆库累积——不是"已有的记忆"。

| 预置类别 | 内容来源 |
|----------|----------|
| 项目概要 | Step1 目的/概要/背景 + 探测摘要 |
| 开发规范 | 扫描的风格 / 目录约定 |
| 构建发布规则 | 扫描的构建/测试命令 + 「部署」字段 |
| 接口库 | API 风格 / 后端栈 |
| 测试规范 | 测试框架 / 命令 |
| 共同库 · 典型参照 · 用户决策 | 按需（可留空） |

### 7.1 可编辑性（生成前最终确认台）

| 项 | 页内 | 说明 |
|----|:---:|------|
| 场景名 / 场景描述 | ✏️ 可编辑 | |
| 团队成员（子 agent 引用） | ✏️ 可增删 | 摘要与预览**两处都可**增删；**推荐在预览**操作 |
| 主 agent 提示词 | ✏️ 可编辑 | 复用既有 `AgentEditor` |
| 子 agent **引用正文** | 🔒 只读 | 与场景编辑一致，去「扩展 · 智能体」页改 |
| 项目记忆 | ✏️ 可编辑 | 见 7.2 |

> 生成后即是**普通场景**，仍可在场景编辑页再改；预览只是「生成前的最后一次改」。

### 7.2 记忆的可编辑范围（种类 / 内容 / 提示词）

| 维度 | 可编辑 | 落点（**既有**，零新增主题） |
|------|:---:|------|
| 内容 | ✏️ | `data-memory-save`（单类全文） |
| 种类 | ✏️ | **新增项目级自定义类别 / 删除自定义类 / 启停类别**：建类走 `data-memory-save`、删类走 `data-memory-delete`；**预置 8 类不可删**（只能清空 / 停用）；门控 `memory.enabled`、`memory.category.<类别>` |
| 沉淀提示词 | ✏️ | 每类重写指令 = `memory.prompt.<类别名>`（缺省回落内置默认），复用「设置 · 上下文管理页」的【编辑提示词】（`data-prj-config-*`） |

> ⚠️ **两个不同概念，勿混**：页内**文本框 = 该类「内容」**（累计知识，落 `memory/<类别>.md`）；**「沉淀提示词」= 该类的「重写指令」**（system prompt，`memory.prompt.<类别>`，缺省回落 `defaultRewriteSystemPrompt`）。二者不同：**AI 优化**是对「提示词 / agent 提示词」的**动作**，不改记忆内容。

### 7.3 提示词 AI 优化（每处均可）

- **所有提示词编辑处**——每个 **agent（含主 agent）** 的提示词、每类记忆的**沉淀提示词**——都提供【**AI 优化**】/【恢复】，对齐 [SCEN-005](../30-function-points/37-场景.md)：`prompt-optimise` → 流式 `optimize-token` / `optimize-done` / `optimize-error`。
- 入参 `{title, useCase, prompt}`：`useCase` 区分 `agent` / `memory`（沿用既有 `useCase` 字段，**零新增主题**）。

### 7.4 生成过程（非阻塞 + 进度）

> 生成（合成提示词、**建索引**）可能较慢，**不自动关闭**向导。

- 点「生成」后切「**生成中**」态：展示步骤与进度；**用户可手动关闭**（后台继续，不打断）。
- 步骤：① 合成提示词 → ② 写场景目录 → ③ 写项目记忆 → ④ 写 `project_spec.md` → ⑤ **建索引**（仅启用了 codegraph / vfts 时）。
- **索引进度条**：复用既有 `codegraph.status` / `vfts.status`（`{state:"indexing", phase, progressDone, progressTotal}`）—— 二者可能较慢，故**不阻塞**、逐步刷新。
- 完成 → 提示成功并可「打开场景」；失败 → 分步标红、可重试（**不丢已成功步骤**）。

- 点「生成」：
  1. 合成提示词（[03](./03-提示词合成设计.md)）；
  2. 写 `<workDir>/.chonkpilot/capability/scenarios/<id>/`（`scenario.json` + `main.agent.md`）；
  3. 写**项目记忆** `<workDir>/.chonkpilot/memory/<类别>.md`（经**记忆门面**，见 [05 §4.4](./05-插件与消息设计.md)；失败**不阻断**场景生成）；
  4. 写 `project_spec.md`（含技术栈等，见 [04](./04-目录探测与project_spec.md)）；
  5. 前端刷新场景列表并选中该场景。

### 7.5 记忆种子的可扫描性（8 类）

> 向导生成的是**初始种子**；**不是 8 类都能扫到**——按来源分三档，低档必须标「待补充」。

| 预置类别 | 可扫描性 | 扫描来源 |
|----------|:---:|----------|
| 开发规范 | ✅ 高 | lint/format 配置（`.eslintrc`/`.prettierrc`/`gofmt`）、EditorConfig、目录约定 |
| 构建发布规则 | ✅ 高 | `package.json` scripts、Makefile、`*.ps1`、Dockerfile、CI（`.github/workflows`） |
| 测试规范 | ✅ 高 | 测试框架配置、`test/` 目录、运行脚本 |
| 接口库 | 🟡 中高 | OpenAPI/proto、路由注册、类型定义、消息常量 → 可枚举，语义需归纳 |
| 项目概要 | 🟡 半 | README / docs / 清单 description / git log → 初稿；**目标与边界**需 LLM 归纳 |
| 共同库 | 🟡 半 | 目录结构、shared/公共包、导入关系 → 列清单；"约定"需归纳 |
| 典型参照 | ❌ 低 | 扫描只能给**候选**；"哪个值得参照"需 LLM / 用户判断 |
| 用户决策 | ❌ 无 | ADR（`docs/decisions`）可扫**部分**；多数决策无留痕 → 靠 Step1 + 后续沉淀 |
| （用户偏好） | ❌ | **用户级、跨项目**，不在项目扫描范围 |

- **实现要求**：种子内容**逐类标注来源与置信度**（`扫描` / `LLM 归纳` / `待补充`）；🟡❌ 类**留空或标「待补充」，不编造**。
- 扫描不到 ≠ 生成失败：记忆随使用**由记忆库自动累积**，种子只需给一个可用起点。
- 类别清单权威源：[`memoryCategorySpecs`](../../src/lib/data/internal/memory/memory.go#L66-L75)（8 项目级 + 用户偏好）。

## 10. 按钮语义

| 按钮 | 动作 | 写文件 | 关闭对话框 | 下次 |
|------|------|:---:|:---:|------|
| 上一步 | 回上一步（保留已填） | 否 | 否 | — |
| 下一步 / **生成** | 前进；末步**生成**（§7.4） | 生成时写 场景 + 记忆 + `project_spec.md` | 生成中**不闭合**；完成提示「打开场景」 | 有 spec → 不再自动弹 |
| **默认**（Step2 内） | 用**全部默认**（LLM 推荐 + 各步默认）一步生成 | 生成时写 场景 + 记忆 + `project_spec.md` | **是**（写后即关闭；生成后台继续，§7.4） | 有 spec → 不再自动弹 |
| **存为预设** | 把当前**全部选择**（Step1–4）存为**项目级预设** | 写 `<workDir>/.chonkpilot/wizard/preset.json`（**不写** `project_spec.md`） | **否** —— toast「已保存为预设」，**继续留在向导** | 下次开向导**自动加载**预填 |
| **关闭** | 关闭向导，**丢弃未生成的选择** | **不写任何文件** | **是** | **只要没有 spec → 下次启动必弹** |

**要点**
- 「存为预设」是**中途快照**，不是初始化完成 → **不关闭、不写 spec**。
- 「关闭」**不等于初始化** → 不写 spec；**方案 1：不做持久"不再弹"开关**，只要无 `project_spec.md`，**下次启动必须弹**。
- 「**默认**」= Step2 的**快捷路径**：跳过 Step3–5，用全部默认直接生成并关闭。
- 只有「**生成**」/「**默认**」成功 → 写 `project_spec.md` = **初始化完成标记**。

### 10.1 下次如何打开向导

| 情况 | 自动弹 | 手动入口 |
|------|:---:|------|
| **无** `project_spec.md` | ✅ **启动必弹**（无持久静默开关） | 场景页【向导】按钮（§9） |
| **有** `project_spec.md` | ❌ 不自动弹 | 场景编辑页【向导】按钮（重跑，**覆盖写** spec） |

- 预设文件（`wizard/preset.json`）与初始化标记（`project_spec.md`）**互不影响**：前者只决定"预填什么"，后者决定"是否自动弹"。
