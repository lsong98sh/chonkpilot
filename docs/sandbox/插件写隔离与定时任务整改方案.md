## 1. 现状（核实结论）

### 1.1 沙箱只在 gateway spawn stdio 时施加

- `chonkpilot-agent/gateway/src/provider.go`：`case "stdio"` 才 `sandbox.Prepare(proc, sandbox.Spec{})`；**http/sse 不施加**。
- 插件 MCP 以 **Streamable HTTP** 注册且**不带 runtime**（`src/lib/llm/server/plugin_servers.go`），宿主明令禁止 gateway 再 spawn。
- 插件 exe 由插件管理器 `exec.Command` 拉起（`chonkpilot-framework/plugin/src/mgr/manager.go`），只设了隐藏控制台的 `SysProcAttr`，**无 Low IL / Job**。

**结论**：`file_*` / `task_run` / `web_download` 目前**没有任何 OS 级写隔离**，只剩 R-11 路径形态校验。

### 1.2 安全目录配置（现状）

- 存储：prj `security-<id>` = JSON `{"dir","writable"}`（`src/lib/data/internal/config/validate.go` 强校验 dir 必填 + writable 必填）。
- 消费：`src/lib/llm/server/execconfig.go securityRules()` → gateway `SandboxDirs`；`WritableRoots()` 只取 `writable=true`。
- Low IL 语义本身就是「读不限、只限写」，`writable=false` 的条目实际不产生约束。

### 1.3 crontab 现状

- 调度：1s ticker 单 goroutine；**同任务不重入**（`skipped:overlap`）；**跨任务无并发上限**（每个到期任务直接 `go`）。
- 执行：`scriptrun.Run`（`chonkpilot-util/scriptrun`），`cwd = CreatedBy.WorkDir`，**无沙箱**。
- 任务模型：`Task{ID,Cron,Action,Description,Enabled,CreatedAt,CreatedBy,running_since,NextRunAt}`，**无用户、无沙箱字段**。
- 存储：插件数据目录（按 OS 用户隔离）。

### 1.4 PM / Instance 现状（三个注册表 + 一个窗口树）

| 组件 | 职责 |
|------|------|
| `src/lib/workspace.Manager`（PM） | `work_dir → Space{Layout, Instances}` + 引用计数 + 翻译 `workdir-opened/closed` |
| `framework runtime/instance.Manager` | `instance_id → Info{WorkDir,User,Parent,SessionID}`；`MainInstanceForWorkDir` / `InstanceForSession` |
| `gui hostEnv.projects` | `work_dir → projectCtx{mainHost, windows}`（真正的窗口树） |
| `gui/owner.go` | `session → {instance, turn}` 运行态归属 |

`workspace.Manager` 的 `Instances` 与 `instance.Manager` 的 `recs` 是同一批 `instance-register` 的**两份投影**。

### 1.5 顶层 Dialog 的显示口径（重要，需固化为不变量）

- 列表源 = **prjusr 库的 `dialogs` 表**（`dialog_id/file/title/kind/main_session_id/updated_at`，见 `src/lib/data/internal/sessionstore/dialog.go`）；
- 每个 dialog 是独立库 `dialogs/dialog-<hex>.db`；**主 session = 库内 `parent_id==""` 的行**；
- 列表直接取 `dialogs.main_session_id`，不短开每个对话库。

⚠️ **风险**：`dialogs/` 目录有启动对账（`src/lib/data/persist/reconcile.go`），会**扫目录补行**。若为定时任务新建 dialog 库而不打标记，对账会把它补进 `dialogs` 表 → 出现在用户列表。

## 4. 隔离能力下沉（C5）

当前 Low IL + Job 实现位于 `chonkpilot-agent/sandbox`（`Start/Prepare/EnsureLowIL`）。插件（task / crontab）需要复用：

- **方案**：下沉到 `chonkpilot-util`（新增 `chonkpilot-util/sandbox`，或并入 `winproc`），`chonkpilot-agent/gateway` 改引用 util；
- `chonkpilot-util/scriptrun` 的 `Options` 增加：

```go
type Sandbox struct {
    Enabled  bool
    Writable []string // 已 EnsureLowIL 的目录
    Limits   sandbox.Limits
}
```

- `scriptrun.Run` 在 `exec.Command` 后：`Enabled` → `sandbox.Start(cmd, spec)`，否则保持现状；
- 依赖方向：插件 → util（不再需要依赖 `chonkpilot-agent`）。

## 5. 插件逐个整改

### 5.1 file 插件（C4）

- 写工具 7 个：`file_write` / `file_patch` / `file_replace` / `file_copy` / `file_move` / `file_delete` / `file_iconv`；
- 只读 4 个（`read/find/diff/detect`）不校验；
- 校验点：`chonkpilot-plugins/file/src/lib/toolset`，与现有 R-11 校验同一入口；
- 判定字段：`targets[].path` / `targets[].from` / `targets[].to`（`move` 的 `from` 为删除语义，需一并判定）；
- 语义（落地口径）：**调用前预检**，任一项越界 → **整次调用拒绝**（未做任何写入；提示含越界路径）。原「该项失败」需下沉到 `filetool` 各 handler，暂不做（[41 G-94](../spec/40-roadmap/41-未决项登记.md#2-已收口--历史只读不再待决)）；
- 路径判定：两侧统一解析真实路径（兼容 junction/软链），按前缀判定「在可写目录内」。

**通道（C3）**：`_meta.chonkpilot.sandbox = {enabled, writable_dirs}`，由宿主在调用前按 `(instance→work_dir)` 取配置快照填入。插件为 `product:true` + `origin:"builtin"`，`_meta` 已注入（`contract.Meta(ctx)`）。

> 未启用（无该字段 / `enabled=false`）→ 不校验（保持旧行为）。

### 5.2 task 插件（C5）

- `task_run` 调 `scriptrun` 时传 `Sandbox{Enabled, Writable}`；
- 执行前对 `cwd`（= work_dir）与各 `writable_dirs` 执行 `EnsureLowIL`（幂等）；
- 开关：usr `tool_sandbox.mcps["task"]`（沿用现有两态语义：开 = 传，关 = 不传）；
- `task_run` 的 `file`（脚本文件）只读，不要求可写。

### 5.3 web 插件（C6）

- `web_download` 落盘前按最终路径判定：`saveAs` / `dir + filename` / 默认目录；
- 默认目录 `~/Downloads/chonkpilot` 不在白名单时 → 明确失败并提示（不自动放行）。

### 5.4 mcp 插件（C7）

- `mcp_invoke` → `plugin/v1/tools.call` → 宿主 → gateway，链路不变；
- 被调工具所属插件的校验自动生效，无需额外改动。

### 5.5 crontab 插件（C5/C10–C14）

#### 5.5.1 任务模型

```go
type Task struct {
    ... // 现有字段
    CreatedBy struct {
        InstanceID, SessionID, WorkDir string
        User string // 新增：创建者 OS 用户（审计/身份）
    }
    Sandbox struct {           // 新增：任务级开关（缺省继承插件配置）
        Enabled  bool
        OverrideDirs []string  // 可选：覆盖项目白名单
    }
    DisabledReason string      // 新增：work_dir_missing 等
}
```

> **落地口径（P2，2026-11-03）**：`Sandbox` 实现为 **`*bool`**（`nil` = 继承插件配置
> `plugins.crontab.sandbox`），未引入 `OverrideDirs`（目录覆盖留待需要时再加）；
> `CreatedBy.User` 未加（当前执行身份 = 插件进程 OS 用户，C10 的「创建者用户」待 P5/P6 与多用户数据面一并落地）。

#### 5.5.2 执行前链路

> **P2/P3 状态（2026-11-03）**：①②③④ 均已实施；③ 按用户口径调整为：**未命中在册实例 → 只用内置默认项**
> （不短开 bbolt）——P3 起 ② 会先隐藏打开项目，故正常情况下 ③ 必有在册实例（[41 G-96](../spec/40-roadmap/41-未决项登记.md#2-已收口--历史只读不再待决) 已标「已消除」）。

```
① os.Stat(CreatedBy.WorkDir)
   └─ 不存在 → disabled(work_dir_missing) + 记 skipped:workdir-missing（仅首次通知）   ✅ P2
② 宿主 plugin/v1/workdir.ensure {work_dir, hidden:true}                              ✅ P3
   ├─ 已打开（在册顶层实例）→ 返回主实例 id（opened=false，不建窗）
   └─ 未打开 → 隐藏打开项目（§7/§8），等 instance-register（≤12s）
         └─ 失败 → skipped:workdir-open-failed（本轮跳过，下轮重试；**不 disable**）
③ 宿主 plugin/v1/sandbox.resolve {work_dir}                                          ✅ P2
   ├─ 命中在册实例 → 用内存态 securityRules
   └─ 未命中 → 只用内置默认项（work_dir + <work_dir>/.chonkpilot/tmp）              （G-96）
④ EnsureLowIL(cwd + writable_dirs) → scriptrun(Sandbox)                              ✅ P2
```

- ②③ 未合并为一次调用（P3 落地口径：两个方法各自单一职责；合并不改语义、留待需要时再做）；
- ② 失败（目录在但建窗/登记失败）→ 跳过本轮 + 记错（可重试），**不 disable**；
- `workdir.ensure` 失败**不**导致任务失效；
- ③ 失败（拿不到策略）→ **不阻断任务**：按不隔离执行，并在 `RunRecord.Detail` 记 `sandbox_unavailable: <原因>`。

#### 5.5.3 会话归属（C11）

```
cron 对话（dialog，kind="crontab"）
└─ 根会话 id = "crontab-xxxxxxxx"（真实行，parent_id=""）
   └─ 每任务 1 个 sub_chat 会话（`kind="crontab_task"`，parent_id="crontab-xxxxxxxx"）
        └─ 每轮 = turn
```

- 用 `SessionEnsure` 建：根会话走「根自举」建 dialog；子会话显式带 `DialogID`；
- 建完 `rememberDialog(parentID→dialogID)`，否则后续写入缺 `dialog_id` 被拒；
- 执行主体标记：`origin=scheduler`（审计/UI 展示），不冒充用户。

> **落地口径（P4，2026-11-03）**：`crontab` 插件经宿主 UDS 能力 `plugin/v1/session.ensure` /
> `.ensure-turn` / `.complete-turn` 建会话与轮次（**插件不直接开库**，C8）；宿主实现 =
> `src/lib/llm/server/plugin_caps.go`（`SessionEnsure` + `rememberDialog`），数据面 =
> `data-session-ensure-session`（`title` / `origin` 只增字段）。根会话 id 由 `work_dir` 确定性派生
> （`crontab-<8hex>`），子会话 id = `crontab-<task_id>`；重复执行幂等（同一 dialog / 会话行不重复建）。
> 归属失败**不阻断执行**（`RunRecord.Detail` 记 `session_bind_failed: …`）。

#### 5.5.4 列表可见性（C12）

## 7. 项目树（PM = Project Manager，C15）

### 7.1 四层模型

```
L1  work_dir + user  → 数据访问面（prj 库共享 / prjusr 按用户）
L2  instance(window) → 可见性、承载关系（visible|hidden）
L3  dialog           → 该实例/项目下的对话
L4  session          → 对话内的会话（轮次挂此）
```

PM 只存 **ID + 关系 + 状态**，不存消息/文件内容。

### 7.2 对外门面

```
OpenProject(work_dir, user)
CreateWindow(project, kind, visible) / Hide / Close
CreateDialog(project | instance)
CreateSession(dialog, params)
Route(topic, payload) → []Target      // MQ 调度策略
```

### 7.3 与现状映射

| 现状 | 归入 |
|------|------|
| `workspace.Manager`（spaces/byInst） | L1 |
| `framework runtime/instance.Manager`（recs） | L2 |
| `gui hostEnv.projects` | L2 的关系（窗口句柄留在 gui 的 WindowFactory） |
| `gui/owner.go` | L3/L4 关系 |
| `gui/mqpolicy.WorkDirPolicy` | `PM.Route` |
| `gui.Env.OpenProject` / `open-chat` | PM 门面的实现方 |

### 7.4 边界

1. PM **不持有窗口句柄**（否则无法在无 GUI 形态运行）；
2. `create*` 是薄门面，业务动作走工厂接口 / 既有 MQ；
3. L1 键 = `(work_dir, user)`；prj 库 work_dir 级共享，prjusr 用户级私有。

### 7.6 项目生命周期口径（✅ 2026-11-03 P3 定稿，回应 §14 U1）

**结论：项目（work_dir）生命周期 = 项目主窗口生命周期，不与窗口解耦。**

| 阶段 | 触发 | 行为 |
|------|------|------|
| 打开 | 用户（托盘 / `gui.dir.open`）或宿主隐藏打开（`plugin/v1/workdir.ensure`） | `Env.OpenProject`（同 work_dir 唯一）→ 桥发 `instance-register` → 实例视图登记 → 工作区管理发 `workdir-opened` |
| 隐藏 | `gui.ProjectConfig.Hidden=true` | 唯一差异 = 窗口不显示（`AutoFocus=false` / 导航完成不 Show / 不套用几何 / 不进「最近活动项目」）；其余（桥、认领、通知插件、索引）与正常打开**逐条相同**（C17） |
| 显形 | 托盘「项目列表」点选（`ActivateProject` → `show()`） | 变普通可见项目 |
| 关闭 | 用户关闭该项目主窗口 / 托盘退出 / `/quit` | 既有 `finish`：关本项目小窗口 → `instance-exit` → 注销实例 → `workdir-closed` |

- **隐藏实例不随「一次定时任务结束」退出**，也不做引用计数自动关窗（P3 不做；见 [41 G-98](../spec/40-roadmap/41-未决项登记.md#2-已收口--历史只读不再待决)）；
- 常驻到**用户显式关闭该项目主窗口**或**进程退出**——与用户自己打开的项目完全一致；
- 详见 [13-生命周期 §1A](../spec/10-architecture/13-生命周期.md)。

## 9. 禁止直接访问 bbolt（C8 / C9 / C18）

- 契约：任务命令/脚本**不得**打开 `.chonkpilot/**/*.db`；
- bbolt 排他锁（3s 超时）只能提供部分保护：能力端已开库 → 脚本开库失败（安全）；脚本先占库 → 能力端开不了（危险）；
- **沙箱不再承担「防写库」职责**（C18：数据根保留在可写项内），因此该约束是**契约 + 能力端点**，不是 OS 边界；
- 真正的解 = **能力化**：会话/配置/知识库的读、写、**建桶**全部由能力端点提供，任务只调能力。

### 9.1 数据能力端点（✅ P6 已落地 2026-11-03；G-104 二期 2026-11-03）

| 端点 | 用途 | 状态 |
|------|------|------|
| `plugin/v1/data.kv.get` / `.set` / `.del` / `.list` | 项目/用户级键值读写（键空间 = **(插件 id, work_dir, user)**；值 ≤ 64 KiB，超限 `value_too_large` 不截断）；`.set` 支持可选 `ttl_seconds`（过期按不存在），`.list` 不返回过期项 | ✅ 已实现（TTL = G-104） |
| `plugin/v1/data.kv.del-prefix` | 当前命名空间内**前缀批量删除**（`prefix` 必填非空，返回 `deleted`） | ✅ 已实现（G-104） |
| `plugin/v1/data.bucket.ensure` / `.list` | **建桶**（知识库/归集产物等自定义桶）与列举，幂等 | ✅ 已实现 |
| `plugin/v1/data.bucket.query` | 桶内查询：`records.jsonl`（`{id, key?, value, created_at?}` 追加写）+ 分页 + 前缀过滤 | ✅ 已实现（G-104） |

- 全部为宿主/数据层端点，**插件与任务脚本不接触库文件**（桥不暴露任何库句柄 / 库路径）；
- 入参统一显式 `work_dir`（+ 需要时 `user`），不依赖「当前进程恰好属于谁」；
- **授权（G-102，2026-11-03 已实施）**：显式跨用户仅放行「历史记录读取」类（`session.get` / `session.history` / `session.export`）；KV / 桶的读、写跨用户仍 `auth_required`（判定落点 = `plugindata.Store.resolveUser`，`Options.Authorize` 为宿主级追加口）；同用户（缺省 user）行为不变；不模拟登录 / 不提权；

## 10. 跨用户归集（C16）

### 10.1 能知道什么

| 信息 | 来源 |
|------|------|
| 一个 work_dir 有哪些用户 | 枚举 `<work_dir>/.chonkpilot/users/<用户名>/` |
| 某用户当前是否在用 | 短超时试开其库：失败 = 被 writer 占用（启发式） |
| 当前进程的实例 | 仅本用户（desktop 单进程 = 单 OS 用户） |
| 全机器有哪些 work_dir | ❌ 无权威来源（仅能从任务与当前项目推） |

### 10.2 需要的能力

```
plugin/v1/prj.users.list    {work_dir}        → [{user, db_present, in_use, dialog_count, last_active}]
plugin/v1/session.export    {work_dir, user?, session_id} → 会话完整 JSON 内联导出（✅ 已实施，G-103）
plugin/v1/session.list      {work_dir, user}  → 会话列表（不含正文；仍未实现）
```

- prjusr 落点按 `usersRoot(workDir)/<user>` 直算（`plugindata.sessionPrjUsrDir`；共享数据根形态 prjusr = `data_dir`，与 user 无关），不改 `LayoutOf` 签名；
- **不需要模拟登录/提权**：prjusr 只是目录名，能否读由 NTFS ACL 决定；
- 占用时**不抢锁**，记 `skipped:user-busy`，下一轮重试；
- 审计：记录 `{actor_user, target_user, work_dir, at}`；
- 隐私（G-102 拍板后的实际口径）：**不做「按用户默认关」开关** —— 跨用户放开但仅限历史记录读取，KV/桶读仍拒绝；每次跨用户读取记审计（留存策略仍待拍板）。

### 10.3 归集流程

```
① prj.users.list(work_dir)
② 逐用户 prj.user.export（busy → 跳过）
③ 合并 → 写项目级共享知识区
```

> 原判断「在线跨用户实时读不可行（bbolt 排他锁）」已部分修订（G-103，2026-11-03）：**单库短开读可行**（`data.OpenExistingDialog`，不持有句柄；与在写回合由 bbolt 超时自然互斥）—— `session.export` 即走该通道；持锁**长期跨用户**读写仍不可行（KV/桶也不提供跨用户写）。
