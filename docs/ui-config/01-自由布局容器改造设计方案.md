## 1. 问题与目标

### 1.1 现状（问题）

**布局写死在代码里**：`src/frontend/src/views/layout/MainLayout.vue` 用 5 层 `SplitPanel` 硬编码嵌套（`toolbar / [ [filetree|preview]、[session-tree|session-chat] ] | chat / statusbar`），**区块集合、层级、显隐开关、尺寸上下限全部是常量**：

| 写死的东西 | 位置 | 后果 |
|------------|------|------|
| 区块树（谁在谁里面、上下还是左右） | `MainLayout.vue:3-35` | 用户无法把「任务区」搬到底部、把「预览」挪到左侧 |
| 显隐开关（仅 3 个：chat / filetree / task） | `MainLayout.vue:68-72`、`Toolbar.vue:170-198` | 无法新增/删除区块，也谈不上"配置" |
| 尺寸系数与 clamp 规则（`PREVIEW_MIN` / `NARROW_MAX=900` / 各 `eff*Width`） | `MainLayout.vue:86-151` | 改一处阈值要改代码、要重新构建 |
| 持久化字段（7 个） | `MainLayout.vue:196-211` | 只够记住"当前这套布局"的尺寸，装不下别的布局 |
| 预览区页签 | `CodeView.vue`（10 种 `kind`、15 种 `renderType`） | 预览区不能拆、不能复制、不能换容器 |

**参考工程已经打通了这条路**：`layout-free` 用「区域树 + 配置 JSON + MQ 命令」实现了自由布局（`src/components/layout/*`）、内容设置编辑器（`src/components/settings/*`，5 页签）、栏三区（`components/bar/*`）、具名抽屉（`components/drawer/*`）、标签栏四向 + 溢出 + 右键菜单（`components/tabs/*`），并带 `scripts/smoke.mjs`（CDP 131 断言）与 `scripts/audit-topics.mjs`（主题无死代码审计）。

### 1.2 目标（可验收）

| # | 目标 | 验收口径 |
|---|------|---------|
| G1 | **一个大组件**：`<ChonkLayout>` + `<ContentSettingsDialog>`，入参一份布局 JSON，出参渲染 | 宿主只传数据、交互全走 mq；组件内不含任何 ChonkPilot 业务 |
| G2 | **本系统区块全部注册为 view** | 见 [§3.4 注册表](#34-区块注册表本系统全部区块--view)：8 个一期区块 + 6 个二期候选，逐个有 `viewKey` / 组件 / 模式 |
| G3 | **内容设置编辑器**：布局编辑 / 顶部工具栏 / 状态栏 / 自定义工具栏 / 抽屉 五页签，保存后生效 | 编辑态改草稿、保存后写 `live` 并落库；重启可恢复 |
| G4 | **尺寸 / 显隐 / 交换 / 背景 / 标签栏位置由配置驱动** | 区域 `min/max`（`max=min` 即锁定拖不动）、同级交换、六处背景色、`tabPosition` 四向均由 JSON 决定 |
| G5 | **与既有体系一致** | 零新增后端主题；主题/i18n/构建脚本/测试口径（mq 驱动）全部沿用 |

### 1.3 非目标

1. **不自研完整拖拽停靠引擎**（六向落点 / 浮动窗口 / popout 多窗口）—— 与参考工程结论一致（`layout-free/README.md` §11「明确不做」）。
2. **阶段 1 不改预览区页签模型**：`CodeView` 自带页签（file + 功能页签）继续由它自己管，「预览区」整体作为一个 view 装进容器。
3. **不做区块多实例**：现有区块一律 `singleton`（主题为全局广播、无实例过滤，见 [§6](#6-边界与异常)）；多实例需先补"实例标识通道"。
4. **不做布局云同步 / 跨项目共享**：布局随项目实例落 prj 配置（与现有 `layout.*` 同域）。

## 2. 总体方案

```text
┌─ src/frontend/src/layout-free/ ─── 机制层（复制自 layout-free，与宿主无关；并入主工程） ───┐
│  engine.js            🆕 大组件门面：createLayoutEngine({ mq, views, persist, i18n, icons })│
│  components/layout/*  区域树渲染（Split/Leaf/NodeRenderer/FreeLayoutContainer）            │
│  components/settings/* 内容设置编辑器（5 页签）                                             │
│  components/bar/*     栏三区（BarZones/BarStrip/BarItem/BarMenuTree）                      │
│  components/{drawer,tabs,icon,ui}/*  抽屉 / 标签栏 / 图标 / 下拉                           │
│  config/ utils/ events/             配置规范化 · 树算法 · 命令 · 主题表                     │
│  stores/*             Pinia：布局文档 / 编辑器 UI / 运行态 / 变量（见 §3.7）                 │
└───────────────────────────────────────────────────────────────────────────────────────┘
                              ▲ 依赖注入（mq / views / persist / i18n / icons）
┌─ src/frontend/src/layout/ ──────── 适配层（ChonkPilot 侧策略，新增） ───────────────────┐
│  views.registry.js   区块 → 组件 + 定义（mode/host/可设计态）                              │
│  commands.js         命令 → 本系统落点（preview-tab-open / file-open / dialog.show）        │
│  persist.js          layout.free ↔ gui.ui.save / gui.init-data                            │
│  icons.js            复用 components/icon/icons.js → iconResolver                         │
│  theme.css           --lf-* → 既有 token（--bg-primary / --accent / --border …）           │
│  i18n.js             复用语 zh-CN / en-US 下的 layoutFree.json                             │
└───────────────────────────────────────────────────────────────────────────────────────┘
┌─ src/frontend/src/stores/ ──────── Pinia 状态层（🆕 新增依赖，见 §3.7） ────────────────┐
│  selection.js        跨 view 共享：workDir / activeFile / activeSession / activeTask …      │
└───────────────────────────────────────────────────────────────────────────────────────┘
                              ▲ 装配
   src/frontend/src/views/layout/MainLayout.vue
     = 读配置(layout.free) → <ChonkLayout> + 顶部/状态栏 + <ContentSettingsDialog> + 全局对话框
```

**数据流（与 [17-前端状态与MQ](../spec/10-architecture/17-前端状态与MQ.md) 一致，无 watch）**：

```text
UI（v-mq:topic.click） → mq 主题 → mqCommands 订阅者 → 配置 store（draft / live）
                                                      │
                                            响应式绑定 → 容器重渲染
```

**分层职责**：机制层只认"区域树 + 命令 + 配置协议"，**不认识任何一个 ChonkPilot 区块**；适配层只认"区块 ↔ viewKey ↔ 打开落点"，**不含布局算法**。

### 3.2 大组件 API

```js
// src/frontend/src/layout-free/engine.js（新增，集成唯一入口）
export function createLayoutEngine({
  mq,             // 宿主 mq（emit/on/off）；缺省 = 内置 standalone mq（纯前端）
  views,          // { definitions: [{key,label,icon,mode,host,designable}], components: {key: Component} }
  persist,        // { load(): Promise<doc|null>, save(doc): Promise<void> }；缺省 localStorage
  i18n,           // t(key, params)；缺省恒等
  iconResolver,   // (name) => svgString | null（接管图标取值）
}) → {
  install(app),        // 注册 v-mq 指令与 provide
  state, actions,      // 配置状态与动作（供诊断/测试直取，不供组件直写）
  renderLayout,        // 首页渲染用布局树（结构取 live、节点背景取 draft）
  renderBar(barKey),   // 栏渲染对象（条目取 live、背景取 draft）
  editing, selectedNodeId,
  validate(),          // 保存前校验（引用完整性 / 单例占用 / min≤max）
}
```

```vue
<!-- MainLayout.vue 装配（示意） -->
<template>
  <div class="main-layout">
    <ChonkLayout
      :layout="engine.renderLayout"
      :design="engine.editing"
      :selected-id="engine.selectedNodeId"
    />
    <DrawerHost />
    <ContentSettingsDialog />
    <AskUserDialog />
  </div>
</template>
```

**口径**：

| 项 | 口径 | 理由 |
|----|------|------|
| 交互 | **全部走 mq**（`v-mq`），组件不 `emit` 业务事件、不 `@click` 调 action | 项目规则「通信约定（MQ）」+ 参考工程「全工程 `@click` 0 处」 |
| 入参 | 只用 `props` 传数据；`provide` 传设计态标记（`LAYOUT_CONTEXT`） | 设计态需被 view 内部读取（`useDesign()`） |
| 输出 | 无业务输出；需要宿主动作时发 mq 主题（如命令落点由适配层订阅者执行） | 机制层不认宿主业务 |
| 区块组件 | **由宿主注册表提供**，机制层只按 `viewKey` 解析 | 子工程保持通用 |

### 3.3 配置模型

沿用参考工程 `defaultConfig.js`（`version: 6`）的单文档模型，**不改结构**：

```jsonc
{
  "version": 6,
  "layout":       { "id": "split_x", "type": "split", "direction": "row", "sizes": [0.5, 0.5],
                    "children": [ /* split | leaf 递归 */ ] },
  "topToolbar":   { "background": "", "zoneBackground": {"left":"","center":"","right":""}, "items": [] },
  "statusbar":    { /* 同 topToolbar */ },
  "toolbars":     [ { "id": "tb_detail", "label": "文件工具", "items": [] } ],
  "drawers":      [ { "id": "drawer_files", "label": "文件", "position": "right", "size": 380,
                      "modal": true, "toolbarId": "tb_detail", "toolbarPosition": "bottom", "tabs": [] } ]
}
```

| 概念 | 语义 | 本系统映射 |
|------|------|-----------|
| `split` 节点 | 容器（`direction: row|column` + `sizes` 占比 + `toolbar?` + `background?`） | 现有 `SplitPanel` 的嵌套层级 |
| `leaf` 节点 | 区域：`kind ∈ single / fixed-tabs / free-tabs`、`view` 或 `tabs[]`、`tabPosition`、`min{Width,Height}/max{Width,Height}`、`background`、`toolbar?` | 现有 5 个 `SplitPanel` pane 的位置与尺寸约束 |
| `kind: single` | 一个 view | 如 `explorer`、`chat` |
| `kind: fixed-tabs` | 固定页签（配置期固定） | 预留（现有预览页签**不在此**，见 [§3.5](#35-命令模型与落点映射)） |
| `kind: free-tabs` | 运行期装入（命令 `open-tabs` 目标） | 参考工程默认给的「工作区」区域；本系统一期可给"自由页签区" |
| 栏（`topToolbar` / `statusbar` / `custom:<id>`） | `{background, zoneBackground, items[]}`（**对象而非数组**） | 顶部工具栏 / 底部状态栏 / 挂到抽屉与区域边的自定义栏 |
| 栏条目 `kind` | `button`（图标+命令）/ `menu`（树，叶子带命令）/ `view`（栏里内嵌 view，定宽高或 `grow`） | 现有 Toolbar 的按钮 / 下拉 / 中段搜索框 |
| 命令 | `open-dialog` / `open-tabs` / `open-drawer` / `close-tabs-active` | 见 [§3.5](#35-命令模型与落点映射) |

**规范化与迁移**：`config/config-normalize.js` 的 `normalize()` 负责旧结构升级（旧裸数组栏 → `asBar()`；旧 `view.viewKey==='fixed-tabs'|'free-tabs'` → `kind`；区域/抽屉引用已删工具栏 → 清空引用）。**本系统追加一条迁移**：见 [§3.9](#39-持久化)（旧 7 字段布局 → 生成等价默认文档）。

### 3.11 设计态与区块保活（关键风险）

参考工程的设计态约定（运行态不显示区域标题、设计态 view 只读 + 可点选 + 右键菜单）**照搬**，但落到本系统有一个**新增硬约束**：

> **区块必须常驻保活**：显隐用 CSS（`display:none` / `visible:false` 保持挂载），自由页签容器切换用 `v-show` 或 `<KeepAlive>`，**禁止用 `v-if` 卸载区块**。

依据（现有实现就是这样保活的）：

| 事实 | 位置 |
|------|------|
| `SplitPanel` 的 `visible:false` 只是隐藏，不卸载 | `components/split/SplitPanel.vue`（`panes[].visible`） |
| `ChatPanel` 必须持续挂载（会话/流式/队列状态在组件内） | `MainLayout.vue:134-136` 注释"主内容面，须持续挂载" |
| `ExplorerPane` 四模式用 `v-show` 同挂载不销毁 | `ExplorerPane.vue:44-55` |
| `CodeView` 页签（文件内容/临时页签）在组件内 | `CodeView.vue`（`tabs/activeKey` 为组件内 ref） |

**落地口径**：区域渲染 `<KeepAlive>` + `:key="viewKey + '|' + instanceKey"`，`include` 恒为全部已注册 view；节点被删除（配置里移除该区域）时**才卸载**；显隐与标签栏切换一律不卸载。**设计态**下容器加 `pointer-events: none`（view 内部如需自定义只读渲染，读 `useDesign()`）。

**参考工程现状（已核对，必须改）**：

| 位置 | 现状 | 处置 |
|------|------|------|
| `views/FreeTabsView.vue:15` | `v-for` + `v-show="tab.tabId === activeId"` → **自由页签保活（✅ 已符合）** | 保留 |
| `views/FixedTabsView.vue:11` / `views/ViewHost.vue:4` | `v-if="current"` / `v-if="comp"` → **固定页签切换、viewKey 变化即卸载重建（❌）** | 改 `<KeepAlive>` + 键控复用 |
| `components/layout/LayoutLeaf.vue:48` | `v-if="kind === 'free-tabs'"` 分支 → **区域类型切换卸载重建（❌）** | 改 `v-show` 分支（保活双分支），或统一由一个宿主组件按键控 `KeepAlive` |

> 即"保活"不是照搬就能得到，参考工程只在自由页签做到了；**本系统的区块（会话/流式/页签状态在组件内）要求三处（单容器 / 固定页签 / 自由页签）全部保活**。

**设计态兜底**：区块依赖真实数据（filesys / 会话 / 任务），设计态若触发取数会污染真实状态 → 对 `designable: false` 的 view，设计态**只渲染标题 + 骨架占位**，不挂载真实组件。

## 6. 边界与异常

| 场景 | 兜底 |
|------|------|
| `layout.free` 解析失败 / 结构非法 | `normalize()` 修正 → 仍非法则回落默认文档，并提示"布局已重置"（不静默丢库） |
| 配置引用了不存在的 view（区块被删/改名） | 渲染占位「该 view 暂未实现（key）」；`validate()` 在保存时拦下并提示 |
| 单例 view 被占用 | 下拉禁用 + 标注占用位置；校验拦截 |
| **顶部栏被删 / 被清空** | 窗口是 **frameless**（`-webkit-app-region: drag` 提供拖拽区，窗口控件提供最小化/最大化/关闭）→ **禁止删除顶部栏**（编辑器置灰该操作）；同时把"拖拽区 + 窗口控件"实现为容器外壳的**固定不可配置部分**，即使栏条目被清空仍可操作窗口 |
| **关键区块被配成两份**（如两个 `preview` / 两个 `chat`） | 现有主题为**全局广播、无实例过滤** → 两个实例会同时抢开页签/会话。防线三层：① 编辑器单例占用登记（禁用已占用项）；② 保存校验拦截；③ **运行期兜底**——装配时对重复单例**只渲染第一个并在控制台/状态栏告警**，其余渲染占位（防手改 JSON / 导入配置绕过编辑器） |
| 配置"自伤"（把区域删空 / `min` 设极大） | 提供【恢复默认布局】入口（编辑器内 + 兜底命令）；`min/max` 在 apply 时按视口 clamp（沿用现有 `MainLayout` clamp/窄屏逻辑），保证区块不会被挤成 0 |
| `min > max` | 保存校验拦截；运行期按 `min` 生效 |
| **多实例（主题无实例过滤）** | `task-detail` / `dsl-steps` 等即便 `mode:'multi'`，两个实例会同时响应同一广播主题 → **一期按 singleton 处理**；要真正多实例，须先给相关主题补实例标识（payload 增字段，属"只增不改"）或改走 `payload.id` 过滤（`MessageList` / `TabbedContainer` 已有按 id/ownerId 过滤的先例） |
| 窄屏（现 `NARROW_MAX=900` 自动收文件树） | 阶段 2 映射为区域 `minWidth` + 容器"窄屏自动隐藏"；阶段 1 由适配层在 apply/save 时 clamp（行为与现状一致） |
| 区块被配置删除（如删掉"对话区"） | 卸载该 view → **会话状态丢失**是预期代价，编辑器在删除单例关键区块时**二次确认**（提示"该区块状态将丢失"） |
| 窗口尺寸异常（启动 Hidden 阶段 `vw/vh < 200`） | 沿用现有 `applyLayout` 守卫：尺寸不合法时不套用配置（保持默认） |
| 编辑器保存时后端失败 | 保持编辑器打开 + 错误提示；`live` 不变（避免"看着生效其实没落库"） |
| 两套对话框 / 两套图标 / 两套 split | 去重表（[§3.10](#310-样式主题与组件去重)）作为**验收项**：bundle 内同名实现只允许一份 |
| 栏条目化的既有测试失效 | `test_toolbar` 等按 `.toolbar-right .tb-btn` **固定下标**定位（`Toolbar.vue` 注释）→ 改为按 `title` / `data-lf-item` 定位；配置化后条目顺序可变 → 测试先应用**固定测试配置**再断言 |
| 栏"视图条目"缺取值函数 | 配置只存**键名**（如 `memToken`）；宿主需注册 provider 表（记忆 token / 队列数 / 索引状态）→ 缺失时回退渲染 `label` 占位，**不报错** |
| `selection.activeFile` 镜像时机 | 一期 CodeView 自管页签 → 镜像为**只读派生**（订阅 `file-open` / `preview-tab-open` / 页签本地变更时回写），**不反向驱动 CodeView**；若将来 CodeView 改为受控页签，再做双向 |

### 7.2 P5 增强评估结论（2026-10-17，按需）

> 判据 = 「设计稿是否硬要求 + 前序是否留下必须补的缺口」；**不为凑数做增强**。五项**结论均为「不做」**（登记 [49-待实现项](../spec/40-roadmap/49-待实现项.md)）：

| 增强项 | 结论 | 理由（前序无硬缺口） |
|--------|:----:|----------------------|
| 布局预设 `profiles[]` | 🟢 **已实施（2026-10-21，用户裁决 · UILAYOUT-2）** | 原判「⛔ 不做」作废：用户要求多套布局切换。落地口径见 [31 WIN-026](../spec/30-function-points/31-窗口与布局.md)（`layout.profiles` / `layout.activeProfile` + 顶栏 `layout-profiles` 下拉 / 新建对话框 / 保存≠应用）· [42 §2.31](../spec/40-roadmap/42-决策记录.md) |
| 命令面板 `Ctrl+K` | ⛔ 不做 | 顶栏 / 状态栏条目化 + 右键菜单已覆盖命令入口；命令面板需**新主题表 + 新快捷键协议**，非硬要求 |
| 快捷键 + `when` 上下文 | ⛔ 不做 | `when` 上下文是**配置模型新协议**（条件表达式），与裁决 2「条件由组件自持 `v-if`、不加协议」直接冲突；一期不做 |
| tab ARIA / 键盘导航 | ⛔ 不做 | 无障碍增强，非本轮诉求；现有 `LfTabbedContainer` 交互（点击 / 右键 / 溢出）功能完整，未发现阻断性缺口。**登记为可后续补**（不改契约） |
| 区域最大化 / 还原 | ⛔ 不做 | 需在机制层新增**节点运行时状态 + 新主题**（`lf-area-maximize` 等），属消息面/协议扩展；一期诉求未覆盖，且与「布局文档 = 唯一结构源」的简洁口径有冲突 |

> 说明：以上「不做」**不改变任何既有契约**（无主题增删改、无 payload 变更、无配置结构扩展）；如后续用户明确要求，逐项按各自「需否扩协议」评估后再实施。
