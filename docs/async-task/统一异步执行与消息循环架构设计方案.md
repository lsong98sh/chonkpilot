## 1. 问题与目标

### 1.1 要解决的问题

当前异步处理**不是一套模式**，而是「两条主干各自统一 + 大量局部自写」：

| 链路 | 现状 |
|---|---|
| LLM 调用 | `router` 有完整的 `RetryPolicy / RetryContext / RetryObserver / RetryWait`，并分「透明重发 / 可见重试」两层 |
| 工具调用 | gateway 有完整的「统一异步模型」（`async=auto/always/never/manual` + 超时裁决），**但没有自动重试引擎** |
| 其余 | 插件重启、gateway respawn、上下文压缩、workdir 轮询、各类 IPC/探测超时，各写各的 |

量化症状（2026-11-06 扫描）：

| 指标 | 数量 |
|---|---|
| `context.WithTimeout/WithDeadline` | 62 处（三仓合计） |
| 硬编码时长常量 | 60+ |
| 退避实现 | 5 套不同公式 |
| 超时表示 | `int` 秒 / `float64` 秒 / `time.Duration` 三种 |
| 「未设置 vs 显式 0/-1」 | 3 套 Set 标记 |
| 错误分类 | 2 套（router 6 类 / gateway 自有）+ 1 处纯字符串 |
| 「轮询等状态 / sleep / 同步 RPC / 阻塞等用户」 | 14 处（见 §10） |

### 1.2 目标（可验收）

1. **统一执行模型**：所有编排走消息循环；循环内只做「读消息 → 改状态 → 投消息」。
2. **单次调用统一外壳**：LLM 一次往返、工具一次调用共用同一个壳（`Async / AttemptLimits / Retries / Timer`），业务语义放 `ctx` extraData。
3. **消灭 4 类等待**：轮询、sleep、同步 RPC、长时间阻塞等用户。
4. **状态分层唯一**：内部 `success/timeout/fail`，对外 `complete/error`，记录层 `pending/running/done/error/cancelled/interrupted`。
5. **生命周期唯一**：只有 session 有终点；turn/step 只是标签与迭代。
6. **取消统一**：句柄式 `Cancel(cause)`，first-cause-wins，转异步后仍可达。

### 1.3 非目标

- 不把**所有 IO** 消息化（见 §2.4 白名单）。
- 不重写数据层、MQ 传输层。
- 不改变 `61-消息一览` 已冻结的消息形状；确需新增须按 61 §0 登记。
- 不改变工具 `timeout=0/-1` 的「绝对无上限」语义。
- 不把「进程生命周期监管」（插件重启）塞进单次调用外壳。

## 2. 总体架构

### 2.1 一句话

> **整个后端只有一种执行模型：消息循环。循环内只做「读消息 → 改状态 → 投消息」；所有会阻塞在「别人」身上的事情拆成「发起 + 结果消息」。唯一的 blocking point 是循环驻留的那个 `select`。**

### 2.2 三个执行域

| 执行域 | 允许 | 禁止 |
|---|---|---|
| **session 循环 goroutine** | 本地有界读写、内存状态变更、非阻塞投递 | 等子进程/网络/用户/别的 goroutine；`sleep`；`Emit().Wait()`；大文件/全表扫描 |
| **总线派发线程**（共享设施） | 解析消息、非阻塞入队 | 任何同步等待（含 `feed` 的 5s 兜底） |
| **后台 goroutine**（压缩、插件监管、执行器） | 可以 sleep / 轮询 / 阻塞等待（这是其职责） | 直接改循环状态；结果必须**投消息**回来 |

### 2.3 六条不变量

1. **单写者**：每个会话状态只由其循环 goroutine 写；跨 goroutine 只投消息。循环内理论上不需要锁。
2. **回调短事务**：`OnComplete / OnError / OnTick / OnDelta / OnToolDone` 只做状态变更 + 非阻塞投递；不做 IO、不 sleep、不调同步 RPC。
3. **唯一阻塞点**：循环的 `select`。其他 `<-chan` / `Wait()` / `Sleep()` 均为违例。
4. **投递非阻塞 + 有界**：生产者不得因邮箱满而阻塞；有界缓冲 + 明确丢弃/合并策略；终态消息永不丢。
5. **计时器是消息**：timeout/idle 由 timer goroutine 到点投 `Tick` 消息，不是循环里 sleep。
6. **取消是消息 + ctx**：循环收到取消 → 标记 cause → 向下发 cancel；不等待下游确认，下游终态自己作为消息回来。

### 2.4 循环内同步调用白名单

判据不是「是不是 IO」，而是**「完成时间是否依赖外部参与者」**。

| 允许（本地有界，「自己的事」） | 禁止（等别人 / 无界） |
|---|---|
| 内存索引读写 | 另一个 goroutine / 子进程 / 网络对端 |
| 本地 `bbolt` 单键/单记录、小事务 | 插件桥 / 跨进程 MQ 应答 |
| 本地小文件读写（建议上限 ≤1MB） | 用户裁决 / `ask_user` 阻塞等待 |
| 配置值读取、日志写入 | 全表扫描、递归目录、大文件、压缩/备份/索引重建 |
| JSON 编解码 | 定时退避（循环内） |

> 大文件、全量遍历、压缩等即使本地也不允许在循环里做——它们的耗时没有上界。

## 3. 分层模型

### 3.1 session 是唯一生命周期对象

```
session 状态：active → quiescent
quiescent = 最后输出是 text
          && 无 pending ask
          && 无在飞工具（工作记录 running）
          && 无 inbox 待消费
```

### 3.2 turn / step 只是标签

| 名称 | 本质 | 有终态吗 |
|---|---|---|
| turn | 消息分组用的 `turn_id` 标签 | **没有** |
| step | 会话循环的一次迭代（一次 LLM 往返） | **没有** |
| session | 唯一的生命周期对象 | 有（quiescent） |
| 单次调用 | LLM 一次往返 / 工具一次调用 | 有（complete / error） |

**禁止**在 turn/step 上引入 `Start/Wait/terminal` 语义；禁止「复活已终态的 turn」。

### 3.3 单次调用外壳

```
Spec{ Async, AttemptLimits, Retries, Timer }
```

- **无** `TotalTimeout`：总超时是调用方 ctx 的 deadline（deadline 传播），不是壳字段。
- **无** `FirstActivity / IdleTimeout` 等业务词：阈值与相位在 `ctx` extraData。

### 3.4 记录（record）投影

工具/任务的持久化状态独立于调用状态：

| 时刻 | 调用 outer | record |
|---|---|---|
| 工具同步成功 | complete(value) | done |
| 工具转异步 | complete(占位值) | running |
| 异步工作完成 | 不变（已 complete） | done / error |
| 用户取消 | error(cause=cancelled) | cancelled |
| 重试中（内部失败） | 不变 | 保持 running |
| 重试耗尽 | error | error |

> 规则：**父级推进看 record，不看 outer**。outer complete 是「调用者拿到答复」，record terminal 是「工作真的结束」。

## 4. 单次调用外壳（暂名 `taskx`）

> 名字避开 `Task`：仓库中 `Task` 已被任务树/异步任务占用（`src/lib/task`、gateway `ExecTask`、session `TaskNode`、`facade.Task`）。

### 4.1 Spec

```go
package taskx

// 壳只认识机制，不认识业务。
type Spec struct {
    Async         bool          // 是否允许转异步
    AttemptLimits int           // 尝试次数硬上限（防嵌套/放大）；0 = 不限
    Retries       int           // 允许的重试次数（不含首次）；0 = 不重试
    Timer         TimerFactory  // 单一定时器工厂（可注入假时钟）
}
```

`AttemptLimits` 与 `Retries` 的分工：实际次数 = `min(1+Retries, AttemptLimits)`。前者是硬护栏，后者是策略值。

### 4.2 业务语义：ctx extraData

泛型 key，域层 key 不进口壳包：

```go
type Key[T any] struct{ name string }
func NewKey[T any](name string) Key[T]
func With[T any](ctx context.Context, k Key[T], v T) context.Context
func Get[T any](ctx context.Context, k Key[T]) (T, bool)

// 域层自定义（示例）
var (
    KeyPhase   = taskx.NewKey[string]("chat.phase")      // first_byte / stream / awaiting
    KeyEmitted = taskx.NewKey[int]("chat.emitted")       // 决定能否重发
    KeyMode    = taskx.NewKey[string]("tool.async.mode") // auto/always/manual/never
    KeyOptions = taskx.NewKey[[]string]("tool.options")  // detach/wait/cancel
)
```

### 4.3 回调

```go
type Verdict int
const (
    Fail Verdict = iota
    Retry
    Continue   // 继续等，重设点
    Detach     // 转异步，交回域层
    Cancel
)

type Handler[T any] interface {
    // 内部：每次 attempt 失败都来，返回是否重试
    OnAttemptError(ctx context.Context, attempt int, err error) Verdict
    // 内部：定时器到点（域层读 extras 决定）
    OnTick(ctx context.Context) Verdict
    // 对外：唯二终态，各一次
    OnComplete(ctx context.Context, v T)
    OnError(ctx context.Context, err error, cause Cause)
}
```

**内部失败不对外**：重试期间的 `timeout/fail` 不触发 `OnError`，不写 record。

### 4.4 执行模型（无 wait）

外壳自身是一个 goroutine，把事件投回调用方（session 循环）；循环里不出现 `Wait`。

```go
func run[T any](job *Job[T], h Handler[T], action Action[T]) {
    defer job.commitOuterOnce()

    attempts := 0
    for {
        if job.cancelCause() != nil {
            job.setOuter(Error, job.cancelCause(), Cancelled)
            return
        }
        attempts++
        inner := runAttempt(job, h, action)

        switch inner.Kind {
        case InnerSuccess:
            job.setOuter(Complete, inner.Value)
            return
        case InnerCancelled:
            job.setOuter(Error, job.cancelCause(), Cancelled)
            return
        case InnerTimeout, InnerFail:
            if attempts >= job.effectiveLimit() {
                job.setOuter(Error, inner.Err, inner.Cause)
                return
            }
            switch h.OnAttemptError(job.ctx, attempts, inner.Err) {
            case Retry:
                job.post(RetryScheduled{Attempt: attempts, Wait: job.wait(attempts)}) // 由 timer 投 Tick
            case Detach:
                job.setOuter(Complete, Pending{Token: job.token})
                return
            case Cancel:
                job.CancelWith(ErrCancelledByHandler)
                return
            }
        }
    }
}

func runAttempt[T any](job *Job[T], h Handler[T], action Action[T]) Inner {
    done := make(chan result, 1) // 带缓冲：Action 永不阻塞
    go func() { v, err := action(job.ctx, job.reporter); done <- result{v, err} }()

    timer := job.spec.Timer.New(job.armed) // 设点值由域层 Arm(d) 给
    for {
        select {
        case r := <-done:
            if r.err == nil { return Success(r.v) }
            return Fail(r.err)
        case <-job.activity:                 // 只写 lastActivity，不 Reset
            job.markActivity()
        case <-timer.C:                      // 到点：投 Tick 消息，不在壳里做业务判断
            job.post(Tick{})
        case item := <-job.inbox:            // 插话输入
            job.post(Insert{Item: item})     // 交给会话循环，不在壳内判相位
        case <-job.ctx.Done():
            return Cancelled
        }
    }
}
```

### 4.5 Cancel

```go
func (j *Job[T]) Cancel()              { j.CancelWith(ErrCancelledByUser) }
func (j *Job[T]) CancelWith(cause error) {
    j.cancel(cause)          // context.WithCancelCause：首次 cause 生效，后续 no-op
    j.fireCancelHook()       // once：让非 ctx-aware 资源（子进程/连接）也能停
}
```

- 幂等、非阻塞、终态后调用为 no-op。
- **成功优先**：action 已完成、cancel 晚到 → 交付真实结果。
- **detached 仍可取消**：`Delegate` 之后句柄不失效，只退化为取消路由器。
- **`TotalTimeout=0`（无限）不能关掉 cancel**。
- 取消后不触发重试、不调 `OnAttemptError`。
- 取消阶梯（L0 协议取消 → L1 grace → L2 关连接 → L3 杀进程树）留在域层，壳只保证送达。

## 5. 会话消息循环

### 5.1 事件源（统一邮箱）

| 事件 | 来源 |
|---|---|
| `UserInput` | inbox（用户发送 / `next_run` 落库项） |
| `InsertRequest` | 插话意向 |
| `ToolWorkDone` | 异步工具完成（记录已回写） |
| `AskAnswered` | `ask-user-reply` |
| `Tick` | 单次调用的 timer |
| `Cancel` | session/turn/tool 取消消息 |
| `ChildState` | 单聊 / 群聊参与者会话状态 |

### 5.2 循环

```go
func (s *Session) loop() {
    for {
        ev := s.waitEvent()   // 唯一阻塞点
        s.apply(ev)           // 短事务：改状态 / 落库（本地有界）/ 非阻塞投递

        if !s.readyForLLM() {
            if s.quiescent() { return }
            continue
        }

        // 一次 LLM 往返：外壳 goroutine，事件投回本循环
        s.startLLMCall()

        // 回调中（OnComplete / OnError / OnTick）只做状态转移与投递
    }
}

func (s *Session) readyForLLM() bool {
    return s.hasNewInput && len(s.inflight) == 0   // 有在飞工具时不发请求
}
```

### 5.3 异步工具完成

```go
func (s *Session) onToolWorkDone(toolCallID, result string, err error) {
    s.persistToolResult(toolCallID, result, err)  // 回写工具调用记录（唯一事实源）
    delete(s.inflight, toolCallID)
    s.push(Notify{ToolCallID: toolCallID,
                  Text: "tool-call-id 已经给出结果，请继续"})
}
```

- **不需要** `FeedToolResult` 到某个活着的 turn；
- 结果已落库，下一次组 LLM 请求从库里读历史，自然带上 `role=tool`；
- 同一 turn 还是新 turn **语义无关**（turn_id 只是标签）。

## 6. 插话

### 6.1 定位

插话是 **session 邮箱中的一类消息**，不是独立轮询机制。

- 生产者（MQ handler / UI）只投递，不判断相位；
- 消费者（session 循环 / Action）在自己的边界取用；
- **删除 100ms ticker**（`engine_turn.go:236` 的存在理由就是「相位变化没有事件」）。

### 6.2 插入点

| 插入点 | 说明 |
|---|---|
| step 边界（主） | 每次 LLM 往返收口后、下一次请求前；确定性、无轮询 |
| 工具等待（可选） | 工具进入等待时发 `Waiting` 事件，session 收到后立即检查一次 inbox（保留「工具在飞时纠偏」能力，仍无轮询） |

### 6.3 保留的不变量

- 批量：一次把当前全部 pending 投入（现实现「批量插话」）。
- LIFO：插入帧栈式执行，出栈回父帧。
- 深度上限 `maxInsertDepth = 5`（`chat/src/engine.go:33`）。
- 插入帧与 `MaxSteps` 独立双保护。

## 7. 取消

### 7.1 归属树，不是 ctx

```go
type Node struct {
    id       string
    parent   *Node
    children map[string]*Node
    cancel   context.CancelCauseFunc
}
func (n *Node) Cancel(cause error) {   // 幂等；首次 cause 生效
    n.cancel(cause)
    for _, c := range n.children { c.Cancel(cause) }
}
```

- 不能用 ctx 隐式级联：`task_llm` 故意用 `context.Background()`（`subllm.go:32-34`），父轮次正常收尾不应连带取消独立作业。
- 显式取消仍应送达（`task-stop` / `llm-cancel` / `mcp-tasks-cancel` / 关窗）。
- 取消注册表键统一：`(instance_id, session, turn, tool_call_id|task_id)`，解决前端 id 漂移与重复投递。

### 7.2 取消后的状态投影

| 场景 | outer | record |
|---|---|---|
| 同步执行中被取消 | error(cancelled) | cancelled |
| 已转异步后被取消 | 不变（已 complete） | cancelled |
| 取消与完成同时到达 | 成功优先（交付真实结果） | 按实际完成态 |

## 8. 与既有机制的对齐

| 既有机制 | 处置 |
|---|---|
| router 的 `RetryPolicy / RetryObserver` | 决策逻辑保留（纯函数）；执行循环可迁入外壳，或外壳复用其 policy 端口 |
| `Emitted == 0` 重发判据 | 保留，作为域层 extraData 上报，外壳只执行闸门 |
| gateway `async=auto/always/never/manual` | 收敛为 `Async bool` + extras（阈值/选项） |
| gateway 超时裁决（detach/wait/cancel） | 保留，作为 `OnTick` 的返回指令 |
| `ask_user` | **已是目标形态**（注册 waiter → 立即返回 askID → 答复作为新消息） |
| `handler_task` 的 `asyncDone` 非阻塞投递 | 方向正确；建议改有界邮箱，避免无界 goroutine |
| `next_run` / `consumeNextTurn` | 保留；`onError` 不消费（现有 `turn_id` 失效规则自清理） |
| 工具 `timeout=0/-1` 无上限 | 保留为「不设点」，cancel 永远有效 |
| 插件进程重启退避 | 不进单次调用外壳；复用同一 `BackoffPolicy`，独立监管器 |

## 9. 关键取舍与已知问题

1. **本地同步 IO 白名单**：不把 100 个本地调用改造成消息往返，否则代码膨胀不可维护。
2. **后台 goroutine 可以等待**：压缩、插件监管、执行器自己的等待不是问题；只需补 ctx 取消。
3. **独立作业不计入 session 静默**：`task_llm` 后台委派不应阻止父会话 idle；只有前台子会话（单聊/群聊参与者）计入。
4. **`next_run` 位置**：建议放 inbox **最后**（back），且 LLM 来源保持 last-wins（同 turn 只留一条），避免模型自续提示插队 / 堆积。
5. **`onError` 不处理 inbox 的副作用**：用户排队项会延迟到下一次成功 turn 结束才消费，可能出现顺序倒置；LLM 的 `next_run` 由 `turn_id != latestTurn` 自清理。
6. **单步超时宽限**：`PendingWait` 默认 2h（`pending_task_timeout_sec`）在改为消息驱动后应由 session 静默 + 任务记录取代，不再作为长阻塞点。
