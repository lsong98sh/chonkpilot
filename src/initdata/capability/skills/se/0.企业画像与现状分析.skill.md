# 第00步 Skill：企业画像与现状分析

[meta]

[description]
第00步：企业画像与现状分析——摸清企业规模/业务/组织、业务现状与痛点、IT 现状（系统/数据/技术栈），给出复用 vs 新建建议

[content]

## 一、理论

这是整个设计流程的起点。后续所有步骤的输入，都来自这一步的产出。

**为什么需要这一步：**

同样的“CRM”，放在不同企业里，设计完全不同：

- 10人销售团队 vs 1000人销售团队 → 权限层级不同
- 卖标准产品 vs 卖定制项目 → 生命周期不同
- 单一公司 vs 集团多分公司 → 数据隔离不同
- 有企业微信 vs 什么都没有 → 集成方式和预算不同

**不了解企业画像，后面的每一步都可能做错。**

**这一步的目标：**

让LLM和用户对“这家企业是什么样、现在怎么运转、有什么系统”达成共识。

---

## 二、LLM的思考框架

### 预判（问之前）

LLM在问之前，先根据已有信息推测：

**根据业务类型预判：**
- 卖标准产品 → 大概率有ERP
- 卖定制服务 → 大概率有项目管理系统
- 卖SaaS → 大概率有自研系统
- 做贸易 → 大概率有进销存

**根据企业规模预判：**
- 10人以下 → 可能只有企业微信+Excel
- 10-50人 → 可能有企业微信+财务软件
- 50-200人 → 可能有企业微信+财务+OA
- 200人以上 → 可能有企业微信+财务+OA+ERP+自研

**预判的目的：** 不是替用户回答，而是准备好“如果用户说X，我接下来问什么”。

### 识别（问之中）

听用户回答时，识别这些信号：

| 信号 | 用户说 | LLM判断 |
|---|---|---|
| 确定 vs 模糊 | “我们有ERP” | 确定，继续问什么ERP |
| 确定 vs 模糊 | “好像有个ERP” | 模糊，换方式问“库存用什么管” |
| 支持 vs 抵触 | “企业微信用得挺好” | 支持复用 |
| 支持 vs 抵触 | “OA太烂了，不想再用” | 抵触复用 |
| 有痛点 | “财务系统还能用，但审批很慢” | 可能不想复用OA |
| 有版本 | “用友U8” | 老版本，API能力有限 |
| 有负责人 | “IT小王在管” | 有专人，可以对接 |

### 兜底（用户答不出来时）

**场景1：用户说“我不知道公司有什么系统”**

> “没关系，我们换个方式。你们财务用什么记账？”
> “你们审批怎么走？纸质还是系统？”
> “你们库存用什么管？”
> “你们和客户沟通用什么？微信还是企业微信？”

**用具体场景反推系统，而不是直接问“有什么系统”。**

**场景2：用户说“系统是总部管的，我不清楚”**

> “那你们总部有没有IT部门？能不能帮我约一下？”
> “你们新员工入职，账号是谁开的？”

**场景3：用户说“好像有，但我不确定”**

> “可能是这几种：用友/金蝶（财务）、泛微/致远（OA）、企业微信/钉钉（沟通）、Salesforce/销售易（CRM）。你们有没有类似的？”

### 纠偏（用户答得不对时）

**场景1：用户说“我们没有任何系统”**

要判断这是真没有还是不知道：

> “完全没有吗？那你们财务怎么做账？手工Excel？”
> “你们审批怎么走？微信上说一下就行？”

如果确认真的没有，IT现状就是“零基础”，后续设计要考虑：登录认证要自己做、所有数据要新建、没有复用节省。

**场景2：用户说“我们什么系统都有”**

要判断这是真齐全还是有重复：

> “那这些系统之间数据怎么同步？手工导出导入？”
> “有没有统一登录？还是每个系统单独登录？”

如果发现系统之间不互通，IT现状就是“孤岛”，后续要考虑：集成工作量大、数据迁移复杂。

**场景3：用户说“我们想换掉所有系统”**

> “换掉所有系统，周期和预算会大幅增加。建议先做CRM，跑通后再考虑替换其他系统。否则风险太大。”

### 映射（回答之后）

用户回答后，立刻映射到后续设计：

| IT现状 | 映射到 |
|---|---|
| 已有企业微信 | 第06步：登录用企业微信，权限从企业微信同步 |
| 已有财务系统 | 第02步：回款从财务同步；第08步：对接接口 |
| 已有OA | 第02步：合同审批走OA；第08步：对接接口 |
| 已有ERP | 第01步：产品/库存不在CRM管；第02步：产品从ERP同步 |
| 有源代码 | 第12步：评估增量还是重构 |
| 无统一认证 | 第11步：需要单独做认证，周期和预算增加 |
| 无运维团队 | 第12步：必须买云服务，不能自建机房 |
| 技术栈是Java | 第10步：新系统建议Java，降低维护成本 |
| 数据在Excel里 | 第00步：需要数据迁移方案，增加周期 |

## 四、执行流程

### 阶段1：企业画像

**问题1：公司有多少人？**

| 用户回答 | LLM追问 | 判断 |
|---|---|---|
| <10人 | 销售团队几个人？ | 小团队，权限简单，流程简单 |
| 10-50人 | 销售团队几个人？销售怎么划分？ | 中等团队，需要权限层级 |
| 50-200人 | 有几个销售团队？有没有销售经理？ | 需要多级权限 |
| >200人 | 是集团吗？有几个分公司？ | 需要多组织数据隔离 |

**问题2：你们是做什么的？**

| 用户回答 | LLM追问 | 判断 |
|---|---|---|
| 卖标准产品 | 一单多少钱？成交周期多久？ | 短周期，状态少 |
| 卖定制服务 | 项目周期多久？谁负责交付？ | 长周期，状态多 |
| 卖SaaS | 客户是自助注册还是销售跟进？ | 需要产品驱动流程 |
| 做贸易 | 有库存吗？有供应商吗？ | 可能需要进销存 |

**问题3：客户是企业还是个人？**

- 企业客户 → 需要联系人管理、工商信息查询
- 个人客户 → 需要个人信息管理、隐私合规

**问题4：销售团队怎么划分？**

- 按区域 → 第06步权限按区域隔离
- 按行业 → 第06步权限按行业隔离
- 按产品线 → 第06步权限按产品线隔离
- 不划分 → 权限简单

**问题5：有没有销售经理？几个层级？**

- 无经理 → 权限扁平
- 一层经理 → 销售→经理两级
- 两层经理 → 销售→主管→经理三级

**问题6：谁会用这个系统？**

- 销售、经理、财务、高管、管理员
- 大概多少人用？
- 主要用电脑还是手机？

### 阶段2：业务现状分析

**问题7：你们现在怎么管客户？**

| 用户回答 | LLM追问 | 判断 |
|---|---|---|
| Excel | 一个文件还是多个？多少人同时编辑？有没有版本冲突？ | 需要数据迁移+版本控制 |
| 微信 | 记录在聊天记录里？离职后怎么交接？ | 需要系统化记录 |
| 已有系统 | 什么系统？有什么问题？ | 评估复用还是替换 |
| 纸质 | 怎么查找？怎么统计？ | 需要数字化 |

**问题8：你们现在怎么管商机？**

- 同上，根据回答走对应分支

**问题9：你们现在怎么管合同？**

- 同上

**问题10：你们现在怎么管回款？**

- 同上

**问题11：现在最大的痛点是什么？**

- 如果只能解决一个问题，你最想解决哪个？

**问题12：数据现状**

- 现在有多少客户数据？
- 现在有多少历史成交数据？
- 数据分散在几个人手里？
- 数据质量怎么样？

### 阶段3：IT现状分析

**问题13：你们现在有哪些系统？**

| 用户回答 | LLM走分支 |
|---|---|
| 有CRM | 走分支A（见下） |
| 无CRM，用Excel | 走分支B（见下） |
| 有ERP，无CRM | 走分支C（见下） |
| 有OA | 走分支D（见下） |
| 什么都没有 | 走分支E（见下） |

#### 分支A：用户说“有CRM”

> “有CRM的话，我需要了解这套系统的情况。”

**追问1：自研还是采购？**

- 自研 → 追问：有源代码吗？能读吗？什么技术栈？谁开发的？还在职吗？
- 采购 → 追问：哪家的产品？买了哪些模块？有没有API文档？年费多少？

**追问2：这套系统现在有什么问题？**

- 哪些功能不好用？哪些功能缺失？性能怎么样？用户愿意用吗？数据准不准？

**追问3：这套系统什么时候上线的？**

- 3年内 → 技术栈较新，建议增量开发
- 5-10年 → 技术栈可能过时，需要评估重构
- 10年以上 → 技术栈很可能已不符合当前标准，建议重构

**追问4：如果重构，数据怎么办？**

- 老系统数据能导出吗？数据量多大？数据质量怎么样？

**追问5：如果增量，怎么集成？**

- 老系统有没有API？能不能在现有基础上加模块？谁来开发？

#### 分支B：用户说“无CRM，用Excel”

**追问1：Excel怎么用的？**

- 一个文件还是多个？多少人同时编辑？有没有版本冲突？谁负责维护？

**追问2：数据量多大？**

- 多少行客户数据？多少行商机数据？文件多大？打开卡不卡？

**追问3：数据质量怎么样？**

- 有没有重复客户？有没有必填字段缺失？格式统一吗？

**追问4：迁移方案**

- 数据能导出成CSV吗？需要清洗吗？谁来负责迁移？迁移后Excel还继续用吗？

#### 分支C：用户说“有ERP，无CRM”

**追问1：ERP是什么？**

- 哪家的？覆盖了哪些模块？有没有客户管理模块？

**追问2：ERP里的客户数据能用吗？**

- 有客户信息吗？能导出吗？能通过API同步到CRM吗？

**追问3：CRM和ERP怎么分工？**

- 客户基本信息在ERP管还是CRM管？订单在ERP管还是CRM管？回款在ERP管还是CRM管？

**追问4：如果重叠，怎么处理？**

- ERP已经有的功能，CRM不重复做。ERP没有的，CRM做。两边都有的，以ERP为准。

#### 分支D：用户说“有OA”

**追问1：OA是什么？**

- 泛微还是致远？覆盖了哪些流程？

**追问2：OA的审批流能复用吗？**

- 合同审批走OA吗？报价审批走OA吗？如果走OA，CRM只做发起，不做审批。

**追问3：OA有API吗？**

- 能不能从CRM发起OA审批？审批结果能不能回传CRM？

#### 分支E：用户说“什么都没有”

**追问1：确认底线**

- 财务怎么做账？审批怎么走？客户信息记在哪里？

**追问2：如果什么都没有，意味着：**

- 登录认证要自己做
- 所有数据要新建
- 没有复用，预算和周期都要增加
- 需要从零开始建设IT基础

**追问3：建议**

- 先做核心功能，不要一次做全

## 五、完成标志

- [ ] 企业画像已明确（规模、业务、组织、用户）

- [ ] IT现状→设计影响的映射已确认
- [ ] 复用vs新建的建议已确认
- [ ] 用户确认无遗漏
