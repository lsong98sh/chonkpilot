# 调研提问：启动阶段的问题协议

在新的或有歧义的设计工作开始时，跑一轮结构化提问。**问对问题是设计质量最大的杠杆**——坏设计源于缺上下文，而非缺技能。

## 阶段 1：先读已附上的材料

提问之前，先读每一份已附上的资源——代码库、截图、品牌指南、链接的设计体系或 UI kit、已声明的任务书。人家刚附了品牌指南你还问"你有品牌指南吗"，是最快失去用户信任的方式。

## 阶段 2：决定要不要问

**要问**的情形：工作是新做的或含糊的；输出、受众或保真度不明；不知道在用哪套设计体系、UI kit 或品牌；变体数量未定；或任务留下多个非平凡的维度敞开。

**跳过**的情形：用户已把一切都给了你；只是小调整或跟进；范围、受众、约束都明确；或任务是"照这个一模一样复刻"。

若这个开放问题会改变设计方向（受众、格式、品牌、范围），就问。若是你能有理有据自行拍板的小选择（一个标签、一个默认值、两种等价做法），就拍板、动手做，并在总结里注明，而不是去问。

## 阶段 3：组好问题集

包含以下**必问**问题，外加任务书真正留下的问题专属项（通常 3–6 个）：

- **起点**（不可妥协——没有上下文就做高保真会产出坏设计）。"有没有要对齐的 UI kit、设计体系、代码库、品牌指南或截图？若没有，我需要从零定一套审美——确认这没问题。"
- **变体。** 整体设计要几个？沿哪些轴（视觉、布局、交互、文案、语气）？某些元素要不要变体（"hero 要几个"）？
- **新颖度。** 循规蹈矩、新颖/创意，还是混合？
- **可调项。** 最终设计里哪些可实时调整（颜色、文案、布局、组件）？
- **聚焦轴。** 流程、文案还是视觉——探索的力气往哪使？

问题专属示例：

- **Deck：** 受众与知识水平；时间预算/页数；语气；演讲者备注；已有素材？
- **落地页：** 期望的用户动作；主要用户画像；欣赏或否掉的参考；移动优先还是桌面优先？
- **原型：** 流程与页面；高保真还是中保真；设备外框；目标态；示例数据？
- **品牌/审美：** 三个形容词；欣赏的设计（及具体欣赏什么）；禁区；行业语境？

按歧义程度定这一轮的规模：真正开放的任务书可能值得约 10 个问题；半指定的可能只需 3–4 个。绝不要为凑数而注水——一个答案不会改变你要做的东西的问题就是噪音。

## 阶段 4：组织提问轮次

用 `ask_user` 工具提问——它把问题（及可选项）交给用户按结构化方式回答。每题：

- **优先单选**；始终提供"先探索几个选项"和"你替我决定"作为逃生口，再加"其他"作为开放式兜底（放进 `options`；`multi: true` 允许多选）
- 视觉类选择（布局、图标风格、色卡、气质）用图形化选项（如给出 SVG 预览）；数值区间用滑块（边界给宽些）；素材用文件选择；真正开放的问题用自由文本
- 用 `recommended` 高亮推荐项
- 最重要的放最前——用户可以先答前面的；标题保持简短，副标题为可选的澄清

## 阶段 5：提交提问，再据答案推进

`ask_user` 会挂起等待用户回答，答案作为工具结果返回——**在答案回来之前，不要自行臆测并继续推进**。答案回来后，全部读完，然后：

- 简要复述最影响设计的那几个选择
- 注明你想反驳的答案（温和些——用户是管理者）
- 进入合适的构建技能（`make-a-deck`、`make-a-prototype`、`wireframe` 等）并自主执行。这一轮是你提问的机会——不要为小决策再回头追问；自己拍板并列进总结。
- 若日后发现早期某个答案是错的（如用户说"不要新颖的点子"，但其反馈又要更大胆的选择），把矛盾摆出来重新问，而不是把错误假设一直带下去。

## 反模式

- **不要跳过提问。** "我直接开做"会产出错失任务书的设计。
- **不要什么都问。** 上限约 10–15 个；打包成一次提问，不要跨轮次一个个问。
- **不要问你能推导出的东西。** 附上的品牌指南里已有主色，就别再问主色。
- **不要为求稳而问。** 一个问题是否正当，取决于其答案对设计的影响，而非你的不确定。
