# 制作原型：可交互点击原型

构建一个可用的交互原型——可点击、可导航，带真实状态与反馈。当用户要原型、mockup、demo 或"做成可交互的"时使用。**原型要能交互**——用 `<a>` 标签把静态截图串起来不算数；重点是用真实的点击、输入、校验、成功、失败去测试流程。

## 阶段 1：调研

动手前先确认：**流程**（页面、入口、目标态——列成一张表）；**保真度**（高保真还是中保真）；**设备外框**（桌面浏览器、iOS、Android、macOS 窗口）；**变体**（一条流程还是多条对比）；**品牌/设计体系**（务必确认——若没有，先调用 `frontend-aesthetic-direction`）；**示例数据**（像真的内容，不要 Lorem ipsum）。

## 阶段 2：梳理页面与状态

动手前先把流程写下来，并以注释块放进文件，让用户看到计划：

```
页面：
  1. 欢迎——"开始"CTA → 2
  2. 邮箱输入——校验格式 → 合法进 3，非法就地报错
  3. 资料——姓名、上传头像 → 4
  4. 完成——"你进来了" → 1（循环演示）

状态：
  - currentScreen: 1
  - email: ""
  - emailError: null
```

## 阶段 3：逐屏构建

对每一屏：挂进 DOM（同一页内用显示切换或 React 状态）；高保真视觉与设计体系一致——真实组件，不要通用方框；像样的真实内容（真实姓名、产品文案、数字）；每屏一个主 CTA，次要操作更小、更弱化。

设备外框用纯 HTML/CSS 自绘（桌面浏览器、iOS、Android、macOS 窗口等常见外框），或直接整页不加外框——本仓没有现成的设备框起手组件。外框保持固定；原型活在外框内。

## 阶段 4：接通交互

每个交互都要接通，不只是顺路：

- **导航。** 主 CTA 前进，返回后退，状态跨屏保留。
- **表单校验。** 空提交 → 就地报错；格式错 → 与具体字段绑定的错误；合法 → 继续。
- **加载态。** 异步动作显示加载指示并禁用按钮以防重复提交。用 `setTimeout` 伪造延迟——不要因为活儿是假的就跳过加载态；它是被测内容的一部分。
- **成功与失败反馈。** Toast、就地确认或页面跳转；错误可清除并与对应字段或动作绑定。
- **状态变化。** 开关、选择、筛选都要立即更新 UI。

## 阶段 5：子状态与持久化

让有意义的子状态可响应：选中态、筛选/排序态、弹窗/下拉的展开态（焦点移入弹窗，Escape 关闭它）、表单值与错误。

把要紧的东西经 `localStorage` 跨刷新保留：当前屏、表单草稿、可调项的值（见 `make-tweakable`）。迭代中途刷新是最常见的用户动作之一——状态留不住会让原型显得是坏的。

## 阶段 6：验证

在预览中（用 `browser_run`）走完整条流程：每个 CTA 都通向某处、每个表单都校验、每个错误都清楚且可恢复、每个异步动作都有反馈、每个状态变化都可见、键盘导航可用（Tab 遍历、Enter 提交、Escape 关闭）、焦点可见。若某个行为无法验证，就在总结中说明，而不是声称成功。

## 阶段 7：变体（如被要求）

把变体暴露为浮动面板里的可调项（`make-tweakable`）、画布上并排（单文件 HTML/CSS）、或原型内开关。**不要把 v1.html / v2.html / v3.html 散在项目里——一个文件、多种变体。**

简洁总结：哪些流程可用、哪些是伪造的（如"提交调用了一个 setTimeout 假动作"）、哪些留给用户决定。
