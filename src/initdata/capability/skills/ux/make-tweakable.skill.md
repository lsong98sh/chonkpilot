# 可调节化：给设计加实时调节控件

给一份已完成的设计加一个浮动控制面板，让用户实时调整选定的方面——颜色、字体、间距、文案、布局变体、功能开关。当用户想"玩玩不同选项""看看不同版本"或比较视觉选择时使用。**一个文件、多种变体**——不要 v1.html / v2.html / v3.html 满地散。

## 阶段 1：确定哪些方面可调

与用户确认——或先提议再确认——要暴露哪些方面：颜色（主色、强调色、背景色调）、排版（字体族、基准字号、字号比例）、密度（紧凑/常规/宽松）、布局变体、组件变体（填充/幽灵按钮、卡片处理）、文案（主标题、副标题、CTA 文本）、功能开关（显示/隐藏章节）。

**把可调面保持小**——3–8 个控件。几条有意义的轴供探索，不要一个 Figma 克隆。如果用户没要求可调、但设计有明显的变化轴，就默认加 1–2 个，把有意思的可能性摆出来。

## 阶段 2：设计调节面板

面板活在原型内部，浮动（通常在右下角），半透明加一层细微边框，标题为 **"Tweaks"**，与页面上的开关文案一致。按值类型选合适的控件：颜色用取色器；字体与变体用下拉或按钮组；数值用带合理上下限的滑块；布尔用开关；文案用文本输入。控件保持紧凑——一个窄的纵向堆叠列胜过一大片散开的面板。

## 阶段 3：接通实时更新

用 CSS 自定义属性承载视觉 token，让所有引用它们的部分一起更新：

```js
document.documentElement.style.setProperty('--tweak-primary', newColor);
```

对非 CSS 的值（文案、布局变体、功能开关），用 JS 状态配合重渲染或 DOM 操作。

## 阶段 4：实现面板开关（本仓无宿主编辑模式协议）

本仓没有原稿所述的外部宿主工具栏协议（`window.parent.postMessage` 的 `__edit_mode_available` / `__activate_edit_mode` / `__edit_mode_set_keys` 等消息在 chonkpilot 里不存在，不要照搬）。改为页面内自带一个可见开关，步骤如下：

1. **先让开关逻辑就绪**：打开 → 显示 Tweaks 面板；关闭 → 隐藏面板。
2. **再渲染开关本体**（固定角落的小按钮，文案如"调节"），保证任何时候都能切换。原稿强调"先注册监听、再宣告可用"的核心教训是：**开关的可用状态必须先就绪**，别做出点了没反应的死开关。
3. **值变化时持久化**：把当前值写入 `localStorage`（键名固定），刷新后回读并合并。

## 阶段 5：把默认值落盘

用注释标记包裹可调的默认值，便于脚本自身重写（或人工回落）：

```js
const TWEAK_DEFAULTS = /*EDITMODE-BEGIN*/{
  "primaryColor": "#D97757",
  "fontSize": 16,
  "dark": false
}/*EDITMODE-END*/;
```

标记之间的块**必须是合法 JSON**（键与字符串都用双引号），且只能有这样一个块，位于根 HTML 文件的一个内联 `<script>` 里。改默认值时用 `filesys_run` 把新值写回该块，保证改动在刷新后仍在（运行时改动走阶段 4 的 `localStorage`）。

## 阶段 6：关闭时隐藏控件

Tweaks 关掉后，面板要完全隐藏——不是变暗，也不是收成角落一小块。这不可妥协：任何可见的编辑模式残余都会让设计显得没完工。

## 阶段 7：验证并总结

在预览中（用 `browser_run` 打开页面）：切换面板开/关；逐个改动每个可调项并确认实时更新；刷新后确认值仍在；确认面板关闭时设计读起来像一份成品。

总结：暴露了哪些可调项及其值类型、默认值、考虑过但排除的可调项（及原因）、这一组是否覆盖了用户的探索轴。
