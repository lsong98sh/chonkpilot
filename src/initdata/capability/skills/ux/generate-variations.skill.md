# 生成变体：产出 3 个以上设计选项

产出同一屏、组件或流程的多个明显不同的设计变体，让用户挑最强片段混搭。当用户要选项、备选、"不同版本"或"给我看几个"时使用。**变体是通往好设计最便宜的路**——一个设计就是一次下注；三个让用户可以否掉不要的、组合要的。

## 阶段 1：确立基线

确认：**变化对象是什么**（屏、组件、流程、视觉处理——范围决定多少个变体才有用）；**已有设计上下文**（变体应扎根于已有的 UI kit/设计体系，除非明确要求打破）；**数量**（默认 3；5–6 是健康上限）；**偏好轴**（视觉、交互、布局还是文案/语气——用户想在哪里加重探索？）。

## 阶段 2：选定变化轴

选 2–4 个维度做变化：视觉处理（色调、密度、阴影、圆角、字重）；布局（居中 vs 非对称、单列 vs 多列、满版 vs 内缩）；交互模型（单页 vs 多步、弹窗 vs 内联）；信息层级；语气；组件风格。写下每个变体在哪些轴上变化——它让对比对用户可读。

## 阶段 3：有意图地构建——从基础到大胆

从最循规蹈矩到最新颖排序：

1. **循规蹈矩。** 匹配既有模式与惯例——最稳妥的选项。
2. **精炼。** 结构不变，推进一两个维度——更大胆的字体、更自信的布局、更富表现力的颜色。往往是用户真正会挑的。
3. **新颖。** 一个真正不同的做法——非常规布局、强烈的视觉隐喻、大胆的审美。它拉伸讨论，并浮现出用户自己都未必知道的偏好。
4. **4–6（如被要求）。** 光谱上的混合，或换一条轴的野牌。

**两端都要覆盖。** 全稳妥浪费时间；全野忽略任务书。

## 阶段 4：做实质变化，而非表面修饰

变体应在布局、层级、主次关系、字体系统、密度、交互方式或文案策略上有别——而不只是按钮颜色、强调色深浅或阴影不透明度。若两个太接近，砍掉一个换成更实质的替代。用户应该能用一句话说清任意两个变体的差别。

**动手前把每个变体具体写清**——不同的调色板家族、不同的字体搭配、不同的布局骨架，逐变体写下来。多样性要靠设计，不能靠碰运气：不指定的话，变体会漂向同一个默认观感（通常是编辑式暖调风格）。对"新颖"变体，刻意挑一个跳出常规分布、有意思的东西。

## 阶段 5：在一个文件里呈现

静态变体并排用单文件 HTML/CSS 排布（本仓没有现成的画布起手组件）；若变体共享结构、只差几条轴，则用 **tweaks**（`make-tweakable`）。对流程类，把每个变体做成画布内的小故事板。**不要产出 v1.html / v2.html / v3.html**——一个文件，所有变体同时可见或可切换。

## 阶段 6：标注并推荐

用一两句话给每个变体配说明（"变体 2——精炼。结构不变，更有表现力的标题字体，更暖的调色板。"）。说明文字是一种思考工具：写不出一句清楚的说明，说明该变体还不够不同。

结尾给一个明确的推荐——由用户决定，但设计师要给出观点（"变体 2 是我的选择——有 1 的稳妥，又更有视觉自信"）。不要含糊地说所有选项一样好；它们并不是。

然后建议下一步：在选定方向上做一轮精修、换一条轴再做一轮变体、用 `make-a-prototype` 做成可交互、或用户准备交付时走 `polish-pass`。
