# 抽取组件：从设计里识别可复用组件

走查一份设计，识别其中隐藏的可复用组件，产出一份组件清单，供用户转化为组件库或设计体系。当用户有一份已完成的页面或流程，想"把它变成体系""建一个组件库"或交接结构化部件时使用。

**页面是组件的排布。** 把它们抽出来，一堆一次性的东西就变得可维护了。

## 阶段 1：确定对象

确定要走的范围——单个设计文件、多页流程，还是整个项目。读所有相关文件，在脑中建立正在使用的视觉词汇模型。

## 阶段 2：走查设计并盘点

逐节地，对每个视觉元素问：

1. **这个确切的模式出现了不止一次吗？**
2. **它有可能出现在别处吗？**（一种卡片样式、表单输入或页头，即便现在只有一处，也可能重复。）
3. **它有变体吗？**（按钮：主/次/幽灵。卡片：带图/不带图。）
4. **它有状态吗？**（hover、active、disabled、focus、loading。）

任一为"是" → 组件候选。把发现归入标准类别：

- **基础**——颜色、间距、字体、圆角、阴影、动效 token（token 级细节见 `design-system-extract`）
- **原子**——按钮、输入、复选框/单选/开关、下拉、标签/胶囊/徽章、头像、图标（在用的尺寸 + 图标集）、链接
- **分子**——表单字段（label + input + 辅助 + 错误）、卡片、toast/alert、弹窗、下拉菜单、tooltip、分页
- **有机体**——页头/导航、页脚、侧栏、标签组、表格、表单、hero、功能网格、空状态
- **模板**——落地页、详情页、列表/索引页、空状态页

## 阶段 3：为每个组件记录

- **名称**——简短、约定俗成（如 `Button`、`FormField`）
- **用途**——一句话说明何时用它
- **变体**与**尺寸**
- **状态**——default、hover、active、focus、disabled、loading（凡适用者）
- **用到的 token**——引用了哪些颜色、间距、字体 token
- **组合**——由哪些其它组件组成（如 `Card` 用到 `Button`）
- **无障碍注记**——键盘支持、ARIA、对比度
- **Do / Don't**——各至少一条（如"不要在一行里叠两个主按钮"）

## 阶段 4：识别缺口

把这些作为交付物的一部分标出来——它们是把设计变成真体系所需的工作：

- **不一致**——三处略有不同的按钮样式而本应一个就够；给出一个规范版本
- **缺失状态**——有 hover 无 focus、没有 disabled 态
- **缺失变体**——如设计里有删除动作却没有危险按钮
- **脱轨值**——超出既定 token 尺度的间距或尺寸；吸附回去

## 阶段 5：产出并交接

把清单写入文件（如 `component-inventory.md`，用 `filesys_run` 的 `INS` 落盘），每个组件一节，按上面的结构组织——一份用户可交给开发者的文档。可选地渲染一个"组件库"页面，展示每个组件及其变体与状态（单文件 HTML/CSS 网格即可）。

然后建议下一步：若 token 还没做，走 `design-system-extract`；把库构建成真实代码；对组件走 `polish-pass`；或对库用 `make-tweakable`。总结：按类别盘点的组件、标出的不一致与缺口、输出文件路径、建议的下一步。
