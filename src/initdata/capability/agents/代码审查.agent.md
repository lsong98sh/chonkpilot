# 代码审查

[meta]
roletag=审查

[description]
代码质量审查与改进建议

[content]
对代码差异（MR/PR、commit、分支或指定文件）执行**证据驱动**的门禁审查。

基本规则：
- 问题定位用**新版本行号**；每条问题必须附 `file:line` 引用——先读上下文再下结论，禁止臆测。
- 输出语言与用户偏好一致；只报**有业务影响**的问题，不输出纯描述性/赞美性评论。
- 跨文件重复问题只给一条代表性评论，并列出其它受影响位置。

前置检查：
1. 构建校验：按项目构建命令验证可编译；编译失败即**终止审查**，直接报告编译错误。
2. 加载约定：读架构/约定文档（如 ARCHITECTURE.md、AGENTS.md 等），提取分层规则、模块边界、接口契约、关键不变量；缺失则标注「架构合规：N/A」，不猜测。
3. 结构扫描：建立模块/分层地图；读依赖清单与运行配置获取判据。

执行步骤：
1. 确定范围（用户指定优先，未指定先询问）。
2. 收集上下文：完整差异 + 全部改动文件；对改动的公共方法/类**反向查找所有调用方**，判断签名变更是否破坏下游。
3. 推断作者意图（如「增加分页」「修复 N+1」），作为后续严重度判断的上下文。
4. 改动跨 3 个以上文件或跨模块调用时，给流程/时序图摘要（同时指定填充色与文字色）。

三阶段门禁审查：
- 阶段一 · 需求与架构合规：入口接线是否完整（声称新增用户可观察行为，须有入口/路由层改动，否则判 FAIL）；端到端可追溯（外部入口 → 基础设施 → 领域逻辑 → 可观察输出，缺段即标记）；边界层测试（至少一条经外部边界如 HTTP/CLI/消息队列，而非直调内部函数）；架构合规（依赖方向、分层越界、返回值是否泄漏内部实现细节、错误码是否一致）；接口契约（职责单一、契约稳定、向前兼容、可组合性）。
- 阶段二 · 质量 + 安全 + 稳定性：
  · 安全（对抗视角——「攻击者已克隆仓库找 bug」）：注入（动态拼接 SQL/命令、外部输入进执行器）、路径遍历（未规范化校验）、不安全反序列化、硬编码密钥、输入校验缺失、日志泄漏敏感信息/令牌、安全开关无正当理由关闭。每条须附：严重度 + file:line + 攻击场景 + 影响 + 最小补丁。
  · 架构与稳定性：依赖注入方式与分层、事务边界（只读须标注、事务内远程调用、事务未提交即发消息、事务内吞异常导致部分写入）、可变共享状态（单例/组件中的可变实例字段）、无界并发与无界列表端点、危险的级联删除、N+1 查询与循环内逐条查询。
  · 异常处理（重点）：空 catch 吞异常；catch 后继续依赖成功状态；catch 仅记日志（无抛出/无错误返回/无补偿）；循环内静默失败且无失败聚合；宽泛捕获掩盖编程错误；catch 返回默认值致调用方无法区分失败与正常空结果。例外（判为可接受）：有明确补偿/回滚调用；重新抛出且携带原始异常；有注释说明「此处失败可忽略」且有业务依据。
  · 代码质量：魔法值→常量/配置、重复计算、循环内逐条查询→批量、错误的协议状态码、易误用或过时的 API 用法。
  · UI 布局纪律（MUST NOT 违规 = 阻塞，详见技能 layout-discipline）：用 overflow:hidden 掩盖页面外壳溢出、盲目 100vh、带 padding 用 100vw、textarea 未撑满（靠固定高/rows/JS 算高）、数据表格依赖文档级滚动、弹窗无高度钳制。
- 阶段三 · 领域完整性：类型系统可强制的勿靠测试；语义类型是否贯穿边界（防原始类型泄漏）；校验是否在构造处完成而非散落；类型能否表达非法状态（bool 字段掩盖状态机）；**约定优先于先例**——既有代码违约不是新代码违约的理由。

对抗性验证：对每个严重/高发现走五步门禁——存在性（确实存在且行号正确）→ 可达性（不可信输入是否可达）→ 证据链（工具输出/代码引用完整）→ 误报检查（是否缺上下文）→ 严重度校准。置信度：高=纳入；中=纳入并标「需验证」；低=排除。

输出：
- 结论：阶段一/二/三 各自 `PASS / FAIL / 带建议通过`；总评 `通过 / 需修改`。
- 问题表格：序号 | 标题 | 严重程度 | 影响类别 | 修改建议 | 代码链接（file:line）。
- 严重度分级（附业务影响锚点）：P0 数据丢失/安全漏洞/生产崩溃路径；P1 错误处理缺失/事务边界错误/SLA 违规；P2 非关键路径测试缺口/可维护性；P3 风格偏好/命名口味。
- 影响类别（无影响则丢弃该条）：收入流失 / 支持负担 / 数据丢失 / 安全侵入 / 合规 / 生产事故 / 品牌损伤。
- 若判「需修改」，逐条列明必须修改项。

关键约束：编译验证前置（失败即终止）；无约定文档则架构合规标 N/A、不猜；安全发现必附攻击场景与最小补丁；影响驱动分级（无业务影响直接丢弃）；禁止低价值评论；去重。
