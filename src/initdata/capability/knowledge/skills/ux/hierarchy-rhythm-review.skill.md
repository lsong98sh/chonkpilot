# 层级与节奏复审

复审当前设计的视觉层级与节奏——这两项最能区分"有意图"与"AI 生成"——并修复发现的问题。**层级引导视线**（先看什么、再看什么、最后看什么）；**节奏让设计显得有意图**（有策略变化的重复）。两者对了，设计扫起来毫不费力。

## 阶段 1：确定对象

复审用户刚编辑或刚问起的那份 HTML/CSS 文件；否则是最近修改的设计文件；若不清楚，就问。读该文件及其引用的样式，并记录媒介（幻灯片/页面/移动端/仪表盘）——规则随语境而变。

## 阶段 2：并行启动两个复审子会话

用 `llm_run` 在一条脚本里通过 `PARALLEL` 块并行委派给「团队成员」中的两个子会话（该场景无合适成员时的后备：由主会话自己依次完成两项复审）。

明确要求两个子会话：报告发现的每一个问题，包括不确定与低严重度的，并对每项给出置信度与严重度估计。覆盖是子会话的职责；过滤放到汇总阶段（阶段 3）。

### 子会话 1：层级复审

对每一屏、每一页或每个主要章节：

1. **主/次/三级。** 应该先看什么、再看什么、最后看什么？若看不出来，层级就是坏的。
2. **尺寸。** 标题明显大于正文；主 CTA 大于次要操作。把"同类内容尺寸差异很大"（不一致）与"不同重要度的内容尺寸相近"（平）都标出来。
3. **颜色。** 主操作用饱和品牌色，次要用中性色，弱化项用浅灰。把"全都一个颜色"（无信号）与"不重要的元素最亮"（信号错）标出来。
4. **字重。** 大标题粗、正文常规、说明文字细。把"全都粗"与"全都常规"标出来。
5. **位置。** 视线从左上开始（LTR）；最重要的内容应在黄金位置。把"主元素被埋到右下"标出来。
6. **密度。** 松间距表示"注意这里"，紧间距表示"这是辅助"。把"重要内容挤成一团、填充物却在透气"标出来——那是反的。
7. **5 秒测试。** 首次到访的用户应在 5 秒内知道该看什么、该做什么。

### 子会话 2：节奏复审

对整份文档：

1. **间距尺度。** 所有 padding/margin/gap 值都吸附到一致尺度（4px 或 8px 的倍数）。列出实际隐含使用的尺度，并标出离群值（`padding: 7px`、`gap: 13px`）。
2. **字号尺度。** 标出随意尺寸（16/20/24 的设计里出现 `17px`、`23px`）。
3. **重复。** 网格里的卡片、列表项、功能块共享 padding、gap、尺寸、结构。标出"微妙地不同"的近似重复——要么完全一致，要么刻意不同，不能模棱两可。
4. **策略性变化。** 长页面或 deck 偶尔打破自身模式（背景变化、更宽的章节、居中 CTA）。标出"完全一致"（单调）与"每节都不同"（混乱）。
5. **调色板纪律。** 3–5 种颜色加明暗变化。标出 8 种以上不同颜色，或不同地方出现略有差异的蓝/灰。
6. **章节结构。** 章节视觉上可区分（背景变化、分隔线、间距变化）但保持一致。标出"毫无分隔"与"分隔方式过多"。
7. **对齐。** 标出偏离网格几个像素的元素——那不是刻意的偏移，而是不一致的边距。

## 阶段 3：汇总并修复

等两个子会话返回，汇总发现，然后直接修（用 `filesys_run` 的 `RPL`/`PTC`/`APD` 改文件）：

- 随机间距/字号 → 吸附到文件的尺度（缺失就定义一个——4px 或 8px 的倍数）
- 层级平 → 引入对比（更大的标题、更突出的主 CTA、一致的正文中性色）
- 层级反了 → 交换信号（把喧闹的不重要元素压下去，把被埋的主元素移到该在的位置）
- 单调 → 引入一处策略性破格；混乱 → 收敛到最强的那个模式

对有歧义的情况，倾向更果敢的层级——过强比过弱更容易调回来。

总结：按类别列出发现并修复的问题、需用户复核的判断、开放的建议。
