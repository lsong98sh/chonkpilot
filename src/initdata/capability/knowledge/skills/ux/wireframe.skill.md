# 线框图：快速探索多个想法

产出低保真线框图或故事板，在投入高保真设计前探索一个流程、布局或想法。当用户想"探索选项""先草草画一下""看几个方向"，或问题足够开放、直接做高保真会白费功夫时使用。**线框图是一次性的**——其价值在于方案的广度，而非任何一张的保真度。

## 阶段 1：理解目标

确认：**要探索什么**（一个页面、一个流程、一个导航模式、一套信息层级、一种交互模型）；该页面或流程的**用户目标**；**约束**（移动端还是桌面端、已有上下文还是全新、不可妥协的元素）；**变体数量**（每轮最少 3 个，上限 5–6 个）；**变化轴**（布局？密度？步骤数？CTA 位置？）。

如果用户只说"给注册流程画个线框图"，就提出 2–3 个变化轴（例如"单页表单 vs 多步向导 vs 渐进式披露"），并询问要探索哪一个。

## 阶段 2：确立线框图约定

坚持线框图的视觉语言，让用户把它们读成线框图，而不是"坏掉的高保真"：

- **仅灰阶**——黑、白、2–3 种灰；不用品牌色
- **系统无衬线字体**——不带字体个性；此时用户还不该形成字体偏好
- **内容区域用方框**，并加标签（"标题""图片""功能卡"）
- **图片用斜纹占位块**配等宽字体标签（`product shot 1200×800`）——绝不用真实图片；它们会抢焦点
- **用 Ipsum 或骨架文案**——此阶段不放最终文案
- **欢迎标注**——在关键决策处加编号标注

这是唯一允许出现"手绘感" SVG（矩形、线条、简单图标）的场景——一切都处于同一低保真度。

## 阶段 3：勾画变体

产出**至少 3 个**在既定变化轴上不同的变体。单页面变体用单文件 HTML/CSS 并排排布（本仓没有现成的画布起手组件，直接写 HTML/CSS/SVG）；流程类变体做成小故事板（每个 3–5 个画面）。

在布局（居中/分屏/网格）、信息密度、流程结构（单页/多步/渐进式披露）、CTA 位置或导航模式上做区分。从最循规蹈矩到最新颖排序——当稳妥选项与更冒险的选项并排时，用户更容易挑到有意思的东西。

在勾画前先写下每个变体的区分性结构。若不明确指定，各变体会趋同到几乎一样的布局——要把差异做成刻意的，并至少让其中一个真正"跳出常规分布"。

## 阶段 4：标注

为每个变体加 2–4 条标注，放在变体旁边（不要单独一份文档），让用户把变体与其理由一起读：

```
- 变体 1（单列向导）：简单、聚焦，但慢
- 变体 2（单页表单）：路径最快，首屏负担重
- 变体 3（渐进式披露）：两者兼顾，JS 状态更多
```

## 阶段 5：记录决策并交接

用户选定方向后，记录：选中的变体（或其混合）、吸引他们的点、他们明确否掉的点，以及浮现出的新约束。这份记录就成为后续高保真工作的简要任务书。

然后建议 `make-a-prototype`（高保真可交互）、`make-a-deck`（若线框图是为演示服务的）或再做一轮低保真。不要在那些线框图本身投入高保真打磨——它们已完成使命。

总结：产出的变体、变化轴、建议的下一步、浮现出的开放问题。
