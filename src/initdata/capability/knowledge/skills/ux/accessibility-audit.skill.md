# 无障碍审查：WCAG 与包容性设计复审

对照 WCAG 与包容性设计复审当前设计，覆盖对比度、语义结构、键盘导航、动效与表单，并修复发现的问题。**好的无障碍就是好的设计——它让所有人受益。**

## 阶段 1：确定审查对象

审查用户刚编辑或刚问起的那份 HTML 文件；否则是最近修改的设计文件；若不清楚，就问。端到端读它（用 `file_read`），并记录所用框架、期望级别（默认 WCAG AA）以及任何用户声明的约束。

## 阶段 2：并行启动四个复审子会话

用 `llm_run` 在一条脚本里通过 `PARALLEL` 块并行委派给「团队成员」中的四个子会话（该场景无合适成员时的后备：由主会话自己依次完成四项），每项都带上完整文件内容。

明确要求每个子会话：报告发现的每一个问题，包括边缘与低严重度的，附置信度与严重度估计。覆盖是子会话的职责；过滤放到汇总阶段（阶段 3）。

### 子会话 1：对比度与颜色

1. **文字对比度。** 常规文字（18px 以下）需 4.5:1；大文字（18px+ 粗体或 24px+）需 3:1；UI 组件（按钮、图标、焦点环）需 3:1。对任何能解析出的颜色组合算出实际比值；把每个不达标的都标出，附比值与所需下限。
2. **仅靠颜色传达。** 标出任何只靠颜色传达的状态——无图标的绿/红、无下划线的链接、无图例或标签的图表。
3. **困难组合。** 红+绿（最常见的色盲）、明度相近的蓝+黄、白底浅灰、明度相近的彩底彩字。
4. **白与黑。** 标出 `#000000` 上的纯 `#FFFFFF`；更宜用细微调色（`#FAFAFA` / `#1A1A1A`）。这是风格建议，不是 WCAG。

### 子会话 2：语义化 HTML 与结构

1. **标题层级。** 恰好一个 `<h1>`，不跳级；标题描述内容，而非视觉大小。
2. **角色用对元素。** 用 `<button>` 而非 `<div onclick>`；用 `<a href>` 而非样式化的 `<div>`；用 `<label for>` 关联输入；用 `<nav>`/`<main>`/`<article>`/`<section>`/`<aside>` 地标。
3. **每张有意义的图片都要 alt 文本。** 装饰性图片用 `alt=""`；有意义的图片描述它传达什么（`alt="无线耳机，侧视图"` 而非 `alt="产品"`）。
4. **表单标签。** 每个输入都有相关联的 `<label>`（或 `aria-label`）。仅有占位文字不算标签。
5. **只在语义化 HTML 做不到时才用 ARIA。** 标出本可用 `<button>` 却写成带 `role="button"` 的 `<div>`。

### 子会话 3：键盘导航与焦点

1. **键盘可达。** 一切可点击之物都能 Tab 到达——仅 hover 的菜单、仅鼠标的下拉、键盘不可达的弹窗都算失败。
2. **逻辑 Tab 顺序。** 遵循阅读顺序；标出大于 0 的 `tabindex` 值。
3. **交互模式。** 弹窗按 Escape 关闭；下拉用 Enter/Space 打开并用方向键导航；表单可在字段上按 Enter 提交。
4. **可见焦点环。** 标出无可见替代方案的 `outline: none`——替代方案需与相邻背景对比度达 3:1。优先用 `:focus-visible` 而非 `:focus`。
5. **跳转链接。** 在重复导航较多的页面上建议"跳到主内容"。

### 子会话 4：动效、表单与杂项

1. **尊重 `prefers-reduced-motion`。** 超过几百毫秒的动画需要一个 `@media (prefers-reduced-motion: reduce)` 块来缩短或移除它们。
2. **不闪烁** 每秒超过 3 次（光敏性癫痫风险）；标出并要求提供暂停控件。
3. **表单错误**要具体（"邮箱地址无效"而非"无效"），视觉上并与 `aria-describedby` 一起绑定到对应字段。
4. **必填字段**用文字和/或图标加 `required` 属性标记，不靠颜色。
5. **输入类型与自动填充。** 用 `type="email"`、`type="tel"`、`autocomplete` 属性以支持自动填充和移动端键盘。
6. **点击目标**在触摸面上至少 44×44px。

## 阶段 3：汇总并修复

等四个子会话全部完成。把它们的发现汇总成一份去重清单，并逐项直接修复（用 `filesys_run` 改文件）。对边缘情况（如对比度 4.4:1），照样应用修复——无障碍是地板，不是天花板。若某项是明显的误报或超范围（如子会话标出了你改不了的第三方嵌入内容），记录并跳过。

总结：按类别（对比度/语义/键盘/动效-表单）列出发现的问题、已修的问题、以及留给用户的项。
