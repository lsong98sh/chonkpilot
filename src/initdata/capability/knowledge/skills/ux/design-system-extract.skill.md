# 抽取设计体系：从来源中提取 token

从品牌参考、代码库或截图中抽取设计 token（颜色、排版、间距、圆角、阴影），产出结构化的 token 文件。当要开始的设计工作需匹配一套既有视觉语言时使用。token 存在后，后续设计引用它们——无需再向用户重复索要数值，也能保持体系一致。

## 阶段 1：确定来源

用户可能提供代码库（读主题文件：`theme.ts`、`tokens.css`、`_variables.scss`、`tailwind.config.js`、设计体系源码）、线上站点或截图、品牌指南（PDF、Figma、文档）或既有的 UI kit 项目。若未指定，就问——臆造的 token 违背初衷。

## 阶段 2：按类别抽取

从来源中抓取具体值——绝不要猜。

### 颜色

- **品牌主色与强调色**（含已定义的明/暗变体）
- **语义色**——成功、警告、错误、信息（含已定义的浅色背景）
- **中性色阶**——通常 9–11 级，从近白到近黑，调性一致（暖/冷/中性）
- **表面色**——背景、前景、卡片、遮罩、边框

每一项：hex（或 oklch）值、来源中的名字、以及有记录的用途。把不一致标出来——多个略有差异的蓝、调性不统一的中性色——作为发现交给用户。不要悄悄合并它们；不一致本身就是信息。

### 排版

- **字体族**——无衬线、衬线、等宽，附完整回退栈
- **字号**——实际在用的尺度，而非通用尺度
- **字重**——只列实际加载了的
- **行高**——至少：标题紧（~1.1）、正文常规（~1.5）、长文松（~1.7）
- **字距**——通常只对全大写标签有意义
- **命名字体样式**（"Heading 1""Body Large""Caption"）若来源有定义

### 间距

实际在用的尺度（常见基准：4px 或 8px，通常到 64–128px）。若来源对 inset / inline / block / 组件间有分开的尺度，全部抓取。

### 圆角与阴影

圆角值（通常 3–5 个不同值：`0 / 4 / 8 / 12 / 9999`）以及高度尺度，含完整 CSS 值（偏移、模糊、扩散、颜色、不透明度）。

### 其它 token（若存在）

z-index 尺度、动画时长与缓动、断点、容器宽度。

## 阶段 3：产出 token 文件

写一个 `tokens.css`——或匹配来源的格式与命名惯例（带类型导出的 `tokens.ts`、`tokens.json`、Tailwind 配置扩展）。按类别分组并用清晰名字（用 `filesys_run` 的 `INS` 落盘）：

```css
:root {
  /* 品牌 */
  --color-primary: #...;   --color-accent: #...;
  /* 语义 */
  --color-success: #...;   --color-error: #...;
  /* 中性色 */
  --color-gray-50: #...;   /* … 直到 --color-gray-900 */
  /* 表面色 */
  --color-bg: #...;   --color-surface: #...;   --color-border: #...;

  --font-sans: "...", -apple-system, sans-serif;
  --text-base: 16px;       /* 来源中的完整字号尺度 */
  --weight-regular: 400;   /* 只含实际加载的字重 */
  --leading-normal: 1.5;

  --space-1: 4px;          /* 来源中的完整间距尺度 */
  --radius-md: 8px;
  --shadow-md: 0 4px 6px rgba(0, 0, 0, 0.1);
}
```

## 阶段 4：记录发现

总结：**用到的来源**；**抽取的类别**；**缺口**——来源未定义的 token 集（这些是用户的决策，不要悄悄填上）；**不一致**——值得合并的近似重复值或脱轨离群值；**建议的下一步**——通常是和用户一起过一遍这个文件，然后在后续设计中用它。
