# 交互状态核查

核查每个交互元素是否具备完整状态集（default、hover、active、disabled、focus、loading）以及过渡与反馈；补齐缺失的。**没有状态反馈的交互元素会显得是坏的**——没有 hover 的按钮看起来像标签；焦点环被移除会挡住键盘用户。这是设计交给用户前的一道安全网。

## 阶段 1：盘点交互元素

走查设计，列出每一个交互元素：按钮（含 `role="button"` 与任何带点击处理器的元素）、链接、表单输入、开关（复选框、单选、滑动开关）、可点击的卡片或行、导航项（标签页、侧栏链接、面包屑）、以及自定义控件（下拉、手风琴、弹窗、popover）。

## 阶段 2：逐元素核查状态

对每个元素核查以下六个方面。全部标出来，包括边缘情况——对拿不准的发现标一个置信度，而不是悄悄丢掉。

1. **Default。** 静止状态下就明显可交互：按钮的填充或边框与正文文字区分；链接看起来像链接；输入有可见边框或填充。把"只有 hover 才显出可交互"的元素标出来——触摸与键盘用户永远不会 hover。
2. **Hover。** 光标移入时有视觉变化——至少是颜色变化；更好的是颜色 + 阴影 + 轻微位移（`translateY(-2px)`）。不要用降低不透明度做 hover；那读起来像 disabled。
3. **Active / 按下。** 更深的颜色、轻微缩小（`transform: scale(0.98)`）或回到底线——在动作完成前确认点击已登记。
4. **Disabled。** 降低不透明度（~0.6）、无 hover 效果、`cursor: not-allowed`，与 default 和 hover 都不同。若因条件暂时禁用（"填完所有必填项"），说明*为什么*——tooltip、就地提示或 `title` 属性。
5. **Focus。** 通过 `:focus-visible`（不是裸 `:focus`）给出可见环：与相邻背景对比度 3:1，至少 2px 粗、偏移 2px。`outline: none` **绝不**在不给替代方案时使用。
6. **Loading**（针对触发异步工作的元素）。点击时禁用以防重复提交，把标签换成 spinner 或"加载中…"，完成后恢复。渲染时拉取的数据要有骨架屏、spinner 或进度指示。

## 阶段 3：核查过渡

每次状态变化都平滑过渡，而非硬切（`transition: background 0.2s ease, transform 0.2s ease, box-shadow 0.2s ease`）：

- **0.15–0.3s** 用于状态变化（hover、focus、active）；**0.3–0.5s** 用于入场/退场（弹窗、抽屉、toast）
- 微交互避免超过 0.5s（会显得迟钝），也避免 0s/无过渡（显得坏）
- 动效较重的过渡包在 `@media (prefers-reduced-motion: reduce)` 里

## 阶段 4：核查动作反馈

每个动作都显示可见结果：提交成功（toast、就地提示或带确认的跳转）、提交失败（明确的错误，字段相关时就绑到该字段）、校验错误（在失焦或提交时出现，修好后清除）、状态变化（立即视觉更新）。把"无声成功"和"无声失败"都标出来——两者都显得坏。

当前状态也要可见：当前页面或标签页、选中项、生效的筛选或排序，都要视觉上可区分。

## 阶段 5：应用修复并总结

用设计体系的 token 补齐每个缺失的状态或反馈元素。体系未定义时用：hover 深 10–15%（或 `color-mix`）；active 再深 10% 或 `scale(0.98)`；disabled 不透明度 0.6 + `cursor: not-allowed`；focus `outline: 2px solid var(--color-primary); outline-offset: 2px`；过渡 `0.2s ease`。若正确状态不明显（如切换按钮"在 active 上的 hover"），做一个判断并注明（用 `filesys_run` 改文件）。

总结：盘点了哪些元素、按类别补了哪些状态、新增或归一了哪些过渡、补了哪些反馈、哪些判断需要用户复核。
