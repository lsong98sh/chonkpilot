# 打磨收尾：设计终点的质量关口

在一份设计展示给干系人或交付前，跑一遍全面的质量检查。**打磨过的设计与未打磨的设计是同一个想法在不同用心程度下的执行——而人们真正看到的就是这个差距。** 本技能是四个更窄复审技能的总纲；把它当作交付前的最后一道关口。

## 阶段 1：确认范围

打磨用户刚完成或刚问起的那份 HTML 文件；否则就是项目的主交付物；若不清楚，就问。读它（用 `file_read`），并记录媒介（幻灯片/页面/移动端/仪表盘）、部署语境（内部/面向客户/营销）以及任何已声明的约束。

如果设计明显还在半途（布局破碎、章节缺失、占位内容仍在迭代），就指出来，并询问是现在打磨，还是等结构稳定后再打磨。

## 阶段 2：并行启动四个复审子会话

用 `llm_run` 在一条脚本里通过 `PARALLEL` 块并行委派给「团队成员」中的四个子会话（该场景无合适成员时的后备：由主会话自己依次完成四项复审）。每个子会话运行一个等价于独立复审技能的任务，范围限定在这份文件。

明确要求每个子会话：**报告发现的每一个问题，包括不确定与低严重度的，并对每项给出置信度与严重度估计。** 覆盖是子会话的职责；过滤与排优先级放到阶段 3。自我审查掉"小"发现的子会话会悄悄拉低召回。

1. **无障碍审查**（`accessibility-audit`）：对比度与颜色（WCAG AA 底线、仅靠颜色传达、纯白/纯黑）；语义化 HTML 与结构（标题层级、button vs div、label、alt 文本、ARIA 克制）；键盘导航与焦点（可达性、Tab 顺序、可见焦点）；动效、表单与点击目标尺寸。
2. **AI 味检查**（`ai-slop-check`）：过激渐变；emoji 装饰；默认左边框卡片；手绘 SVG；滥用默认字体（Inter、Roboto、Arial、Fraunces、裸系统字体栈）；把"编辑式暖调"当无声默认（奶油色 + 衬线标题 + 赤陶色，且无品牌理由）；纯白/纯黑；臆造颜色；脱轨间距。
3. **层级与节奏复审**（`hierarchy-rhythm-review`）：通过尺寸、颜色、字重、位置、密度区分主/次/三级，以及 5 秒测试；间距与字号尺度纪律、重复、策略性变化、调色板纪律、章节结构、对齐。
4. **交互状态核查**（`interaction-states-pass`）：每个元素的 default/hover/active/disabled/focus/loading；过渡时长（0.15–0.3s 的状态变化，入场/退场更长）；`prefers-reduced-motion`；动作反馈与状态可见性。

## 阶段 3：汇总、去重、排优先级

等四个子会话全部返回。合并重复发现（如 accessibility 与 interaction-states 都报的"焦点环被移除"）。归入：

1. **阻断项**——无障碍失败（对比度低于 WCAG、缺键盘支持、焦点环被移除、缺 label）。这些会让真实用户无法使用设计；全部修掉。
2. **质量问题**——AI 味套路、层级破碎、交互状态缺失。这些会拉低设计质感；全部修掉。
3. **打磨建议**——更细微的改进（色调偏移、间距尺度收紧）。在范围内就应用；超出范围就标记出来。

## 阶段 4：修复并复检

直接修掉每一个阻断项与质量问题（用 `filesys_run` 的 `RPL`/`PTC`/`APD` 改文件）。对有歧义的修法（如设计用了 Inter 但未声明品牌字体），挑一个站得住脚的默认值并注明，以便用户覆盖。对明显的误报（如第三方嵌入内容的对比度）做记录并跳过。

然后复检高风险区域：对比度修复是否把品牌色冲淡了？新加的焦点环是否与相邻内容重叠？主 CTA 现在是否真的显得是主操作？看着不对的就修；拿不准的就标出来。

## 阶段 5：最终总结

简洁汇报——用户可再要求细节：

- **判定**——"可交付" / "用户确认被标记的决策后可交付" / "打磨无意义，需再迭代"
- **已修阻断项与已应用的打磨**——按类别计数
- **待定的开放决策**——需要拍板的判断题（字体选择、色调偏移、强调程度）
- **超出范围**——注意到了但未动（文案修改、内容增补、新功能）
